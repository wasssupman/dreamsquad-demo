# Phase 7 스코프 제안 초안

> Superseded: 확정/구현 완료 내용은 `PHASE7.md`에 통합됨. 본 문서는 히스토리/리뷰 기록으로만 유지.

이 문서는 `docs/PRD.md`, `docs/TRD.md`, `docs/PHASE6.md`와 기존 Phase 문서 제목/범위를 바탕으로 작성한 **후보 제안**이다.
아직 Phase 7 구현 범위를 확정하지 않으며, 아래 3안 중 하나를 선택해 다음 상세 문서로 좁히는 것을 목표로 한다.

## 1. 현재 상태 요약

- Phase 0에서 실시간 디펜스 기본 루프가 들어왔다: 적 이동, 방어 유닛 자동 공격, 승패 판정, 결과/로그.
- Phase 1에서 드래프트가 들어왔다: 10종 풀에서 7종 픽, 재시작/리드래프트 흐름, draft 로그.
- Phase 2~4에서 전투 해석력이 올라갔다: 고정 스킬 3종, Effects 맥락 활성화, 투사체/체력바, 배치 시 효과/인접 시너지, 적의 방어 유닛 공격.
- Phase 5에서 수직 슬라이스 완성도가 올라갔다: 3분 타이머, 더미 봇 스코어 비교, 측정 프로토콜 연동, 헤드리스 시뮬레이션 하네스, Billboard 기반 비주얼 업그레이드.
- Phase 6에서 리소스 제약이 들어왔다: 배치 페이즈, 코스트 충전/소모, CostDisplay, 코스트 부족 피드백, `cost_spent` 로그 확장.

## 2. Phase 7 후보

### A. 코스트 경제 확장

한 줄 요약: Phase 6에서 막 도입한 코스트를 더 게임다운 판단 축으로 확장한다.

이 시점에 하기 좋은 이유
- Phase 6 직후라 코스트 관련 UX와 런타임 경계를 아직 작은 비용으로 다듬을 수 있다.
- `PRD.md`의 H2와 직접 연결된다. 지금은 "쓴다/못 쓴다" 중심이므로, 보너스/회수/예외 규칙이 붙으면 실제 판단 폭이 넓어진다.
- `PHASE6.md`에서 명시적으로 유보한 "코스트 보너스 이벤트"가 자연스러운 다음 후보로 남아 있다.

이 시점에 하기 나쁜 이유
- 코어 경제를 먼저 넓히면 아직 부족할 수 있는 측정 루프나 콘텐츠 읽기성이 뒤로 밀릴 수 있다.
- 보상 규칙을 성급히 늘리면 H2는 풍부해져도 H1/H3 해석은 오히려 흐려질 수 있다.

예상 작업 덩어리
- P7-01: Phase 6 실제 플레이 피드백 기반 코스트 규칙 정리
- P7-02: 보너스 코스트 발생 조건 1종 도입
- P7-03: UI/로그에 보너스 코스트 원인 노출
- P7-04: Restart/Result/Replay 흐름에서 경제 상태 일관성 점검
- P7-05: 최소 밸런스 튜닝 및 회귀 테스트

대략 `P7-01 ~ P7-05` 정도.

### B. 측정·검증 라운드 강화

한 줄 요약: 새 기능보다 먼저 H1/H2/H3를 더 잘 읽을 수 있게 계측, 리플레이, 테스트 루프를 다듬는다.

이 시점에 하기 좋은 이유
- Phase 6까지 오면서 드래프트, 스킬, 시너지, 타이머, 코스트가 모두 들어와서 이제야 검증 루프를 본격적으로 돌릴 수 있다.
- `PRD.md`는 처음부터 "기획 검증용 프로토타입"을 강조한다. 지금 시점의 가장 보수적이고 해석 가능한 다음 스텝이다.
- `PHASE5.md`의 측정 프로토콜/하네스와 자연스럽게 이어진다.

이 시점에 하기 나쁜 이유
- 플레이어가 체감하는 신규 기능이 적어서 진행 체감이 약할 수 있다.
- 실제 전투 콘텐츠가 충분히 변별적이지 않다면, 측정만 정교해져도 얻는 인사이트가 제한될 수 있다.

예상 작업 덩어리
- P7-01: 현재 로그 필드와 가설 매핑 재정리
- P7-02: 반복 플레이 비교용 뷰 또는 분석 스크립트 정리
- P7-03: 실패 원인 가시화 보강안 정리
- P7-04: Android/에디터 기준 검증 체크리스트 정리

대략 `P7-01 ~ P7-04` 정도.

### C. 콘텐츠 밀도 확장

한 줄 요약: 현재 루프는 유지한 채, 공격 패턴/유닛 데이터/전투 상황의 조합 폭을 넓혀 수직 슬라이스를 더 검증 가능한 상태로 만든다.

이 시점에 하기 좋은 이유
- PRD의 핵심 검증은 반복 플레이 속 선택 개선이다. 같은 시스템이라도 패턴과 상황의 폭이 늘어야 드래프트/배치 판단 신호가 더 또렷해질 수 있다.
- 기존 아키텍처는 데이터 주도와 맥락 분리를 전제로 깔아두었으므로, 신규 시스템 추가보다 상대적으로 안전한 확장 후보다.

이 시점에 하기 나쁜 이유
- 콘텐츠를 늘리기 시작하면 밸런스, 가독성, 로깅 요구가 같이 커져 Phase 7이 쉽게 비대해질 수 있다.
- 아직 코스트 경제나 검증 루프가 덜 정리된 상태라면, 콘텐츠 추가가 문제 위치를 더 흐릴 수 있다.

예상 작업 덩어리
- P7-01: 어떤 데이터 축을 늘릴지 결정
- P7-02: 후보 패턴/유닛/상황 데이터 작성
- P7-03: UI/로그에서 새 데이터 식별 가능 여부 점검
- P7-04: 반복 플레이 시나리오와 결과 비교 기준 정리
- P7-05: 최소 밸런스 패스
- P7-06: 회귀 테스트

대략 `P7-01 ~ P7-06` 정도.

## 3. 선택 요청

아래 중 하나를 골라주면 그 방향으로 `PHASE7.md` 초안을 좁히겠다.

- A: 코스트 경제를 먼저 확장한다.
- B: 새 기능보다 측정·검증 라운드를 먼저 강화한다.
- C: 시스템 추가보다 콘텐츠 밀도를 먼저 늘린다.

현재 문맥만 보면 **가설 검증 우선이면 B**, **플레이 감각 보강 우선이면 A**, **수직 슬라이스 폭 확장 우선이면 C**가 맞다.
