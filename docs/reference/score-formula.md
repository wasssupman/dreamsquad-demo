# 점수 산식 — 어디서 나오고 얼마인가

> 한 판 끝나면 나오는 최종 점수의 전부. 판의 성적은 `Scripts/Core/MatchTally.cs` 값 하나로
> 취합되고(조립 지점 = `BattleBridge.BuildTally`), 서버로 가는 수는 그 `SubmissionScore` 하나다.
> 상세 설계·결정 이력은 `docs/spec/three-minute-kill-race/`(현행) ·
> `docs/spec/three-minute-survival/`(직전) · `docs/spec/battle-score-formula/`(구 3축).

## 한 줄 요약

**잡은 만큼 받는다. 1킬 = 1점, 예외 없음.**

```
총점 = 제출값 = 화면 숫자 = 잡은 마리 수
```

- **보스도 1점, 분열체도 1점.** 등급으로 점수를 가르던 `killScore` 축은 은퇴했다
  (2026-08-16 사용자 결정 A). 강함의 차이는 체력·공격력·등장 빈도로 표현한다.
- **놓친 적은 0점.** 골을 뚫은 적은 "잡은 것"으로 안 친다(`EnemyKilledEvent` 미발화).
  각성치도 같은 이유로 안 들어온다 — 이것이 **유일한 페널티**이자 그 전부다.
- **감점이 없다.** 유출·마음 붕괴·조기 제출 어느 것도 점수를 깎지 않는다.
- **만점이 고정값이 아니다.** 웨이브 구성이 바뀌면 총합도 바뀌므로 이 숫자에 의존하는 코드를
  만들면 안 된다.

## 판을 끝내는 것은 둘뿐

**패배가 없다.** 3분 고정이고 전원이 완주한다.

| 종료 | `Outcome` | 비고 |
|---|---|---|
| 3분 만료 | `complete` | 자연 종료 |
| 유저 「제출」 | `submitted` | 경과 60초 후 개방(P1). 무페널티 |

시스템이 판을 끝내는 판정은 **하나도 없다.** `BattleBridge.EndMatch` 를 부르는 코드를
새로 만들면 그게 곧 패배 조건의 부활이다.

> **은퇴한 판정(2026-08-16)**: 골 붕괴 즉시 패배 · 스트레스 상한 패배 · 적 마음 붕괴 승리 ·
> 웨이브 전멸 승리 · 타이머 만료 시 `안정도 ≥ 적마음` 승패 비교.

## 마음(골 안정도)은 점수·판정에 관여하지 않는다

- 적이 골에 도달하면 **거기 남아 마음을 때린다**(그 적의 공격력으로 지속 피해). 이때는
  아직 필드에 살아 있으므로 **잡을 수 있다** — 유출이 아니다.
- 예외: 공격 수단이 없는 돌격형(`Enemy_Runner`·`Enemy_Swift`)은 몸을 부딪고 사라지며
  `stabilityDamage`(일반 1 / 엘리트 2 / 보스 5)만큼 1회 피해를 준다.
- **마음 HP 0 = 그 셀이 유출 지점으로 열린다.** 그때부터 그 문으로 오는 적은 잡을 기회 없이
  사라진다 = 못 번 점수. **판은 계속된다.**
- 최대치는 `Deck_*.asset` → `goalStabilityMax`. 정본은 `GoalTowerHealth` 싱글턴.
- 화면에 **게이지로 그리지 않는다**(균열 연출). 설계는 `docs/spec/goal-tower-siege/`.

## 서버에 보내는 수 = 화면에 보이는 수

가공이 없다. 서버는 int 점수 하나만 받고(`TournamentApi`), 거기 들어가는 값이 곧 총점이다.

```
제출값 = 잡은 마리 수     // 전투 중 HUD 숫자와 완전히 같은 수
표시값 = 서버가 준 score  // 변환 없음
```

- **동점은 그냥 동점이다.** 정렬은 서버 규칙에 맡긴다.
- 상한·saturate 도 없다 — 인코딩이 만들던 제약이었다.
- 구 인코딩 기록(`1,000,047,599` 같은 값)은 **변환하지 않는다**(사용자 결정).
  리더보드·히스토리에 원값 그대로 뜨고, 룰이 다른 데모 기록이라 그대로 둔다.

> **은퇴한 인코딩(2026-08-07 ~ 08-15)**: `1,000,000,000 + killScore합 × 1000 + 안정도permille`
> 로 동점 판정을 값에 실었다. 안정도가 점수에 섞이는 것을 없애면서 디코딩 3곳
> (`ScoreMath.DisplayScore`)과 함께 제거했고, 이어 `ScoreMath` 자체가 `MatchTally` 로
> 흡수됐다(점수 정본이 둘이 되지 않게).

## 마감 파이프라인 — 취합 → 기록 → 통보 → 표시

종료 2경로는 **판정만** 하고 `BattleBridge.EndMatch(outcome)` 한 곳으로 들어온다.

| 단계 | 어디 | 하는 일 |
|---|---|---|
| 취합 | `BattleBridge.BuildTally` | 흩어진 재료(처치 수·안정도·도달 웨이브·유출)를 `MatchTally` 하나로 |
| 기록 | `BattleLogger.SetResult/SetScore` | 로컬 `GameLogs` 배틀 로그 |
| 통보 | `TournamentMatchReporter.ReportResult` | `tally.SubmissionScore` 를 서버로 |
| 표시 | `ResultScreen.Show` | 총점 + 3줄 |

**제출이 표시보다 앞이라는 순서는 계약이다** — 화면을 기다리다 앱이 죽으면 기록이 사라진다.

## 값 바꾸는 곳

| 값 | 위치 |
|---|---|
| ~~적별 처치 점수~~ | **없다.** 1킬 = 1점 고정 |
| 적별 각성 보상 | `Data/Enemies/*.asset` → `awakeningReward` |
| 적별 안정도 피해 | 같은 파일 → `stabilityDamage` (코드 기본값 1) |
| 마음 최대치 | `Scripts/Data/Decks/Deck_*.asset` → `goalStabilityMax` |
| 제한시간 180초 | 같은 파일 → `timerDurationSec` |
| 제출 개방 시점(P1) | 경과 60초 — `docs/spec/three-minute-kill-race/3_player_submit.md` |

## 전투 중 화면 위 점수

**우상단 HUD 숫자 = 최종 점수**다. 잡을 때마다 **1** 오르고, 전투가 끝나면 그 숫자가 그대로
결과 화면의 총점이자 서버에 올라간 수다. 합산 연출(탤리)은 제거됐다 — 더할 축이 없다.

버스트 플래시 임계(`ScoreHudView.burstScoreThreshold`)는 4다. 1킬 1점이라 이제 그냥
**「4마리 동시 처치」** 를 뜻한다.

## 결과 화면에 뭐가 뜨나

총점 아래 세 줄:

```
처치          47기
남은 안정도    12 / 20 (60%)
도달 웨이브    14
```

「점수」와 「처치」가 같은 수이므로 두 줄 통합은 `three-minute-kill-race` unit 4 가 정리한다.
안정도 줄은 «얼마나 버텼나» 를 읽히게 하는 정보다 — 점수와 무관하다.
