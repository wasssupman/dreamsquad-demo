# unit 7 — LOS 경로 평활화 (D2-(a))

## 목적

**진짜 직선 이동.** 이 spec 의 검증 질문에 답하는 unit 이다.

unit 4 로 L 자는 사라졌지만 방향이 **8단계로 양자화**돼 있다. 기울기가 정확히 45°가 아니면 대각 구간과 직축 구간이 꺾여 붙는다("꺾인 빗변"). 8×6 삼각형이면 대각 6칸 + 직선 2칸 = 10.49 로, 진짜 빗변 10 보다 5% 길다.

## 구현

### 후보 생성 = D2-(a)

flow field 는 **명시 경로를 주지 않는다.** string pulling 은 경로가 있어야 하므로, **필드를 따라 앞으로 K 셀 전진**시켜 후보 지점을 만든다(`DefaultLookahead = 8`).

- (b) per-agent A\* 는 더 정확하지만 에이전트마다 경로를 유지해야 한다
- (c) 골로 직접 레이캐스트는 가장 싸지만 중간 장애물에서 **코너 스치기가 안 나온다**

(a)는 필드를 유지한 채 경로를 **국소적으로만 물질화**한다. D1-b 의 재빌드와 자동으로 정합한다(재빌드된 필드를 그대로 따라가므로).

### 가시선 판정에 반지름을 포함한다

선분만 검사하면 **몸통이 걸리는 통로로 직행**하게 되고, `AgentCollision` 이 매 프레임 막아 제자리 진동이 난다. 그래서 선분을 반지름 기반 간격으로 샘플링하고 각 지점에서 **원이 벽에 겹치는지** 본다.

Bresenham 대신 이 방식을 쓰는 이유가 그것이다 — 셀 관통 여부가 아니라 **원이 지나갈 수 있는가**가 질문이다.

### 필드를 대체하지 않는다

평활화는 필드 **위에 얹는다**. 후보를 필드가 만들기 때문에 오목 지형(U자 벽)에서도 갇히지 않는다. 순수 스티어링 회피로 대체하면 그 성질을 잃는다.

zero-flow 복구 경로(`FlowRecovery`)에는 평활화를 걸지 않는다 — 거긴 "고립에서 빠져나오기"라 직선화의 대상이 아니다.
