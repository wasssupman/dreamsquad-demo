# unit 8 — 에이전트 간 겹침 해소

## 목적

연속 이동으로 바꾸면서 **잃어버린 억제를 되돌린다.**

점 충돌 + 셀 clamp 시절에는 셀 경계가 겹침을 우연히 억제했다. unit 3 이 그 clamp 를 없앴으므로, 그대로 두면 적들이 서로를 관통한 채 한 점에 뭉친다.

## 구현

### 순서 무관이 결정론 계약이다

A→B 를 먼저 처리하면 B→A 가 **갱신된 위치**를 보게 되어 순회 순서에 따라 결과가 갈린다. 그래서 2단계로 나눈다:

1. 모든 쌍의 밀어냄을 **누적만** 한다 (아직 아무 위치도 안 건드림)
2. 그 뒤에 **일괄 적용**

`PairPush` 는 반대칭이라(`push(a,b) == -push(b,a)`) 쌍을 한 번만 보고 `pushes[j] -= push` 로 처리한다.

### 소프트 분리

밀어내되 관통을 **하드 블록하지 않는다**. 1타일 복도에서 하드 블록은 교착을 만든다 — 정체는 게임플레이지만 교착은 버그다.

겹침 깊이에 비례하되 `strength` 로 감쇠한다. 즉시 완전 분리하면 튕겨 나가고, 여러 프레임에 걸쳐 풀면 밀집 대열이 자연스럽게 벌어진다. 한 프레임 밀림은 **반지름**으로 상한한다.

### 완전 겹침의 처리

같은 좌표에 스폰된 두 유닛은 밀어낼 **방향이 없다**. 임의 방향을 주려면 난수가 필요하고 그러면 결정론이 깨진다 — `zero` 를 돌려주고 다음 프레임에 다른 요인(이동·외력)이 벌리게 둔다.

### 시스템 위치

`[UpdateAfter(MovementSystem)]`. 이동 결정과 겹침 해소를 한 루프에 섞으면 밀어냄이 다음 에이전트의 **이동 입력**이 되어 순서 의존이 다시 생긴다.

밀어낸 결과는 `AgentCollision.Resolve` 를 한 번 더 태운다 — 서로 밀다가 벽을 뚫으면 안 된다.

### 공간 분할은 만들지 않는다

O(n²) 다. 동시 적 수가 수십 규모라 실측상 문제가 아니고, 필요해지면 그때 만든다(제약 8). 미리 만들면 쓰이지 않는 추상이 남는다.
