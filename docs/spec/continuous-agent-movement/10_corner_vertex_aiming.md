# unit 10 — 코너 꼭짓점 조준 (코너 덜컹임 구조 제거)

## 목적

코너에서 조준점이 왕복하며 생기는 덜컹임을 **구조적으로** 없앤다.

원인은 실측으로 특정됐다(2026-08-08, 스폰B 궤적 f455~473): 조준 후보가 **경로 위 셀 중심**이고 관찰자(유닛)가 움직이므로, 코너를 스치는 몇 cm 사이에서 가시선 판정이 매 프레임 뒤집힌다 — 조준거리가 6.5타일 ↔ 0.9타일로 왕복하고 헤딩이 ±20~85° 튄다.

해법: 가시선이 막히면 **막은 벽 타일의 코너 꼭짓점 + (반지름+skin) 대각 오프셋**을 조준한다. 이 점은 (차단 셀, 꼭짓점) 쌍에서만 파생되는 **월드 고정 좌표**라, 유닛이 어디 있든 같은 코너면 같은 점이 나온다. 꺾임은 코너를 지나는 순간 1번 — 브레인스토밍에서 확정한 기하("직선+꺾임, 코너 밀착") 그대로다.

> **⚠ 정정 (2026-08-09 독립 감사)** — 이 문서는 원래 "재계산해도 왕복이 **불가능**하다"고 썼다. **과장이다.** 관찰자 무관인 것은 `(차단 셀, 코너)` **쌍이 고정됐을 때의 좌표**뿐이고, 그 쌍을 고르는 건 관찰자다(레이가 어느 셀에서 처음 막히는가 + 두 코너 중 어느 쪽인가 = 거리 타이브레이크 2개). 그래서 왕복은 배제된 게 아니라 **억제**됐다. 단일 코너에서는 억제가 충분해 사용자 체감이 사라졌지만, 기둥이 흩어진 구역에서는 남아 있다 — `MapDocument_MovementStress` 스폰 (12,2) 에서 13.4타일 주행에 헤딩 45°↑ 전환 6회 · 총회전 1161° (unit 11 하네스 실측). 이 잔여는 unit 11 이 고치지 않는다(다른 증상이다). 조준 기준을 "레이가 처음 막히는 지점"에서 **전역 비용 최소**로 바꾸는 후속 작업 소관이다 — 아래 "후속" 참조.

### 브레인스토밍 결정 기록 (D4)

- **채택: C안(무상태 코너 꼭짓점 조준)** — 적별 상태 0, 무효화 표면 0, 동적 장애물은 매 프레임 재파생으로 자동 대응(unit 5 재빌드가 선행 보장).
- **기각: A안(코리도+funnel, 적별 웨이포인트)** — 재빌드·넉백·포탈·블링크마다 무효화 훅이 필요. 재론 조건: C 실측에서 잔여 팝이 남으면 승격(코너 기하는 동일 부품이라 버려지지 않음).
- **기각: B안(조준점 히스테리시스)** — 유지하던 조준이 코너 한복판에서 비가시가 되는 순간 팝이 그대로 남음. 구조 해결 아님.
- 범위: **경로 기하만.** 회전 관성·가감속(운동학)은 별도 spec.
- 결정론: 순수 기하 + 고정 타이브레이크 — 기존과 동일 지형(가변 dt·교차기기 float 는 battle-sim-extraction 소관).

## 구현

### 꼭짓점 산출 (전부 순수, 고정 타이브레이크)

```
가시선 실패 시:
  1. 차단 셀 B = 세그먼트 샘플링에서 처음 걸린 막힌 셀 (샘플 순서·셀 스캔 순서 고정)
  2. apex 선택 — 1차 키: 마지막 가시점에 최근접  /  2차 키(동률): 에이전트에 최근접
  3. 조준점 = 꼭짓점 + B 중심 반대 방향으로 (±(r+skin), ±(r+skin))
  4. 검증: 조준점에 반지름 원이 안 겹치면 채택. 겹치면 현행 폴백(마지막 가시 셀 중심)
```

**apex 두 키가 모두 필요하다는 것이 구현 중 각각 실측됐다** (2026-08-09, 회귀 테스트로 고정):

- 1차 키를 "에이전트 최근접"으로 하면 **이미 돌아 나온 코너를 뒤로 다시 조준**해 그 자리에
  동결된다 (장애물 언더사이드 — 전방 apex 대신 후방 코너를 봄. `EscapeAim` 테스트가 고정).
- 2차 키 없이 1차 키만 쓰면 **동률이 스캔 순서로 벽 건너편에 풀려** 방향이 막힌 축 위주가
  되고, 충돌 해결 후 남는 수직 성분으로 0.1배속 크리프가 난다 (아레나 입구 164프레임 정체.
  `CornerAim_Tie_ResolvesToAgentSide` 테스트가 고정).

### 공유 헬퍼 `TryStepTarget` — 라인 ≡ 이동선을 구조로

"평활화 성공 → 그 점 / 실패 → 필드 한 스텝의 셀 중심 / 골·고립 → false" 선택 규칙이 `MovementSystem` 과 예고 라인에 각각 인라인돼 있었다. 이 규칙이 갈라지면 "라인과 이동이 다르다" 부류가 재발한다 — 호출처 2곳 + sim-critical 로 제약 10 의 추출 조건 충족. `PathSmoothing.TryStepTarget` 하나로 접는다.

### 계약 수리 — `FlowFieldRebuildSystem`

재빌드의 합성 마스크 루프가 벽 술어(정적∪장애물)를 인라인 재구현하고 있었다 — unit 1·2 의 "벽 질의는 NavGrid 하나" 계약 위반(자가 감사에서 발견). `MovementCellTrim.FillWalkMask` 한 줄로 교체. 동작 불변.

### 교착 방지 규칙과의 관계

"첫 후보 무조건 채택"(`06f5b0db`) 은 유지된다 — 꼭짓점 조준은 **둘째 후보부터** 가시선 실패 시 발동한다. 기존 테스트 중 `FirstCandidate_IsAcceptedEvenWhenNotVisible` 은 "탈출 조준 = 셀 중심(정수 좌표)" 을 박아뒀는데, 이제 탈출 조준이 더 정밀한 꼭짓점(비정수)이 되므로 **계약 진화로 기대값을 갱신**한다 — 탈출의 본질(측면 성분 존재)은 `OffCenterAgent_GetsLateralAim` 이 계속 지킨다.
