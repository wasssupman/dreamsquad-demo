# 5 — 카드에 발사 명세 개방

## 목적

「누구를 겨냥해 · 몇 발 · 어떤 순서·간격·방향으로」를 말하는 **발사 명세**(`ProjectilePatternData`)
는 이미 있고 보스가 쓴다. 카드 경로만 막혀 있다 — 그 문을 연다.

이 단위의 배당금은 카드 한 장이 아니다. 열고 나면 **부채꼴 난사 · 융단폭격 · 산개 유도탄이
전부 코드 0줄**로 열린다(unit 6 은 그중 한 장을 저작할 뿐이다).

## 남은 일은 카드 bake 한 곳뿐이다

초판은 「거절 주석이 필요한 것을 지목해 뒀고 그 셋을 채운다」고 썼다. **둘 다 틀렸다** —
주석은 한 줄짜리 경고일 뿐 아무것도 지목하지 않고, 셋 중 둘은 **이미 완성돼 있다**:

| 초판이 「해야 한다」고 본 것 | 실제 |
|---|---|
| defender 템플릿(`BuildPatternTemplate(hostIsEnemy:false)`) | **이미 있다.** 진영과 통행 층을 host 의 `AttackState` 에서 도출하는 것까지 끝. 주석에 「향후 defender/카드 경로가 같은 함수를 호출하도록 미리 분리해 둔다」고 적혀 있다 — **변경 0** |
| 적용성(`DcApplicability`) | **이미 통과한다** — 이 payload 는 어느 축으로도 게이트되지 않는다. **변경 0** |
| 발동 arm(주기 트리거) | 이미 진영 중립이고 방어유닛 주기는 content-4 가 열었다. **변경 0** |
| 카드 bake | **여기만 남았다** |

## 변경 대상

- `Bridge/BattleBridge.Dreamcatcher.cs` — 현재의 loud 거절을 실제 배선으로 교체

> 유닛 정보 화면의 이 payload 문안(「배치 시 … 미사일 낙하」)은 **손대지 않는다.** 그 함수는
> 유닛 자기 규칙의 **배치 트리거만** 훑으므로 카드는 도달하지 않는다 — 카드 문안은
> `DreamcatcherCardText` 가 소유한다.

## 구현 — 카드 bake 가 채울 것

1. **패턴 슬롯**: 카드의 패턴 SO 를 값으로 구워 `PatternSlot` 버퍼에 넣고 인덱스를
   `slot.patternIndex` 에 싣는다.
2. **발사 인스턴스 버퍼**: `EmitterInstance`. 발동 arm 이 여기 push 하고 emitter 가 소비한다.
3. **템플릿**: `BuildPatternTemplate(pattern, barrelIndex, host, hostIsEnemy: false)` 호출.

### ⚠ 카드는 **살아 있는 유닛**에 붙는다 — 유닛 스폰 경로를 복붙하면 버그가 난다

유닛 경로는 스폰 시점이라 버퍼를 무조건 새로 만든다. 카드 경로에서 그렇게 하면
**두 번째 카드가 첫 카드의 패턴 슬롯과 진행 중인 발사 인스턴스를 통째로 지운다.**
슬롯 인덱스가 「방금 추가한 마지막 칸」으로 잡히므로 첫 카드의 인덱스가 stale 이 되어
**다른 패턴을 쏘거나 범위를 벗어난다.**

- 버퍼는 **`HasBuffer ? GetBuffer : AddBuffer`** 로 얻는다(같은 파일의 `DcTriggerSlot` 선례).
- **ECB 로 미루지 않는다** — 한 프레임에 여러 장이 붙을 수 있고, 지연 `AddBuffer` 는
  **마지막 하나만 남긴다**(같은 자리의 기존 주석이 그 이유를 적어 뒀다).
- **버퍼 추가는 `DcTriggerSlot` 핸들을 잡기 «전»에** 끝낸다 — 구조 변경이 기존 핸들을
  무효화한다(유닛 경로 주석이 같은 경고를 남겨 뒀다).

### ⚠ `patternIndex` 기본값 함정

`0` 은 struct 기본값인데 **유효한 인덱스처럼 보인다** — 현재 거절이 존재하는 이유다.
패턴이 없으면 `-1` 을 굽고, arm 의 기존 `>= 0` 가드가 그것을 막는지 확인한 뒤 통과시킨다.

### ⚠ 반복 주기는 트리거가 소유한다

패턴의 `shots` 는 「한 번의 발사 안의 연발」이고, 3초마다 쏘는 것은 주기 트리거다(계약 11).
패턴이 스스로 반복하게 만들지 않는다.

> 즉발(`None` 트리거)과의 조합은 **새로 막을 것이 없다** — 카드 bake 가 이미 전역 거절한다.

## 완료 기준

- [ ] 카드에 발사 명세를 붙이면 **실제로 발사된다**(현재의 「붙었는데 아무 일 없음」 소멸)
- [ ] 패턴 미저작(`pattern = null`) 저작이 loud 경고 + 슬롯 미생성
- [ ] **같은 유닛에 발사 명세 카드 2장** — 둘 다 자기 패턴을 쏘고 카운터를 밟지 않는다
      (초판 설계대로 만들면 여기서 빨개진다)
- [ ] 보스 발사 명세 **무회귀** — 기존 패턴 소비자 전량 자동 테스트 초록
- [ ] 부착 유닛이 죽거나 퇴근하면 슬롯·인스턴스가 같이 사라진다(잔류 발사 0)
