# 3 — 부메랑 카드 (`boomerang`)

> N번째 공격마다 부메랑이 앞으로 날아갔다 돌아온다. 스치는 적을 진행 방향으로 밀어낸다 —
> 나갈 때는 밀리고, 돌아올 때는 딸려온다.

## 목적

unit 1(왕복 궤적)·unit 2(넉백)를 카드 한 장으로 묶는다. **조합은 `AttackN × ProjectileToTarget`**
— 신규 payload 를 만들지 않는다.

## 변경 대상

- `Battle/Combat/AttackSystem.cs` — `SpawnNeedleCarrier` 가 슬롯의 궤적 축을 존중
- `Bridge/BattleBridge.Dreamcatcher.cs` — bake(궤적 축 · `tileRange` 재해석)
- `UI/Dreamcatcher/DreamcatcherCardText.cs` — 문안
- `Data/Projectiles/Projectile_Boomerang.asset` · `Data/Dreamcatcher/Card_Boomerang.asset` — **신규**
- `Data/Dreamcatcher/DreamcatcherCardCatalog.asset` — 등록

## 구현

**핵심 발견 — 지금 카드의 추가 투사체는 탄 에셋의 궤적을 무시한다.** `SpawnNeedleCarrier` 가
호밍/단일착탄을 **하드코딩**하고 있어, 저작자가 탄 SO 에 어떤 비행을 골라도 유도탄으로 나간다.
부메랑은 이 결함을 고치는 자리에 얹힌다:

- 캐리어가 `slot.projectileMovement/projectilePayload`(unit 0 이 bake 한 축)를 그대로 싣는다.
- 축이 **방향 바인딩**이면 `direction = normalize(targetPos − origin)` · `maxDistance` ·
  **`retargetTileRange = 0`** 을 싣는다.
  - 방향은 헬퍼가 `origin`·`targetPos` 를 이미 받으므로 내부에서 만든다.
  - **거리는 타일→월드 변환이 필요한데 헬퍼에 `tileSize` 가 없다.** 인자를 하나 더해
    **호출부 3곳**(주 RESOLVE · 폭탄맨 arm · 캐스트 드레인)을 기계적으로 갱신한다.
    세 곳 모두 스코프에 `tileSize` 가 없으면, bake 가 월드 거리를 슬롯에 구워 보낸다.
  - 재조준(`retargetTileRange`)은 **겨눌 대상 엔티티가 없어서** 의미를 잃는다. 지금은 사전
    스캔이 호밍으로 좁혀져 있어 실어도 무해하지만 그건 **우연한 무해**이므로 0 으로 명시한다.
- **회귀 없음**: 이 경로의 유일한 카드 소비자인 비수(`poke_needle`)의 탄이 유도탄이라 축이
  종전과 같다. 자동 테스트로 고정한다.

**`tileRange` 의 의미가 갈린다.** 이 payload 에서 `tileRange` 는 원래 「대상이 죽으면 다시 겨눌
반경」인데, 부메랑 축에서는 **날아가는 거리(타일)** 로 읽는다. 재조준은 겨눌 대상 엔티티가
없어 성립하지 않으므로 그 둘은 **배타**다(겸직이 아니라 대체).
⚠ 단 **세 번째 의미와는 여전히 겸직**이다 — 캐스터·폭탄맨 경로에서 같은 값이 「폴백 대상
탐색 반경」으로도 쓰인다(`PickFallbackTarget`). 그 host 에 이 카드를 붙이면 「4타일 안에서
적을 찾아 그 방향으로 4타일 날린다」가 되어 우연히 정합하지만, **한 값을 튜닝하면 둘이 같이
움직인다**(리뷰 L6).

## 「나갈 때 한 번, 돌아올 때 한 번」의 실제 조건

두 타격 사이 간격은 **적의 거리에 달렸다**. 발사점에서 `d` 타일 떨어진 적은
`2(maxD − d) / v` 초 만에 두 번째로 스친다 — 즉 **끝에 있는 적일수록 두 타격이 붙는다**
(끝점에서는 두 통과가 겹친다). 그래서 재타격 쿨타임보다 간격이 짧아지는 지점부터는 한 번만 맞는다.

> **두 번 맞는 경계** `d < maxD − (쿨타임 × 속도) / 2`

초판은 「왕복 1초 < 쿨타임×2 = 1초」라고 적었는데 부등식 자체가 거짓이었고, 애초에 이 판정과
무관한 식이었다.

## 저작(초기값)

| 값 | 자리 | 초기값 |
|---|---|---|
| 발동 | 카드 `trigger.period` | **2번째 공격마다** (초기 5 → Play 확인 중 하향, 2026-08-17) |
| 피해 | 카드 `magnitude` | 25 |
| 날아가는 거리 | 카드 `tileRange` | 4타일 |
| 비행 속도 | 탄 SO `speed` | 6 (왕복 약 1.33초 — 눈에 보이게 느리게) |
| 스치는 굵기 | 탄 SO `hitThreshold` | 0.5 |
| 재타격 쿨타임 | 탄 SO `rehitCooldownSec` | 0.3 → **경계 3.1타일**(사거리의 약 3/4까지 두 번) |
| 넉백 | 탄 SO `knockbackDistance` / `Duration` | **1.5 / 0.3초**. ⚠ 이 값은 **월드 단위**다 — 「날아가는 거리」(타일 저작 후 변환)와 달리 변환을 안 거친다. 현재 `tileSize = 1` 이라 우연히 같다 |
| 생김새 | 탄 SO `projectilePrefab` / `facing` | 수리검 · **`SpinAroundUp`**(눕혀서 평면 회전) · 배율 1.2 |

**넉백 저작은 Play 체감으로 0.4 → 1.5 로 올렸다**(2026-08-17 사용자 확인). 0.4 는 왕복이 밀고
당긴 양이 서로 상쇄돼 «비틀거림» 조차 안 보였다. 골 쪽으로 밀리는 위험(계약 7)은 남아 있으므로
이 값이 상한 근처다 — 더 키우면 «날려버림» 이 되어 유출을 앞당긴다.

⚠ **부메랑의 그림은 크기가 아니라 «회전축» 이 만든다.** 초판은 `AlongVelocity`(진행 방향 정렬)에
`spinSpeed` 만 얹어 «앞을 보고 나는 불덩이» 였다. 눕혀서 도는 `SpinAroundUp` 으로 바꾼 뒤에야
부메랑으로 읽혔다 — 배율을 키우는 것으로는 해결되지 않는 축이다.

## 완료 기준

- [ ] Play: 발동 주기마다 부메랑이 나갔다 **돌아오고**, 스친 적이 **나갈 땐 밀리고 돌아올 땐 딸려온다**
- [ ] **발사점 가까이(경계 안)의 적**이 한 왕복에서 두 번 피해를 받는다.
      끝쪽 적이 한 번만 받는 것은 **사양**이다(위 식) — 검증 더미를 양쪽에 놓고 둘 다 확인한다
- [ ] 보스에게는 피해만 들어가고 밀리지 않는다
- [ ] 벽 안으로 밀려 들어가는 적이 없다
- [ ] 비수(`poke_needle`) 무회귀 — 자동 테스트로 궤적 축이 여전히 유도탄임을 고정
- [ ] 카드 문안이 발동/피해/거리/넉백을 에셋에서 읽어 표기(수치 문자열 복제 0)
