# 2 — 관통탄 넉백 (진행 방향으로 민다)

## 목적

경로를 훑는 투사체(`PayloadKind.PathHit`)가 스친 적을 **맞은 순간의 진행 방향으로** 밀 수 있게
한다. 부메랑 전용이 아니라 **관통탄 공통 축**이며 `0 = 꺼짐`이라 기존 관통탄은 전부 무변화다.

## 변경 대상

- `Battle/Combat/Projectile/ProjectileHitSystem.cs` — PathHit arm 에 넉백 분기
- `Bridge/BattleBridge.cs` — `SpawnProjectile` 이 탄 SO 의 넉백 2필드를 `ProjectileState` 로 복사
- `Tests/EditMode/PathHitRehitCooldownTests.cs` — 기존 픽스처에 합류(별도 파일을 만들지 않는다 — 재타격 쿨타임과 같은 월드·같은 스위퍼 픽스처를 그대로 쓴다)

## 구현

**기구는 전부 기존 것을 탄다** (계약 6). 새로 만드는 채널·컴포넌트·시스템이 없다:

```
ProjectileHitSystem ──EnemyCcEvent{Impulse, vector, remainingTime}──> CcApply ──> MovementSystem 변위
```

`ProjectileHitSystem` 은 이미 이 큐의 생산자다(폭탄의 수면/스턴탄). **같은 writer 를 쓴다.**

**방향** = 그 프레임 스윕 방향 `normalize(pos − prevPos)`. **`direction` 필드를 읽지 않는다** —
그 필드는 왕복 궤적에서 **발사 축(불변)** 이라 돌아오는 다리에서도 안 뒤집힌다. 실제 이동분만이
「맞은 순간의 진행 방향」이며, 왕복이 두 다리에서 반대 힘이 되는 것은 그 결과다(계약 5).
퇴화(변위 0)면 **쏘지 않는다** — 방향 없는 넉백은 기존 근접 넉백도 막고 있다(review B LOW1 선례).

**세기** = `knockbackDistance / knockbackDuration` 을 속도로, `knockbackDuration` 을 지속으로.
드레인이 SO 에서 `ProjectileState` 로 복사한다(`rehitCooldownSec` 와 같은 자리).

**재타격 쿨타임과의 관계.** 넉백은 **피해가 들어간 그 순간에만** 나간다 — 쿨타임에 막혀
피해를 안 준 프레임은 밀지도 않는다. 안 그러면 스치는 동안 매 프레임 밀려 적이 날아간다.

## 공짜로 성립하는 것 (전부 의도된 동작)

- **벽/장애물로는 안 밀린다** — `AgentCollision.Resolve` 가 변위를 이미 막는다
- **보스는 안 밀린다** — `CcActionLock` 넉백 면역
- **잠/스턴 중에도 밀린다** — 행동 정지는 자기주도 이동만 막고 외력은 유지한다(기존 주석)

⚠ **넉백 슬롯은 피해자당 하나다.** 병합 키가 종류 하나뿐이라 남은 시간은 큰 쪽이 이기고
방향은 **나중 것이 덮어쓴다** — 부메랑의 두 번째 타격이 첫 임펄스의 잔여 시간을 물려받고,
밀치기 같은 다른 넉백과도 같은 슬롯을 다툰다. 저작값이 짧아서 실용상 무해하지만,
「밀었다 당김이 겹치면?」을 다음 사람이 처음부터 조사하지 않도록 여기 적어 둔다.

⚠ **거리는 짧게, 시간은 넉넉히.** 이유는 **계약 7**(밀기가 적을 골 쪽으로 보낼 수 있다)이지
프레임 변위 상한이 아니다 — 그 상한은 초당 50타일 급이라 저작값의 수십 배이고 실제로는
절대 안 걸린다. 상한을 근거로 삼으면 값을 10배 키워도 아무 일이 없어 경고가 거짓말이 된다.
**코드로 클램프하지 않는다**(클램프하면 저작자가 상한을 못 본다 — 팽이의 현(chord) 상한과 같은 판단).

## 완료 기준

      값 0 이면 이벤트 자체가 없음(기존 관통탄 무회귀)
- [ ] EditMode(통합): 부메랑 왕복에서 **같은 적이 받는 두 넉백의 방향이 반대**

- [ ] 샷건너(기존 관통탄) 회귀 없음 — 탄 SO 무저작이라 이벤트 0
