# 9 — 재현: 낡은 조준(stale aim)

> 선행: unit 8(`8_visual_density_fanout.md`) 이 만든 결함의 재현. 수정은 unit 10·11.

## 목적

사용자 제보 2건을 **계측기 안에서 빨갛게** 만든다. 고치기 전에 재현한다(CLAUDE.md 버그 수정 절차).

1. 「범위 안 5기 확인 → **5발 떨어졌는데 피해 0**」
2. 「범위 안 5~7기인데 **낙하가 2발로 보인다**」

**왜 기존 5개 테스트가 초록인가 = 이 유닛의 핵심.** `OnPlaceSkyStrikeTest` 의 더미는 **가만히 서
있다.** 캐논 미사일은 발사 시점의 **칸**을 겨누고 `impactTileRange 0` 이라 **같은 칸에 있어야만**
맞는데, 안 움직이는 더미는 칸을 벗어날 수 없다. 실제 판의 적은 걸어간다:

| 실측(라이브 월드) | 값 |
|---|---|
| 예고 | `telegraphSec 0.4` + 칸 순번 × `fanOutStaggerSec 0.08` → 첫 발 **0.40s**, 5칸이면 마지막 **0.72s** |
| 적 속도 | **2.00** 타일/초 (일부 1.20) |
| 0.40s 이동 | **0.80 타일** |
| 0.72s 이동 | **1.44 타일** |
| 칸 소속 유지 폭 | 중심 **±0.50 타일** |

`0.80 > 0.50` — 속도 2 적은 **최소 예고에도 자기 칸을 벗어나고**, 뒤 슬롯은 전원 벗어난다.
unit 8 전에는 `target` 이 비어 있어 **그 칸에 누가 있든** 때렸고, 행군하는 뒤 적이 빈 칸을 채워
피해가 계속 들어갔다 — 조준이 낡았다는 사실이 우연히 가려져 있었다. unit 8 의 임자 게이트가
그 보상을 없애자 **완전 헛방**이 됐다.

## 변경 대상

- `Assets/_Project/Tests/PlayMode/OnPlaceSkyStrikeTest.cs`

## 구현

기존 픽스처(`Prepare` / `SilenceOtherAttackers` / `MissilesAimedAt`)를 그대로 쓴다.

1. **`MovedDuringTelegraph_StillTakesDamage`** — 더미 1기를 스코프 안에 놓고 캐논 배치 →
   캐리어가 드레인된 뒤(1프레임) 더미의 `LocalTransform` 을 **자기 칸 밖으로 0.8타일** 옮긴다
   (실측 속도 2 × 0.40s 과 같은 폭, 스코프 안은 유지). 착탄까지 대기 → **체력이 줄었다**를 단언.
   지금은 빨강(피해 0).
   ⚠ 이동은 «적이 걸었다» 의 대역이다 — 경로 추종에 의존하면 맵·통행 층·시드에 묶여 테스트가
   부서진다. 옮기는 폭만 실측에서 가져온다.
2. **`BunchedEnemies_LandOnDistinctPoints`** — 더미 2기를 **같은 칸**에 놓고 배치 → 생성된 두 탄의
   `impact` 거리를 잰다. 지금은 `SubCellOffset` 이 **0.28타일**(미사일 `visualScale: 6`)이라
   화면에서 한 발로 접힌다 → **≥ 0.5타일** 을 단언해 빨강.

**절대 피해량을 리터럴로 못박지 않는다**(unit 8 실측 함정 — 판 위 남의 공격원이 값을 흔든다).
단언은 «줄었다/떨어졌다» 라는 부호와 거리뿐이다.

## 완료 기준

- 새 테스트 **2개가 빨강**이고 실패 메시지가 원인을 그대로 읽어준다.
- 기존 5개는 **초록 유지** — 이 유닛은 제품 코드를 한 줄도 바꾸지 않는다.

### 검증 (2026-08-17)

사용자 지시로 units 9~11 을 **먼저 다 구현한 뒤** 한 번에 돌렸다. 그래서 「빨간 것을 먼저
본다」를 순서로는 못 지켰고, 대신 **통제 실험**으로 대체했다 — `Projectile_CannonStrike` 의
`flightMode` 만 옛 축(4=SkyFall)으로 되돌려 같은 7개를 재실행:

- 옛 축: **7개 중 6개 빨강.** 계측 줄이 `slots=0 patSlots=0 maxCarrier=0 maxProjectile=0` 이라
  unit 11 의 bake 검증이 실제로 발화해 패턴을 거절했음이 확인됐다(콘솔에 「fanOutToAllCandidates
  인데 탄의 조준이 Cell 다」 경고 7판 전부). 즉 이 테스트들은 **축에 실제로 물려 있다.**
- 새 축 복원: **7/7 초록**(22.3초).

⚠ 이 실험이 증명한 것은 「테스트가 축 전환에 반응한다」이지 「낡은 조준 그 자체를 잡는다」가
아니다. 후자의 근거는 테스트가 아니라 실측이다(예고 0.40s × 속도 2.00 = 0.80타일 > 칸 유지 폭
0.50타일, `IsInTileRange(cell, center, 0)` 는 칸 일치를 요구).
