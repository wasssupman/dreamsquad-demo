# 3. 보스 재케이던스 — 간격 9 · 덱별 1종 · 호위가 블록 컨셉을 입는다

## 목적

보스를 희소하게 만들고 블록 리듬에 정렬한다. 사용자 결정(2026-08-13): **5마다는 너무 잦다 → 간격 9**.

간격 9 의 근거 셋:

1. **블록과 정렬된다.** `conceptHoldWaves=3` 이면 9는 블록 2(웨이브 7·8·9)의 **마지막** 웨이브다. 「컨셉을 두 웨이브 배우고 → 세 번째에 보스가 그 컨셉을 입고 온다」는 학습→시험 구조가 공짜로 생긴다. 10은 블록 3의 **첫** 웨이브라 «새 컨셉 + 보스»가 한 웨이브에 겹쳐 부하가 몰린다.
2. **보스를 못 보는 판이 없다.** 최악 케이스 도달이 `floor(180/20)+1 = 10` 웨이브이므로 간격 10 이면 시간이 몇 초 모자란 판은 보스 없이 끝난다 — 3분 판에 클라이맥스가 없는 결말이 나온다.
3. **체감 빈도는 10과 같다.** 실제 도달이 10~16웨이브이므로 둘 다 **판당 보스 1기**다.

점수 예산 영향은 미미하다: 판당 일반 킬이 100~200점 규모이고 보스 `killScore` 10 이 2~3기에서 1기로 줄면 −10~20 이다.

## 변경 대상

## 구현

### 호위가 블록 컨셉의 성질·위상을 입는다

현재 보스 후처리는 웨이브를 통째로 치환한다 — 보스 1기 + **랜덤 1종** 호위(`WavePatternGenerator.cs:157~182`). 블록 구조에서 그러면 블록의 마지막 웨이브에서 컨셉이 깨진다.

대신 호위를 **그 블록 컨셉의 슬롯 규칙으로** 편성한다:

```
보스 웨이브 i:
  escortTotal = rng.NextInt(bossEscortMin, bossEscortMax+1)
  groups[0]   = (boss, 1, lane = 컨셉 첫 슬롯의 lane)
  groups[1..] = 컨셉 슬롯들 — 필터·lane 은 그대로, 수량만 escort 예산으로 재분배
                DistributeSlotCounts(escortTotal, countMul: 1.0, slotCount, maxUnits)
```

⚠ **호위 예산에는 `countMul` 을 적용하지 않는다.** `bossEscortMin/Max`(3~4)가 이미 예산이므로 배율을 다시 곱하면 이중 스케일이 된다 — 「중장」(0.4)이면 `3 × 0.4 = 1.2` 가 되어 하한(슬롯 수)으로 클램프되고, 배율의 의미가 사라진 채 컨셉마다 호위 수가 제멋대로 달라진다. 컨셉이 호위에 주는 것은 **성질과 위상**이고 수량은 보스 파라미터가 소유한다.

결과:

- 「원거리」 블록 → 보스가 사거리 호위를 끼고 협공 위상으로 온다
- 「벌떼」 블록 → 보스가 소형몹 떼와 함께 한 입구로 온다
- 「중장」 블록 → 벽 뒤의 벽

**보스는 컨셉 첫 슬롯의 lane 을 쓴다.** 협공 컨셉(슬롯 2개, lane 2개)이면 보스는 한쪽에 서고 호위는 양쪽에 갈린다 — 보스가 있는 쪽이 «본대»로 읽힌다. 슬롯이 무지정(`-1`)이면 보스도 무지정이라 기존 분산 경로를 탄다.

`RoundRobin` 이 라운드 0 에서 `groups[0]` 부터 emit 하므로 **보스가 먼저 스폰된다**(현행 유지). 다만 보스 이동속도가 호위보다 느려 도착 순서는 역전된다 — 이 spec 범위 밖의 별개 문제이며 README 후속 후보 「보스 이동속도 저작 조정」에 근거와 숫자를 남겼다.

### 덱별 보스 1종

판당 보스가 1기면 3종 풀에서 시드로 뽑는 것은 의미가 없다 — `waveSeed` 가 고정이라 **어차피 맵마다 보스 1종이 영구 고정**되고, 어느 맵이 어느 보스를 받는지만 시드에 맡겨진다. 덱에 직접 적으면 6맵에 3종을 의도대로 배분할 수 있고("이 맵의 주인"이 생긴다), rng 소비도 하나 줄고 의도가 데이터에 보인다.

배분(6맵 ÷ 3종 = 각 2맵). 맵 성격과 보스 기믹의 궁합으로 저작 시점에 확정한다:

| 덱 | 보스 |
|---|---|
| Serpent · Coil | Boss_Nightmare |
| Twin · Spiral | Boss_Jjangssen |
| Zig · Hook | Boss_Mamemo |
| Endless | 로테이션 3종 유지 — 판이 길어 여러 기를 만난다 |

`bossPool` 이 1종이면 생성기의 보스 선택은 **rng 를 소비하지 않는다**(기존 가드 `bosses.Count == 1` 이 그대로 작동). `bossUnit` 필드는 폴백으로 남긴다 — 키를 바꾸면 YAML orphan 이 되고 생성기가 «보스 없음»을 graceful no-op 으로 처리해 **에러도 경고도 없이 전 맵에서 보스가 사라진다**(`boss-jjangssen` unit 0 경고 승계).

## 완료 기준

- **EditMode**
  - 보스 웨이브가 9·18·… 에만 생기고 5·10·15 에는 없다
  - 보스 웨이브의 호위 종류가 **그 블록 컨셉의 슬롯 필터를 따른다**(「원거리」 블록이면 호위가 Shooter)
  - 호위 총량이 `[bossEscortMin, bossEscortMax]` 안이고 `maxPerWave` 를 넘지 않는다 — `countMul` 이 곱해지지 않았음을 「중장」 블록(0.4)에서 확인
  - 보스의 lane 이 컨셉 첫 슬롯의 lane 과 같다
  - `bossPool` 1종일 때 rng 소비가 늘지 않는다(2종+ 대조로 확인)
  - 7덱 전부 보스가 실제로 배정돼 있다 — `bossPool` 이 비고 `bossUnit` 도 null 인 덱이 없다
- **Play 육안 (사용자 확인)** — 보스 웨이브가 그 블록 컨셉의 «강화판»으로 읽히는가 · 판당 1기가 적절한 빈도인가
