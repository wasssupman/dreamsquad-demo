# 전투 트레이 통합 + 코스트 물통

> 상태: 작성 2026-07-21 · 리뷰 3-lane 반영 (rev 2)

## 목표

전투 하단 HUD 를 **하나의 통합 박스**로 재편한다. 지금은 코스트 레일(별도 캔버스, 트레이 상단에 겹친 탭)과 유닛 트레이가 따로 떠 있고, 모바일 실기에서 유닛명·코스트·클래스 태그가 거의 읽히지 않는다.

두 축으로 고친다.

1. **구조** — 코스트를 트레이 안 왼쪽 셀로 흡수. 코스트 표현을 세그먼트 바에서 **물통 충전**으로 교체(각성 게이지의 차오름 어휘 이식). 물통이 가득 차면 상단 `현재/최대` 숫자가 +1 되고 물통은 리셋된다.
2. **가독성** — 클래스 배지 제거(대체 앵커는 이름 밴드 틴트), 슬롯 코스트 숫자 확대, 유닛명 어두운 밴드 + 흰 텍스트, 슬롯 확대.

## 검증 질문

> 실기기(모바일)에서 **손가락을 떼지 않고도** 남은 코스트와 유닛 가격을 읽고 배치 판단을 내릴 수 있는가?

## Feature-wide 계약

- **통합 박스는 트레이 패널 하나다.** 단 `HorizontalLayoutGroup` 자식은 `[코스트 셀][슬롯 컨테이너]` **2개**다. 슬롯은 컨테이너 안에 들어간다 — `RebuildSlots` 가 자식을 전부 파괴하기 때문에 셀과 같은 부모에 둘 수 없다(unit 1 D1).
- **`childForceExpandWidth = false` 다.** `true` 이면 uGUI 가 per-child `flexibleWidth` 를 `Max(flexible, 1)` 로 덮어써 고정폭 계약이 무효화된다(`HorizontalOrVerticalLayoutGroup.cs:237-238`). 셀은 `flexibleWidth = 0`, 슬롯 컨테이너는 `1`.
- **트레이 폭은 상수가 아니라 산출값이다.** `costCellWidth + n×slotWidth + gap + padding` 을 슬롯 수 `n` 에서 유도한 뒤 **`SafeAreaRoot 폭 − cornerReservedWidth`** 로 클램프한다. 슬롯 수는 7 이 표준이지만 씬 직렬화 pool 은 8 이다(unit 4 D8).
- **코스트 뷰의 소유자는 여전히 `CostDisplay` 다.** `PulseInsufficient` / `SetSuppressed` / `CostRuntime` 읽기 계약은 그대로. 바뀌는 것은 *위치를 누가 정하는가* 뿐이다.
- **억제는 `SetActive` 가 아니라 `CanvasGroup.alpha` 로 한다.** 셀이 레이아웃 자식이 되면 비활성화가 슬롯 리플로우를 일으킨다(unit 1 D9).
- **활성 판정은 `activeInHierarchy` 다.** 트레이 자식이 되면 `activeSelf` 는 부모가 꺼진 상태를 못 본다.
- **물통은 `CostRuntime.Current` 의 소수부다.** `숫자 = floor(Current)`, `물통 = Current - floor(Current)`. 별도 충전 상태를 만들지 않는다.
- **`Current == Max` 는 물통을 가득 채운다.** max 에서는 리젠이 멈춰 소수부가 0 이므로, 그대로 그리면 만땅이 빈 통으로 보인다.
- **폴링 판정에는 sentinel 과 epsilon 이 필수다.** `_prevInt = -1` 로 첫 프레임을 소비만 시키고(안 하면 배치 진입마다 MaxBurst 오발), 소수부 비교는 `fill < _prevFill - kFillEpsilon` 으로 한다(안 하면 `AddCost(1)` 의 약 10% 가 오분류). 근거는 unit 0·2.
- **코스트 값은 프레젠테이션이 절대 쓰지 않는다.** 읽기 전용(기존 계약 유지).
- **모든 치수는 `BattleHudTrayConfig` 가 소유한다.** 컴포넌트 매직 넘버 금지(기존 action-tray unit 1 계약 연장).
- **연출 코루틴은 `Time.unscaledDeltaTime` 을 쓴다.** 물통 fill 자체는 `CostRuntime` 추종이라 Battle 도메인 슬로모/포즈를 자동 반영하고, 팝/플래시 같은 UI 피드백만 실시간으로 돈다.

## 치수

슬롯 수 `n` 은 스쿼드 7슬롯 강제(`PlayerProfile.SquadSave.SlotCount = 7`)와 드래프트 10−3 이 모두 7 로 수렴한다. 단 `BattleScene.unity` 의 직렬화 `defenderPool` 은 8 이라, 에디터 직접 Play 경로에서는 8 슬롯이 뜬다.

| | 현재 | 목표 | 산출 |
|---|---|---|---|
| 슬롯 | 128×112 | **154×134** | 현재 ×1.2 |
| 코스트 셀 | — | 슬롯과 동폭, `≤ 슬롯 폭` | 위계 계약 |
| 트레이(n=7, 무클램프) | 980×136 | **1324×158** | 36 + 154 + 8 + (7×154 + 6×8) |

**폭은 화면비에 따라 클램프된다.** 상한 = `SafeAreaRoot 폭 − 640`(코너 위젯 실측, unit 4 D3/D4):

| 화면비 | S | 상한 | 실제 트레이 | 슬롯 |
|---|---|---|---|---|
| 16:9 | 1920 | 1280 | 1280 | ~148 (+16%) |
| 19.5:9 | 2340 | 1700 | 1324 | 154 (+20%) |
| 20:9 (주 타겟) | 2400 | 1760 | 1324 | 154 (+20%) |

클램프가 걸리면 축소분을 코스트 셀과 슬롯이 **같은 비율로** 나눈다 — 셀만 고정폭을 지키면 셀이 슬롯보다 넓어져 위계가 뒤집힌다(unit 4 L13).

## 하단 점유 (정정)

레일이 삭제되므로 클러스터 상단은 **낮아진다**:

```
현재  = 레일 상단 198  (트레이 32+136=168, 레일이 그 위 154~198)
신규  = 트레이 상단 190
→ 8 units 감소
```

보드 최하단은 화면 밑변에서 약 435 units 로 **245 units 여유**가 있다(FOV 40°·pitch 55°·gridSize 20×10 기준 정적 계산, unit 4 에서 Play 실측). 세로는 제약이 아니다. **제약은 가로**다.

## 결정 기록

- **물통 = 소수부 (사용자 결정 2026-07-21).** 리뷰가 "보유량 + 눈금" 대안을 제시했으나(max 분기·wrap·자연충전/획득 구분이 전부 소멸) 사용자가 원안을 유지하기로 했다. 대가로 unit 2 의 sentinel·epsilon·복합 변동 계약을 전부 구현한다.
- **클래스 배지 제거 + 이름 밴드 클래스 색 틴트 (사용자 결정 2026-07-21).** 배지는 지우되 `roles` config 데이터는 **유지**한다. `first-session-tutorial` unit 11(2026-07-21 커밋)이 첫 배치 직후 5개 클래스 설명을 강제로 읽히는데, 배지를 완전히 지우면 화면에 대응 앵커가 하나도 안 남는다. 밴드 틴트는 신규 픽셀 0 으로 앵커를 유지한다.
- **Battle 슬림 축소는 부활시키지 않는다.** `battleSize == placementSize` 는 무효화가 아니라 **사용자 product 결정**이다(`battle-hud-action-tray/2_energy_rail_phase_density.md` rev 2, 2026-07-12, 근거: 근육 기억 형성). 되살리려면 사용자 재확인이 필요하다. 하단 점유가 오히려 8 units 줄어 상쇄 대상도 없다.
- **손패 폭 점프를 수용한다.** 트레이가 1324 로 넓어지면 손패(`handSize` 980)와 344 차이가 나 "좌표 점프 없는 제자리 플립" 불변식이 폭 축에서 깨진다. 이번 spec 은 폭 점프를 받아들이고, 손패 폭 정합은 후속으로 둔다 — 손패 카드 크기가 `DreamcatcherHandView.cs:973` 에 하드코딩(172×200)이라 패널만 넓히면 간격만 벌어져 별도 작업 단위가 필요하다.

## 후속 후보 (현 spec 범위 밖)

- **드림캐쳐 손패 폭·카드 크기 정합** — 위 결정 기록 참조. 카드 크기 하드코딩 해소가 선행.
- **코스트 사운드·햅틱** — 정수 도달 틱(직전에 부족 차단을 겪었을 때만 강조) + `PulseInsufficient` 짧은 햅틱. "화면을 안 봐도 되는" 신호라 82px 애니메이션보다 값싸다. 검토했고 이번 범위에서 뺐다.
- **코스트 물통 아트 교체** — 현재 계획은 절차 생성 스프라이트(`UiRoundedSprite`).
- **트레이 프레임 아트** — `trayConfig.trayFrame` 은 여전히 미할당이라 라운드 폴백을 쓴다.
- **`CostRuntime` 이벤트화** — 폴링으로 소비/획득을 추정하는 대신 이벤트를 노출하면 unit 2 의 판정 기계가 통째로 사라진다. 스코프 확대라 이번엔 하지 않는다.
