# 5 — 배선 확인 + Play e2e 검증

## 목적

신규 씬 배선이 0 인지 확인하고(전 유닛이 기존 참조 재사용), feature 전체를 Play 로 관통
검증한다. 카메라 채널 합성(인스펙트 줌 + 손패 헤드룸 동시) 체감도 여기서 판정한다.

## 변경 대상

- (코드 없음 — 검증 전용. 발견 결함은 해당 unit 파일에 rev 로 기록 후 수정)

## 구현

- 배선 확인: `DcInspectController.handView` / `DreamcatcherHandView` 의 기존 참조가 씬에
  연결돼 있는지 확인(BattleScene). 이 spec 은 **신규 SerializeField 배선을 요구하지 않는다**
  — 새 참조가 생겼다면 설계 위반이므로 되돌린다.
- Play e2e 시나리오(에디터, 이후 실기기 스모크):
  1. 유닛 탭 → 줌+리티클+패널+플립북+손패 딜인 동시 등장
  2. 카드 탭 즉발 → 부착·재딜인·손패 유지 → 다른 유닛 탭 → 선택 전환 → 다시 탭 즉발
     (연속 부착 흐름 — 이 feature 의 핵심 체감)
  3. 카드 D&D 로 제3 유닛 부착 → 리티클 재주장 확인
  4. 빈 보드 탭 → 전부 해제 / 재탭 토글 / 항아리 토글(손패만) 각 1회
  5. 사용 가능 0장 자동 닫힘 + 선택 유지 → 게이지 회복 → 항아리 재오픈 → 즉발 재개
  6. 이동모드 진입 → 손패+선택 해제 → 이동 커밋 정상
  7. 포탈 카드: 선택 중 입구/출구 커밋 → 손패 유지 + 리티클 복귀
  8. 페이즈 이탈(Result) → 전부 강제 해제, lease 누수 없음(콘솔 0)
- **카메라 체감**: 인스펙트 줌 + 손패 헤드룸이 동시에 걸린 화면(줌인+피치)이 과한지 확인.
  과하면 config 노브(`inspectDolly`/`handHeadroomPitchDeg`) 튜닝만 — 코드 분기 금지(계약 9).
- **원격 검증 폴백**: 사용자 부재 시 PlayMode 테스트로 상태 머신 검증
  (`remote-play-verification-playmode-tests` 메모리 — Step/reflection 구동 선례).
