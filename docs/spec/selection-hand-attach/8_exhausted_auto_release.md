# 8 — 부착 후 재화 고갈 시 선택까지 자동 해제

> 추가 2026-07-29 (사용자 결정). 계약 7 의 **유일한 예외** — 손패 단독 닫힘이 선택을 데려간다.

## 목적

선택 중 카드를 부착해 게이지를 다 쓰면, 손패는 자동으로 닫히지만(use-flow 계약 2) 선택은
계약 7 에 따라 살아남아 **줌 + 슬로모 0.3× 상태로 할 일 없이 남는다**. 빈 보드를 탭해야 풀린다.
"카드를 써서 바닥났다" 는 자연스러운 종료 신호이므로 그 순간 선택도 함께 풀어 기본 진행
상태로 되돌린다(편의성).

**"부착을 1회라도 했을 때만" 이라는 조건은 별도 플래그가 필요 없다** — 신호가 `OnCardUsed`
안에서만 발화하므로 "사용이 실제로 있었다" 가 신호에 내포된다. 게이지 0 인 채 선택만 한
경우는 이 경로를 타지 않아 손패가 열린 채 대기한다(사용자 결정: 그대로 둔다).

## 변경 대상

- `Assets/_Project/Scripts/UI/Dreamcatcher/DreamcatcherHandView.cs` — `UsableCardsExhausted` 이벤트
- `Assets/_Project/Scripts/UI/Dreamcatcher/DcInspectController.cs` — 구독 → `Close()`

## 구현

`OnCardUsed` 의 `!anyUsable` 분기에서 이벤트를 발화하고 컨트롤러가 자기 `Close()` 를 부른다.
양쪽 `Close()` 가 이미 멱등이라 새 상태·새 시그니처가 없다(코드 ~12줄).

**발화 위치가 계약이다** — `BindEmpty` 루프 **뒤** + `Close()` **앞**:

- `BindEmpty` 앞이면 침강 연출이 이미 날아간 카드를 다시 보여준다(use-flow 의 기존 의도 훼손).
- `Close()` 뒤면 뷰의 `Close()` 가 `FocusCleared` 를 쏘는 시점에 선택이 아직 살아 있어
  컨트롤러가 **리티클을 재주장한 직후 곧바로 지우는** 1프레임 깜빡임 + lease churn 이 생긴다.

이 순서에서 실제 실행 흐름(탭 즉발·D&D 공통):

1. `CommitAttach` → `HandChanged(Used)` → `OnCardUsed` → BindEmpty → **이벤트**
2. 컨트롤러 `Close()`: 선택 해제 + 슬로모 lease 해제 + 리티클 off + 패널/플립북 숨김 →
   `CloseFromSelection()` → 뷰 `Close()`(침강 시작)
3. `OnCardUsed` 의 `Close()` 는 이미 `UnitStrip` 이라 no-op
4. 뷰 `Close()` 의 `FocusCleared` → 컨트롤러는 `_selected == Null` 이라 즉시 반환(재주장 없음)
5. `CommitNow` 로 복귀 → **사전 캡처한 중심**으로 확정 펄스(unit 3 B — 독립 타이머라 생존) →
   `EndInteraction` → `FlyCardToUnit`

## 알려진 시각 겹침

카드 고스트가 유닛으로 날아가는 동안 슬로모가 풀리고 카메라가 줌아웃한다. 고스트는 매 프레임
유닛 앵커를 재조회하므로 깨지지 않지만 궤적이 살짝 흐를 수 있다. 거슬리면 비행 완료 콜백까지
해제를 미루는 옵션이 있으나(콜백 배선 추가) 우선 즉시 해제로 체감을 본다.
