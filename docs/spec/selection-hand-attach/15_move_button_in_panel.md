> 추가 2026-07-30 (사용자 결정). unit 7 이 껐던 재배치 진입구를 패널에 되살린다.

## 목적

unit 7 에서 유닛 주변 아이콘 플립북을 숨기며 **재배치가 도달 불가 상태로 잠들었다**
(이동 버튼이 유일한 진입 경로였다). 이제 정보가 좌측 패널로 모였으니 조작도 같은 자리에 둔다 —
유닛 주변에 위성 UI 를 띄우지 않으면서 재배치가 되살아난다.

**기존 플립북은 폐기한다**(토글로 되살리지 않는다).

## 변경 대상

- `Assets/_Project/Scripts/UI/Dreamcatcher/DcInspectPanelView.cs` — 이동 버튼
- `Assets/_Project/Scripts/UI/Dreamcatcher/DcInspectController.cs` — 플립북 제거 + 콜백 전달

## 구현

### A. 버튼 — 패널 맨 아래 전폭

`Show(..., System.Action onMove)` 로 콜백을 받는다. **null 이면 버튼을 감춘다**
(`relocationController` 미배선). 스타일은 패널의 색 언어 그대로 — 라운드 플레이트 + 청록
테두리(`unitBorder`), 라벨 "이동". 정보(위)와 조작(아래)이 갈려 읽기 순서가 선다.

### B. 레이캐스트 — 계약의 유일한 예외

패널은 지금까지 **완전 비-인터랙티브**였다(모든 그래픽 `raycastTarget=false`,
`CanvasGroup.blocksRaycasts=false`) — "카드 드롭/조준 판정 비간섭" 계약 때문이다.
버튼이 생기면서 이 계약을 **최소 범위로만** 연다:

- `blocksRaycasts` 는 그룹 전체 스위치라 켤 수밖에 없다. 대신 **히트 대상은 버튼 하나뿐**이다
  — 나머지 그래픽은 `raycastTarget=false` 그대로다(검증: 패널 내 raycastTarget 개수 = 1).
- `blocksRaycasts` 는 `Update` 에서 `_visible` 과 함께 움직인다. 페이드 아웃 중에 눌리면
  이미 해제된 선택으로 재배치를 시작하게 된다.
- 캔버스 순서상 패널(9) > 손패 dismiss 캐처(5)라 버튼 탭이 캐처에 먹히지 않는다.

즉 카드 드롭이 막히는 곳은 **좌측 버튼 사각형뿐**이고, 그 자리는 패널이 그려져 있어 보인다.

### C. 기존 플립북 폐기

컨트롤러에서 `actionFlipbook` 필드·`showActionFlipbook` 토글·Show/Hide 호출을 제거한다.

**`DcActionFlipbookView` 클래스와 씬의 `DcActionFlipbook` 오브젝트는 남긴다.** 지금 씬을
저장할 수 없고(타 세션 WIP), 클래스를 먼저 지우면 씬에 missing script 가 남는다. 아무도
구동하지 않으므로 **inert** 하다 — 씬을 안전하게 저장할 수 있을 때 오브젝트+클래스를 함께
제거한다(후속).
