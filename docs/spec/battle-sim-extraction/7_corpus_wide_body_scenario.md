# 7 — 코퍼스의 사각: 「자기 자리 폭발」 축을 관측 가능하게

> `distance-based-range` unit 23 이 두 번 A/B 를 돌리고도 **효과를 측정하지 못했다.**
> 회귀가 없어서가 아니라 **코퍼스가 그 축을 볼 수 없어서**다. 이 unit 이 그 사각을 없앤다.

## 목적

unit 23(원점 항 통일)의 A/B 는 8/8 바이트 동일로 끝났는데, 그것이 **무회귀의 증거이지
「효과 없음」의 증거가 아니라는 것**을 그때 문서로만 적어 뒀다. 다음 사람이 같은 자를 만질 때
코퍼스가 다시 침묵하면 그 문장을 또 써야 한다 — **탐지기 자체를 고친다.**

### 왜 못 봤나 (실측 · unit 23 문서)

| 23 이 바꾸는 것 | 코퍼스에서 | Δ |
|---|---|---|
| 자기중심 광역의 원점 항 = 시전자 몸 | 배치되는 4기에 **배스티온이 없다**(Δ 최대 유닛, 몸 1.5) | 0 |
| 자기 자리 폭발이 원점 몸을 나른다 | 자폭 저작인 **브루저가 덱에 없고**, 나머지는 전부 드림캐쳐 카드인데 **하네스는 카드를 안 붙인다** | 0 |
| 도약·강습 슬램 | 코퍼스 보스 `boss_jjangssen` 의 몸이 **정확히 0.5** = 칸 반폭 | 0 |

세 경로 **모두** 구조적으로 0 이다. 「총계 무변」이 성공 신호로 오독되기 쉬운 형태다.

## 구현

```
new Scenario { name = "wide_body", seed = 20260822, ticks = 1800,
               placementTicks = new[] { 150, 330, 510, 690, 900 },
               defenderIds = new[] { "bastion", "bruiser", "cannon" } }
```

- **배스티온**(몸 1.5) — 배치 스킬이 **집단도발**(자기중심 광역). 도형 반경이 `2 + 1.5 = 3.5`
  라 옛 칸 상수(2.5)와 **Δ 1.0**. unit 23a 축의 최대 진폭이 여기 들어온다.
- **브루저**(몸 1.0) — `Ability_MeleeBurst_Bruiser` 는 트리거 **OnPlace**(kind 9)라 하네스가
  놓는 순간 결정론적으로 터진다. 페이로드가 투사체를 물고 있어 `ProjectileHitSystem` 의
  `ReachFromImpact` 를 지난다 = **unit 23b(원점 운반) 축의 유일한 «유닛 저작» 경로**.
- **캐논** — 판을 건강하게 유지하는 화력. `summoner` 시나리오가 캐논을 빼봤다가 킬 9→1 ·
  유출 0→1 로 무너진 선례가 있다(그 주석 참조). 근접 2종만으로는 유출 판이 된다.
- 배치 슬롯 5개 · 1800틱 — `summoner` 가 검증한 「3종 · 1800틱」 형태를 그대로 따른다.

⚠ **기존 8건을 다시 굽지 않는다.** `Bake Missing Goldens Only` 로 신규 1건만 굽는다 —
전체 재생성은 기존 기준선을 「지금 코드」로 덮어 그 시나리오들이 지키던 회귀 감시를 그 자리에서
무효로 만든다(그 메뉴 주석이 같은 경고를 이미 적어 뒀다).

## ⚠ 선행 결함 — 코퍼스의 방어 덱이 **개발자 프로필**을 따라간다 (2026-09-07 발견)

`wide_body` 를 구우려다 코퍼스 전건이 빨간 것을 발견했고, 추적 결과 **코드가 아니라 조건**이었다.

**증거**
- `profile.json → squads[selected].unitIds` = `malphite shotgunner shield_shuttle busters cannon bastion anti_air`
  = 하네스가 실제로 배치하는 덱과 **정확히 일치**.
- 씬에 저작된 `defenderPool` = `archer guardian cannon healer fire/ice/poison blocking` — **완전히 다르다.**
- 8건 중 **`summoner` 만 통과** — 유일하게 `defenderIds` 로 덱을 명시한 시나리오다.
- C-1(`fc6bfa7c`) 을 통째로 되돌려도 숫자가 **한 자리도 안 변한다** → 코드는 원인이 아니다.
  (덤으로 이것이 **「코퍼스는 23b 를 관측할 수 없다」의 재확인**이다.)
- 같은 세션 2회 실행 **완전 동일** → 심의 결정론은 정상.

**원인 — 캡처가 한 줄 늦다**

```csharp
// StartMatch
bridge.PrepareDraftMap();                    // ← 프로필의 «선택된 스쿼드» 가 덱에 적용된다
ApplyScenarioPool(bridge, sc);
  └─ if (_sceneDefaultPool == null) _sceneDefaultPool = bridge.DefenderPool;  // ← 그 뒤에 캡처
```

이름은 「씬 기본 풀」인데 값은 **프로필 스쿼드**다. 이름이 거짓말을 해서 아무도 다시 안 봤다.

**왜 같은 종류가 반복되나** — 코퍼스가 조건을 **선언하지 않고 라이브 부팅 경로에서 상속**하기
때문이다. 게임에 머신 상태 입력이 하나 늘 때마다 코퍼스 입력이 조용히 하나 는다.
지금까지: `DevMapOverride`(PlayerPrefs · 09-04 핀으로 차단) · 시트 임포트 in-memory 값(문서 규율만) ·
**프로필 선택 스쿼드**(오늘) · 우발적 로컬 dirt(`Street.asset.meta` GUID 깨짐 — 오늘 원복).
**핀은 아는 축만 막는다.**

**처방(미구현 · 다음 작업)**
1. 모든 시나리오가 덱을 **명시**하고, 암묵 상속 폴백을 **셋업 실패**로 바꾼다
   (지금은 조용히 씬/프로필 덱으로 진행해 실수가 안 보인다).
2. **조건 지문을 골든에 함께 굽고 실행 때 대조**한다 — 맵 인덱스·스테이지 이름·덱 id 목록.
   지금 `configHash` 는 「다르다」만 말하고 **무엇이** 다른지 안 말해서, 드리프트마다 수동 추적이
   필요하다. 골든이 「덱이 A 였는데 지금 B 다」를 **첫 줄에서** 말하게 만든다.
3. 그 뒤에 9건 전량 클린 재베이크(도메인 리로드 → BattleScene 직행 → 첫 동작).
