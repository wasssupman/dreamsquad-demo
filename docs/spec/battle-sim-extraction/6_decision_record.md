# 6 — 결정 기록: 기각된 대안과 재론 조건 (ADR)

> 설계 세션(2026-08-03)의 논박 보존용. 채택 근거는 설계 정본에 있고, 여기는 **왜 다른 길이 아닌지**를 남긴다. 재론하려면 해당 항목의 재론 조건부터 반박하라.

## D1. 계보 B(분리 틱 시뮬) 채택 — 기각: 계보 A(Unity 컴포넌트식 표준: 유닛 프리팹 + Health/Movement/Attack MonoBehaviour + Update 구동)

- 기각 근거: ① 프레임레이트 의존 거동 — 같은 seed 판의 점수 차가 실력이 아니라 기기에서 나옴(랭킹 파는 게임의 잠재 부채) ② 헤드리스/EditMode 시뮬 테스트 불가 — 회귀 검증이 Play 육안으로 후퇴 ③ 리플레이/고스트 원리적 불가(로드맵 확정 항목) ④ "표준이라 진입이 쉽다"는 A의 실무 장점은 1인+에이전트 체제에 해당 없음.
- 논쟁 기록: **성능은 기각 근거가 아니다** — 이 게임 유닛 규모(수십~이백)에선 A도 충분. 초기에 성능 논거를 과장했다가 결정론·테스트 가능성으로 좁힌 것 자체가 논쟁 결과.
- 재론 조건: 리플레이/고스트가 로드맵에서 빠지고 토너먼트 공정성 요구가 철회될 때.

## D2. 리플레이 정본 = 이벤트 스트림 — 기각: 커맨드로그+재시뮬 정본

- 기각 근거: 재시뮬 정본은 **재생하는 모든 기기에서 비트 동일 결정론**을 요구한다. 이기종(ARM/x64·IL2CPP/CoreCLR)의 float·트리그(`math.sin` 등 libm) 편차 때문에 이는 고정소수점 수학 전면 이식 + 전 수치 재튜닝이라는 최대 리스크를 로드맵에 불러들인다. 스트림 정본이면 결정론 요구가 검증 러너 단일 환경으로 국한된다.
- 단서(Codex 라운드에서 보강): 무결성 축은 커맨드로그를 **병용**(정본 이원화). 단 IL2CPP(클라)↔CoreCLR(러너) 편차 때문에 M3 전 재시뮬 대조는 advisory flag만 — exact 자동 판정 금지.
- 재론 조건: 스트림 저장이 예산(압축 ~300KB/판)을 계속 초과할 때.

## D3. "계약은 지금, 배치는 나중" — 기각 A: 순수 Mono로 먼저 만들고 나중에 서버 업그레이드 / 기각 B: 지금 실서버 동시 구축

- A 기각: 인프로세스 기간에 클라권위로 부패하는 3모드 — 계약 우회(같은 프로세스라 seam을 돌아감) · 직렬화 미검증(네트워크에 못 탈 페이로드 침투) · 지연 0 가정(UI가 같은-프레임 응답 전제). 부패 후 "업그레이드" 비용 = 이번 마이그레이션 전체를 한 번 더.
- B 기각: 움직이는 표적 2개(시뮬 이식과 네트워크 프로토콜을 동시 디버깅) · Firebase→상태ful 틱 서버는 운영 체급 점프 · 플레이 가능 빌드 수개월 공백.
- 절충의 실체: 부패 방지를 의지가 아니라 구조로 강제하는 가드 6종 + M2(리플레이 유저 기능화)가 스트림 계약을 제품이 지키게 함.
- 감시 신호: **M2까지 밀리면 이 절충이 부패 중이라는 뜻이다.**

## D4. BattleBridge는 해체가 목적지 — 기각: 표면 동결 후 이면만 교체 (초기안, 자기 철회)

- 기각 근거: 갓-매니저(겸직 10+ · 실코드 소비자 82파일 · 본체 7k줄)를 새 아키텍처에 그대로 계승하게 된다. ECS↔Mono 두 세계가 사라지면 "단일 창구" 제약의 존재 이유도 소멸 — 대체 불변식은 창구가 아니라 **asmdef 의존 방향**.
- 순서 역전(critic 2트랙이 독립적으로 동일 결론): 해체·이식보다 **seam(IMatchSession 파사드) 도입이 먼저**. 스왑 반경을 "세션 구현체 교체 1곳"으로 줄이고 재배선 회귀와 sim 회귀를 분리 검증.

## D5. 28채널은 세리머니가 아니다 (자기 철회 2회 기록)

- 1차 판단 "27채널은 ECS 세리머니 → Queue 1:1 치환" → 철회: 서버권위 프레임에서 채널 목록은 **이벤트 프로토콜 분류학의 초안**이다("넉업은 뷰가 구분 못 하니 사건으로 신호" 같은 결정들이 곧 semantic event 설계).
- 2차 판단 "단일 스트림으로 붕괴" → 철회(Codex): 같은 틱 소비 계약인 내부 phase 메시지(CastEvents→AttackSystem 등)와 AMR을 혼합하면 공격·텔레포트가 1틱 늦는다 → **이벤트 3분리**가 최종.
- 교훈: "뷰는 게임 규칙을 소유하지 않는다"는 이 게임의 설계 자산이지 ECS 산물이 아니다.

## D6. 백지 설계 + 스트랭글러 실행 — 기각: 번역본 설계 / 기각: 그린필드 재작성 실행

- 번역본 설계 기각(사용자 프레임): 기존 구조는 기득권 없음 — "애초에 Mono 기반으로 설계했다면"의 그림에서 재도출로만 생존.
- 그린필드 실행 기각: second-system 함정 — 수개월 플레이 불가 빌드 + 코드에만 박힌 미문서 규칙(넉업=짧은 스턴, DoT (origin,element) 2축 병합 등) 유실.
- 절충: 설계는 백지, 이행은 conform/adapt/rewrite/discard 4등급 + 항상 플레이 가능 유지.

## D7. 기본값 2건 (사용자 미확정 — 이견 시 README 계약 갱신)

- 콘텐츠 동결(신규는 신 lib에만, 구 sim 조기 프리즈): Bridge 최근 60일 334커밋 속도에서 A/B 이중 유지보수는 성립 불가가 근거.
- lag compensation 미채택: 단순성 우선. 재론 조건 = RTT 150ms 주입 디자인 리뷰에서 통과 못 하는 스킬·카드가 나올 때.
