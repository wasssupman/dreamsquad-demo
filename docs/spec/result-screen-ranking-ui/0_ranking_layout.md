## 목적

점수를 화면의 주인공으로 올리고, 순위를 즉시 읽히게 하고, 폰트를 모바일 기준으로 키운다.

## 변경 대상

- 수정 `Assets/_Project/Scripts/UI/ResultScreen.cs` (렌더링 계층만)

## 구현

### 왜 2컬럼인가

게임은 **가로 전용**이다 (`ProjectSettings.asset`: `allowedAutorotateToPortrait: 0`, 양쪽 landscape 만 1).
그런데 기존 패널은 1920 기준폭에서 880만 쓰고 **좌우 520씩 버렸다** — 가로 화면에 세로형 패널을 놓은 꼴.

가로를 제대로 쓰면 폰트를 전반적으로 한 단계씩 올릴 여유가 나온다. 그게 이 재배치의 실제 목적이다.

```
pad 30 │ 좌 520 (내 결과) │ gap 28 │ 우 832 (랭킹) │ pad 30   = PanelW 1440

좌: 리본 → 히어로 점수 → 순위 → [flex] → 스탯 행 → [flex] → 로비로
우: "랭킹" 라벨 → 리스트
```

### 높이는 우측이 정한다

패널 = `HorizontalLayoutGroup` + `ContentSizeFitter(vertical=PreferredSize)`,
`childForceExpandHeight = true` 로 좌측 컬럼이 우측 높이에 맞춰 늘어난다.

우측 리스트는 `ContentSizeFitter` 로 행 수에 붙으므로 슬롯 수가 곧 패널 높이다:

| 상태 | 행 | 패널 |
|---|---|---|
| 실데이터 / 로그인 대기 | 10 | 1440 × 748 |
| 미로그인 폴백 | 5 | 1440 × 616 |

좌측 컬럼의 로비로 버튼은 **flexible 스페이서 2개**(스탯 행 위·아래)로 항상 바닥에 붙는다.
스페이서가 없으면 버튼이 패널 중간에 뜬다.

### 순위 콜아웃

순위는 렌더 직전 행 목록에서 `IsPlayer` 를 찾아 얻는다. `ShowResult`(폴백)와
`UpdateLeaderboard`(실데이터) **양쪽에서 갱신**해야 한다 — 실데이터가 오면 순위가 바뀐다.
`Rank == 0`(순위 미상)이면 `내 점수` 만 표시한다 — unit 1 참조.

### 손대지 않는 것

`Row` / `BuildRows` / `DisplayName` — 서버 데이터 경로는 불변 (계약 1).
`ResultLeaderboardModelTests` 가 이걸 덮고 있다.
