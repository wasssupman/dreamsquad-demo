# 1 — 봇 폴백을 "참가자 찾는 중" 대기 상태로

## 목적

폴백 리스트가 **없는 순위를 지어내지 않게** 한다.

기존 `BuildBotRows` 는 플레이어 점수의 0.5~1.5배 구간에서 봇 5명의 점수를 생성하고
그 안에서 플레이어 순위를 매겼다. "봇-1" 이라 밝히는 동안은 그래도 정직했지만,
**라벨을 "참가자 찾는 중" 으로 바꾸면 생성된 숫자가 실제 참가자의 실제 기록으로 읽힌다.**
라벨만 바꾸면 오해를 줄이려다 더 그럴듯한 오해를 만든다.

## 변경 대상

- 수정 `Assets/_Project/Scripts/UI/ResultScreen.cs`

## 구현

`BuildBotRows` → `BuildPendingRows`. 내 행 1개 + `참가자 찾는 중` 대기 행 N개를 반환한다.

- 내 행: 실제 점수, `IsPlayer=true`, `IsWaiting=false`
- 대기 행: 점수 0, `IsWaiting=true` → 기존 WAITING 렌더링(흐린 색 + `-`)을 그대로 탄다
- **모든 행의 `Rank = 0`** — "순위 미상" 센티넬이다. `BuildRows`(서버 경로)는 0을 절대 내지 않으므로 충돌하지 않는다

**`Rank = 0` 이 세 곳을 동시에 처리한다**:

1. `UpdateCaption` 의 `rank > 0` 검사가 실패 → 캡션이 `내 점수` 만 표시 (순위 주장 없음)
2. `CreateRow` 의 뱃지가 `-` 를 그린다 (`row.Rank > 0 ? ... : "-"`)
3. 뱃지 switch 가 default 로 떨어져 네이비 뱃지 — 금/은/동을 안 준다

### 슬롯 수는 "왜 폴백인가"에 따라 갈린다 — **unit 2 에서 대체됨**

> **rev 2026-07-29 (unit 2)**: 슬롯은 **항상 5** (`PendingSlots`) — 서버 실측

> maxEntryCount 가 10이던 시절의 계약이며 제거됐다. `2_pending_race_bracket_fix.md` 참조.

폴백은 두 상황에서 뜬다. 같은 화면이지만 의미가 다르므로 슬롯 수를 나눴었다 (구 계약):

| 상황 | 슬롯 | 이유 |
|---|---|---|
| 토너먼트 세션 없음 (게스트/미로그인/서버 URL 없음) | **5** | 이 리스트가 **최종**이다. 아무것도 대체하지 않는다. 10칸을 보여주면 채워지는 중인 대진표처럼 읽힌다 |
