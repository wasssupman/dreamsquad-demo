# skill-data-table — 스킬 데이터 표 재설계

> **상태: units 0~5 구현 완료 2026-09-29 · 2부(units 7~10 — 시트 구조 리팩토링): unit 7 보류 · unit 8 완료 2026-09-29(단계 A · 이전 적용 · 단계 B · 재직렬화 · EditMode · PlayMode Core · core-reviewer APPROVE) · unit 9 · 10 미착수.** 2부 근거 = 시트 export 에서 드러난 옛 형식 잔존(카드 전용 탭 2 · 열 이름 혼용 · 쿨다운 두 원천) + 독립 비평(Fable) 검토. 1부 인계 = `6_handoff_summary.md`. core-reviewer 묶음 2회 APPROVE(1a–3 · 4–5). 선행 = `docs/spec/unified-effect-layer/`(완료 — 실행 층 통일 · 하드 케이스 1~4). 근거 = 그 README 「하드 케이스 3·4 막는 곳」 표 + 3자 토론(리드 · 독립 비판 · 게임 선례 조사) 합의. **기존 시트 구조는 폐기 전제** — 새 표는 이 spec 이 정한다.

## 상위 목표

**스킬을 소유한 대상이 스킬을 쓴다.** 효과에 정체(안정 id)를 주고, 카드 · 방어유닛 · 적은 같은 형식으로 그 id 를 참조한다. 소유자를 바꾸는 일이 복사가 아니라 **참조 한 줄**이 되게 한다.
검증 질문: ① 개사기(AA)가 캐논 배치 폭격과 **같은 효과 id** 를 다른 트리거로 참조해 복사 없이 동작하나 ② 짱쎈의 도약 효과를 방어유닛이 **그 id 로** 소유해 발동하나(자리는 몸을 따라가나) ③ 적이 든 플레이어 자원 효과가 무효인가.

## 사용자 결정

- **U6 스킬 = 효과(종류 + 수치)** — 소유자는 「언제(트리거 × 주체) → 효과 id」를 든다. A 의 배치 스킬 = (내 배치 → E), AA = (남의 배치 → 같은 E).
- **U7 수치는 스킬마다 「고정」 또는 「특정 스탯 기준 비율형」** — 기준 스탯은 스킬마다 고른다(초안 = **공격력 · 최대 체력**). 값은 **시전 순간**의 **최종 스탯**(버프·모디파이어 반영)으로 고정해 싣는다(2026-09-28 — 착탄 순간안은 철회). **공격력 = 모든 공격력 변형 효과가 반영된 최종 수치**(평타 1회가 내는 피해의 최종값).
- **U8 같은 효과를 두 번 가지면 둘 다 발동** — 현행 쌓임 규칙 유지(중복 거절은 지금처럼 일부 상태만).
- **U9 고유 스킬은 지금 정의하지 않는다** — 칸·규칙 0. 「그 효과를 참조하는 소유자가 하나」가 사실상 고유.
- **U10 패턴·장판 피해는 효과 줄로 옮긴다**(2026-09-28) — 패턴·장판은 모양(발 수·간격·범위·지속)만, 피해는 효과 줄. 같은 패턴을 피해만 다르게 여러 효과가 쓴다. 오늘 스킬 경로 패턴 피해 = `PatternDef.Damage`(`IntentApplier.cs:333`) · 장판 피해 = `HazardEffectDef.Magnitude` · 슬램 = `SlamDamage` 칸 · 길막 폭발 = `BlockingHazardDef.ExplodeDamage`(폭탄맨 배럴 — unit 0 발견). 장판의 비피해 수치(감속 배율 등)는 장판 줄에 남는다(`tables.md` §6).
- **U11 비율형의 「공격력」 = 평타 한 발의 출력 합 × 공격자 쪽 배율만**(2026-09-28) — 대상에 따라 달라지는 배율(대 CC · 수면 · 최전방)과 강타는 뺀다. 계산은 상태를 건드리지 않는 새 순수 함수(강타 카운터 전진 금지 — `AttackMod.cs:121`).
- **U12 표 모양 승인**(2026-09-28) — `tables.md` 구조(스킬(효과) 표 + 보유 줄 표 + 탄·패턴·장판·카드·유닛·적 표).
- **U13 수치가 같아도 효과 줄을 나눈다** — 소유자마다 따로 조정할 수 있게(병합하지 않는다). 강타 ×2 세 장 · 짱쎈 순간이동 2줄 각각 별 줄.
- **U14 실드 셔틀 실드 반경 = 효과 줄의 고정값** — 유닛 사거리 파생(`BindingDefinitionBuilder.cs:78`) 을 끊는다. 이전 때 오늘 파생값을 그대로 적어 라이브 무변.
- **U15 연출은 효과 기준** — 같은 효과면 누가 줬든 같은 연출. 오늘 출처(드림캐쳐 · 보스)에 묶인 연출 규칙은 데모라 따르지 않는다(`naming-census.md` B 「실행자가 출처를 박는 곳」 — unit 2 에서 출처 대신 효과로).
- **U16 카드 발동 연출(카드 펄스 · 발동 임팩트)은 카드 보유 줄일 때만** — 「카드를 썼다」의 표시.
- **U17 「남의 사건」(주체 `Any` — 남의 배치) × 비율형의 기준 스탯 = 규칙 소유자(카드가 붙은 숙주)** — 사건 주체(놓인 유닛)가 아니다. 발사 자리 · 킬 귀속은 그대로 놓인 유닛(U3). 주인 없는 시전(판 · 액티브 · 드림스톤 · 판 주기)은 여전히 `NoRatioBasis`(unit 3).
- **U18 액티브 스킬은 추후 드림캐쳐에서 분리한다 · 비용은 20 그대로**(2026-09-29) — `SkillData` 흡수는 그 분리 spec 으로 미룬다(이 spec 에선 `skill` 칸 · `SkillData` · DcSkills 탭 유지). 카드 문안의 비용 표시는 실제 비용(`AwakeningConfig.costActive` = 20)을 보여 준다(옛 `SkillData.cost` 2~4 표시 은퇴).
- **U19 시트 이름**(2026-09-29 · 리드 추천 승인) — 효과 표 탭 = `Skills`(U6: 스킬 = 효과) · 보유 줄 탭 = `SkillOwners` · `owner_kind` 값 = `card` · `defender` · `enemy`(기존 `Defenders` 탭과 같은 어휘) · 효과 종류 열 옆에 한국어 표시 열.
- **U20 공격 변형(강타 · 튕김 · 최전방 · 수면 특효)** — 코드는 소유자 종류를 구분하지 않지만 **시트는 방어유닛 쪽 소유자만 받는 구조**(2026-09-29). 적 소유 줄 · 적 숙주 카드 줄 × 공격 변형 = 시트 import 거절(unit 9). 강타 포함은 리드 파생(같은 공격 변형 — 오늘 카드 3장만 든다).
- **U21 진영 버프를 방어유닛 · 적이 들면 소유 시작 순간 이미 판 위에 있던 아군도 받는다**(2026-09-29 — 카드와 같다) · 이후 서는 아군 상속 · 소유자가 떠나면 회수(unit 7).
- **U22 진영 버프 · 「남의 배치」 규칙의 수혜자 = 시전자와 같은 진영**(2026-09-29) — 적이 든 「모든 아군 공격력」은 적 전원.
- 리드 파생(사용자 확인 대상 — 반대 시 뒤집는다): **D1** 적의 소유 시작 = 등장(스폰 조립 끝)이고, 적의 등장이 적 진영의 「배치」 사건이 된다(나중에 나온 적이 상속받으려면 필요 · 라이브 적 소유 줄 중 배치 트리거 0 → 무변) — ⚠ 비평: 파생이 아니라 새 축(「적이 등장하면 X」 · 「남의 등장에 폭격」이 원리상 열린다) → **사용자 질문 Q1** · **D2** 순찰 소환물은 오늘처럼 진영 버프 수혜 밖 · **D3** 보유 줄 탭 = 한 탭(`SkillOwners`) 유지 — 소유자별 3탭은 같은 스키마를 소유자 종류로 되박는다(비평 반영 · 「이 스킬을 누가 드나」가 필터 한 번) · **D4** 방어유닛의 소유 시작 = 배치 완료(배치 모션 중엔 수혜를 주지 않는다).
- **U23 적 등장을 「배치」로 여는 범위 = 진영 버프 상속만**(2026-09-29 · Q1-A) — 「적이 등장하면 X」 · 「남의 등장에 X」 는 굽기 거절 유지.
- **U24 같은 진영 버프를 든 적 N마리 = N번 쌓인다**(2026-09-29 · Q2-A — U8 그대로 · 수는 적 저작이 조절).

## 계약

1. **정체는 효과 줄에 있다.** 효과 표 = 종류 + 수치 + 수치 방식 + 안정 `Id`(탄·패턴·장판 표와 같은 id 참조 표 — 새 층이 아니라 네 번째 표). 수치가 다르면 다른 효과 줄 — **소유자별 덮어쓰기 없음**.
2. **소유 = 참조 줄.** 소유자는 (트리거 · 주체 · 게이트 · 수명 → 효과 id) 줄을 든다. 카드 · 유닛 · 적의 저작 형식은 하나(오늘 네 저장처 `mechanics` · `UnitSkillAbility` · `nightmareMechanics` · 코드가 굽는 `ShieldCastAbility` 를 합친다).
3. **스킬은 소유자를 묻지 않는다.** 소유자에 따라 결과가 달라야 하면 **그 상태의 담당자가** 정한다 — 자리 이동은 `PlacementService` · 판 자원은 `CostLedger`/`HandDeck` 이 진영을 본다. 능력 선언 칸은 두지 않는다(소유자 종류 · 기존 사실에서 파생).
4. **부여 게이트 ↔ 실행 분리.** 어느 숙주에 붙을 수 있나는 카드 속성(`HostKinds`, 기본 방어유닛)이고, 굽기가 그 종류마다 검증한다. 실행은 숙주를 모른다.
5. **「아무 소유자 × 아무 스킬」을 보장하지 않는다.** 계약은 검증 함수(`EffectComboRule`)다.
6. **서버 어휘 = 효과 id.** 정의표 줄 번호(매치마다 다름)는 정체가 아니다.
7. 라이브 동작 무변(비율형 도입 전까지) · 판정 자 하나(제약 13) · enum append-only.
8. **해시에는 해석된 값만 싣는다** — 효과 id 문자열·효과 표 순서는 해시 밖. 새 칸은 기본값이면 해시에 쓰지 않는다. 목표 재베이크 0회 · 불가피하면 그 unit 끝 **격리 커밋**.
9. **「시전 순간」의 정의**: 규칙이 발동해 스킬이 실행되는 드레인 순간. 연사(버스트)는 **개시 순간 한 번**, 모든 발이 공유. 주인이 떠난 뒤 발동(사망·퇴근)은 **감지 순간 스냅샷**을 사건에 싣는다(제약 13 의 몸 스냅샷 선례). 주인 없는 시전(판 시전 · 액티브 · 드림스톤 · 판 주기)의 비율형은 검증에서 거절. 최대 체력은 모디파이어 단계에서만 갱신돼 같은 틱 버프는 한 틱 늦게 보인다.
10. **id 는 표 안에서 유일**(탄 · 패턴 · 장판 · 효과 각 네임스페이스). 오늘 탄과 패턴이 `cannon_strike` 등 3건 겹치고 장판 id 는 에셋 이름이다 — 개명하지 않는다.
