# skill-data-table — 스킬 데이터 표 재설계

> **상태: spec 초안 2026-09-28 · 승인 대기.** 선행 = `docs/spec/unified-effect-layer/`(완료 — 실행 층 통일 · 하드 케이스 1~4). 근거 = 그 README 「하드 케이스 3·4 막는 곳」 표 + 3자 토론(리드 · 독립 비판 · 게임 선례 조사) 합의. **기존 시트 구조는 폐기 전제** — 새 표는 이 spec 이 정한다.

## 상위 목표

**스킬을 소유한 대상이 스킬을 쓴다.** 효과에 정체(안정 id)를 주고, 카드 · 방어유닛 · 적은 같은 형식으로 그 id 를 참조한다. 소유자를 바꾸는 일이 복사가 아니라 **참조 한 줄**이 되게 한다.
검증 질문: ① 개사기(AA)가 캐논 배치 폭격과 **같은 효과 id** 를 다른 트리거로 참조해 복사 없이 동작하나 ② 짱쎈의 도약 효과를 방어유닛이 **그 id 로** 소유해 발동하나(자리는 몸을 따라가나) ③ 적이 든 플레이어 자원 효과가 무효인가.

## 사용자 결정

- **U6 스킬 = 효과(종류 + 수치)** — 소유자는 「언제(트리거 × 주체) → 효과 id」를 든다. A 의 배치 스킬 = (내 배치 → E), AA = (남의 배치 → 같은 E).
- **U7 수치는 스킬마다 「고정」 또는 「특정 스탯 기준 비율형」** — 기준 스탯은 스킬마다 고른다(초안 = **공격력 · 최대 체력**). 값은 **시전 순간**의 **최종 스탯**(버프·모디파이어 반영)으로 고정해 싣는다(2026-09-28 — 착탄 순간안은 철회). **공격력 = 모든 공격력 변형 효과가 반영된 최종 수치**(평타 1회가 내는 피해의 최종값).
- **U8 같은 효과를 두 번 가지면 둘 다 발동** — 현행 쌓임 규칙 유지(중복 거절은 지금처럼 일부 상태만).
- **U9 고유 스킬은 지금 정의하지 않는다** — 칸·규칙 0. 「그 효과를 참조하는 소유자가 하나」가 사실상 고유.
- **U10 패턴·장판 피해는 효과 줄로 옮긴다**(2026-09-28) — 패턴·장판은 모양(발 수·간격·범위·지속)만, 피해는 효과 줄. 같은 패턴을 피해만 다르게 여러 효과가 쓴다. 오늘 스킬 경로 패턴 피해 = `PatternDef.Damage`(`IntentApplier.cs:333`) · 장판 피해 = `HazardEffectDef.Magnitude` · 슬램 = `SlamDamage` 칸.
- **U11 비율형의 「공격력」 = 평타 한 발의 출력 합 × 공격자 쪽 배율만**(2026-09-28) — 대상에 따라 달라지는 배율(대 CC · 수면 · 최전방)과 강타는 뺀다. 계산은 상태를 건드리지 않는 새 순수 함수(강타 카운터 전진 금지 — `AttackMod.cs:121`).
- 이어받는 결정: U3(킬 = 탄이 나간 유닛) · U4(적이 든 플레이어 자원 효과 = 무효) · U5(방어유닛 기준 카드 = 방어유닛 전용 전제).

## 계약

1. **정체는 효과 줄에 있다.** 효과 표 = 종류 + 수치 + 수치 방식 + 안정 `Id`(탄·패턴·장판 표와 같은 id 참조 표 — 새 층이 아니라 네 번째 표). 수치가 다르면 다른 효과 줄 — **소유자별 덮어쓰기 없음**.
2. **소유 = 참조 줄.** 소유자는 (트리거 · 주체 · 게이트 · 수명 → 효과 id) 줄을 든다. 카드 · 유닛 · 적의 저작 형식은 하나(오늘 세 저장처 `mechanics` · `UnitSkillAbility` · `nightmareMechanics` 를 합친다).
3. **스킬은 소유자를 묻지 않는다.** 소유자에 따라 결과가 달라야 하면 **그 상태의 담당자가** 정한다 — 자리 이동은 `PlacementService` · 판 자원은 `CostLedger`/`HandDeck` 이 진영을 본다. 능력 선언 칸은 두지 않는다(소유자 종류 · 기존 사실에서 파생).
4. **부여 게이트 ↔ 실행 분리.** 어느 숙주에 붙을 수 있나는 카드 속성(`HostKinds`, 기본 방어유닛)이고, 굽기가 그 종류마다 검증한다. 실행은 숙주를 모른다.
5. **「아무 소유자 × 아무 스킬」을 보장하지 않는다.** 계약은 검증 함수(`EffectComboRule`)다.
6. **서버 어휘 = 효과 id.** 정의표 줄 번호(매치마다 다름)는 정체가 아니다.
7. 라이브 동작 무변(비율형 도입 전까지) · 판정 자 하나(제약 13) · enum append-only.
8. **해시에는 해석된 값만 싣는다** — 효과 id 문자열·효과 표 순서는 해시 밖. 새 칸은 기본값이면 해시에 쓰지 않는다. 목표 재베이크 0회 · 불가피하면 그 unit 끝 **격리 커밋**.
9. **「시전 순간」의 정의**: 규칙이 발동해 스킬이 실행되는 드레인 순간. 연사(버스트)는 **개시 순간 한 번**, 모든 발이 공유. 주인이 떠난 뒤 발동(사망·퇴근)은 **감지 순간 스냅샷**을 사건에 싣는다(제약 13 의 몸 스냅샷 선례). 주인 없는 시전(판 시전 · 액티브 · 드림스톤 · 판 주기)의 비율형은 검증에서 거절. 최대 체력은 모디파이어 단계에서만 갱신돼 같은 틱 버프는 한 틱 늦게 보인다.
10. **id 는 표 안에서 유일**(탄 · 패턴 · 장판 · 효과 각 네임스페이스). 오늘 탄과 패턴이 `cannon_strike` 등 3건 겹치고 장판 id 는 에셋 이름이다 — 개명하지 않는다.
