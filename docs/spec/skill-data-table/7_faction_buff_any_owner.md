# 7 — 진영 버프를 누가 들어도 같게 (코어)

## 목적

「모든 아군 공격력 +8%」(오늘 스쿼드 카드 13장) 같은 **진영 버프**를 방어유닛 · 적이 들어도 카드와 같은 규칙으로 돌게 한다(U21 · U22).
오늘은 카드 경로에만 「판 위에 이미 있던 아군에게 즉시」 전개가 있고(`CardBindings.FireOnAttach` 의 Squad 루프),
「남의 배치」 규칙(`BindingSubject.Any`)의 수혜 판정(`TriggerDispatcher.SubjectPasses`)이 **진영을 보지 않는다**.

## 규칙 (게임에서 일어나는 일)

- 버프를 가진 쪽이 **판에 서는 순간**(카드 = 부착 · 방어유닛 = 배치 완료 · 적 = 등장) 이미 판 위에 있는 **같은 진영** 아군 전원(필터 통과분 · 소유자 자신 포함)이 받는다.
- 그 뒤에 서는 같은 진영 아군도 받는다(상속 — 오늘 카드와 같다).
- 소유자가 떠나면(사망 · 퇴근) 판 전체에서 회수된다(오늘 `RevokeOnExpire` 와 같다).
- 한 규칙은 한 유닛에 **한 번**만 건다(시작 전개와 상속이 겹치지 않는다).
- 적이 든 버프는 **적만** 받는다. 방어유닛 · 카드 · 드림스톤이 든 것은 방어유닛만 받는다(D1: 적의 등장이 적 진영의 배치 사건이다).
- 순찰 소환물은 오늘처럼 받지 않는다(D2 — 배치 사건이 없다).

## 변경 대상

- `Scripts/BattleCore/Trigger/TriggerDispatcher.cs` — `SubjectPasses` 에 **진영 조건**(주체 진영 = 규칙의 `CastFaction`)을 넣는다. `Any` 규칙 전부가 지난다(개사기 · 배치 오라 · 드림스톤 · 스쿼드 — 오늘 전부 플레이어 진영이고 배치 주체도 방어유닛뿐이라 라이브 무변). 직업 · 코스트 필터는 지금처럼 방어유닛 정의를 본다.
- 적 등장 = 적 진영의 배치 사건: `World/EnemySpawn.At` 끝(조립 완료 — 웨이브 · 분열 · 디버그 공통 한 자리)에서 `CoreEvent` 하나를 내고, 디스패처가 그 적을 주체로 `OnPlace` 를 올린다(`OnActivated` 와 같은 모양). 로그/트레이스 정거장을 같이 연다.
- 소유자의 진영 버프 줄: `MatchDefinition` 의 유닛 · 적 정의에 카드의 `SquadBindings` 와 같은 칸(규칙 줄 번호 배열 — 빈 배열 = 기본값, 해시 밖). 등록부가 **소유 시작 순간**(방어유닛 = `DefenderActivated` · 적 = 위 등장 사건)에 붙이고, 판 위 같은 진영 유닛에 한 번씩 전개한다.
- 전개 함수 하나: `CardBindings.FireOnAttach` 의 Squad 루프를 카드 부착 · 방어유닛 시작 · 적 시작이 **같은 함수**로 부른다(`SubjectPasses` 가 한 함수인 이유와 같다 — 같은 답).
- `EffectComboRule` 은 바뀌지 않는다(이 unit 은 굽기 입력이 없다 — 저작 연결은 unit 8).

## 이식 제외 · 결정론

- 순회 = `SimEntityId` 오름차순(전개도 월드 목록 순) · 같은 틱의 시작 전개 → 상속 순서는 오늘 카드 부착과 같다.
- 방어유닛 소유자가 **배치 모션 중**에는 수혜를 주지 않는다(D4 — 시작 = 활성화).

## 완료 기준

- 탐침 테스트(`Tests/EditModeCore/`, 빌더 없이 정의표 직접): ① 방어유닛이 「모든 아군 공격력 +X」를 들고 배치 완료 → 먼저 있던 방어유닛 둘 + 자신 + 이후 배치분이 받는다 · 소유자 사망 → 전원 회수 ② 적이 들고 등장 → 먼저 있던 적 + 이후 등장 적(분열 자식 포함)만 받고 방어유닛은 안 받는다 ③ 한 유닛에 한 번 ④ 적 등장이 개사기(남의 배치 → 폭격)를 발동시키지 않는다 · 드림스톤이 적을 버프하지 않는다.
- 하드 케이스 탐침 갱신(해당하는 `현행_` 단언).
- 라이브 무변: 굽기 스냅샷 2종 동일 · 헤드리스 전 초록 · EditMode Core · PlayMode Core 초록 · 골든(Unity) 무변.
