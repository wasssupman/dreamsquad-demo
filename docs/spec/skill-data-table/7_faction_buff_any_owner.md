# 7 — 진영 버프를 누가 들어도 같게 (코어)

> **상태: 보류 — 후속으로 이관(2026-09-29 사용자 승인).** 진영 버프를 든 방어유닛 · 적 콘텐츠가 0 이라 지금 배선하면 소비자 없는 코어가 된다(계약 5 — 「아무 소유자 × 아무 스킬」을 보장하지 않는다). 규칙(U21~U24 · D1 · D2 · D4)과 아래 설계 · 비평 반영은 **그때 이 문서대로** 구현한다. 그때까지 방어유닛 · 적 × 진영 버프는 굽기가 「배선 전」으로 거절한다(unit 8).

## 목적

「모든 아군 공격력 +8%」(오늘 스쿼드 카드 13장) 같은 **진영 버프**를 방어유닛 · 적이 들어도 카드와 같은 규칙으로 돌게 한다(U21 · U22).
오늘은 카드 경로에만 「판 위에 이미 있던 아군에게 즉시」 전개가 있고(`CardBindings.FireOnAttach` 의 Squad 루프),
「남의 배치」 규칙(`BindingSubject.Any`)의 수혜 판정(`TriggerDispatcher.SubjectPasses`)이 **진영을 보지 않는다**.

## 규칙 (게임에서 일어나는 일)

- 버프를 가진 쪽이 **판에 서는 순간**(카드 = 부착 · 방어유닛 = 배치 완료 · 적 = 등장) 이미 판 위에 있는 **같은 진영** 아군 전원(필터 통과분 · 소유자 자신 포함)이 받는다.
- 그 뒤에 서는 같은 진영 아군도 받는다(상속 — 오늘 카드와 같다). 소유자가 떠나면(사망 · 퇴근) 판 전체에서 회수된다(`RevokeOnExpire`).
- 한 규칙은 한 유닛에 **한 번**만 건다. 같은 효과를 든 소유자가 여럿이면 소유자마다 따로 건다(U8 · 오늘 카드 두 장과 같다).
- 수혜자 = 시전 진영(`Binding.CastFaction`)에서 **배치 사건을 올리는 종류**뿐 — 플레이어 = 방어유닛 · 적 = 적. 순찰 소환물은 오늘처럼 받지 않는다(D2 — 순찰도 플레이어 진영이라 진영만 보면 들어온다 · `CombatPhase.cs:346`). 배치 모션 중인 유닛은 전개에서 빠지고 활성화 때 상속으로 받는다(D4).
- 적이 든 버프는 적만, 방어유닛 · 카드 · 드림스톤이 든 것은 방어유닛만 받는다. 적 숙주 카드의 시전 진영 = 카드를 쓴 쪽(플레이어 — 오늘 `CastFaction` 그대로).

## 변경 대상 · 구현

- `Trigger/TriggerDispatcher.cs` `SubjectPasses` — 진영 조건(주체 진영 = `CastFaction`)과 종류 조건(위 수혜 종류)을 **필터 0 조기 반환(`:287`) 앞**에 둔다. `Any` 규칙 전부가 지난다 — 개사기 · 배치 오라 · 드림스톤 · 스쿼드는 오늘 전부 플레이어 진영 · 배치 주체도 방어유닛뿐이라 라이브 무변.
- **적 등장 = 적 진영의 배치 사건**(D1 — Q1 답에 따라 범위가 정해진다): 디스패처가 `UnitSpawned`(종류 Enemy) 를 구독해 그 적을 주체로 `OnPlace` 를 `Seam.Periodic` 에 올린다(`OnActivated` · `TriggerDispatcher.cs:190-197` 과 같은 모양). 새 사건 종류 0 — 사건은 틱 끝 배달이라 수신 시점엔 `EnemySpawn.At` 조립이 끝나 있고, 적 스폰은 `EnemySpawn.At`(`World/EnemySpawn.cs:57`) 한 자리다(웨이브 · 분열 · 디버그 · 보스). 선례 `GimmickBindings.OnSpawned`.
- 소유자의 진영 버프 줄: `MatchDefinition` 의 유닛 · 적 정의에 카드 `SquadBindings` 와 같은 칸(규칙 줄 번호 배열 — 빈 = 기본값 · 해시 밖).
- **소유 시작 순서(구독 순서로 표현 — 코어 제약 1)**: 방어유닛 `DefenderActivated` · 적 `UnitSpawned` 에서 ① 등록부가 소유자에게 진영 버프 줄을 붙인다 → ② 디스패처가 소유자의 `OnPlace` 를 올린다(소유자 자신은 여기서 받는다 — 방금 붙은 `Any` 줄이 듣는다) → ③ 판 위 수혜자 전개 **소유자 제외**. ① 이 ② 보다 앞서도록 `EventOrder` 를 명시한다.
- 전개 함수 하나(`CardBindings.FireOnAttach` 의 Squad 루프를 추출) — seam 인자: 카드 부착 = `Immediate`(커맨드 콜스택 드레인 · `CommandPhase.cs:63-72`) · 방어유닛 · 적 시작 = `Periodic`(사건에서 오므로 Immediate 에 넣으면 다음 커맨드까지 갇힌다).
- `EffectComboRule` · `SkillRouting.HasDetector` · 저작 사본 `DcTrigger.HasDetector` 는 Q1 답대로 같은 unit 에서 맞춘다(닫으면: 적 `Self × OnPlace` · 적 소유 `Any` × 비버프 효과는 굽기 거절 유지 — 코어가 터뜨리는데 굽기가 「안 터진다」고 거절하는 불일치를 남기지 않는다).
- 구조 문서 `docs/reference/battle-core-architecture.md` §1.11(`:185` 「배치는 적에게 사건 자체가 없다」)을 먼저 갱신한다.

## 완료 기준

- 탐침 테스트(`Tests/EditModeCore/`, 정의표 직접): ① 방어유닛이 「모든 아군 공격력 +X」를 들고 배치 완료 → 먼저 있던 방어유닛 둘 + 자신 + 이후 배치분 · 순찰 제외 · 소유자 사망 → 전원 회수 ② 적이 들고 등장 → 먼저 있던 적 + 이후 등장 적(분열 자식 포함)만 · 방어유닛 제외 · 플레이어 입력 없이 걸린다(주기 seam) ③ 한 번 = 수혜자당 그 규칙의 슬롯 1개 · `ModifierApplied` 1건 · `FireCount` = 수혜자 수 ④ 적 등장이 개사기를 발동시키지 않는다 · 드림스톤이 적을 버프하지 않는다.
- 하드 케이스 탐침 갱신(해당 `현행_` 단언). 라이브 무변: 굽기 스냅샷 2종 동일 · 헤드리스 · EditMode Core · PlayMode Core 초록 · 골든(Unity) 무변.
