## 상위 목표

배치 스킬이 없거나(실드셔틀) 유닛 컨셉과 어긋난(샷건맨) 두 유닛에 **평타로는 구조적으로 불가능한
사건**을 하나씩 준다. 둘 다 `DcMechanic{OnPlace × 기존 페이로드}` 규칙으로 표현한다 —
`OnPlaceEffectType` enum 은 늘리지 않는다.

| 유닛 | 평소 (에셋 실측) | 배치 순간의 사건 |
|---|---|---|
| 실드셔틀 (HP750 · 근접 58 · 도발 2) | 4초마다 **체력 낮은 아군 2명**에게 실드 150 | 반경 2 **아군 전원**에게 즉시 **더 두꺼운** 실드 |
| 샷건맨 (부채꼴 산탄 · 쿨 3초 · 사거리 2) | 산탄 10발 ±30°, **넉백 없음** · 배치 = **무방향** 밀쳐냄 | 적이 오는 쪽으로 **충격파 한 방 + 통째로 밀어냄** |

**왜 평타가 이 사건을 못 만드나**
- 실드셔틀: 평소 실드는 쿨을 기다리고 **가장 약한 2명만** 고른다 — 만피 아군은 평생 한 겹도 못 받는다.
  배치는 선별 없이 전원 동시다. 그리고 **적이 0마리여도 유효한 최초의 배치 스킬**이 된다.
- 샷건맨: 평타 산탄에는 넉백이 0이고 3초에 한 번이다. "밀어내서 진격을 되돌린다"는 사건은 평타를
  아무리 쌓아도 안 나온다. 지금 배치 스킬(무방향 밀쳐냄)은 사방으로 조금 미는 데 그쳐 산탄 유닛의
  그림이 아니다 — **적이 오는 쪽으로 큰 한 방을 몰아준다.**
  ⚠ 차별화 축은 «더 많이·더 넓게» 가 아니라 **종류**다(사용자 지적 2026-08-18): 평타가 작은 알갱이
  다발이므로 배치는 **큰 덩어리 소수 + 강한 넉백**이어야 화면에서 갈린다. 발수·각도·피해를 조금씩
  올리는 저작은 정도의 차이라 캐논·배스티온·말파이트가 걷어낸 증상으로 되돌아간다.
  ⚠ 샷건맨은 **조준 UX 가 없는 유닛**이다(`requiresFacing 0`). "겨눈 방향" 이라고 쓰지 않는다 —
  방향은 «사거리 안 최근접 적» 에서 나온다. 조준을 켜는 것은 후속 후보다.

## Feature-wide 계약 (load-bearing)

1. **신규 어휘 0.** 신규 `DcPayloadKind` 0 · 신규 NativeQueue 채널 0(28 불변) · 신규 ECS 시스템 0.
   실드셔틀은 `GrantShield`(19), 샷건맨은 `EmitProjectilePattern`(17) 를 그대로 쓴다.
2. **레거시 enum 을 늘리지 않고, 오히려 한 조각 죽인다.** `on-place-skill-rework` 계약 2 는 다음
   on-place 작업의 선행 조건으로 「레거시 전량 이관」을 걸어 뒀다. 이 spec 은 그 이관을 **하지 않지만
   과도기를 키우지도 않는다** — 신규는 전부 규칙 경로다. 실측: `onPlacePush*` 가 0 이 아닌 유닛은
   **샷건맨 하나뿐**이므로(배스티온은 부모 spec 이 이미 껐다) 이 spec 이후 그 3필드와
   `ApplyOnPlacePush` 의 소비자는 «한 조각» 이 아니라 **0** 이 된다 — 이관 작업이 첫 조각을
   **무비용으로** 뗄 수 있다. 나머지(enum 9개 소비자·브리지 switch)는 별도 작업으로 남는다.
   ⚠ 부모 계약을 1회 예외로 넘긴 사실은 구현 커밋에서 부모 README 에 한 줄로 남긴다.
3. **배치 실드는 상시 실드와 «구분되어» 보여야 한다.** 둘이 한 슬롯을 공유하므로(아래) 두께가
   같으면 배치 순간이 화면에서 사건으로 안 읽힌다 — 검증 질문 ②를 스스로 못 통과한다.
   (얼마나 두껍게는 튜닝 값이다 — 여기서 숫자를 못박지 않는다.)
4. **실드는 출처 하나가 슬롯 하나다** — 단 그 병합은 **대상별**이다. 같은 아군에게 반복 부여하면
   깎인 만큼만 차서 펌프가 안 되지만, **재배치로 셔틀을 옮기면 새로 반경에 들어온 아군들이**
   만료 없는 실드를 받는다(hop 을 반복하면 라인 전체가 두른다). 코스트를 내는 행위라 설계상
   허용하되, Play 에서 실제로 성립하는 폭을 확인한다(리뷰 M2). `ShieldMath` 의 병합 키가 `source` 라, 실드셔틀의 배치 실드와
   상시 캐스트 실드는 **같은 host 에서 나와 한 슬롯을 공유**한다(같은 출처 = max 갱신). 두 겹으로
   쌓이지 않는다 — 게임에서는 "셔틀이 배달한 방탄복을 셔틀이 계속 수리한다"로 읽힌다. 이걸 두 겹으로
   만들려면 출처를 갈라야 하는데 그건 실드 시스템 변경이라 이 spec 밖이다.
5. **`GrantShield` 는 host 를 제외한다**(페이로드 계약). 실드셔틀 자신은 배치 실드를 못 받는다 —
   "남 지키러 온 놈" 이라는 정체성과 일치하므로 우회하지 않는다.
6. **방향 결정 규칙은 이미 정해져 있고, 새로 만들지 않는다**(사용자 결정 2026-08-15,
   `defender-on-place-skills` unit 4): ① 조준(`DeployedFacing`)이 있으면 그 방향, ② 없으면 사거리 안
   **가장 가까운 적** 방향. 조준이 최근접보다 세다. 이 규칙은 지금 브리지 레거시 경로에만 있으므로
   unit 1 에서 **순수 함수 1곳**으로 뽑아 두 경로가 같은 것을 보게 한다(제약 10 의 «2+ 호출처»).
7. **이미 조준된 템플릿이 우선한다.** 발사 arm 은 방향을 미리 실어 보내는 소비자(무타겟 방향
   패턴 — 후보 0이어도 발사)와 공유된다. 배치 스킬 경로는 **방향이 비어 있는 템플릿**에만 개입한다.
   이 구분을 지우면 스냅샷 원점이 host 위치로 덮여 기존 패턴이 엉뚱한 곳에서 나간다
   (`ProjectileEmitterIntegrationTests` 가 고정).
8. **후보 = «탄이 닿는 거리 안» 합법 후보다.** 선별기는 셀(체비셰프)이고 탄 사거리는 월드
   (유클리드)라 **두 자가 다르다** — 대각선 끝 칸의 적은 후보이면서 사거리 밖이고, 그 적이 유일
   후보면 «발사 연출만 나가고 아무도 안 맞는다». 후보 루프가 월드 거리로 한 번 더 거른다(리뷰 M1).
   후보 조건 나머지: 방향을 정하는 후보는 살아 있고(`DeadTag` 없음) 판 안이고
   (`UltimateLeapState` 없음) host 가 때릴 수 있는 통행 층이며 **`tileRange` 안**이어야 한다.
   공유 적 풀에는 필터가 하나도 없어서, 안 걸면 시체나 비행 적이 총구를 가져가거나 맵 반대편 적이
   방향을 정해 «허공에 쏘는» 그림이 된다. 조준도 합법 후보도 없으면 **발사하지 않는다.**
   ⚠ **취소는 «다음 프레임 재시도» 가 아니라 소실이다.** 배치 태그는 그 프레임에 걷히고 재무장은
   재배치뿐이라, 사거리 안에 합법 후보가 없는 자리에 놓으면 **코스트를 내고 스킬이 사라진다.**
   방향 (0,0) 탄을 내보내는 것보다 낫다고 보고 그대로 둔다(리뷰 M2 — 계약으로 명시).
   ⚠ 그 귀결로 **배치 페이즈(적 0마리) 배치는 스킬을 통째로 잃는다** — 코스트만 나간다. 캐논처럼
   요청이 큐에 남지는 않지만 플레이어에게는 "아무 일도 안 일어났다" 이고, 샷건맨은 이 spec 이후
   배치 스킬이 존재 이유라 체감이 더 크다. 고치는 것은 부모 spec 후속 후보 「배치 페이즈 발동 정책」.
9. **패턴 템플릿은 host 사양을 싣는다.** `targetTraversalLayers` 는 `BuildPatternTemplate` 이 이미
   host 에서 도출한다 — 지상만 때리는 유닛의 산탄이 비행 적을 때리지 않는다(캐논이 규칙 경로로 옮기며
   한 번 잃었던 게이트).
10. **평타 패턴은 버퍼 0번을 지킨다.** `AttackSystem` 다연발은 `PatternSlot[0]` 하나만 읽고, bake 순서
   (`BakeDefenderDirectionalPattern` → `BakeUnitMechanics`)가 그것을 고정한다. 샷건맨은 이 spec 이후
   **패턴 슬롯 2개를 가진 최초의 유닛**이 되므로 이 순서를 되돌리면 평타가 배치 산탄을 쏜다.
   커버는 PlayMode `OnPlaceRuleTriggerTest`(volley + 능력 SO 공존, slot0 = volley)가 갖고 있다.
11. **밀쳐냄과 산탄은 공존하지 않는다.** 한 배치에서 두 힘이 걸리면 어느 쪽도 안 읽힌다
   (배스티온 선례). 레거시 push 는 0 으로 끈다.

  세 개를 채우면 열린다. 사용자가 「먼저 둘」로 잘랐으므로 다음 차례.
- **배치 실드가 깨질 때 터진다** [M] · 실드 파열(`OnShieldBreak`) 페이로드가 이미 있지만 드림캐쳐
  카드 부착 경로 전용이다. 유닛 규칙에서 선언하는 길이 열리면 "셔틀이 배달한 게 폭발물이었다" 가 된다.
- **샷건맨을 조준 유닛으로** [S] · `requiresFacing 1` 로 켜면 배치 스킬이 플레이어 조준을 그대로
  물려받는다(계약 6 의 ①). 머신거너가 이미 그 UX 를 쓴다. 켜면 **넉백이 적을 골 쪽으로 미는 사고도
  플레이어 통제로 들어온다.** 배치 UX 가 바뀌는 product 결정이라 이 spec 은 현행(최근접 적)을 유지하고,
  문안도 "겨눈 방향" 대신 "가까운 적 쪽" 으로 쓴다.
- **배치 페이즈 발동 정책** [M] · `on-place-skill-rework` 후속 후보 그대로. 이 spec 의 두 스킬은
  계약 8·실드의 sim 즉시 적용 덕에 그 결함을 밟지 않지만, **배치 페이즈의 실드 부여 VFX 는
  `_running` 아래 드레인이라 전투 시작 시점에 몰려 터질 수 있다**(unit 0 검증 항목).
