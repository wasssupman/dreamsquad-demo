# 4 — 튜토리얼 당김 안내 복원

## 목적

첫 판 온보딩에 당김 안내를 되돌린다. `three-minute-survival` unit 2 가 「도크에 누를 버튼이 없고, 전멸하면 자동으로 다음 웨이브가 오므로 '점수를 위해 당겨보라'는 안내가 거짓이 된다」는 이유로 `NextWaveHintSteps` 를 제거했다(`FirstSessionTutorialController.BattleHud.cs:171`). 버튼이 돌아왔으므로 그 이유가 사라졌다.

**문구는 그때와 같지 않다.** 「점수를 위해 당겨라」는 이제 틀린 말이다 — 당김은 항상 옳은 선택이 아니고, 겹칠지 말지의 판단이다.

## 변경 대상

- `Assets/_Project/Scripts/UI/Tutorial/FirstSessionTutorialController.BattleHud.cs` — 힌트 스텝·문구 상수·`waveDock` 참조 복원
- `Assets/_Project/Scripts/UI/Tutorial/` 문구 상수 소유 파일 (스텝 정의 위치는 구현 시 확인)
- 테스트: `Tests/PlayMode/FirstSessionTutorialSmokeTest` 갱신

## 구현

**1. 스텝 위치** — 배치·스트레스 안내 뒤. 당김은 «판을 안정시킨 다음»의 결정이라 배치를 모르는 상태에서 먼저 가르치면 순서가 뒤집힌다.

**2. 문구 방향** — 세 가지를 말한다:
- 무엇: 다음 웨이브를 지금 부른다
- 대가: 지금 적과 **겹친다**
- 언제: 정리가 끝나가고 여유가 있을 때

「점수를 벌려면 눌러라」로 쓰지 않는다. PRD §4.3 대로 당김의 핵심 질문은 «누를 수 있는가»가 아니라 «지금 누르는 것이 내 덱에 유리한가»이며, 튜토리얼이 전자를 가르치면 신규 유저가 무지성 연타를 배운다.

**3. 예고와 함께 가리킨다** — unit 1 의 예고 줄이 같은 도크에 있다. 당김 버튼만 가리키지 말고 «여기 뜨는 게 다음에 올 것»을 같은 스텝에서 짚는다. 판단 재료와 판단 수단이 붙어 있어야 한 번에 이해된다.

**4. 상한은 가르치지 않는다.** 첫 판에서 상한에 닿을 만큼 누르는 유저는 드물고, 닿으면 버튼이 잠기며 사유를 말한다(unit 0 계약 3). 튜토리얼에 규칙을 하나 더 얹는 값이 이득보다 크다.

**5. 대상 대기** — 도크가 lazily 활성화되므로 기존 `WaitForHintTarget` 을 그대로 탄다. 시간이 지나도 비활성이면 그 스텝만 생략한다(fail-open — 전투 플레이를 잠그지 않는다).
