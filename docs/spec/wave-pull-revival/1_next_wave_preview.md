# 1 — 다음 웨이브 구성 예고

## 목적

당김 버튼 앞에서 **무엇을 겹치게 되는지** 알려준다. 지금 도크는 「다음 12초 · 벌떼」까지만 말한다 — 묶음이 바뀌는 순간에만, 그것도 성격 이름 하나만. 무슨 적이 몇 마리 오는지 모르면 당김은 주사위다.

PRD §6.3 이 이 항목을 **당김과 동일 릴리즈**로 못박은 이유가 그것이다: 「유저의 고민이 '저 적이 뭐지?'가 아니라 '이 조합을 현재 적과 같이 받아도 되는가'에서 시작되게」.

## 변경 대상

- `Assets/_Project/Scripts/Bridge/BattleBridge.cs` — 다음 웨이브 구성 읽기 창구
- `Assets/_Project/Scripts/UI/NextWaveDock.cs` — 예고 줄 표시
- 테스트: `Tests/EditMode/NextWavePreviewTests.cs`(신규)

## 구현

**1. 브리지 창구** — 실제 스폰과 **같은 데이터**에서 나와야 한다(계약 4). `GeneratedWave.groups`(= `WaveSpawnGroup[]`, 각각 `unit`·`count`·`laneIndex`)를 그대로 노출한다:

```csharp
public bool TryGetNextWaveComposition(out IReadOnlyList<WaveSpawnGroup> groups)
```

`_nextWaveIndex` 가 가리키는 웨이브를 준다 — 당김으로 순서가 앞당겨져도 **내용은 플랜 순서 그대로**이므로(계약 8) 이 인덱스 하나면 충분하다. 별도 캐시를 두지 않는다: 플랜은 판 시작에 확정되고 이후 불변이라 매 프레임 읽어도 할당이 없다.

**2. 표시 문구** — 드래프트 브리핑 스트립이 이미 쓰는 형식(`{유닛명} ×{수량}`, `WavePatternStripView.cs:480`)을 따른다. 두 화면이 같은 말을 해야 «브리핑에서 본 그것»이 전투 중에 이어진다.

```
다음 12초 · 벌떼
러너 ×8  ·  스위프트 ×6
```

슬롯이 2개를 넘으면(현재 저작 최대 2) 잘라내지 않고 그대로 붙인다 — 저작이 늘면 그때 접기를 판단한다.

**3. 성격 라벨을 상시로 바꾼다** — `wave-concept-blocks` unit 5 는 묶음이 바뀌는 순간에만 라벨을 붙였다. 근거는 「3웨이브 내내 같은 문구 = 장식」이었는데, **unit 2 가 묶음 가운데를 섞으면 그 근거가 사라진다**(안쪽 웨이브도 성격이 다를 수 있다). 그리고 당김 판단에는 매 순간 필요하다. 상시 표시로 전환한다.

**4. 마지막 웨이브 이후** — `NextWaveHasNext` 가 거짓이면 예고 줄을 끈다. 빈 줄을 남기면 레이아웃이 흔들린다.
