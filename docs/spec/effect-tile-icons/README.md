# effect-tile-icons

> 상태: 완료 2026-07-31 (unit 0)

## 한 줄

효과 타일 오버레이 5종의 글리프를 **효과를 말하는 아이콘**(칼 · 번개 · 하트 · 금 간 방패 · 방패+칼)으로 교체한다. 색·구조·배선은 건드리지 않는다.

## 배경 (왜)

기존 글리프는 기하 기호였다 — `^`(공격력), `»`(공속), `+`(재생), `v`(취약), `◇`(글래스캐논). 색으로 "버프/디버프"는 읽히지만 **무슨 효과인지**는 색을 학습해야 알 수 있었다. 아이콘이면 처음 보는 판에서도 타일 위에 유닛을 놓을지 판단할 수 있다.

## 검증 질문

인게임 타일 크기(셀 1개)에서, 5종이 서로 구분되고 각자의 효과가 읽히는가?

## Feature-wide 계약

1. **아이콘 매핑은 효과에서 나온다.** `effect_tile_damage`(공격력 +25%) → 칼, `effect_tile_attack_speed`(공속 +20%) → 번개, `effect_tile_regen`(+1 HP/s) → 하트+`+`, `effect_tile_fragile`(받는 피해 +25%) → 금 간 방패, `effect_tile_glass_cannon`(공격 +40% / 받는 피해 +40%) → 방패+칼.

2. **색 언어는 그대로다.** 주황(공격) · 파랑(공속) · 초록(재생) · 빨강(취약) · 보라(글래스캐논). 색이 이미 버프/디버프를 구분하고 플레이어가 학습한 신호라, 아이콘은 그 위에 "무엇"을 얹는 역할만 한다. 실측 팔레트(fill/border)를 그대로 재사용한다.

3. **타일 구조 불변**: 64×64 · 불투명 · 3px 다크 보더(fill 의 어두운 버전) · 흰 글리프. `EffectTilePulse` 셰이더가 알파를 유지하고 밝기만 펄스하므로, 이 구조를 지키면 인게임 합성이 이전과 동일하다.

4. **파일 in-place 교체 = 배선 무접촉.** 같은 경로·파일명으로 PNG 바이트만 바꾼다 → `.meta`(GUID·PPU 64·pivot·filter) · `Tile` 에셋(`ET_*.asset`) · `EffectTileData.overlayTile` · `MapThemeData.effectTiles` 전부 무변경. 롤백은 `git checkout` 한 줄.

5. **아이콘은 생성기로 저작한다.** 좌표가 코드에 있으므로 굵기·크기 조정이 재현 가능하다(스크립트는 산출물이 아니라 도구 — 저장소에 두지 않고 `0_icon_set.md` 에 파라미터만 기록).

6. **겹치는 두 도형은 색 간격으로 분리한다.** 글래스캐논처럼 아이콘 2개를 얹을 때, 위 도형의 실루엣을 팽창시켜 아래에서 파낸다. 안 하면 64px 에서 흰 덩어리 하나로 뭉친다.

## 파이프라인 커버리지

**N/A** — 새 플레이 오브젝트도, 생성→렌더 경로 변경도 아니다. 기존 정거장(`MapThemeData.effectTiles` → `EffectTileData.overlayTile` → `Tile.m_Sprite` → `TilemapMapView._effectTilemap`, sorting −15)의 **마지막 칸에 있는 스프라이트 바이트만** 교체한다. `docs/reference/object-pipeline-map.md` 갱신 사유 없음.

## 후속 후보

- **타일 효과 툴팁/범례** — 아이콘이 "무엇"은 말하지만 수치(+25% 등)는 말하지 않는다. 타일 탭 또는 배치 중 툴팁으로 `displayName` 을 띄우는 것은 별개 UI 작업. Scope: S
- **테마별 색 대비 점검** — 지금은 forest(초록 지면)에서만 검증했다. desert 테마는 `effectTiles` 가 비어 있어 대상이 아니지만, 채우는 시점에 주황·빨강 타일의 지면 대비를 다시 본다. Scope: S
