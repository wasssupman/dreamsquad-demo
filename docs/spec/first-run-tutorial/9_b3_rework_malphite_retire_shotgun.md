# 9 — B3 재설계: 말파이트 → 퇴근 → 샷건맨

## 목적

첫 배치 구간을 **한 유닛 한 번**에서 **놓고 → 물리고 → 다시 놓는** 3블록으로 넓힌다.
캐논 하나로는 「배치 스킬이 있다」까지만 말할 수 있었다. 성격이 다른 배치 스킬 둘
(**멈춰 세운다** / **날려버린다**)을 연달아 보여주고, 그 사이에 **퇴근**을 끼워
「놓은 유닛은 되돌릴 수 있다」까지 첫 판에서 가르친다.

## 기본 편성 (반영 완료)

`defaultSquadUnits` 에서 **이쑤시개(`Defender_Slasher`) → 샷건맨**, 자리는 **2번째**
(배스티온과 교환). 튜토리얼이 가리킬 두 셀(말파이트 1번 · 샷건맨 2번)이 트레이 앞쪽에
붙어 시선이 양 끝으로 튀지 않는다.

```
1 말파이트  2 샷건맨  3 실드셔틀  4 버스터즈  5 캐논  6 배스티온  7 넉백머신
```

⚠ **이미 저장된 편성은 바뀌지 않는다.** `ProfileStore.EnsureDefaultSquad` 는 **빈
스쿼드일 때만** 시드한다(플레이어 선택을 덮지 않는다는 기존 규칙). 신규 설치는 그대로
받고, 개발 계정은 로비 `DEFAULT LOADOUT` 으로 재시드해야 한다.

## 시퀀스

| 블록 | 스텝 | 시계 |
|---|---|---|
| **B3a** 말파이트 | ① 트레이 셀 포커스 `"유닛을 터치 해보세요"` | 정지 |
| | ② 접근 대기 `"악몽이 배치 영역 안으로 들어오면!"` | **해제**(사건 대기) |
| | ③ `"말파이트는 주변 악몽을 3초간 기절시킵니다!"` | 정지 |
| | ④ `"악몽 무리 위에 말파이트를 배치 해보세요!"` | 정지 · 차단막 내림 |
| | ⑤ 배치 스킬 관람 | **해제** `onPlaceWatchSeconds` |
| | ⑥ `"배치 스킬은 놓는 즉시 한 번 터집니다"` | 정지 |
| **B3b** 퇴근 | ⑦ 말파이트 셀 포커스 `"말파이트를 다시 선택 해보세요"` | 정지 |
| | ⑧ 퇴근 버튼 포커스 `"지친 유닛은 철수시켜 자리를 비울 수 있습니다"` | 정지 |
| | ⑨ 퇴근 연출 관람 | **해제** `retireWatchSeconds` |
| **B3c** 샷건맨 | ⑩ 트레이 셀 포커스 `"이번엔 샷건맨을 터치 해보세요"` | 정지 |
| | ⑪ `"샷건맨은 가까운 악몽들을 밀어냅니다!"` | 정지 |
| | ⑫ `"빈 자리에 샷건맨을 배치 해보세요!"` | 정지 · 차단막 내림 |
| | ⑬ 배치 스킬 관람 | **해제** `onPlaceWatchSeconds` |
| | ⑭ `"강력한 배치스킬들을 활용하여 전황을 유리하게 이끌어 보세요"` | 정지 |

**⑨ 는 정지를 풀어야 한다.** `DefenderRetireFlight` 는 `TimeManager.DeltaTime(TimeDomain.Battle)`
로 도는 3막 **1.6초** 연출이다(연결 0.25 → 저항 0.85 → 뽑힘 0.50). 정지한 채 기다리면 유닛이
공중에 멈춘 채로 B3c 의 정지 스텝 셋을 통과해 **샷건맨 관람 창에서야 마저 날아간다** —
보드 위에 유닛 인형이 세 스텝 동안 떠 있는다. `Time.timeScale` 이 항상 1이라 코루틴
`WaitForSeconds` 가 정지 중에도 흐르는 것과 **다른 이야기다**(이 연출은 도메인 델타를 직접 읽는다).

**⑫ 는 접근 대기를 다시 돌지 않는다.** `AnyEnemyWithinTilesOfGoal` 은 B3a 에서 이미
참이 된 조건이라, 그대로 두 번 돌리면 ② 의 문구가 **0프레임** 노출된다(전에 물렸던
증상 그대로). 접근 대기는 B3a 의 소유다.

## 구현

`RunPickAndPlace` 를 **유닛을 인자로 받는 블록**으로 바꿔 두 번 돌리고, 사이에
`RunRetire` 를 넣는다. 문구는 블록마다 다른 상수 묶음을 받는다.

```csharp
IEnumerator RunPickAndPlace(DefenderUnitData unit, bool waitForApproach, string pick,
                            string skillHint, string place, string done)
IEnumerator RunRetire(DefenderUnitData unit)
```

### 새 기계는 하나뿐 — 퇴근 버튼 rect

`DcInspectPanelView._actionButton` 이 private 이라 구멍을 뚫을 수 없다.
`AwakeningGaugeView.HitRect` 선례대로 읽기 전용 접근자를 연다.

```csharp
/// first-run-tutorial unit 9 — 퇴근 버튼. 미빌드/비활성이면 null.
public RectTransform ActionRect => ...
```

**퇴근 자체는 기존 경로가 한다**(계약 1) — 튜토리얼은 버튼을 가리키기만 하고,
성사 신호는 `BattleBridge.DefenderRetired` 이벤트로 받는다.

### 새 config 값

| 필드 | 기본 | 뜻 |
|---|---|---|
| `retireWatchSeconds` | **1.7** | 퇴근 비행(1.6초)을 **정지 해제 상태로** 끝까지 보여준다 |
| `retirePanelGraceSeconds` | 2 | 선택 후 패널/버튼이 뜰 때까지의 **상한**. 지나도 null 이면 블록을 건너뛴다 |

기존 값 하나를 함께 줄인다 — **`resumeBeforeAttachSeconds` 2.0 → 0.5**. 그 창은 B3 끝과 B4
사이의 「끊긴 느낌」을 없애려던 것인데, 이제 바로 앞이 샷건맨 관람 2초(정지 해제)라 그 끊김이
이미 없다. ⑨ 가 정지 해제 예산 1.7초를 새로 쓰므로 그만큼을 여기서 돌려받는다(README 전제의
예산표 참조). 부착 대상이 없을 때의 **추가 대기는 이 값과 무관**하므로 안전 밸브는 그대로다.

## 가드 (계약 11 — 만족 불가는 진입 전에 스킵)

- **B3a**: `IsSlotUsableNow(말파이트)` 거짓 → 구간 전체 스킵 (현행과 동일)
- **B3b**: `TrySelectableHost(말파이트)` 거짓(죽었다) 또는 `ActionRect` 가 상한 안에
  안 뜨면 → 블록 스킵, B3c 로
- **B3c**: `IsSlotUsableNow(샷건맨)` 거짓(편성에 없다) → 블록 스킵, B4 로
- **`_b3Completed` 는 세 블록을 다 완주해야 찍는다.** 하나라도 건너뛰면 기록하지 않는다
  (계약 11 그대로). 「샷건맨이 없는 계정에서 무한 반복」을 우려해 best-effort 로 두려
  했으나, **그런 계정은 개발 계정뿐이다** — 신규 설치는 정의상 기본 편성을 받고 거기
  샷건맨이 있다. 개발 계정은 `DEFAULT LOADOUT` 으로 푼다. 퇴근을 검증 질문에 넣어놓고
  스킵해도 완료로 찍으면, 계약 11 이 막으려던 「핵심을 한 번도 못 본 계정」이 그대로 생긴다.

## 되돌리면 안 되는 것

0. **안내 문구의 «철수» 는 버튼 라벨(`DcInspectController.RetireLabel`)과 같은 말이어야 한다.**
   기능 이름은 퇴근이지만 화면에 뜨는 글자가 정본이다 — 라벨이 바뀌면 이 문구도 바뀐다.

1. **`OnPlaced` 는 유닛을 확인하고, 블록 진입 때 플래그를 리셋한다.** 지금은 `OnPlaced(DefenderUnitData _) => _placed = true`
   라 어느 유닛을 놓아도 통과한다. 배치 스텝은 차단막을 내리는 구간이라, 샷건맨을 놓으라
   해놓고 다른 셀을 눌러도 넘어간다. 유닛이 하나일 땐 무해했고 둘이 되며 의미가 생겼다.
   `OnArmed` 도 같다.
2. **B4 의 호스트 우선순위는 샷건맨 → 말파이트 → 그 밖.** 퇴근한 말파이트는 배치
   엔티티가 없어 자동 탈락하지만 순서를 명시한다.
3. **퇴근 블록은 ⑨ 를 빼고 정지다.** 말파이트는 근접(사거리 1)이라 풀어두면 맞는다.
   ⑤ 의 2초는 배치 스킬의 **3초 스턴**이 덮어 버틴다(스턴 > 관람). ⑨ 는 대상이 이미
   판을 떠난 뒤라 맞을 유닛이 없다 — 보드가 비는 1.7초이고, 그게 「자리가 비었다」의 그림이다.
5. **⑦ 에서 손패도 같이 열린다.** 유닛 선택의 부수 효과다(`DreamcatcherHandView`).
   구멍이 퇴근 버튼 하나뿐이라 조작은 막히지만 **화면에는 손패가 뜬 채**로 퇴근을 가리킨다.
   손패는 슬로모를 `priority: 50` 으로 요청하므로 정지(100)를 이기지 못한다.
   퇴근이 성사되면 `DcInspectController.Close()` 가 패널·손패를 함께 접는다.
6. **블록마다 `_placed`/`_armed` 를 리셋한다.** 안 하면 B3c 가 진입 즉시 통과한다.
4. **`Time.timeScale` 은 항상 1** 이라 배치 연출(`WaitForSeconds` 0.45초)은 정지 중에도
   끝난다 → `PendingDeployment`(=`CanRetire` 의 `busy`)가 풀리지 않는 함정은 없다.

7. **배치 대기 술어에 «아직 지불 가능한가» 를 건다.** 배치 스텝은 차단막만 내리고 **정지는
   유지**하는데 코스트는 Battle 도메인이라 회복되지 않는다. `OnPlaced` 의 유닛 확인(위 1번)과
   합쳐지면, 플레이어가 다른 유닛들을 놓아 잔여 코스트를 대상 유닛 밑으로 떨어뜨리는 순간
   그 대기는 **영영 만족 불가**가 된다 — 매치 타이머도 멈춰 있어 계약 13 의 정리 경로조차
   오지 않는다(강종 외 탈출구 없음). 유닛 확인이 없던 시절엔 엉뚱한 배치가 그냥 통과해
   이 상태가 없었다: **가드를 조이면서 새로 생긴 구멍**이다.
   판정은 반드시 `_placed` 로 한다 — 배치에 성공해도 슬롯은 «소진» 이라 술어가 참이 된다.
8. **`DcInspectPanelView.ActionRect` 는 «누를 수 있는가» 까지 본다**(`_visible` · `interactable`).
   `Hide()` 는 `_visible=false` 만 세우고 루트는 알파가 0.02 밑으로 갈 때까지 켜져 있으며
   그동안 `blocksRaycasts=false` 다 — `activeInHierarchy` 만 보면 **누를 수 없는 rect** 를
   몇 프레임 내주고, 거기 구멍을 뚫으면 온보딩은 열어줬다고 믿고 영원히 기다린다.
   퇴근 대기도 같은 이유로 `_retired || ActionRect == null` 로 받는다: grace 구간에 트레이
   셀을 다시 탭하면 그것은 «닫기» 이고, 그때 빠져나가야 다음 판에 다시 뜰 수 있다.
   이 접근자가 `interactable` 을 보므로 **배치 연출이 안 끝나 버튼이 잠긴 경우**(누가
   `deploymentDuration` 을 올린 경우)도 grace 상한에 걸려 스킵된다.
9. **블록을 건너뛸 때는 콘솔에 이유를 남긴다.** 스킵은 `_b3Completed` 를 거짓으로 만들고,
   그 계정은 이후 **모든 판**이 온보딩 판(60초 · 토너먼트 제외)으로 돈다. 배선 실수가
   조용히 그 상태를 만들면 원인을 찾을 단서가 없다.
