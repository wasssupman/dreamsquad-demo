# 7 — Sniper · FireCaster · Healer 컷신 추가

## 목적

컷신 3종 추가. 실측 결과 **소스가 두 계열로 갈렸다**. Sniper 는 무난, FireCaster 는 사용자가
순백 배경으로 재수급해 해결, Healer 는 구 체커 소스라 격자 잔존을 **감수하고 진행**
(사용자 결정 2026-07-16).

## 변경 대상

- `Sprites/Cutscene/Sniper/Sniper_001..049.png` (276×204) + `Depth/Sniper_depth.png` (138×102 R8)
- `Sprites/Cutscene/FireCaster/FireCaster_001..049.png` (320×180) + `Depth/` (160×90 R8)
- `Sprites/Cutscene/Healer/Healer_001..049.png` (320×180) + `Depth/` (160×90 R8)
- `Data/Defenders/Defender_{Sniper,FireCaster,Healer}.asset`
- Fix: `Modules/DepthParallax/Tools~/depth_layer_remap.py` — CLI 기본값이 rev2 가드와 모순

## 구현

### 소스 계열이 결과를 가른다 (실측 2026-07-16)

| 유닛 | 파일명 주장 | 실제 | 배경 | 체커 비침 | 판정 |
|---|---|---|---|---|---|
| Cannon (기출시) | 1932×1428 | 276×204 | 체커 | 2.3% | 기준선 |
| **Sniper** | 1932×1428 | 276×204 | 체커 | 4.6% | 양호 |
| **FireCaster** | 2240×1260 | 320×180 | **순백**(재수급) | — | 양호 |
| **Healer** | 2240×1260 | 320×180 | 체커 | **16.6%** | 격자 잔존 감수 |

**`2240×1260` 체커 계열은 반투명 수채 VFX 를 체커 위에 합성한 뒤 알파를 평탄화**해 내보냈다.
그 픽셀은 `반투명 VFX + 체커`가 섞여 있어 **원본 알파 없이는 복원 불가**다. 격자가 파스텔
워시에 비치고, 더 근본적으로 **반투명이어야 할 글로우가 불투명 덩어리**가 된다.

시도했다 폐기한 것:
- **체커 노출도로 알파 역산**: 배경 체커의 고주파 진폭이 1.57 뿐(7배 축소가 뭉갬)인데 아트
  디테일은 28.49 — 신호가 묻혀 분리 불가.
- **창백 영역 휘도 저역통과로 격자 억제**: 격자는 지워지나 흰 색종이 외곽이 뭉개져 아트 손상.
  게다가 불투명 문제는 그대로 — 격자는 증상이지 병이 아니다.

### 배경색이 결정적이다 (2026-07-16 실측)

FireCaster 를 **순백 배경**으로 재수급해 해결했다. 다만 순백도 만능이 아니다 — 이 아트에는
**흰 색종이**가 있어 배경과 같은 값이 되고, `MarginValue` 를 0.1~0.9 로 스윕해도 낮으면 속 빈
윤곽, 높으면 통째 소실로 **온전한 구간이 없다**(실측). 임계 240 에서 음영 있는 종이는 살고
순백 종이 몇 장만 빠지는데, 화면에선 티가 안 나 이걸로 확정했다.

**원리적으로 안전한 배경은 검정 하나뿐이다**: 글로우 VFX 를 검정에 합성하면 `P = a×F`
(premultiplied)라 밝기에서 알파를 되살릴 수 있고(unit 0 의 Ranger 절차가 정확히 이것), 검은
정장은 캐릭터 *안쪽*이라 flood-fill 이 보호한다. 흰 배경은 흰 종이를, 체커는 반투명을 망친다.
→ 다음 유닛 수급 시 **"배경 검정 또는 알파 채널 유지"** 를 요청할 것. 전 컷신이 알파 평탄화
소스에서 왔고(반투명 중간 알파: Ranger 18.0% / Archer 1.5% / Cannon 1.3% / Sniper 1.9%),
Ranger/Archer 가 무사했던 건 배경이 검정이었기 때문이지 운이 아니다.

### Healer 는 격자를 안고 간다 (사용자 결정)

구 체커 소스라 `_025` 부근 파스텔 워시에 격자가 보인다. FireCaster 처럼 재수급하면 해소된다.
프레임만 덮으면 GUID 가 유지돼 재할당 없이 교체 가능하다.

### 임계값도 유닛을 넘지 않았다

`0_sprite_pipeline`/`5_cannon_frames` 의 `luma>=240` 은 유효하다. 단 이번에 `BG-9` 같은
**상대 오프셋으로 "일반화"하려다 오히려 깨졌다** — BG=255 유닛에선 246 이 돼 체커 어두운 칸
(242)을 놓쳐 격자가 남았다. **임계는 240 고정, 디컨탬 상수 BG 만 유닛별 실측**(Cannon 249 /
Healer 255)이 맞다. 흰 아트는 셀 외곽선 + flood-fill 이 보호한다.

### 재생 방향 — 커버리지 프록시가 깨진다

3종 모두 **정방향(줌-인)**. 단 Cannon 에서 쓴 *실루엣 커버리지* 프록시는 VFX 가 지배하는
아트에서 무효다(Healer 40.9→70.7→**71.8**→45.5→34.8 로 중간이 峰). 대체 근거:
Sniper=커버리지 단조 34.2→40.0 · FireCaster=눈 폭 24→26 단조 · Healer=육안(049 가 확연히 큼,
금발 픽셀 감소는 줌-인으로 머리가 프레임 밖으로 잘린 것).

### 툴 결함 수정

`depth_layer_remap.py` 의 CLI 기본값이 rev1 값(`near_lo 0.52`/`body_hi 0.48`)으로 남아
rev2 가드(간극 0 · `body_hi<=0.42`)와 **자기모순**이었다. unit 2 재실행은 명시 플래그를 줘서
통과했을 뿐, 기본값으로 부르면 실패한다. → `0.40`/`0.40` 으로 정정.

### Unity 브리지 없이 임포트·할당한 경위

FireCaster/Healer 98장 임포트 중 **MCP 브리지가 끊겼다**(`instance_count: 0`). 단 Unity 가
죽기 전 `.meta` 는 이미 생성해 둬서 **GUID 가 있었고**, 다음 경로로 Unity 없이 완주했다:

- **meta**: 검증된 `Sniper_001.png.meta` / `Sniper_depth.png.meta` 를 템플릿으로 삼고
  각 파일의 **기존 GUID 만 치환**(두 meta 를 diff 해 GUID 외 파일별 데이터가 없음을 먼저 확인).
- **에셋 할당**: `Defender_*.asset` YAML 에 컷신 블록을 직접 삽입.
  Sprite = `{fileID: 21300000, guid, type: 3}` · Texture2D = `{fileID: 2800000, ...}`.
  필드 위치는 Sniper 를 따라 `deploymentDuration` **앞**(Unity 재정렬 방지).
- 브리지 복구 후 Unity 가 실제로 그렇게 읽는지 **재확인 완료**(아래 완료 기준).
