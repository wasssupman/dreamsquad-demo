# Gift Phase Presentation — "카드 딜러의 선물"

> 상태: 계획 (2026-07-14 설계 승인). 완료된 `gift-phase` 스펙의 연출 업그레이드 후속.

## 한 줄

선물 페이즈의 덱 순서·라우팅은 그대로 두고, 연출을 "축 이동하는 UI"에서 **서사가 있는 카드 안무**로 재작성한다. 서사 = "내가 짠 덱에 루시드/림이라는 존재가 개입해 덱이 변했고, 그 덱이 내 각성치에 장전되어 이번 판을 치른다."

## 검증 질문

> 유저가 이 6초에서 "**내 덱**이 선물로 **변했고**, 그 덱이 내 **각성치에 장전**됐다"는 서사를 읽는가 — 단순히 카드가 멋지게 움직였다가 아니라? 그리고 부채꼴 좌→우 순서가 실제 소비되는 덱 1→12번과 정확히 일치하는가?

## 연출 플로우 (7 스테이지 = 5 서사 비트)

```
인트로(존재의 등장, kind별 앰비언스) → ①딜-인 = "내가 짠 덱" (내덱10, 5×2 그리드, 정돈·익숙)
→ ②선물 리빌 = "존재의 개입" (Lucid: 위에서 금빛 강림 / Rim: 아래·가장자리 붉은 침투)
→ ③스택 수렴 + ④리플 셔플 = "선물이 내 덱에 섞여 든다" (셔플 완료 순간 12장 글로우 리플 = 변화 각인)
→ ⑤부채꼴 딜 = "이것이 이번 판의 내 덱" (하단 아치 제시, 최종순서 1→12)
→ ⑥순차 흡수 = "각성치에 장전" (수신 앵커 링이 카드마다 세그먼트 점등 12/12 → 완료 팝) → 배치 진입
```

## Feature-wide 계약

1. **순서 계약 불변**: `DreamcatcherHandController.GiftFinalOrder()` 가 반환한 entryId 순서와 `DreamcatcherCycleDeck` 단일 인스턴스 재사용(gift-phase 계약 3)은 그대로다. 연출은 위치·회전·스케일·색·sorting 만 바꾼다. 부채꼴 좌→우 = `GiftFinalOrder()` 0→11.
2. **프레임 판정은 데이터가 아니라 출신**: 기존 `GiftAddedEntryIds` + `GiftKind` 로만. 내 덱 10장 = 프레임 없음, Lucid 추가 2장 = 금색 홀로 프레임, Rim 추가 2장 = 적색 홀로 프레임.
3. **홀로 프레임은 기존 자산 재사용**: `UiRoundedSprite` 절차 보더 + `DraftCardFoil_UI` 셰이더 머티리얼(금/적 틴트). 새 스프라이트 아트 0. 틴트만으로 금/적 구분이 안 살면 그때만 셰이더 변형 추가(unit 1 에서 판단).
4. **하드코딩 수치 금지**: 카드 크기·그리드·부채꼴·타이밍·케이던스·색 전부 `GiftConfig` SO 필드 + `GiftConfig_Default.asset` 명시값.
5. **레이아웃 수학은 순수 함수**: 그리드/부채꼴 좌표, 리플 인터리브 순서, 흡수 케이던스 램프는 `GiftPhaseLayout` static(plain in→out, 제약 10) + EditMode 테스트.
6. **unscaled time + 정리 계약**: 모든 트윈은 `_seq` 멤버로 `Stop()` 일괄 정리. 페이즈 이탈/재시작 시 생성된 이펙트 UI 파괴, 중단된 시퀀스를 콜백이 다시 조작하지 않는다. `fastForwardInTestMode` 스킵 경로 유지.
7. **변경 0 영역**: ECS·덱 조합 로직·카드 SO 스키마·씬 배선(GiftPhaseView 는 코드빌드 캔버스, 씬 GO/참조 불변)·`FlyTarget` 고정 근사 좌표.
8. **총 시간 ≤ 6초** (2026-07-14 사용자 결정): `GiftConfig_Default.asset` 기본값 합산으로 인트로→흡수 완료가 6초를 넘지 않는다. 기준 예산 — 인트로 0.6(딜-인과 겹침) / 딜-인 1.2 / 선물 리빌(플립 포함) 1.0 / 스택 수렴 0.5 / 리플 0.9 / 부채꼴 딜+스윕 0.7 / 순차 흡수(피니셔 포함) 1.4 ≈ 5.7s. 임팩트는 길이가 아니라 겹침(스태거)과 가속으로 만든다. 별도 hold 스테이지 없음(부채꼴+스윕이 읽기 구간을 겸함).
9. **서사 계약** (2026-07-14 사용자 결정): 각 스테이지는 기술 안무가 아니라 서사 비트를 구현한다 — ⑴ 내가 짠 덱 ⑵ 존재의 개입 ⑶ 선물이 내 덱에 섞여 듦 ⑷ 이번 판의 내 덱 제시 ⑸ 각성치에 장전. 구체 장치: **kind별 앰비언스**(타이틀 색·배경 틴트·리빌 등장 방향이 Lucid 금빛/하강 vs Rim 적색/침투로 갈림), **셔플 완료 글로우 리플**(변화 각인), **흡수 = 장전**(FlyTarget 위치에 수신 앵커 링을 띄워 카드마다 세그먼트 점등, 12장 완료 시 팝 — 카드가 "사라진다"가 아니라 "저장된다"로 읽히게). 앵커 링은 gift 페이즈 동안만 존재하는 코드빌드 UI 이며 실제 각성 게이지/패널은 건드리지 않는다.
10. **채택 액센트** (2026-07-14 브레인스토밍 확정, 전부 채택): ⓐ **딜 소스 = 하단 중앙**("내 덱이 나로부터 나온다", 손패 딜인 하단 덱 소스와 문법 일관) + 10번째 착지 시 그리드 전체 미세 펄스(덱 완성 박자) ⓑ **카드 플립 리빌** — 선물 2장은 뒷면(프레임 색 단색+절차 문양)으로 등장해 센터에서 플립(scale.x 트릭)으로 정체 공개 ⓒ **내 덱의 움찔** — 개입 순간 그리드 10장이 살짝 밀렸다 복귀 ⓓ **스택 출렁** — 선물 2장이 파고들 때 squash ⓔ **리플 잔상 트레일** — 프레임 카드 교차 시 금/적 잔상 2~3장 페이드 ⓕ **하이라이트 스윕** — 부채꼴 전개 직후 좌→우 광 스윕, 프레임 카드에서 스파크 ⓖ **12번째 카드 피니셔** — 반박자 멈춤 → 강슬램 → 링 찰칵 잠금 팝 → 링이 각성 버튼 위치로 수축 소멸(각성 게이지와의 위치 연결 암시) ⓗ **흡입 문법** — 링 근처 가속+세로 스트레치.
