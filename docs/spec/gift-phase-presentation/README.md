# Gift Phase Presentation — "카드 딜러의 선물"

> 상태: 계획 (2026-07-14 설계 승인). 완료된 `gift-phase` 스펙의 연출 업그레이드 후속.

## 한 줄

선물 페이즈의 덱 순서·라우팅은 그대로 두고, 연출을 "축 이동하는 UI"에서 하스스톤/슬더스급 **카드다운 안무**로 재작성한다: 그리드 딜-인 → 센터 스테이지 선물 리빌 → 스택 수렴 → 리플 셔플 → 하단 부채꼴 딜 → 각성 버튼 순차 흡수.

## 검증 질문

> 카드가 "카드처럼" 움직이는가 — 딜러가 패를 돌리고, 리플로 섞고, 부채꼴로 깔고, 한 장씩 흡수되는 리듬이 임팩트 있게 읽히는가? 그리고 부채꼴 좌→우 순서가 실제 소비되는 덱 1→12번과 정확히 일치하는가?

## 연출 플로우 (7 스테이지)

```
인트로 타이틀 → ①딜-인(내덱10, 5×2 그리드) → ②선물 리빌(2장, 센터 대형+홀로 프레임)
→ ③스택 수렴(12장) → ④리플 셔플(좌우 갈라짐→지퍼 교차) → ⑤부채꼴 딜(하단 아치, 최종순서 1→12)
→ ⑥순차 흡수(1번부터 가속 케이던스, 각성 버튼으로) → 배치 진입
```

## Feature-wide 계약

1. **순서 계약 불변**: `DreamcatcherHandController.GiftFinalOrder()` 가 반환한 entryId 순서와 `DreamcatcherCycleDeck` 단일 인스턴스 재사용(gift-phase 계약 3)은 그대로다. 연출은 위치·회전·스케일·색·sorting 만 바꾼다. 부채꼴 좌→우 = `GiftFinalOrder()` 0→11.
2. **프레임 판정은 데이터가 아니라 출신**: 기존 `GiftAddedEntryIds` + `GiftKind` 로만. 내 덱 10장 = 프레임 없음, Lucid 추가 2장 = 금색 홀로 프레임, Rim 추가 2장 = 적색 홀로 프레임.
3. **홀로 프레임은 기존 자산 재사용**: `UiRoundedSprite` 절차 보더 + `DraftCardFoil_UI` 셰이더 머티리얼(금/적 틴트). 새 스프라이트 아트 0. 틴트만으로 금/적 구분이 안 살면 그때만 셰이더 변형 추가(unit 1 에서 판단).
4. **하드코딩 수치 금지**: 카드 크기·그리드·부채꼴·타이밍·케이던스·색 전부 `GiftConfig` SO 필드 + `GiftConfig_Default.asset` 명시값.
5. **레이아웃 수학은 순수 함수**: 그리드/부채꼴 좌표, 리플 인터리브 순서, 흡수 케이던스 램프는 `GiftPhaseLayout` static(plain in→out, 제약 10) + EditMode 테스트.
6. **unscaled time + 정리 계약**: 모든 트윈은 `_seq` 멤버로 `Stop()` 일괄 정리. 페이즈 이탈/재시작 시 생성된 이펙트 UI 파괴, 중단된 시퀀스를 콜백이 다시 조작하지 않는다. `fastForwardInTestMode` 스킵 경로 유지.
7. **변경 0 영역**: ECS·덱 조합 로직·카드 SO 스키마·씬 배선(GiftPhaseView 는 코드빌드 캔버스, 씬 GO/참조 불변)·`FlyTarget` 고정 근사 좌표.
8. **총 시간 ≤ 6초** (2026-07-14 사용자 결정): `GiftConfig_Default.asset` 기본값 합산으로 인트로→흡수 완료가 6초를 넘지 않는다. 기준 예산 — 인트로 0.6(딜-인과 겹침) / 딜-인 1.2 / 선물 리빌 1.0 / 스택 수렴 0.5 / 리플 0.9 / 부채꼴 딜 0.7 / 순차 흡수 1.2 ≈ 5.5s + 여유. 임팩트는 길이가 아니라 겹침(스태거)과 가속으로 만든다. 별도 hold 스테이지 없음(부채꼴이 읽기 구간을 겸함).
