# siege-duel-map — 듀얼 아레나 (공성 모드의 첫 라이브 맵)

> ## 목표 3줄
>
> 1. **공성 모드가 처음으로 판에 선다** — 적 마음 1개 저작 = 모드 파생(battle-structures unit 6), 그 셀이 스폰지점.
> 2. **클래시 로얄 문법의 대치 구도** — 내 마음 ↔ 적 마음 좌우 미러, 각 진영 본능 1기가 서로 다른 레인을 감제.
> 3. **방어측 본능의 첫 라이브** — «미래의 방어 본능도 코드 변경 0» (파이프라인 맵 주장)의 검증.

### ⚠ 저작 함정 (실제로 밟음)

`MapDocument_Serpent` 계열에는 **`placeMask` 필드 자체가 없다**(파생 폴백). 복사본에 정규식
치환으로 마스크를 쓰면 **매치 실패 → 조용히 무시**되고 파생값(Walk→Path 만)이 그대로 남는다.
증상은 «Ground 배치칸 0» — 필드가 없으면 **삽입**해야 한다.

## 적 타게팅 기본값 리팩토링 (2026-08-12, 사용자 지적)

**증상**: 듀얼 맵의 방어 본능을 적이 한 종도 공격하지 못했다 — 무적 포탑.

**1차 진단(불충분)**: 「기본 마스크에 `DefenderInstinct` 비트가 빠졌다」. 비트를 더해 고쳤다.

**사용자 지적**: *«본능을 특정하라는 게 아니다. 본능도 상대 진영이니 당연히 공격 대상이어야
한다. heartseeker 같이 특수한 놈만 거점 전담이 되는 것이고, 그 관점으로 리팩토링됐나?»*

→ **아니었다.** 비트 하나를 더한 것은 같은 shape(열거)에 특례를 하나 늘린 것이고, 방어측
종류가 또 생기면 똑같이 터진다. **진짜 결함은 «기본값을 열거로 적었다»** 였다.

**리팩토링**:

| | 전 | 후 |
|---|---|---|
| 적 기본값 | `DefenderUnit \| BlockingHazard \| DefenderCore`(열거) | **`Factions.AnyDefender \| BlockingHazard`**(파생 그룹) |
| 이름 | `LegacyEnemyMask` | `DefaultEnemyMask` — 「레거시 재현」이 아니라 「기본값」이다 |
| SO 이니셜라이저 | 같은 열거를 복제 | **같은 상수를 참조** — 두 값이 갈릴 수 없다 |
| 라이브 적 저작 | (1차 수정에서 16종에 29 명시) | **전부 되돌림** — 미저작 = 특수하지 않음 = 기본값 |

**방어측이 이미 이 shape 이었다** — `DefenderUnitData.targetFactions` 이니셜라이저가
`Factions.AnyEnemy`(적 진영 전부)다. 적측만 열거라 비대칭이었고, 그 비대칭이 이번 사고의 원인이다.

이제 방어 진영에 새 종류가 생기면 `AnyDefender` 가 커지고 **적 전원이 자동으로 그것을 노린다** —
종류를 추가한 사람이 이 파일을 기억할 필요가 없다.

**특수 저작은 마음사냥꾼 하나**(28 = 방벽|마음|본능). 「거점 전담」이 거점의 절반(본능)을
무시하던 모순도 같이 해소. 도발 면역은 `AnyUnit` 비트 부재에서 그대로 파생된다.

**회귀선 2개**:
- `DefaultEnemyMask_CoversWholeOpposingSide` — 값이 29인지가 아니라 **`AnyDefender` 를 덮는지**를
  묻는다. 방어측 종류가 늘면 이 단언이 자동으로 그것을 요구한다.
- `OnlySpecialEnemies_NarrowTheirTargets` — 기본값을 좁힌 적이 있으면 **그 적이 왜 특수한지
  테스트에 적혀 있어야** 통과한다. 특례가 조용히 늘어나는 것을 막는다.

⚠ **Unity 임포트 캐시 함정**(1차 수정에서 실측): SO 필드 이니셜라이저를 바꿔도 **키가 없는
기존 에셋은 옛 값을 유지**한다. 강제 재임포트·스크립트 리로드로도 안 바뀌고, 새 `CreateInstance`
는 새 값인데 에셋 로드는 옛 값인 비대칭이 나온다. **에셋 파일이 실제로 바뀌어야**(키 추가/삭제)
재구성된다 — 이번엔 16종의 명시 저작을 넣었다 빼는 과정에서 자연히 해소됐다.

## 웨이브 세대 편입 (2026-08-13, 사용자 지시)

**증상**: Duel 이 뜨는데 웨이브 개선이 하나도 안 붙어 있었다. 원인은 **풀 배선 부재**다 — 맵 풀은 `(document, deck)` 쌍이고, Duel 이 어디에도 없어서 `BattleBridge` 의 직렬화 `deck` = **`Deck_WaveA`** 가 그대로 쓰였다.

| | `Deck_WaveA` (Duel 이 쓰던 것) | 라이브 덱 |
|---|---|---|
| `waveConceptPool` | **없음** | 5종 |
| `bossPool` | **없음** | 1종 |
| `attackUnitPool` | 9종 | 14종(비행·엘리트 포함) |
| `waveGeneratorVersion` | 2 | 5 |
| `bossWaveInterval` | 5 | 9 |

→ 컨셉 블록·보스·비행·엘리트가 **전부 빠진 판**이었다.

**조치**: `Deck_Duel` 신설(라이브와 같은 세대: 컨셉 5종·`conceptHoldWaves 3`·보스 짱쎈 1종·간격 9·적 14종·generator 5·`waveSeed 20260841`) + `MapDocumentPool.devEntries` 에 Duel 배선 → **dev 슬롯 9**(풀 6 + dev 3).

**본편 `entries` 가 아니라 `devEntries` 다.** 본편에 넣으면 `Count` 가 6→7 이 되어 **6맵 전부의 시드·토너먼트 배정이 재추첨**된다. 「라이브 풀 편입」은 그 재편을 동반하는 별건이라 아래 후속 후보로 남긴다.

**레인 경로 축은 적용되지 않는다** — 공성 파생이라 `spawns` 가 저작이 아니고(적 마음 셀 1개), `waypoint-routing` unit 8 이 공성일 때 `spawnRoutes` 를 버린다. 스폰이 1개라 「레인마다 다른 길」자체가 성립하지 않는다. 다만 `waypointPaths[0] = (10,5)` 는 살아 있어 **적 SO 축**(`waypointPathIndex`)은 그대로 작동한다 — Skimmer 가 그 지점을 거쳐 온다.

회귀선 2개: `MapDocumentPoolDevEntriesTests.DuelDevSlot_IsWiredWithCurrentGenerationDeck`(세대 일치를 라이브 덱과 **대조**해서 묻는다 — 라이브가 올라가면 이 단언이 자동으로 따라온다) · `WaypointRoutingLiveTest.DuelDevSlot_RunsCurrentGenerationWaves`(실제 판에서 컨셉 라벨이 붙는가).

## 후속 후보

- **라이브 풀 편입** [S] — 시드 맵 배정 재편 동반(`Count` 6→7 = 6맵 재추첨), 사용자 결정. 지금은 dev 슬롯 9 로만 진입한다.
- **레인 갈래 저작** [M] — 공성 스폰 1개는 필드가 한 레인만 고른다. 상·하 레인 분산은 **적 SO 축의 경로 저작**(지상 경로 적) 또는 스폰 분산 규칙. `spawnRoutes`(레인 축)는 공성에서 구조적으로 불가.
- **적 본능의 마음 사냥꾼 상호작용** 등 emergent 확인.
- **본능 프랍 진영 구분** [S] — 4기가 전부 같은 빨간 시험 프랍이라 화면에서 아군/적이 구분 안 된다. viewPrefab 분리 또는 진영 틴트. **rev 3 에서 4기가 되며 체감 우선순위가 올라갔다.**
- **강 시각 표현** [S] — Env 타일이 렌더에서 빈 공간으로 나온다(구멍처럼 보임). 물 타일/프랍이 필요하다. `traversal-layers` §6 의 물타일 3줄과 합류 가능.
