# 4 — 출전 중 셀의 터치 어포던스 (죽은 칸 → 살아 있는 칸)

## 목적

unit 1 은 소진 셀을 **죽은 칸**으로 만들었고 unit 2 가 거기에 "만지면 판 위 그 유닛으로 간다"를
얹었다. 두 결정이 화면에서 충돌한다 — 옷은 "못 씀"인데 기능은 "눌러라"다. 이 단위는 옷을 기능
쪽으로 옮긴다. **출전 중 = 밝게 살아 있고 · 상시 미세하게 숨쉬고 · 누르면 칸이 먼저 대답한다.**

> ⚠ 이것은 계약 6(소진 표현)과 unit 1 의 "죽은 칸" 전제를 **뒤집는 rev** 다. README 계약 6 을
> 함께 갱신한다. 뒤집는 근거는 아래 진단이다.

## 진단 (왜 안 읽혔나)

트레이에서 **어두움 = 못 쓰는 칸**이 이미 일관된 규칙인데, 출전 중만 "어두운데 눌리는" 예외였다.

| 상태 | unit 4 이전 옷 |
|---|---|
| 코스트 부족 | 얼굴 곱색 `0.42, 0.42, 0.45` |
| 출전 중 | 얼굴 곱색 `0.42, 0.44, 0.50` ← 사실상 같은 회색 |
| 쿨타임 | 셀 전체 검정 스크림 `a 0.55` + 시안 림 호흡 `0.55,0.85,1` |
| 출전 중 테두리 | 시안 `0.55,0.90,1` ← 쿨타임 림과 **같은 색** (움직임 문법만 달랐다) |

여기에 더해 **누른 순간 셀이 아무 응답도 하지 않는다.** 계약 5 는 "카메라가 그 유닛으로 가는 것이
응답"이라고 적었지만 선택 줌은 그 뒤에 꺼졌다(`DcInspectController.InspectZoomEnabled = false`,
2026-08-19). 지금 응답은 전부 화면 반대편(좌측 부착 패널·보드 리티클·손패)에서만 일어난다.

## 구현

**1. 얼굴을 되살린다** — `exhaustedPortraitTint` 를 밝게(`0.85, 0.86, 0.90`). 살짝만 가라앉히고
채도는 유지한다. 이제 트레이에서 **어두운 칸은 전부 못 쓰는 칸**이고 출전 중은 거기 없다.

**2. 테두리를 세게** — 셀 안에 표식(배지·글리프)을 얹는 대신 **테두리 하나에 몰아준다**.

> 리티클 글리프(포트레이트 우상단 4-코너 브래킷)를 먼저 만들었다가 **뺐다**(사용자 결정
> 2026-08-21): *"무슨 의미로 달려있는지 모르겠다."* 보드 선택 리티클과 같은 어휘라는 인과는
> **만든 사람만 아는 인과**였다 — 셀 안의 작은 기호는 배우기 전에는 노이즈다. 대신 이미
> 뜻이 붙어 있는 기존 어휘(테두리 순환)를 키우는 쪽이 옳다. **셀 안에 새 기호를 추가하지 말 것.**

`SlotRimFlow` 셰이더에 셋을 더한다:

- **글로우** — 링 띠에서 안팎으로 번지는 헤일로(`_Glow`·`_GlowStrength`·`_GlowInner`). 하드 링
  하나뿐일 때와 체감이 다르다. 셀 밖으로 번질 자리는 rim quad 를 `rimBleedPx` 만큼 키워 만든다
  (`_Bleed` 로 상자를 되줄여 링은 여전히 셀 경계에 앉는다).
  **`rimBleedPx` 상한 = `slotSpacing` 의 절반**(=4). 틈 8px 를 두 칸이 나눠 쓰기 때문이다 —
  넘기면 겹치는 지점에서 글로우가 아직 0 이 아니라(`outerFade` 는 자기 quad 끝에서야 0) 소진
  셀 2개 사이가 호박빛으로 이어진다. 6 으로 넣었다가 리뷰 지적으로 4 로 내렸다.
- **핫 코어** — 밴드 머리를 흰색 쪽으로 섞는다(`_CoreBoost`). 알파는 `saturate` 에서 1 에
  물려 더 밝아지지 않으므로 **밝기는 색으로 만든다**.
- **머리 상승** — `_Head`. 아래 함정 참조.

값도 같이 올린다: 두께 0.08→**0.095** · 상시 알파 0.22→0.40 · 밴드 세기 1.2→2.6 · 속도 0.35→0.5.
(두께는 0.11 로 올렸다가 0.095 로 되낮췄다 — 글로우가 붙으면 링 자체는 얇아도 세기가 유지된다.)

### 셰이더 함정 3건 (전부 미리보기 렌더로 잡았다)

1. **밴드 머리의 하드 심.** `u` 가 1→0 으로 감기는 자리에서 밝기가 0→1 로 튄다. 원래도 있던
   불연속인데 글로우와 흰 코어가 붙으면서 **링을 가로지르는 직선 절단**으로 보이게 됐다.
   → 머리 바로 앞에서 짧게 올라오는 램프(`_Head`)를 `max` 로 합쳐 잇는다.
2. **바깥 글로우의 사각 컷.** quad 는 셀 밖으로 `_Bleed` 밖에 없어 지수 감쇠가 끝나기 전에
   잘린다 → 헤일로 바깥선이 직사각형으로 딱 끊겨 **판때기가 한 장 더 붙은 것처럼** 보인다.
   → 여백 끝에서 0 이 되는 창(`outerFade`)을 곱한다.
3. **안팎을 각자 거리로 재면 칸 전체가 물든다.** `dOut = max(sdf, 0)` 은 "링 옆"이 아니라
   "밖이 아님"이라 셀 **내부 전체**에서 0 → 글로우 1 이 된다. → 거리는 링 띠까지 **하나**로
   재고, 안팎 구분은 계수(`lerp(outerFade, _GlowInner, innerMask)`)로만 한다.

**3. 호흡** — 죽은 UI 는 안 움직인다. 진폭 2%, 주기 2.2s.

> **호흡은 셀 루트가 아니라 포트레이트 rect 에 건다.** 셀 루트 스케일은 이미 PrimeTween 이
> 소유한다(`PulseSlotFor` 퇴근 도착 · `ReadyFlourishRoutine` 쿨타임 종료 — 둘 다 `StopAll(rect)`
> 로 시작한다). 거기에 매 프레임 스케일을 쓰면 그 연출들이 지워진다 — 트레이가 이미 한 번
> 밟은 「매 프레임 덮어쓰기가 연출을 지운다」 함정(battle-tray-cost-well 의 idle dim). 글리프는
> 포트레이트의 자식이라 같이 숨쉰다. 이름 밴드·코스트 칩은 제자리에 있어 계속 읽힌다.

호흡 대상 판정은 **글리프의 `activeSelf`** 로 읽는다 — 소진 여부를 매 프레임 다시 세지 않고,
`SlotVisual` 이 struct 라 필드 write-back 이 소실되는 함정도 피한다(쿨타임 `cooldownRoot.activeSelf`
선례). 시간축은 `Time.unscaledTime` — 선택 슬로모와 무관해야 하는 시각 플레어(쿨타임 림 선례).

**4. 탭 응답** — 소진 셀의 탭·드래그가 감지되는 **그 자리**(`DefenderDragSlot` 의 소진 분기)에서
셀 punch + 글리프 팝. 이동모드 진입이든 선택이든 **그 뒤에 뭐가 오든 응답은 먼저 나간다**.
슬롯은 `DefenderSelector` 참조가 없었으므로 `Bind` 에 파라미터 하나를 더한다(호출처 1곳).

**5. 림 색** — `_RimColor` 를 호박(`1, 0.72, 0.30`)으로. 쿨타임 림(시안·제자리 호흡)과 색·움직임
둘 다로 갈린다. 룩 knob 은 계속 머티리얼 에셋이 소유한다(unit 1 계약). 코드가 미는 유니폼은
`_Aspect` 와 `_Bleed` 둘 — **둘 다 룩이 아니라 기하**다.

## 완료 기준

- 컴파일 통과 · EditMode 통과 · `BoardLimitTrayStateTest`(PlayMode) 통과.
- Play 육안: 유닛 배치 → 그 셀의 **얼굴이 어두워지지 않는다**. 셀이 느리게 숨쉬고, 두꺼운
  호박빛 테두리가 글로우를 끌고 돈다. **헤일로 바깥선이 사각으로 끊기지 않는다**(함정 2).
- 소진 셀 2개가 나란히 있어도 헤일로가 서로 겹쳐 뭉치지 않는다(`rimBleedPx` ≤ 슬롯 간격).

- 소진 셀을 누르면 **셀이 먼저 튀고** 좌측 패널/보드 리티클이 뜬다.
- 유닛 사망 → 호흡·테두리가 사라지고 포트레이트 스케일이 1 로 돌아온다(호흡 잔여 없음).
- 호흡은 **0.5초 간격 스크린샷 2장의 포트레이트 크기 차이**로 확인한다(정지 1장으로는 증명 불가 —
  battle-tray-cost-well 교훈).

>
> - 호흡은 **포트레이트 rect**에 건다. 셀 루트로 옮기면 퇴근 도착 pulse·쿨타임 종료 flourish 가
>   매 프레임 스케일 쓰기에 지워진다.
> - `_Bleed` 는 **실제 rim quad 에서 유도**한다(config 재계산 아님). rect 는 슬롯을 지을 때 한 번
>   잡히므로 런타임에 `rimBleedPx` 를 만지면 둘이 갈라져 링이 셀 경계에서 밀린다.
> - 글로우 거리는 **하나**(링 띠까지)로 재고 안팎은 계수로만 가른다. 각자 거리로 재면 `max(sdf,0)`
>   이 셀 내부 전체에서 0 이 돼 칸이 통째로 물든다.
> - `rimFlowMaterial` 이 없으면 테두리 위젯 자체가 안 생긴다 → 호흡의 상태 소스(activeSelf)도
>   사라진다. `IsExhaustedShown` 이 그때만 직접 세는 것은 이 때문 — 탈색이 0.85 로 밝아져서
>   테두리도 호흡도 없으면 소진이 화면에서 완전히 사라진다.
> - 호흡 진폭 0 은 **조기 return 이 아니라** 목표 스케일 1 로 같은 루프를 돈다. 조기 return 이면
>   진행 중이던 스케일이 굳고, 소진이 유지되는 한 원복 지점이 없다.
>
> **알려진 좁은 창** — 쿨타임 종료 flourish 는 **코루틴**(`ReadyFlourishRoutine`)이라
> `Tween.StopAll` 로 안 멈춘다. 쿨타임이 끝난 직후 0.22초 안에 그 유닛을 배치해 소진시키고 그 칸을
> 탭하면, 코루틴이 매 프레임 `localScale` 을 덮어써 **탭 punch 가 화면에 안 나온다**(잔여는 없다 —
> 코루틴이 끝나며 1 로 정착한다). 슬롯 루트 스케일의 소유자를 하나로 모으는 것은 이 unit 밖이다 —
> 기존 `PulseSlotFor`(퇴근 도착)도 같은 구조를 안고 있다.
>
> ⚠ 여기서 한 번 틀렸던 전제: "셀 루트 스케일은 **PrimeTween 이** 소유한다(pulse·flourish 둘 다
> `StopAll` 로 시작)". flourish 는 PrimeTween 이 아니라 코루틴이다. 결론(호흡을 셀 루트에 걸지
> 말 것)은 그대로지만 **이유가 더 강하다** — 멈출 수단조차 없는 주인이 하나 더 있다.
