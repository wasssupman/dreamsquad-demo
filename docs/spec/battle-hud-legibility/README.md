## 왜 9번 돌았나 — 이 문서의 존재 이유

같은 실수를 세 번 반복했다. 원인은 셋인데, **전부 「크기를 조정하면 되는 문제」로 착각**한 것에서 나왔다.

| rev | 시도 | 반려 사유 |
|---|---|---|
| 1 | 400×114 예고 패널 | 맵을 가림 |
| 2 | 320×30 툴팁 | 글자가 안 읽힘 |
| 3 | 한 박스 2상태(시계+웨이브+목록) | 텍스트가 너무 많음 |
| 4 | 원터치 + 시계를 점수 스택으로 | 버튼처럼 안 생김 |
| 5 | CTA 분리(밝은 채움 + 립) | 여전히 반려 |
| 6·7 | 시간 = 최상단 12px 게이지 | **전혀 원하던 게 아님 · 잘 안 보임** |
| 8 | 시간 = 상단 중앙 대형 배지 | 맵 영역을 가림 |
| **9** | **좌상단 코너**(메뉴 아이콘 아래) + 도크는 알약 + 말풍선 | **통과** |

### 실패의 진짜 원인 3가지

**① 예약구역을 넘은 자리에서 크기만 조정했다.**
배치 트레이는 폭이 `SafeAreaWidth − cornerReservedWidth(640)` 로 **클램프**되고 바닥 중앙 정렬이다(`DefenderSelector.cs:252·353`). 1920 기준 항상 **x 320~1600**. 즉 **좌측 0~320 이 도크 예산**인데 구 도크는 우측 끝이 328, rev3 은 352 였다. 겹침이 안 사라진 이유가 크기가 아니라 **경계**였다.
→ **슬롯이 10개가 돼도 트레이는 안 넓어진다**(클램프가 같고 슬롯만 좁아진다). 이 예산은 영구적이다.
→ 지금은 `NextWaveDock.BuildCanvas` 가 우측 끝 > 300 이면 **경고를 띄운다.**

**② 「상시 표시 면적」과 「가독성」을 동시에 만족시키려 했다.**
크게 하면 맵을 가리고 작게 하면 안 읽힌다 — 그 사이에 답이 없다. 답은 **상시 표시를 포기**하는 것이었다: 알약은 고정 크기로 늘 있고, 목록은 **탭했을 때만** 위로 뜬다.

**③ 화면 중앙은 전부 보드다.** 「상단 중앙이 비어 있다」는 UI 기준으로만 참이다. 큰 배지를 놓을 수 있는 곳은 **코너뿐**이다.

## Feature-wide 계약

1. **도크 우측 끝 ≤ 300px.** 넘으면 배치 트레이와 겹친다. 알약을 키우려면 **폭이 아니라 높이**를 키운다. `BuildCanvas` 가 위반 시 경고한다.

2. **알약은 절대 리사이즈하지 않는다.** 고정 크기·고정 위치. 커지는 것은 말풍선뿐이고 말풍선은 탭했을 때만 존재한다. (armed 상태의 «숨쉬기»는 `localScale` 이라 레이아웃 크기가 아니다.)

3. **말 대신 연출.** 「탭하면 ~」류 안내문을 두지 않는다. 상태는 움직임으로 말한다:
   - **Off**(잠김·마지막 웨이브) — 정지 + 회색
   - **Ready** — 화살표 6px 왕복, 광택이 1.1초 훑고 1.4초 쉼
   - **Armed**(말풍선 열림 = 한 번 더 누르면 당겨짐) — 화살표 1.25배·10px·빠르게, 알약 숨쉬기, 광택이 0.55초마다 거의 쉬지 않고
   Ready 와 Armed 가 확실히 달라야 «토글됐다»가 읽힌다.

4. **큰 배지는 코너에만.** 화면 중앙(상·하 포함)은 보드다.

5. **타이머는 점수와 같은 문법**(남색 플레이트 + 골드 탭 + 굵은 숫자)으로 그린다. 다른 문법을 쓰면 «배경 크롬»으로 읽힌다 — rev 6·7 의 게이지가 그랬다.

6. **게이지로 그리지 않는다.** 게이지는 HP·마나처럼 **직접 채우고 쓰는** 자원의 문법이다. 이 타이머는 한 방향으로 흐르며 판단을 트리거하는 **시계**고, 경쟁전 시계의 관례는 큰 숫자다. 그리고 폭 1860px 에 3분을 담으면 **1초가 1px 도 안 움직여** 바 자체가 정보를 못 준다.

7. **무한 모드(`TimerDuration ≤ 0`)는 타이머 배지를 통째로 숨긴다.** 「얼마나 남았나」의 기준이 없는데 시계를 그리면 거짓말이다.

8. **HUD 는 브리지를 참조하지 않는다.** 브리지가 매 프레임 push 한다(`SetLeakStatus`·`SetPaceBaseline`·`SetTopBar` 가 같은 방향). 씬 wiring 이 늘지 않는다.

9. **`PullButtonRect` 는 알약을 가리킨다**(말풍선이 아니라). 튜토리얼 포커스 링이 가리켜야 할 것은 «누를 대상»이다(`wave-pull-revival` unit 4).

10. **당김은 `TryPullNextWave()` 로만.** `ForceNextWave()`(기제)를 UI 에서 직접 부르면 겹침 상한이 우회된다.

## 기술 함정 (다시 밟지 말 것)

- **버튼 아트를 키울 수 없다.** `NextWaveButtonFace.png`(476×179)는 9-slice 가 아니고 `preserveAspect=true` 라, rect 를 키우면 늘어나는 대신 투명 레터박스가 생긴다. → 배경은 `UiRoundedSprite.Make` 로 굽는다(CostDisplay·ScoreHudView 선례).
- **광택 밴드는 반드시 잘라야 한다.** 알파를 낮추는 것만으로는 부족 — 버튼 밖으로 나가 허공에 흰 막대로 보인다. **`RectMask2D`** 를 쓴다. `Mask` 를 피하는 이유는 *머티리얼 인스턴스*(9-slice 를 흐린다)이지 클리핑이 아니다 — 둘을 혼동하지 말 것.
- **PrimeTween 의 `useUnscaledTime` 은 Sequence 가 소유한다.** 자식 트윈에 붙이면 「무시됐다」 에러를 매 사이클 뱉는다(`Sequence.cs:345`). 시퀀스에 한 번만 준다.
- **씬이 직렬화한 필드는 코드 기본값을 덮는다.** 새 이름의 `[SerializeField]` 를 만들면 씬에 키가 없어 C# 기본값이 그대로 쓰인다 — 씬을 못 고칠 때의 우회로. 구 필드는 orphan 키로 남지만 무해하다(`fixedWaveIntervalSec` 선례).
- **UI 는 `Awake` 에서 한 번만 지어진다.** Play 중 리컴파일해도 **이미 만들어진 오브젝트는 안 바뀐다** — 「고쳤는데 화면이 그대로」의 원인. Play 를 껐다 켜야 한다.
- **MCP 씬 편집은 활성 씬만 닿는다.** additive 로 열어도 `set_active_scene` 을 해야 `find_gameobjects` 가 찾는다. Play 중에는 아예 막힌다.
