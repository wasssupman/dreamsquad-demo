# directional-attack-shape — 공격 판정에 「좌/우 방향 도형」을 더한다

> 상태: **초안 rev 2 2026-09-12** — rev 1(자유각·부가 타격 게이트)은 사용자 결정으로 **폐기**, 이 rev 가 정본.
> units 0~4 미착수.
> 선행: `distance-based-range`(완료). 그 spec 의 `11_facing_retirement.md` 가 폐기한 것은 «폭 0 셀 레인»과
> «플레이어 방향 지정 조작»이지, 「캐릭터가 보는 쪽으로 때린다」는 문법이 아니다 — 이 spec 은 그 문법을
> 연속 좌표에서 다시 세운다.

## 한 줄

**유닛은 타겟 쪽으로 좌/우 반전하고(지금도 그렇다), 판정은 그 좌/우 방향으로 나간다.** 오른쪽 적 → 오른쪽
찌르기. 왼쪽 적 → 돌아서서 왼쪽. 자유각도 아니고 플레이어 토글도 아니다. 배치는 놓으면 끝.

그러므로 **캐릭터 머리 위(옆이 아니라 정확히 위)의 적은 창이 안 닿는다** — 벨트스크롤(던파·파이널파이트)
문법 그대로. 그 적은 **애초에 타겟이 아니다**(타겟 잡아 놓고 허공을 찌르지 않는다). 사거리 표시도 그 모양이다.

## 배경 — 오늘 전투 판정에 방향이 0 이다

술어는 하나다(제약 13, `SkillMath.Reach` · 진입점 `ReachFromUnit`/`ReachFromCell`):

```
도달 ⟺ |Δ|² ≤ (사거리 + 원점 항 + 대상 몸)²       ← 360° 원, edge-to-edge
```

근접/원거리·아군/적이 전부 이 하나를 지난다(`AttackReach.cs` 헤더 소비처 12곳). 다중 타격(`attackTargetCount`,
근접 전용)은 원 안에서 «가까운 순서 N체» — 등 뒤의 적도 똑같이 맞는다. 배스티온·브루저·말파이트 3체 ·
가디언 2체 · 힐러 3체(아군).

## 검증 질문

> **도형을 저작한 유닛이 「캐릭터가 보는 쪽 도형」 안의 적만 타겟으로 잡고 때리며, 사거리 표시가 그 모양을
> 미리 보여주고, 저작하지 않은 유닛(=360°)은 오늘과 비트 단위로 같은가.**

## 사용자 확정 결정

**rev 1 (2026-09-11)** 중 살아남은 것:
- 타격 수는 `attackTargetCount` 그대로(도형은 후보 필터).
- 적용 범위 = 모든 유닛(아군+적). 저작 기본값 360° = 오늘.
- 스키마 = `AttackOutput` 형태(kind + 형마다 파라미터 하나). 길이는 `attackRange` 소유.
- 참격은 «방향»이다(«뭉침» 스플래시 기각).
- 저작 금지 계약 없음(도발 탱커 예외 X · 힐러는 그냥 360°). 경고만.
- Rect 는 코드까지(술어·bake·배선), 라이브 저작·Play 는 긴창 유닛 spec.
- 적에도 저작 — 보스 1종 unit 4 후보.

**rev 2 (2026-09-12)** — 다른 세션의 벨트스크롤 사례 분석 + 사용자 결정 *「당연히 내가 현재 바라보는 좌/우 방향
기준으로 180도 뒤에 있으면 방향을 바꾸면서 패면 되잖아」*:
1. **판정 방향 = 좌/우 둘뿐.** 자유각 폐기. 유닛이 타겟 쪽으로 반전하고 도형은 그 축(±X)으로 나간다.
   방향의 시각 보증자가 **캐릭터 몸 자체**가 된다(VFX 는 보조).
2. **도형은 타겟 획득부터 적용한다** — rev 1 의 「부가 타격만」 폐기. 후보 = **왼쪽 도형 ∪ 오른쪽 도형**
   (X 대칭이라 `|dx|` 하나로 검사). 그 안에서 최근접 → 그쪽으로 반전 → 부가 타격은 **같은 쪽** 도형 안.
3. **사거리 표시 = 도형 합집합**(띠 / 나비넥타이). rev 1 계약 8(링은 원) 폐기 — 「저 위 적은 안 때린다」가
   화면에서 미리 읽혀야 한다.
4. rev 1 의 자유각·실효각 표·「뭉침」 논의·frontmost 재조준·주 대상 항등 불변식은 **이 모델에서 소멸**했다
   (방향이 대상을 따라 돌지 않으므로). 리뷰 이력은 하단.

## 핵심 형태 — 게이트, 대체가 아니다 (rev 1 과 같다)

```
후보(획득)  = Reach(Δ)  AND  Shape(|dx|, dz)          ← 양쪽 합집합
부가 타격   = Reach(Δ)  AND  Shape(side·dx, dz)       ← side = 주 대상 쪽(±1)
```

- 반경 항은 손대지 않는다. 제약 13 산식은 그대로, 도형은 그 위에 AND 로 곱해진다(길이는 원이 정한다).
- 게이트는 **좁히기만** 한다 → 360° 항등 → 저작 안 한 유닛은 오늘과 같다 → 골든 무변(코퍼스 덱 유닛을
  저작하지 않는 한).
- 도형은 방향이 **+X 고정**이라 회전 수학이 없다 — 부채꼴은 `|dz|·cosθ ≤ dx·sinθ`, 띠는 `|dz| ≤ 반폭`.
  `SkillCone` 처럼 삼각함수는 bake 1회.

## feature-wide 계약

1. **진입점은 `SkillMath` 에만.** `AttackReach` 는 타일 변환 래퍼. 호출부 인라인 재작성은 리뷰 거절.
2. **`AttackReach.InReach` 가 도형을 인자로 요구한다 — 기본값 없음.** «사거리 안»의 뜻이 누가 묻느냐에 따라
   달라지면 `distance-based-range` ①번 문제와 182프레임 교착(헤더 (11))이 재현된다. 소비처가 도형을
   **선언**하게 만드는 것이 이행 방식이다(제약 13 의 「원점 선언」과 같은 형태).
3. **감지(`DetectionSystem`)는 원 그대로.** 「저 놈이 있다」는 방향이 없는 질문이다. 공격 획득만 도형.
4. **side 는 주 대상의 `sign(dx)`. `dx == 0` 이면 +X.** 결정론. 캐릭터 반전(`FaceToward`)도 같은 부호를 본다.
5. **몸 걸침 = 히트.** 도형 가장자리에 대상 몸이 걸치면 맞는다. 원점 항은 `Reach` 가 가지므로 게이트는 대상 몸만.
6. **sim 은 각도를 모른다.** bake 1회 `(sinθ, cosθ)` · 폭 → 반폭. sqrt·삼각함수 0.
7. **정의역 = 전체각 (0°, 180°] ∪ {360°}.** 사이는 bake 가 에러 로그 + 360 취급(fail-open — 게이트라 안전).
8. **0 = 미저작 = 360.** 기존 에셋 YAML 무키 · 코드 생성 `AttackState`(도발 공격·v1 투사체) 전부. 정본은 bake 폴백.
9. **표기는 판정과 같은 술어를 지난다.** 링·배치 프리뷰·부착 프리뷰가 `InCellReach`/`InReach` 에 같은 도형을
   넘긴다 — 「밝은 칸인데 안 때린다」 금지(unit 5 의 존재 이유 그대로).
10. **도형 저작 + `attackTargetCount == 1`** 은 유효하다(rev 1 과 다르다 — 이제 획득도 자르므로 단일 타겟 창병이
    성립한다). 경고 없음.
11. **추격(hunting) 적에는 도형을 저작하지 않는다**(이번 spec). 추격판의 «사격 칸»이 셀 디스크라 도형을
    모른다 — 띠 밖 사격 칸에 도착해 영원히 못 쏘는 교착이 정확히 헤더 (11) 사고다. 경로 진행형 적(보스)만.

## 범위 밖 / 후속 후보

- **긴창 전용 신규 유닛 + Rect 라이브 저작·Play 검증** — 이 spec 은 Rect 코드 경로까지.
- **추격 적 × 도형** — 추격판 사격 칸 수집(`FlowFieldBuilder.CollectDefenderSources`)이 도형을 알아야 한다.
- **스킬 광역에 방향 항** — `AreaSleepSkill` 등은 원으로 모은다.
- **투사체 스플래시** — 착탄점 중심(「자리에 떨어지는 것」), 형이 다르다.
- **`SkillCone.IsInCone` 흡수** — 드래곤 브레스(자유각). 백로그 항목과 동일.
- **반전 flip-flop 히스테리시스** — 적이 유닛 열을 정확히 세로로 지나면 `sign(dx)` 가 프레임마다 뒤집힐 수
  있다. 락이 primary 를 잡아도 side 는 매 공격 재계산. 실측 후 필요하면 side 락.
- **시트 연동**(`UnitStatImportDto`) — 도형 필드는 에셋만.
