# three-minute-kill-race — 패배 없는 3분 킬 경쟁

> 상태: **완료 2026-08-16** (units 0~4 · 자동 검증 + Play 육안 확인 통과)
> 인계: `5_handoff_summary.md` (origin/main `49554c6d` 기준으로 대조 완료)
> 선행: `three-minute-survival`(units 0~7 — 안정도 패배·처치 점수·마감 파이프라인),
> `goal-tower-siege`(공성 모델), `battle-structures`(적 마음 축)
> 정본 갱신 대상: `docs/reference/score-formula.md`, `docs/reference/ingame-flow.md`

## 목표

**판에서 지는 일이 없어진다.** 한 판은 3분이고 전원이 그 3분을 완주한다. 시스템이 판을
끝내는 판정은 하나도 남지 않고, 남는 것은 «3분 동안 몇 마리 잡았나» 하나다.

검증 질문: *"질 수 없다는 걸 알고도 3분 내내 손이 바쁜가 — 못 막은 적이 그대로 못 번
점수라는 게 감점 없이도 체감되는가?"*

## 사용자 결정 (2026-08-16 확정) — 이 spec 의 헌법

| 항목 | 스펙 |
|---|---|
| 판 길이 | **3분 고정** |
| 종료 조건 | **시간 만료 또는 유저의 「제출」** — 이 둘 외에 판을 종료시키는 이벤트는 존재하지 않는다 |
| 패배 조건 | **없음.** 전원 완주 보장 |
| 점수 | **킬 카운트 단일 축. 개체 1킬 = 1점, 예외 없음** |
| 누수 | **무제한 허용, 별도 감점 없음.** 누수 = 미획득 점수 + 미충전 각성치로 **자동 과금** |

**제출(조기 종료 동사)**

- **경과 60초 후 개방** (파라미터 **P1 = 60s**, 튜닝 대상)
- 실행 시: 현재 킬 수로 성적 즉시 확정, 판 종료. **페널티 없음**
- UI 어휘: **「포기」류 금지. 「제출」 고정**
- **종료 권한은 유저 전용. 시스템 발 강제 종료 이벤트 구현 금지**
- 자리는 **햄버거 메뉴**(기존 `MenuPopup`)다. 같은 버튼이 P1 을 기점으로 정체를 바꾼다:

  | 경과 | 라벨 | 동작 |
  |---|---|---|
  | < 60s | 「나가기」 | 기존 그대로 — `AbandonMatch`(0점 마감) + 로비 직행 |
  | ≥ 60s | 「제출」 | 현재 킬로 확정 → **결과 화면**(로비 직행 아님) |

  60초 전 나가기를 남기는 이유는 **서버 attempt 락**이다 — 판을 떠날 길이 없으면 앱 강제
  종료 시 다음 로비 reconcile 까지 잠긴다. 제출이 열린 뒤로는 0점 포기가 **사라지므로**
  「포기류 금지」와 충돌하지 않는다: 포기는 제출이 불가능한 60초 동안만 존재한다.

**마음**: 판정 권한 0. 누수 시 **균열 연출**(게이지 형태 금지). 서사는 해몽에서 회수.

> 「자동 과금」은 코드가 이미 그렇다 — 각성치는 `DrainEnemyKilledEvents` 안에서만 지급되고
> (`EnemyKilledAwakening`), 유출된 적은 `EnemyKilledEvent` 를 발화하지 않는다. 구현 불필요.

### unit 1 의 파장 (2026-08-15 결정을 뒤집는다)

`1e8c1a90` 은 티어 가중(일반 1 / 엘리트 3 / 보스 10)을 유지했다. **1킬 = 1점**이 되면
`killScore` 축 전체가 죽는다. 실측한 소비처 전부:

| 소비처 | 지금 | 이후 |
|---|---|---|
| `AttackUnitData.killScore` + 적 SO **23종** | 0 / 1 / 3 / 10 | **필드 은퇴** |
| `KillScore`(ECS 컴포넌트) · `EnemyKilledEvent.killScore` | 값 운반 | **은퇴** — 이벤트 1건 = 1점이라 실을 값이 없다 |
| `BattleBridge._killScoreTotal` | `+= evt.killScore` | **삭제** — `_killCount` 하나로 |
| `MatchTally.KillScore` / `KillCount` | 두 축 | **한 축**(`Kills`) |
| `ScoreHudView.OnEnemyKilled(points)` · `burstScoreThreshold` 4 | 가변 가산 | `+1` 고정, 임계 재조정 |
| `PaceBaseline.WaveKillScore` | `unit.killScore × count` | `count` 합 |
| 결과 화면 「점수」/「처치 N기」 두 줄 | 다른 숫자 | **한 줄로**(unit 4) |
| `EnemyTier.cs` 주석 · `docs/reference/score-formula.md` 티어 표 | — | 갱신/폐기 |

시트 임포터는 `killScore` 를 다루지 않는다 — 필드를 지워도 시트 동기가 깨지지 않는다(확인함).

> **⚠ 「예외 없음」과 부딪히는 실물이 있다** — 아래 「분열체」 절.

### ⚠ 분열체(슬라임) — 「1킬 1점, 예외 없음」의 유일한 충돌

`Enemy_Slime_Mid`·`Enemy_Slime_Small` 은 **`killScore: 0`** 이다. 쪼개져 나온 파생체가 점수를
주지 않도록 저작된 값이고, `enemy-wave-integration` 스킬도 이걸 규칙으로 적고 있다.

「예외 없음」을 문자 그대로 적용하면 **분열체도 1점**이 되어 슬라임 1마리가 최대 3점이 된다
(원본 + Mid + Small). 슬라임이 점수 효율 1위 적으로 바뀐다 — 밸런스 결정이다.

- **A. 문자 그대로(기본값)**: 분열체도 1점. 규칙에 예외가 하나도 없다. 슬라임 편성 비중은
  웨이브 밸런스에서 따로 조정.
- **B. 분열체만 0점**: 「예외 없음」이 깨지고 `killScore` 필드를 완전히 죽일 수 없다
  (0/1 이진 플래그로 남는다).

**A 를 기본으로 잡는다** — 규칙의 단순함이 이 spec 의 목적이고, 슬라임 편성량은 별도 축이다.
B 로 갈 거면 unit 1 착수 전에 알려달라.

## Feature-wide 계약

- **시스템은 판을 끝내지 않는다.** 3분 만료와 유저 제출 외에 `EndMatch` 를 부르는 경로를
  새로 만들지 않는다. 이 계약이 깨지면 «패배 없음» 이 조용히 되돌아온다.
- **감점은 없다.** 누수·마음 붕괴·조기 제출 어느 것도 점수를 깎지 않는다. 페널티는
  **기회비용 하나** — 못 잡은 적은 점수도 각성치도 안 준다(`EnemyKilledEvent` 미발화).
- **1킬 = 1점, 예외 없음.** 보스도 잡몹도 1점이다. 등급으로 점수를 가르는 필드를 되살리지 않는다.
- **마음은 판정에 관여하지 않는다.** `_goalStability` 는 연출과 로그의 입력일 뿐이며
  종료·점수·제출값 어디에도 닿지 않는다.
- **마음을 게이지로 그리지 않는다.** 남은 수치를 바·숫자로 노출하지 않고 균열 상태로만 보인다.
- **문이 뚫리기 전에는 유출이 0이다.** 도달한 적은 마음을 때리며 **살아 있고**, 그래서 아직
  잡을 수 있다. 유출은 마음 HP 0 으로 그 셀이 열린 **뒤에만** 발생한다 — 이 구조는 그대로 둔다
  (기회비용 모델이 여기에 걸려 있다).
- **제출은 무페널티**다. 남은 시간·미소화 웨이브를 성적에 반영하지 않는다.
- **UI 어휘는 「제출」**이다. 「포기」·「항복」·「나가기」류 표현을 이 버튼에 쓰지 않는다.
- 서버 제출값은 `MatchTally.SubmissionScore` 그대로 — `three-minute-survival` unit 6 계약 유지.
  제출 경로가 둘(만료·유저)이 되어도 **값을 만드는 곳은 하나**다.
- **`GamePhase` enum 의 값을 건드리지 않는다.** 이 enum 은 `Data/Camera/CameraDirectionConfig.asset`
  에 **정수로 직렬화**되어 있다(`phase: 1/2/3/4` + `breathPhases`). 값을 빼거나 중간에 끼우면
  카메라 연출이 통째로 밀린다 — 굳이 바꿔야 하면 **같은 커밋에서 그 에셋도 마이그레이션**한다.
  패배가 사라져도 `Tally` 는 그대로 둔다(전투 HUD 게이팅이 읽는다).
- 새 ECS 컴포넌트·시스템·맥락·이벤트 채널을 만들지 않는다. 마음 관련 sim 은 그대로 두고
  **읽는 쪽만** 바꾼다. (unit 1 의 `KillScore` 컴포넌트 **은퇴**는 예외 — 신설이 아니라
  소비처가 사라진 축의 제거이고, `Units` 맥락 자기 소유다.)

## 머지된 선행 작업과의 관계 (2026-08-16 대조)

`gift-phase-removal`·`waypoint-flight-enemy`·`dreamcatcher-content-4` 가 들어왔다. 대조 결과:

- **선물 페이즈가 사라졌다.** `GamePhase.Gift`(값 2) 제거로 뒤 값이 한 칸씩 당겨졌고,
  진입은 `EnterPlacementOrGift` → `EnterPlacementOrIntro`(기믹 리빌)로 바뀌었다.
  P1 은 `_battleClock` 기준이라 인트로 길이와 무관 — **영향 없음**. 위 계약에 enum 고정만 추가.
- **결과 화면의 RESTART 는 이미 휴면**이다(«결과창 버튼이 "로비로" 가 되면서 호출처가 없다» —
  `OnRestartRequested` 주석). unit 4 가 「다시하기」 분기를 고려할 필요가 없다.
- **`EndMatch`·`BuildTally`·`_goalStability` 를 건드린 커밋은 없다.** `1e8c1a90` 의 마감
  파이프라인은 그대로다.
- 덱 에셋 12개 변경은 `waveGeneratorVersion: 5→6` 과 랩 덱 `goalStabilityMax` 1건뿐 —
  스트레스 한계·마음 HP 정책은 그대로다.

## 확정된 세부 (2026-08-16)

1. **P1 = 경과 60초.** `_battleClock ≥ 60` — 웨이브 소화율이 아니라 **시계** 기준이다
   (웨이브는 전멸 속도에 따라 흔들려 개방 시점이 판마다 달라진다).
2. **스트레스 = 누수 누적 수량만 표기.** 한계(`defeatGoalReachedCount`)와 분모 `N / M` 을 뗀다.
   한계가 아무것도 하지 않는데 분모가 있으면 거짓말이다. **("일단은" — 임시 결정)**
3. **제출 자리 = 햄버거 메뉴.** 별도 확인 팝업을 두지 않는다 — 햄버거 한 번이 이미 한 단계라
   우발 클릭이 아니다.

- **적 마음(공성 맵)의 새 역할** [M] · 부숴도 판이 안 끝나면 지금은 «사격이 멎는 것» 만 남는다.

> 같은 계열 증상을 `gift-phase-removal` 커밋 `2e4aaf63`(teardown `_seq.Stop()` 누락)이
> 한 번 고쳤다 — 남은 것은 다른 시퀀스이고 이 spec 범위 밖이다.
