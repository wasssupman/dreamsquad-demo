# 3 — 「제출」: 종료 권한을 유저에게

## 목적

**판을 끝낼 수 있는 사람은 유저뿐이다.** 3분 만료 외의 유일한 종료를 붙인다.
햄버거 메뉴의 버튼이 **P1(경과 60초)을 기점으로 정체를 바꾼다**:

| 경과 | 라벨 | 동작 |
|---|---|---|
| < 60s | 「나가기」 | 기존 그대로 — `AbandonMatch`(0점 마감) + 로비 직행 |
| ≥ 60s | 「제출」 | 현재 킬로 확정 → **결과 화면**(로비 직행 아님) |

60초 전 나가기를 남기는 이유는 **서버 attempt 락**이다 — 판을 떠날 길이 없으면 앱 강제
종료 시 다음 로비 reconcile 까지 잠긴다. 제출이 열린 뒤로는 0점 포기가 **사라지므로**
「포기류 금지」와 충돌하지 않는다: 포기는 제출이 불가능한 60초 동안만 존재한다.

## 변경 대상

- `Bridge/BattleBridge.cs` — `CanSubmit`·`SubmitMatch()` 공개 창구 2개
- `UI/MenuPopup.cs` — 버튼 정체 전환(라벨 + 동작), 열 때마다 재판정

## 구현

**1. 브리지가 판정을 소유한다.** `CanSubmit` = 전투 중(`_running`) + `_battleClock ≥ 60`.
시계는 **Battle 도메인**(`_battleClock`)이라 일시정지·슬로모에서도 유저가 겪은 판의 길이와
일치한다. `Time.time` 을 쓰면 메뉴를 열어 둔 시간까지 세어 «안 싸웠는데 열린다».

**2. `SubmitMatch()` 는 `EndMatch("submitted")` 한 줄이다.** 마감 파이프라인(취합 → 기록 →
통보 → 표시)을 그대로 탄다 — 제출 전용 경로를 따로 만들지 않는다. 이것이 unit 0 이 만든
단일 관문의 값어치다. 재진입은 `_resultShown` 가드가 막는다.

**3. 라벨은 여는 순간 정한다.** 팝업이 열릴 때 `CanSubmit` 을 한 번 읽어 라벨·색·동작을
맞춘다. 매 프레임 갱신하지 않는 이유: 팝업이 열려 있는 동안 **전투는 멈춰 있어**(`Open()`
이 Battle 도메인 0배속 lease 를 잡는다) 시계가 안 흐른다 — 열린 채로 정체가 바뀌는 일이
구조적으로 없다.

**4. 브리지 참조는 `FindFirstObjectByType` 로 얻는다(의도된 예외).** 원칙은 SerializeField +
씬 배선이지만, `BattleScene.unity` 가 다른 세션의 미커밋 WIP 를 물고 있어 지금 씬을 저장하면
그 작업이 통째로 박힌다. 팝업은 드물게 열리므로 열 때 한 번 찾아 캐시하는 비용이 무해하다.
**씬이 깨끗해지면 SerializeField 로 승격한다**(후속 후보).

## 완료 기준

- [ ] 컴파일 통과, 콘솔 에러 0
- [ ] `EndMatch` 호출부가 **2곳**(`CheckTimer`·`SubmitMatch`)이다 — 그 이상이면 계약 위반
- [ ] Play: 60초 전에 햄버거 → 「나가기」, 누르면 로비(기존 동작)
- [ ] Play: 60초 후에 햄버거 → 「제출」, 누르면 결과 화면이 뜨고 총점 = 그 시점 처치 수
- [ ] Play: 제출로 끝낸 판이 서버에 `score=N`(N = 처치 수)으로 올라간다
- [ ] 로그 `outcome` 이 `submitted` 다(만료는 `complete`)
