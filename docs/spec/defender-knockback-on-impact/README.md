# defender-knockback-on-impact — 유닛 넉백을 착탄 시점으로 + 방향을 「적 진행 반대」로

> 상태: **units 0~2 구현 완료 (2026-08-17).** EditMode 코어 2352 통과 / 0 실패 · PlayMode 이동 8/8.
> 발단: 밀당맨에 「매 피격마다 약한 넉백」을 넣자(사용자 지시) → **세** 결함이 드러남.
> unit 2 는 ECS critic 리뷰로 계획을 4건 정정한 뒤 착수했다(사이트 5→7 · 당김 hoist 불가 ·
> 「제어 흐름 무변경」 거짓 · Halt 적 수 17→18).

## 상위 목표

방어유닛 넉백(`DefenderCcData.knockbackDistance/Duration`)이 **화면에서 말이 되게** 만든다.
바꾸는 것은 **언제 미느냐**와 **어느 쪽으로 미느냐** 둘뿐이다. 저작 위치·필드·병합 정책은 그대로다.

### ① 언제 — 발사 시점 → 착탄 시점

넉백은 `AttackSystem` 이 공격이 성사되는 순간 걸고 있었다. 화살은 그때 막 출발한다.
사거리 4·탄속 12 면 **0.33초 먼저** 밀리고, 0.2초마다 쏘는 밀당맨에서는 한 발치를 넘는
어긋남이라 「맞기도 전에 밀린다」로 보인다(사용자 제보).

### ② 어디로 — 상대속도 합 → 적 진행의 반대

기존 식은 `normalize(D − E)`(D = 사수→적, E = 적 진행)였다. 두 결함이 있다:

- 적이 사수를 **지나쳐 멀어지면** 두 성분이 상쇄된다. 근처에선 옆으로 밀리고, 정확히
  일직선이면 폴백이 `D` 로 떨어져 **적의 진행 방향 = 골 쪽으로 밀어준다.**
- `E` 를 흐름장 `PrimarySlot` 에서 읽었다. **비행 적은 웨이포인트를, 추격 중인 적은 추격장을**
  따라가므로 그 칸의 기본 흐름은 그 적의 진행 방향이 아니다 — 대공 유닛의 주 표적이 정확히
  그 비행 적이라, 기능의 핵심에서 틀리는 형태였다.

디펜스에서 「밀어낸다」는 사수가 어디 서 있든 같은 뜻이어야 한다. → **`-lastMoveDir` 하나.**

### ③ 누가 — 밀리는 쪽 (unit 2)

units 0~1 이 「넉백을 만드는 쪽」을 고쳤더니 **쓰는 쪽**이 끊겨 있는 것이 드러났다.
자기주도 이동을 안 하는 상태(제자리 공격·도발 대치·추격·순찰 대기·고립)가 소비 지점에
닿기 전에 `continue` 해서, **적 18종이 교전 시작 즉시 넉백 면역**이었다. 생산자 무관 결함이라
밀치기 카드까지 같이 죽어 있었다. 상세는 `2_force_composition.md`.

## 계약

- **진행 방향은 관측한다, 재유도하지 않는다.** `PathFollowState.lastMoveDir` 은 Movement 가
  자기주도 변위를 실제로 적용하는 지점에서만 쓴다(`holdingGround` 와 같은 자리·같은 철학).
  흐름장·웨이포인트·추격·복구 어느 경로로 움직였든 값이 맞고, 새 이동 분기가 생겨도 자동 편입.
- **멈춘 프레임에는 갱신하지 않는다.** 교전 중 정지한 적도 직전 진행 방향을 유지해야 뒤로 민다.
- **방향이 없으면 밀지 않는다.** `lastMoveDir == 0`(스폰 직후·고정 구조물) = phantom impulse 금지.
- **넉백은 유닛의 성질이지 화살의 성질이 아니다.** 저작은 `DefenderCcData` 에 남는다 —
  탄 SO 로 옮기면 같은 화살을 공유하는 유닛(밀당맨 ↔ 마크스맨)에 샌다.
- **직격 victim 이 있는 payload 에서만 미룬다.** `SingleSplash` 만. `TileAoe` 등 직격 대상이
  없는 payload 는 넘길 곳이 없으므로 기존대로 발사 시점에 건다(조용히 사라지지 않게).
- **훑는 탄(PathHit)의 넉백은 건드리지 않는다.** 그쪽은 탄 SO 소유이고 방향도 스윕 방향이다 —
  「지나가며 밀어낸다」가 곧 그 능력이라(부메랑은 두 다리에서 반대 힘) 규칙이 다른 것이 의도다.
- **사수가 비행 중에 죽으면 넉백도 없다.** 위협 귀속과 같은 규약.

## 밸런스 메모 (밀당맨, 2026-08-17)

`0.3칸 / 0.08초` = 미는 속도 **3.75칸/초**. 넉백은 피해자당 슬롯 하나를 공유하므로(`CcEffectMerge`,
병합 키 = kind) **여러 기를 깔아도 겹치지 않고**, 보스는 Impulse 면역이다(`CcActionLock.IsBossImmune`).

한 발 주기(0.2초)당 적의 **순 전진 = 적 이동속도 × 0.2 − 거리**. 즉 거리 값이 곧 「한 발마다
빼앗는 전진량」이고, **거리 ÷ 지속이 적 걸음보다 커야** 실제로 뒤로 가는 그림이 유지된다.

초당 5발이라 「걸음 2.5짜리를 뒤로 민다」와 「걸음 1.2짜리가 계속 전진한다」는 **동시에 만족할 수
없다**(산술적으로). 지금 값은 앞을 택했고, 그래서 느린 적(탱커·항아리·스나이퍼)은 사격받는 동안
사실상 묶인다 — 한 번에 한 마리라는 것이 그 대가의 상한이다.

## 유닛 개명 — 대공사수 → 밀당맨 (2026-08-17)

같은 날 전 방어유닛이 `Path|Air` 가 되면서 이 유닛의 「유일한 대공」 정체성이 사라졌고,
그 자리를 넉백이 대신했다. 그래서 이름도 능력을 따라갔다(사용자 결정).

- **`id` 는 `anti_air` 그대로다.** 바꾸면 저장된 덱(`profile.json`)이 Validate 에 걸려 안 열린다.
  에셋 파일명(`Defender_AntiAir.asset`)도 같은 이유로 유지 — 표시 이름만 바뀐다.
- `displayName`·`desc` 는 **시트 소유**(`UnitStatFieldMapper` 반사 매핑, skip-list 밖).
  SO 만 고치면 다음 로그인 임포트가 되돌린다 → 시트 반영이 같이 필요하다.

## 후속 후보

- 훑는 탄(PathHit) 넉백도 「적 진행 반대」로 통일할지 — 지금은 의도적으로 다르다.
- `TileAoe` 유도탄에 넉백을 저작한 유닛이 생기면 착탄 이관 경로가 없다(현재 그런 유닛 0).
- 밀당맨 고유 아트·최종 밸런스(현재 아트는 대공사수 시절 그대로).
