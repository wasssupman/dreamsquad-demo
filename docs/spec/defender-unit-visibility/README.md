# defender-unit-visibility — 유닛 노출 스위치

> 상태: **스펙 작성됨 2026-08-20** (units 0~1 미착수)
> 선행: `dreamcatcher-card-visibility`(완료) — 이 spec 은 그 후속 후보 「유닛(`DefenderUnitData`)에도 같은 스위치」의 실현이다. 계약·용어를 그대로 물려받는다.
> 성격: 데이터 1 필드 + 아웃게임 UI 필터. ECS/BattleBridge 무관 → 파이프라인 커버리지 N/A.

## 검증 질문

`visible = 0` 인 유닛이 스쿼드 페이지 유닛 목록에서 사라지고, 코드 변경 없이 시트에서
껐다 켤 수 있는가?

## 목표

안 쓰는 유닛(미완성·보류·실험용)을 **저작으로 감춘다**. 지금은 `DefenderCatalog.units` 에
들어 있으면 무조건 목록에 뜨므로, 감추려면 카탈로그 배열에서 빼는 수밖에 없다. 그런데
카탈로그에서 빼면 **그 id 를 저장한 프로필이 유닛을 못 찾는다**(`ById` → null → 편성이 조용히
0/7 이 되고 START 가 막힌다). 즉 "목록에서만 감추기"가 지금은 표현 불가능하다.

## Feature-wide 계약

- **`visible` 은 int, 기본 1** (`0` = 숨김, 그 외 = 노출). 드림캐쳐 카드와 같은 표현. `0` 만
  숨김으로 해석하므로 빈 셀·미설정은 노출이다.
- **기존 27개 에셋 백필 없음.** Unity 는 필드명 기반 역직렬화라 YAML 에 `visible` 키가 없는
  에셋은 C# 초기값 `1`(노출)을 유지한다. 27개를 dirty 시키지 않는다.
- **숨김의 의미는 "목록에서 고를 수 없다"뿐이다.** 런타임 유닛 성능·배치·전투는 아무것도
  바뀌지 않는다. 카탈로그에는 그대로 남으므로 **id 해석은 계속 된다** — 이것이 카탈로그
  배열에서 빼는 것과의 결정적 차이다.
- **이미 편성된 숨김 유닛은 건드리지 않는다** (2026-08-20 사용자 결정). 목록에서만 사라지고
  헤더 편성 슬롯에는 남는다. 슬롯을 탭해 상세를 띄우고 [편성 해제]로 뺄 수 있으므로 막다른
  길이 아니다. 카드처럼 로그인 prune 을 두지 않는 이유: 유닛은 7/7 이 깨지면 즉시 START 가
  막히는데, 그 대가를 치를 만큼 급한 정합성 문제가 아니다.
- **시트 왕복은 컬럼 하나 추가로 끝난다.** DTO 필드명이 SO 와 1:1 이라 `UnitStatFieldMapper`
  가 이름으로 읽고 쓴다. exporter/applier/서버 설정은 손대지 않는다.
- **소유/잠금(가챠)과 다른 축이다.** `visible` 은 **저작이 이 유닛을 세상에 내놓았나**이고,
  소유는 **이 플레이어가 가졌나**다. 소유 UI(미보유 셀 dim/잠금)는 여전히
  `squad-character-page` 의 후속 후보로 남는다 — 둘을 한 필드로 겸직시키지 않는다.

## 후속 후보 (본 spec 범위 밖)

- **`defaultSquadUnits` / `AllIds()` 폴백 시딩의 숨김 제외** · 신규 프로필 시드는 저작
  배열(`defaultSquadUnits`)이 이기므로 저작으로 피할 수 있다. 배열이 비었을 때의 폴백만
  숨김 유닛을 집을 수 있는데, 그 경로 자체가 이미 "암묵 규칙" 취급이다.
- **적(`AttackUnitData`)에도 같은 스위치** · 적은 목록 UI 가 없어 지금은 쓸 데가 없다.
  웨이브 편집기가 생기면 재검토.
- **숨김 유닛 편성 시 경고 배지** · 편성 슬롯에 남은 숨김 유닛을 시각적으로 표시.
