# unit 1 — Duel 배치선 전진 (적 본능 앞까지)

> **좌표 갱신 (siege-duel-map rev 5, 2026-08-21).** 규칙(「적 본능 footprint 서쪽 끝 미만」·
> 「경계값은 `structures` 에서 도출」)은 그대로다. Duel 이 23×10 이 되면서 아래 본문의 실측
> 값만 옮겨갔다: 경계 열 **x14 → x16**, 저작 칸 수 **134 → 164**, 다리 셀 **x10·y2,3,8,9 →
> x11·y1,2,7,8**. (칸 수가 는 것은 데코 테두리가 사라져 x0 열이 전부 판이 됐기 때문이다.)

## 목적

배치 가능 영역이 내 진영(x1~9)에서 **강을 건너 적 본능 바로 앞(x14)까지** 넓어진다.
같은 저작에서 **적 본능 뒤쪽(x15~19)의 잠재 구멍**(가디언이 적 마음 뒤까지 놓이던 것)을 닫는다.

- (파생) `MapDocumentPoolDevEntriesTests.SiegeMap_KeepsDuelDesignPhilosophy` ④ 단언

## 구현

### 경계는 어디인가

적 본능 중심 (16,3)·(16,8), footprint 3×3 → **x15~17 이 건물이다.** 그 앞 열이 **x14**.
(Ford·Isle 은 본능이 x15 → 앞 열이 x13. 회귀선은 이 값을 문서에서 **도출**한다.)

### 마스크 규칙 (전 셀 1식)

| 타일 | x | 값 |
|---|---|---|
| `Walk` | ≤ 14 | `07` = Ground\|Path\|Air — 전 유닛 배치 가능 |
| `Walk` | ≥ 15 | `04` = Air — 배치 불가 (**Path 비트 제거 = 구멍 폐쇄**) |
| `Env`(강) | — | `04` |
| `Deco`(테두리) | — | `04` |

- 다리 4칸(`(10,2) (10,3) (10,8) (10,9)`)은 `Walk` · x ≤ 14 이므로 **열린다.** 방어유닛은 적의
  통행을 막지 않으므로(차단은 해저드의 몫) 다리 개방이 길을 봉인하지는 않는다 — 건널목에서
  붙는 자리가 하나 생기는 것이다.
- 저작 칸 수: `Walk ∧ x ≤ 14` = 140 − 강 6 = **134칸**(기존 90).
  라이브에서는 런타임 파생이 방어 본능 2기의 footprint 18칸 + 골 1칸을 닫아 **115칸**(기존 71).

### 회귀선 재정식화

`SiegeMap_KeepsDuelDesignPhilosophy` 의 ④ 「배치칸이 전부 미러축 왼쪽」을 **버렸다.** 새 원칙:

> ④ **어떤 배치층도 적 거점 footprint(그 서쪽 끝) 이상에서 열리지 않는다.**

- 경계값은 문서의 `structures` 에서 도출한다(하드코딩 금지) — 적 진영 거점들의
  `cell.x − footprint/2` 최소값이 곧 「건물의 서쪽 끝」이고, 배치칸은 그보다 작아야 한다.
- **Ground 만이 아니라 `Ground|Path` 를 본다.** 옛 단언이 Ground 만 세어 구멍을 놓쳤다.
- Ford·Isle 은 x ≤ 9 라 완화된 단언을 그대로 통과한다(전선 철학 통일은 후속 후보).
