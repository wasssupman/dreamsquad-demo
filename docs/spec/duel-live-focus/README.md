## 이 spec 의 성격 — **런타임 코드 변경 0줄**

둘 다 **에셋 데이터**로 끝난다.

- 맵 선택: 「시드가 고르는 풀」의 정본이 `MapDocumentPool.entries` 다. 거기에 한 장만 두면
  `MapPoolSelect` 가 이미 `count <= 1 → 0` 이라 코드가 손댈 자리가 없다.
- 배치 경계: 정본이 `MapDocument.placeMask` 다. 진영·거리·"내 땅" 같은 새 술어를 코드에
  만들지 않는다.

**처음에 `MapDocumentPool` 에 「라이브 고정 맵」 필드를 새로 만들고 `BattleBridge` 에 분기를
얹으려 했다가 폐기했다**(사용자 지적 2026-08-17). 그 설계의 유일한 이점은 스테퍼 슬롯 번호가
안 밀리는 것이었는데, 그건 테스트 상수 편의이지 게임의 요구가 아니다. 데이터로 표현 가능한
것을 코드로 표현하면 되돌리기가 «필드 비우기 + 분기 삭제» 가 된다.

## feature-wide 계약

1. **`entries` = 라이브 노출 풀.** 지금은 `[Duel]`. 되돌리기 = 원하는 맵을 `entries` 로 다시
   올리기(순서가 곧 시드 인덱스).
2. **`devEntries` = 스테퍼에서만 닿는 슬롯.** 나머지 12장이 여기 있고, 스테퍼 슬롯 번호는
   `entries.Count + devIndex` 다 — 즉 **`entries` 크기가 바뀌면 dev 슬롯 번호가 전부 밀린다.**
   그 번호를 상수로 박은 PlayMode 테스트가 있으므로 풀을 재편할 때 같이 고친다.
3. **고정 맵도 (문서, 덱) 쌍으로 산다.** `Deck_Duel` 이 같은 엔트리에 물려 있어야 한다 —
   덱이 null 이면 브리지의 직렬화 `deck`(구 `Deck_WaveA` — 컨셉 0·보스 0·적 9종)으로 폴백해
   «맵은 뜨는데 웨이브 개선이 하나도 안 붙은 판» 이 된다(siege-duel-map 에서 실제로 겪음).
4. **배치 경계는 층에 무관하다.** 「x ≤ 14 까지」는 Ground 유닛에게만이 아니라 Path 유닛
   (가디언)에게도 같다 — 기존 결함이 정확히 여기였다(아래).
5. **거점 자리·스폰·골의 배치 배제는 런타임 파생이다**(`BattleBridge.BuildMapForBattle` 말미).
   문서 마스크에 그 구멍을 손으로 파지 않는다.

## 같이 닫은 기존 결함

Duel 의 내부는 **전부 `Walk` 타일**이다(개활지). 파생 마스크는 `Walk → Path|Air` 라, 저작자가
Ground 비트를 얹지 않은 **적 진영 전체와 다리 4칸이 `Path|Air` 로 남아 있었다.** 즉 가디언
(`placementLayers = Path`)은 **적 마음 뒤에도 배치할 수 있었다.**

회귀선이 못 잡은 이유: `SiegeMap_KeepsDuelDesignPhilosophy` ④ 가 **Ground 비트만** 세었다.
unit 1 에서 그 단언을 «어떤 배치층도 적 거점 앞을 넘지 않는다» 로 바꿨다.

**넓힌 단언이 Ford·Isle 도 빨갛게 만들었다** — 두 맵에도 같은 구멍이 있었다(Ford 92칸 ·
Isle 104칸). **배치선은 옮기지 않고 구멍만 닫았다**: `Ground` 비트가 있는 저작 영역
(Ford 80칸 · Isle 70칸)은 그대로 두고, 그 밖의 파생 `Path` 만 제거했다. 세 맵이 같은
규칙이 됐고 Ford·Isle 의 배치 느낌은 한 칸도 바뀌지 않는다.

## 비목표 / 후속 후보

- **Ford·Isle 의 배치선**은 건드리지 않았다. 지시는 Duel 하나였고, 두 맵은 완화된 회귀선
  (적 거점 앞) 안쪽에 그대로 머문다. 세 맵의 전선 철학 통일은 Duel 체감 뒤 결정.
- **전진한 배치선의 하한 회귀선 없음** [S] — 지금 회귀선은 «경계를 넘지 않는다»(상한)만
  건다. 마스크가 옛 범위로 되저작돼도 초록이다. 하한(«x14 열이 열려 있다»)을 박을지는
  체감 확정 뒤 판단.
- **토너먼트 맵 다양성 복귀** — `entries` 에 맵을 다시 올리면 된다. 그때 dev 슬롯 번호가
  다시 밀리므로 위 표와 PlayMode 상수를 같이 갱신한다. 시점은 Project owner 결정.
- **효과 타일이 적 진영에도 뿌려진다** — `EffectTilePlacer` 가 Ground 층 배치칸을 따르므로
  경계가 넓어지면 자동으로 따라온다. 의도된 파생이지만 체감 확인 대상.
