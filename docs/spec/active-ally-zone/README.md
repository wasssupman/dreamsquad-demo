# Active Ally Zone — 아군 버프를 장판으로 + 선택 중 액티브 허용

> 상태: **완료 2026-07-30** — units 0~4 구현 + 리뷰 3회 반영(spec critic REVISE / code-reviewer /
> ecs-reviewer) + 사용자 Play 육안 확인. 인계는 `5_handoff_summary.md`
> 선행: `docs/spec/active-dreamcatcher-tile-aim/` (완료, `e5cdb48a`)

## 배경

`active-dreamcatcher-tile-aim` 으로 액티브 6종이 전부 타일 대상이 됐다. 그 상태로 플레이한
결과(사용자 2026-07-30):

> "공격폭증, 속사를 쓰려다 보니 유닛이 배치된 타일 1개를 포커스하다 보니 어색하다."

원인은 **효과의 소유자**다. 조준은 타일인데 효과는 시전 순간 *그 안에 있던 유닛*에 붙고 영역은
사라진다. 그래서 조준의 목적이 "자리 잡기" 가 아니라 "유닛 있는 칸 찾기" 가 되고, 상태줄이
아군 수를 세어 주는 것도 유닛 조준처럼 읽힌다.

## 목표

액티브를 **예외 없는 한 문장**으로 만든다.

> **액티브는 지정한 칸에 효과 영역을 만든다. 그 안에 있는 대상이 영향을 받는다.**

- 적 대상: 회오리는 진짜 캐리어(`TornadoField`), 운석은 즉발이라 이미 성립한다.
  **단 감속장은 아직 스냅샷이다** — `ApplySlowField` 가 시전 시점 반경 내 적에게 `durationSec`
  모디파이어를 직접 걸어, 나중에 들어온 적은 안 걸리고 나간 적은 계속 느리다. 이 spec 이 끝나도
  "안에 있는 대상이 영향을 받는다" 에는 예외 하나가 남는다(후속 후보) — 다음 세션이 "완료" 로
  읽지 않게 여기 명시한다.
- 아군 대상(공격폭증·속사) — 시간제 **장판**으로 바꾼다. 안에 있는 동안 강화.

부수로, 선택(인스펙트) 상태에서 액티브를 막아 둔 규칙을 없앤다 — 액티브를 집으면 자동으로
필드 문맥으로 나온다.

## 검증 질문

> 공격폭증·속사가 아군이 없는 빈 칸에도 놓이고, 장판 안에 있는 아군이 강화되며 장판을 벗어나거나
> 만료되면 자연히 풀리는가? 조준 문법·상태줄이 액티브 6종 전부 동일해졌는가? 유닛을 선택한
> 상태에서 액티브를 끌면 선택만 풀리고 손패를 유지한 채 필드 조준으로 이어지는가?

## 사용자 확정 결정 (2026-07-30)

1. **아군 장판 반경 = 1 (3×3).** 2(5×5)는 과하다.
2. **지속시간은 현재 값 승계** — 공격폭증 8초 / 속사 6초. 밸런스 변화 축을 하나로 제한한다.
3. **선택 중 액티브 허용** — 막지 말고, 드래그 시작 시 선택을 해제하고 줌아웃(평시 조준 상태)으로
   전환한다.
4. **원칙 문장은 "액티브는 좌표를 겨눈다"** — 단일 유닛 유틸리티가 필요해지면 `range 0`(1칸)으로
   표현한다. 대상축(`SkillTargetType`)은 되살리지 않는다.

## 작업 단위

| 파일 | 작업 구분 | 문서 | 목적 |
|---|---|---|---|
| 0 | ECS+bridge | `0_ally_buff_field.md` | 아군 버프 장판 캐리어 + 멤버십 갱신/만료 |
| 1 | bridge+UI | `1_cast_path_and_aim_cleanup.md` | 캐스트 경로 교체 + 조준 아군 카운트 예고 제거 |
| 2 | 표현 | `2_zone_presentation.md` | 장판 점등(바닥). 유닛 하이라이트는 후속으로 이관 — critic H3 |
| 3 | UI | `3_selection_release_on_active.md` | 선택 중 액티브 허용(선택만 해제 + 줌 복귀) |
| 4 | 검증 | `4_validation.md` | PlayMode + Play e2e |

**순서 의존**: 0 → 1 필수(1이 0의 스폰 API를 호출). 2 는 0 위에. **3 은 독립** — 먼저 떼어
단독 진행 가능(체감 개선이 즉시 나온다).

**순서 주의 (critic M7)**: unit 2(장판 점등)는 마감이 아니라 이 spec 의 **검증 질문 자체를 성립시키는
부품**이다. 구 아군 카운트 예고를 걷어내는 unit 1 만 나가면 "무엇이 강화됐나" 를 말해 주는 표면이
한동안 0 이 된다. Play e2e 사인오프는 **unit 2 이후**.

**선행 spec 과의 순서 (critic M8)**: unit 4 에서 선행 spec 의 PlayMode 케이스를 장판 모델로 고치는
작업은 **선행 spec 의 Play 사인오프 뒤**에 한다 — 먼저 고치면 사용자가 대조할 기준선이 사라진다.

### 기각된 더 싼 대안 (기록)

**장판 없이 예외 두 개만 삭제하기** — 0기 캐스트 허용 + 아군 카운트 예고 삭제 + 3×3 짧은 폭발
텔레그래프. "예외 없는 한 문장" 을 unit 1 + unit 2 일부 비용으로 얻고, 새 아키타입·갱신 기계·뷰 채널이
전부 불필요하다. **기각 사유**: 빈 칸 캐스트가 순수 낭비 카드가 되고, "안에 있는 대상이 영향을 받는다"
가 절반만 참으로 남는다(사후 진입·재배치와 상호작용하지 않는다). 사용자가 장판을 택했다 —
다음 세션에서 재논의되지 않도록 여기 남긴다.

**정직한 한계 (critic M7)**: 방어 유닛은 스스로 움직이지 않으므로 "배치 후 시전" 이라는 주 흐름에서
장판과 스냅샷은 **동작이 거의 같다**. 갈리는 곳은 (a) 배치 전 빈 칸에 미리 깔기 (b) 재배치 (c) 사망뿐이다.
따라서 시뮬 변경 자체의 이득은 작고, 실제 소득은 **문법 통일 + 원인이 보이는 것**(unit 2)이다.

## Feature-wide 계약

1. **액티브는 좌표를 겨눈다.** 유닛 엔티티를 인자로 받는 캐스트 경로를 만들지 않는다.
   커밋 창구는 `CastSkillAtTile` + `CastPortal` 둘 그대로(선행 spec 계약 3 계승).
2. **아군 버프 = 시간제 장판.** 반경은 `skill.range`(=1), 수명은 `skill.durationSec`.
   빈 칸에도 놓을 수 있다 — "범위에 아군이 없으면 거절" 규칙은 **폐기**(선행 spec 계약 5 개정:
   비대칭이 사라져 6종 전부 0기 허용).
3. **멤버십은 Effects 맥락의 ISystem 이 매 프레임 갱신한다.** `AllyBuffFieldSystem`
   (`[UpdateInGroup(BattleSimGroup)]` + `[UpdateBefore(ModifierApplySystem)]`)이 살아 있는
   `AllyBuffField` × 배치 완료 방어유닛(`DefenderTile` + `WithNone<PendingDeployment>`)을 맞춰
   `StatModifierApplyEvent` 를 재발행한다. **선례를 그대로 따른다** — `ZoneApplySystem` 이 해저드
   장판 안 적에게 매 프레임 재발행하는 것과 같은 형태(새 발명이 아니다).
   **bridge 에 tick 을 두지 않는다**: TRD 섹션 5 의 "MonoBehaviour 에 전투 로직 직접 작성" 금지에
   걸리고, `BattleScaledRateManager` 가 정지(scale ≤ 0)에서 `BattleSimGroup` 을 통째로 skip 하므로
   bridge 에 두면 정지 중 큐가 드레인 없이 쌓였다가 재개 프레임에 한꺼번에 터진다.
   bridge 가 하는 일은 **스폰 호출 + 로그용 스냅샷 카운트** 둘뿐이다.
   신규 revoke 프리미티브·항등원 중립화 트릭은 쓰지 않는다.
3-1. **모든 적용은 `EffectSpawner.AllyBuffApplySec` 지속이다 — 최초 적용도 포함.** refresh 가
   `remaining = max(old, new)` 라서 한 번이라도 `skill.durationSec` 로 걸면 이후 갱신이 그 값을
   **내릴 수 없고**, 장판을 벗어나도·사라져도 원래 지속시간만큼 버프가 남는다 = 이 spec 이 없애려는
   스냅샷 동작으로 조용히 회귀한다(그리고 unit 4 의 앞 케이스들은 그대로 통과해 발견되지 않는다).
   `skill.durationSec` 는 **캐리어 수명에만** 쓴다.
3-2. **지연 0**: 시스템이 매 프레임 도므로 캐스트 직후 프레임에 발효된다. cadence 누산기를 두지
   않는다 — 두면 "정지/슬로모에서 어느 시계를 쓰나" 라는 결정이 새로 생긴다.
4. **전용 모디파이어 슬롯 유지** — `AllyBuffField.StackId`(=3, 선행 spec 의 상수를 적용 주체인
   Effects 로 이전). 오라와 합산되고 같은 장판의 반복 갱신은 멱등(refresh).
4-1. **겹친 장판은 누적되지 않고, 승자는 "가장 강한 값" 으로 못박는다.** merge 키가 stat 단위로
   같아서 그냥 두면 어느 magnitude 가 이기는지가 chunk 순회 순서에 달리고, 만료 시 swap-back 으로
   그 순서가 런타임에 바뀐다 → 배율이 다른 장판 2장이 겹치면 승자가 무작위가 된다. 시스템이
   stat 별 최댓값으로 접어 enqueue 한다(부수로 유닛당 enqueue 가 stat 수 ≤2 로 줄어든다).
5. **점등은 전용 zone 타일맵 + 셀 refcount.** 맵 효과 타일(`_effectTilesByCell`)과 조준 프리뷰
   (`RangeDisplayOwner.SkillAim`) 채널을 쓰지 않는다 — 둘 다 단일 owner set/clear 라 서로를 지운다.
   장판은 동시에 여러 장 존재할 수 있으므로 칸별 참조수 없이는 먼저 만료된 장판이 겹친 칸을 지운다.
6. **조준 UI 는 6종 동일**: 상태줄 `놓으면 이 위치에 시전` 하나. 아군 카운트 조회
   (`CountDefendersInRange`)와 그 예고 문안은 제거한다.
7. **선택 해제 트리거는 드래그 시작.** press 에서 풀면 선택 중 **탭 즉발 부착**이 깨진다.
   해제는 "선택·패널·리티클·줌" 만 걷고 **손패와 조준 슬로모는 유지**한다.
8. **카메라를 직접 조작하지 않는다.** 인스펙트 줌은 **피드 중단 = 자동 해제**(staleness 페이드)이므로
   해제 API 를 신설하지 않는다. `TickSelectionAnchor` 가 `!AimingNow()` 일 때만 피드하고 조준 시작이
   `IsAiming` 을 세우므로, 확인만 하면 된다.
9. **밸런스 수치의 정본은 시트다.** `SkillData` 의 `range`/`magnitude`/`durationSec` 은 `DcSkills`
   탭에서 내려오고 런타임 갱신(`DcSheetRuntimeRefresher`)이 인메모리로 덮는다 — **에셋만 고치면
   플레이에서 되돌아간다**(2026-07-30 실제로 겪음: 반경을 에셋에서 1로 바꿨는데 조준이 계속 1칸이었고,
   시트를 고쳐야 3×3 이 나왔다). 반경/배율 조정은 시트 → 임포트가 정순이다.
9-1. **`AllyBuffApplySec` 는 밸런스가 아니다** — 반경·지속시간은 `SkillData`. `AllyBuffApplySec` 는 **밸런스가 아니라
   프레임워크 지연 상한**이라 `EffectSpawner` 의 public const 로 둔다(`MulStatFloor`/`MulStatCeil`
   선례). 테스트가 그 값을 읽어 대기시간을 계산한다 — 상수를 테스트에 복제하지 않는다.
10. **선택 해제 신호는 전용 이벤트로 배선한다.** `AimingNow()` 폴링 금지 — 그 판정엔 배치
   방향지정(`drag.IsAiming`)이 포함돼 아무도 요청하지 않은 동작이 새로 생긴다.

| 정거장 | 이 spec |

| 정리 | 만료 시 엔티티 파괴 + 뷰 회수 (unit 0·2) |

## 후속 후보

- press 시점 범위 프리뷰(카드를 집는 순간 어디에 얼마나 퍼지는지 보이기) — 액티브/부착 공통.
- 장판 겹침 시각 규칙(같은 종류 2장이 겹칠 때의 표현).
- **감속장을 캐리어로** — 지금은 스냅샷이라 원칙의 마지막 예외다(위 배경 참조).
- 적 대상 장판(감속장/회오리)도 같은 오버레이 언어로 통일할지.
- **장판 위 아군 하이라이트**(StatusFx 채널 + 프리팹 1개) — critic H3 로 이 spec 에서 이관.
- 액티브 전용 카드 아트.
