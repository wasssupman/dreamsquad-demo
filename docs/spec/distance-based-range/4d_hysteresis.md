# 4d — 히스테리시스와 어설션

## 목적
경계 진동을 막는다. **마지막에 둔다** — 4a~4c 로 자만 바꿔 놓고 「진동이 실제로 나는가」를
관측한 뒤 폭을 정한다. 지금 `h` 의 값 근거는 어디에도 없다.

## 변경 대상
- `Combat/TargetPersistence.cs:29` — **시그니처 변경 필수**: `KeepsLock(bool, int, int)` → 실수 gap + 히스테리시스
- 호출부 **3곳**: `AttackSystem:743` · `AttackSystem:881` · **`EnemyAiStateSystem:179`**
- 설정 검증(어설션)

## 구현
획득 `gap ≤ N`, 유지 `gap ≤ N + h`. **원칙: 「여기서 쏠 수 있나 · 멈춰도 되나」는 획득,
「이미 문 것을 놓나」는 유지.** 이동 정지 판정에 유지 임계를 쓰면 **적이 사거리 밖에서 멈춘다.**

| 지점 | 임계 |
|---|---|
| `AttackSystem:594` 타겟 선정 | 획득 |
| `AttackSystem:741·879` 락 유지 (+`KeepsLock`) | 유지 |
| `AttackSystem:925` committed 재판정 | 유지 |
| `EnemyAiStateSystem:200` `HasFireTarget` | 획득 |
| `EnemyAiStateSystem:176` 락 미러 | 유지 |
| `PatrolAreaMath.CloseInDir` | 획득 |
| `FlowFieldBuilder.CollectDefenderSources` | 획득 |
| `AllyBuffFieldSystem` 오라 멤버십 | 유지 |

⚠ **「장판」은 대상이 아니다.** 해저드 존 멤버십은 `ZoneApplySystem.cs:55` 의 **셀 해시 조회**라
거리 축이 없다 — 히스테리시스를 걸 대상 자체가 없다(비목표 「해저드 형상」과 같은 사유).

⚠ **`h` 는 코드 상수다.** `sceneKnobs`(`BattleBridge.cs:3303`)에 **등재하지 않는다** — 계약 9.
등재하면 `configHash` 가 움직여 골든 red 가 「조건 드리프트」로 읽히고, 계약 13 의 「관측 도구」
성격이 무너진다. 튜닝이 필요해지면 그건 SO 의 문제이고 이 spec 범위 밖이다.

⚠ **어설션 `프레임당 최대 변위 ≤ h` 는 폐기했다**(결정 5). `MovementCellTrim.cs:127` 의
`maxD = tileSize * 0.9f` 때문에 문자대로 지키면 **h ≥ 0.9** 가 되고, 사거리 1 의 유지 임계가
중심 거리 **2.4** 가 된다 — 지우려는 0.5 보다 **큰 슬랙**을 유지 축에만 비대칭으로 다시 넣는 것이고,
`target-persistence` **D2(2026-08-09 「즉시 해제」 확정)**가 없애려던 「지나쳐 갔는데 락을 붙들고
있는」 상태가 그만큼 돌아온다.

**대신 `h` 는 관측에서 나온다.** 4a·4b 로 자만 바꿔 놓고 경계에 적을 세워 **실제 진동 폭을 재고**,
그 폭을 덮는 최소값으로 정한다(밀어냄 지터 규모 ≈ 0.05 예상). 그래서 이 unit 이 마지막이다.

## 완료 기준
- [~] 4c 시점에 관측한 진동이 사라진다(경계에 적을 세워 프레임별 발사 연속성 확인).
- [x] `h` 의 근거가 문서에 남는다 — **측정한 진동 폭과 고른 값**(추정으로 정하지 않는다).
- [x] unit 0 미러가 **「같은 임계끼리 같은 답」**으로 초록.
- [x] 락이 늦게 풀려 깨지는 것이 없는지: 도발 해제·마스크 변경(`target-persistence` 계약) 회귀 확인.

### 진행 기록 — 완료 2026-08-31

**`h = 0.1` 칸. 추정이 아니라 측정에서 나왔다.**

계측을 코드로 심었다 — `RangePredicateMirrorTest` 가 「멈춘」 적(Engaging/Standoff)이 프레임마다
**실제로 얼마나 움직이는지**를 재서 로그로 남긴다. 멈춘 적은 정의상 자기 이동이 0이지만
밀어냄·분리가 위치를 미세하게 흔들고, **그 폭이 곧 사거리 경계에서 판정이 뒤집힐 수 있는 폭**이다.

| 실측(2026-08-31) | 값 |
|---|---|
| 1회차 | **0.047칸** |
| 2회차 | **0.051칸** |

한 표본에 딱 맞추지 않았다 — 두 번 재도 흔들리고, 지터는 밀집도에 따라 커진다(군집 통과).
`h = 0.1` 은 관측치의 약 2배이면서 **옛 슬랙 0.5 의 1/5** 이다. 사거리 1 의 유지 임계가
1.5 가 아니라 **1.1** 이라, `target-persistence` **D2**(「지나쳐 갔는데 락을 붙들고 있는」 상태
제거)를 사실상 되살리지 않는다.

**획득/유지 축이 함수로 갈렸다.** `TargetPersistence.KeepsLock` 이 히스테리시스를 소유하고
내부에서 `AttackReach.InReach(range + h)` 를 부른다 — 두 축이 **같은 술어**를 쓰되 임계만 다르다.
`AttackReach.InReach` 의 `tileRange` 가 `int`→`float` 이 된 것이 그래서다.

| 지점 | 임계 |
|---|---|
| `AttackSystem` 타겟 선정 · 어그로 sticky · 다중타격 2차 | 획득 |
| `AttackSystem` 적 focus 락 · frontmost 락 · 방어유닛 focus 락 · committed 재판정 | **유지** |
| `EnemyAiStateSystem` 락 미러 | **유지** |
| `EnemyAiStateSystem` guardianInRange · `HasFireTarget` · `HazardCastSystem` · `PatrolAreaMath` | 획득 |

⚠ **정지 판정(`guardianInRange`·`HasFireTarget`)에 유지 임계를 쓰지 않는다** — 쓰면
**적이 사거리 밖에서 멈춘다.**

부수 정리: 유지 지점 5곳이 `InReach`(몸 거리)와 `KeepsLock`(셀 체비셰프)을 **둘 다** 부르고
있었다. 두 자가 겹쳐 걸려 실질 임계가 「더 엄한 쪽」이었고, 이제 하나다.

성공 조건**이고 그대로 나왔다.

#### ⚠ 완료 기준 1 은 **부분 달성**이다 — 정직하게 남긴다

「관측한 진동이 사라진다」를 **직접 확인하지 못했다.** 카나리아가 보는 것은 「멈췄는데 안 쏨」
(교착)이지 「쏘다 말다 하는」(진동)이 아니다. 잰 것은 진동의 **원인**(위치 지터 0.047~0.051)이고,
`h` 가 그 폭을 덮는다는 것은 산술로 참이다. 하지만 「경계에 적을 세워 프레임별 발사 연속성을
눈으로 확인」은 안 했다 — 그건 사람 눈이 필요하고 unit 5(사거리 원 표시)가 그 도구를 만든다.

→ **unit 5 이후에 육안 확인 1회.** 그때 진동이 보이면 `h` 를 올릴 근거가 이 문서에 이미 있다.
