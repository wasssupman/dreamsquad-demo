# 21 — 몸 크기 저작 정합 (적 티어 채우기 + 배스티온 아트)

> unit 20 감사의 후속. 「그림자 = 그 유닛의 기준 크기」를 **저작 값**이 지키게 만든다.
> 코드 변경 0줄 — 전부 SO 저작이다. 사용자 승인 2026-09-04.

## 목적

unit 20 이 유닛 4경로의 배관(판정 몸 ↔ 그림자)이 1:1 임을 확인했다. 남은 어긋남은
배관이 아니라 **저작**이었다. 오프스크린 프리뷰로 스켈레톤을 실제로 세워 렌더 폭을 재보니
두 진영이 정반대로 어긋나 있었다.

| 대상 | 그림자(판정 몸) | 아트 폭 | |
|---|---|---|---|
| 방어유닛 2×2 (다수) | 2.0 | 1.06 | 그림자가 2배 |
| **배스티온 3×2** | 3.0 | 1.06 | 그림자가 2.8배 |
| 버스터즈 1×2 | 1.0 | 1.06 | 유일하게 맞음 |
| 적 잡몹 | 0.5 | 0.82 | 아트가 1.6배 |
| **드래곤 · 소용돌이 항아리 · 슬라임** | **0.5** | 1.44~2.00 | 아트가 **2.9~4.0배** |

## 변경 대상

- `Data/Enemies/Enemy_Dragon.asset` · `Enemy_Whirlpot.asset` · `Enemy_Slime.asset` — `bodySize` Small → **Medium**
- `Data/Defenders/Defender_Bastion.asset` — `spineVisualScale` 1.69 → **2.5**

## 구현

1. **적 티어는 저작된 적이 없었다.** `bodySize` 를 가진 에셋이 보스 3종뿐이고 나머지 21종은
   필드가 YAML 에 없어 로드 시 기본값 Small(0.25)이 됐다. unit 13 이 만든 티어표는
   **소비처가 0** 이었던 셈이다. 아트가 큰 셋(드래곤 2.00 · 항아리 1.91 · 슬라임 1.44)을
   중형(0.5 → 그림자 1칸)으로 올린다. 기존 적의 관례(그림자 ≈ 아트 폭 × 0.6)를 그대로 적용한 값이다.
   ⚠ 대형(1.0)은 계속 예약 — 첫 거대 적이 올 때 쓴다. 슬라임(중)은 아트 1.10 으로 경계라 Small 유지.
2. **아트 폭을 칸에 비례시키는 «규칙»은 채택하지 않는다.** 렌더로 시뮬레이션해 보니
   배스티온(×1.5)은 좋아지지만 버스터즈(×0.5)는 난쟁이가 된다 — 1칸 유닛은 이미 자기 칸을
   꽉 채우고 있어 줄일 여지가 없다. **파생식이 아니라 유닛별 저작 의도**로 둔다.
3. 배스티온만 개별 확대(아트 폭 1.06 → 1.57). 「3칸을 먹는 덩치」가 저작으로 읽히게 한다.
4. 시트는 이 두 필드를 모르므로(`UnitStatImportDto` 에 없음) 로비 임포트가 되돌리지 않는다.

## 알고 남기는 것

- 2×2 유닛의 「그림자가 캐릭터보다 넓다」는 **그대로 둔다.** 그림자 지름이 정확히 점유 칸
  폭이라 「이 유닛이 차지한 자리」로는 일관되고, 25종 아트를 일괄로 키우는 것은 이 unit 의 범위 밖.
- 순찰병(0.73)·소환수(1.33)는 다른 리그라 비율이 갈린다 — 소환물이라 배치 칸이 없어 후순위.
