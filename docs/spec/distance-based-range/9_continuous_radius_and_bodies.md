# 9 — 사거리를 연속 반지름으로, 오차 보정을 몸으로

> **사용자 결정 2026-09-01**: 시트의 `attackRange` 는 **타일 길이를 단위로 하는 연속 반지름**이다.
> `2` = 2칸 거리, `0.1` = 타일 길이의 0.1. 정수일 이유가 없다 — 명시적 인지를 위한 수치일 뿐이다.
> 그리고 **오차 인정 범위 없이** 각 오브젝트가 자기 중심 기준 커버 범위(`bodyRadius`)를 갖고
> 그 수치들의 계산 자체를 신뢰한다.

## 목적

두 가지를 없앤다.

1. **양자화** — `GridMath.RangeToTiles(r) => (int)(r + 0.5f)` 가 `0.1 → 0`, `2.5 → 3`.
   시트 DTO부터 SO까지 **이미 전부 `float`** 이고 연속값을 죽이는 건 이 함수 하나다.
2. **상수 `SelfBodyRadiusTiles = 0.5`** — 원래 이름이 `CellSlackTiles` 였다. 「적이 그 칸
   어딘가에 있는데 어디인지 모른다」는 **타일 시절의 오차 보정**이고, 연속 좌표에선 덮을
   불확실성이 없다.

**지금이 유일하게 공짜인 시점이다** — 저작값이 전부 정수(방어유닛 1~5, 적 전부 정수)라
양자화 제거로 밸런스가 하나도 안 움직인다. 소수를 저작한 뒤엔 공짜가 아니다.

## 값이 틀린 게 아니라 자리가 틀렸다

unit 6 이 보스 몸을 유도한 공식이 `bodyRadius = 0.5 × (배율/1.3 − 1)` 이다.
**저 `0.5` 가 「일반 유닛의 몸 반지름」으로 이미 가정돼 있다** — 짱쎈(2.00배)은 `0.50` 이
저작됐고 상수를 더하면 총 `1.00 = 0.5 × 2.00`. 마메모·나이트메어도 정확히 맞는다.

즉 기존 보스 3종 값은 **상수 위에 얹은 증분**이다. 상수의 문제는 셋:
하드코딩 · 공격자 전용 · 대상 몸이 51종 중 3종만 저작.

## 계약 (기존 계약 2 를 개정한다)

- **판정**: `거리(중심, 중심) ≤ 사거리 + 내 bodyRadius + 상대 bodyRadius`
- **`b` = 0.25** (사용자 결정). 일반끼리 도달 = `사거리 + 0.5` = **오늘과 동일**.
  보스는 `0.25 × 배수` 로 재기준 — 짱쎈 0.50 / 마메모 0.558 / 나이트메어 0.615.
- ⚠ **보스는 어느 값을 골라도 조금 움직인다.** 오늘 공식이 비대칭(공격자 항상 0.5,
  대상 0 또는 저작)이라 「일반끼리 중립」과 「대보스 중립」을 동시에 만족하는 `b` 가 없다.
  사거리 1 유닛의 대나이트메어 허용거리 **2.23 → 1.87칸**.
- ~~계약 2 「저작은 타일 정수 유지」~~ → **폐기.** 저작은 연속 실수다.

## 소비처 분류 (`RangeToTiles` 24곳)

| | 무엇 | 처리 |
|---|---|---|
| **A. 판정** | `AttackSystem:504·326` · `EnemyAiStateSystem:86` · `HazardCastSystem:110` | **raw float** |
| **B. 격자 루프** | BFS 소스 3곳(어그로·사냥·순찰) + 소환사 순찰 **박스**(`AttackSystem:446`) | int 유지, **`ceil`** |
| **C. 표기** | 링·프리뷰·방향조준 (`BattleBridge` 4곳 · `DirectionAimController:138`) | 판정 따라감 |
| **D. 스킬 광역** | `RangeMetric.Chebyshev` 계열 11곳 | **별개 축 — 유지** |

⚠ **B 는 `round` 가 아니라 `ceil` 이다.** `round` 면 사거리 2.4 → 2 로 **덜 덮어** 쏠 수 있는
칸이 소스에서 빠지고 적이 더 멀리서 멈춘다. `ceil` 이면 넘치게 덮고, **넘친 부분은 unit 4c 의
접근 보정이 흡수한다** — 순서가 맞다(4c 가 먼저 들어갔다).

⚠ **D 를 이름으로 가른다.** `SkillData.range` 는 「칸 수」(체비셰프 사각형)이고 `attackRange` 는
「타일 길이 반지름」인데 **같은 함수를 쓴다.** 뜻이 다른 둘이 한 함수를 공유하는 게 혼동의 원천이다.

## 후속 후보 (이 unit 밖)

- 폭탄맨 본공격의 체비셰프 반경 게이트(`NearestTargeting:50`) 수렴 — 연속 반지름 전제에서
  정사각형 게이트가 더 못 버틴다. 지금도 **링이 폭탄맨에 대해 거짓말한다.**
- 사냥 레인 목표 선택이 사격 가능성 필터(`targetMask`·통행층·`classMask`)를 안 지난다 —
  소스 수집도 같아서 선재 결함의 상속이다. `DefenderFieldSystem` 과 함께 맞춘다.
- stale 추격 필드 + 이동 가디언 → 옛 디스크 가장자리 정지. `aggroCapacity > 0` 인
  이동 유닛 저작 한 줄이면 켜진다.
