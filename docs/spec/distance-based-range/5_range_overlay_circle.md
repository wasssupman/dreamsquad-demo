# 5 — 표기: 채움과 윤곽

## 목적

**표기를 판정에 맞춘다.** 안 하면 「밝은 칸인데 가끔 안 때린다」가 되고, 그게 가장 나쁜 종류의
버그다. unit 4 와 **같이 검증**한다 — 4만 하고 멈추면 화면이 거짓말하는 구간이 생긴다.

부수 이득: 반경에서 VFX 크기를 뽑는 **5곳 전부**가 지금 「정사각 반경 r」을 「원 반지름 r」로
읽는다(해저드 장판·회오리·메테오·방향 탄·스킬 후보). 자를 바꾸면 그 환산들이 **처음으로 참말**이 된다.

## 구현

**언어를 둘로 가른다** — 색이 아니라 **형태**로.

- **채움 = 놓을 수 있나 없나.** 내 자리 · 남의 자리 · 못 놓는 지형이 한 질문의 답이므로 한 언어를 쓴다.
- **윤곽 = 어디까지 닿나.** 안을 안 칠하므로 어떤 채움과도 안 섞인다. 펄스를 독점한다.

지금 채움은 **네 뜻을 겸직**하고 그중 둘이 같은 빨강이다(내 자리 충돌 α.6 / 못 놓는 지형 α.3).
→ **지형 불가를 무채색으로 내린다.** 「이 땅은 원래 못 놓는다」는 판의 **정적 사실**이고
「지금 네 배치가 충돌한다」는 **네 행동에 대한 응답**이다. 정적 사실은 조용해야 한다.

**무효일 때는 footprint 가 빨강으로 말하고 링은 채도만 낮춘다** — 2026-08-28 결정의 계승
(링을 붉히면 「왜 안 되는지」와 「어디까지 닿는지」가 한 색에 겹친다).

**링은 원이 아니라 둥근 사각형**이다(footprint 를 사거리만큼 부풀린 형태). 1×1 이면 거의 원이고,
multi-cell 이면 몸 모양을 따라간다 — 그게 판정이다.

**되밟지 말 것 3가지**
1. 그리드가 `Euler(90,0,0)` 이라 `plane.normal` 은 **아래**를 향한다(리프트는 월드 +Y).
2. 바닥 높이는 스테이지가 선언한다(StreetDay 만 0.87) — 절대 상수를 쓰면 파묻힌다.
   정본은 `BoardSpace.RaycastPlane().ClosestPointOnPlane(p).y`.
3. **정렬 3티어 상승 규칙에 편입**한다. 빠뜨린 타일맵이 `−13` 에 굳는 사고가 이미 있었다
   (궁극기 예고). 밀집 전투 중 적 뒤에 깔리면 이 표시가 가장 필요한 순간에 안 보인다.

**아웃라인 스프라이트에는 다크 라이너가 구워져 있다**(밝은 배치 칸 위에서 살아남게).
링에도 같은 처리가 필요하다. **URP Decal 금지** — 렌더러 피처가 패스를 늘려 모바일에서 비싸다.

**방향 지정 유닛은 링을 안 쓴다.** 지금도 네모 사거리를 안 그리고 4레인 십자를 흐리게 그린다
(«방향 유닛에게 네모 사거리는 거짓말이다 — 레인만 때린다»). 레인은 폭 0 정수 격자 술어라
거리로 옮길 수 없다(비목표). 현재 해당 유닛은 머신거너 1종.

## 파이프라인 — 가장 가까운 아키타입은 「예고 오버레이」다

`docs/reference/object-pipeline-map.md` 의 **예고 오버레이(스폰 라인)** 행이 정본이다
(그 절이 「새 예고류는 이 표를 기준으로 삼는다」고 직접 지시한다). 방어유닛/적 아키타입이 아니다.

| 정거장 | 이 링의 처분 |
|---|---|
| **트리거** | 폴링 — 배치 세션이 매 프레임 앵커를 먹인다(판정과 **같은 함수**에서 반경을 뽑는다) |
| **정렬** | ⚠ `BoardSortOrder` 에 **새 상수가 필요**하다. 현행 상승 스위치는 `TilemapMapView.SetHighlightAbove` 의 **타일맵 렌더러 3장 전용**이고 링은 `SpriteRenderer` 라 대상이 아니다 — **4번째 렌더러를 그 스위치에 추가**한다 |
| **씬 wiring** | 신규 `Presentation/` 컴포넌트를 브리지가 잡는 방식(SerializeField / 풀 / 뷰 자식)을 정한다. `unity-feature-wiring` 스킬 대상 — 사용자 수작업으로 미루지 않는다 |
| 저작 SO | 스프라이트 1장 + 다크 라이너 |
| 스폰·bake · ECS 컴포넌트 · 채널 | **N/A** — 엔티티도 시스템도 만들지 않는다 |
