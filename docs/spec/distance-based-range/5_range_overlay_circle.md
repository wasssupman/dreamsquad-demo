# 5 — 표기: 채움과 윤곽

## 목적

**표기를 판정에 맞춘다.** 안 하면 「밝은 칸인데 가끔 안 때린다」가 되고, 그게 가장 나쁜 종류의
버그다. unit 4 와 **같이 검증**한다 — 4만 하고 멈추면 화면이 거짓말하는 구간이 생긴다.

부수 이득: 반경에서 VFX 크기를 뽑는 **5곳 전부**가 지금 「정사각 반경 r」을 「원 반지름 r」로
읽는다(해저드 장판·회오리·메테오·방향 탄·스킬 후보). 자를 바꾸면 그 환산들이 **처음으로 참말**이 된다.

## 구현

**언어를 둘로 가른다** — 색이 아니라 **형태**로.

- **채움 = 놓을 수 있나 없나.** 내 자리 · 남의 자리 · 못 놓는 지형이 한 질문의 답이므로 한 언어를 쓴다.
- **윤곽 = 어디까지 닿나.** 안을 안 칠하므로 어떤 채움과도 안 섞인다. 펄스를 독점한다.

지금 채움은 **네 뜻을 겸직**하고 그중 둘이 같은 빨강이다(내 자리 충돌 α.6 / 못 놓는 지형 α.3).
→ **지형 불가를 무채색으로 내린다.** 「이 땅은 원래 못 놓는다」는 판의 **정적 사실**이고
「지금 네 배치가 충돌한다」는 **네 행동에 대한 응답**이다. 정적 사실은 조용해야 한다.

**무효일 때는 footprint 가 빨강으로 말하고 링은 채도만 낮춘다** — 2026-08-28 결정의 계승
(링을 붉히면 「왜 안 되는지」와 「어디까지 닿는지」가 한 색에 겹친다).

**링은 원이 아니라 둥근 사각형**이다(footprint 를 사거리만큼 부풀린 형태). 1×1 이면 거의 원이고,
multi-cell 이면 몸 모양을 따라간다 — 그게 판정이다.

**되밟지 말 것 3가지**
1. 그리드가 `Euler(90,0,0)` 이라 `plane.normal` 은 **아래**를 향한다(리프트는 월드 +Y).
2. 바닥 높이는 스테이지가 선언한다(StreetDay 만 0.87) — 절대 상수를 쓰면 파묻힌다.
   정본은 `BoardSpace.RaycastPlane().ClosestPointOnPlane(p).y`.
3. **정렬 3티어 상승 규칙에 편입**한다. 빠뜨린 타일맵이 `−13` 에 굳는 사고가 이미 있었다
   (궁극기 예고). 밀집 전투 중 적 뒤에 깔리면 이 표시가 가장 필요한 순간에 안 보인다.

**아웃라인 스프라이트에는 다크 라이너가 구워져 있다**(밝은 배치 칸 위에서 살아남게).
링에도 같은 처리가 필요하다. **URP Decal 금지** — 렌더러 피처가 패스를 늘려 모바일에서 비싸다.

**방향 지정 유닛은 링을 안 쓴다.** 지금도 네모 사거리를 안 그리고 4레인 십자를 흐리게 그린다
(«방향 유닛에게 네모 사거리는 거짓말이다 — 레인만 때린다»). 레인은 폭 0 정수 격자 술어라
거리로 옮길 수 없다(비목표). 현재 해당 유닛은 머신거너 1종.

### 진행 기록 — **채움만 완료** 2026-08-31 (윤곽/링은 미착수)

이 unit 을 둘로 갈랐다. **먼저 급한 절반만 했다.**

#### 왜 나눴나 — 화면이 이미 거짓말하고 있었다

unit 4a 로 사거리가 둥글어진 순간부터 **프리뷰는 정사각형을 칠하고 있었다.** 사거리 3 캐논이면
네 모서리 칸이 밝게 켜지는데 그 칸의 적은 안 맞는다. 이 unit 의 목적 문장이 경고한
「밝은 칸인데 가끔 안 때린다」가 **unit 4a 시점부터 실재했다.** 링을 만드는 동안 그대로 둘 수 없다.

#### 한 것 — 칠하는 칸이 판정에서 나온다

`TilemapMapView.SetPlacementRange` 가 `dx,dz` 이중 루프로 모양을 그리던 것을
`AttackReach.InCellReach` 로 거른다. 그 함수는 `SkillMath.InBodyReach` — **판정과 같은 본체**다.
프리뷰가 모양을 **다시 그리지 않는다**(완료 기준 1).

실측(Play, 캐논 사거리 3, 격자 한가운데):

```
옛 정사각형 48칸          새 모양 44칸
#######                  .#####.
#######                  #######
#######                  #######
###+###        →         ###+###
#######                  #######
#######                  #######
#######                  .#####.
```

네 모서리만 잘린다 — `(3,3)` 은 v=(2.5,2.5)=3.54 > 3, `(3,2)` 는 v=2.92 ≤ 3 으로 남는다.
스크린샷: `Assets/Screenshots/dbr_unit5_range_preview.png`(비추적 스크래치).

**스킬 조준·텔레그래프만 정사각형을 유지한다**(`squareShape: true`). 거짓말이 아니라 **사실**이다 —
스킬 광역의 멤버십이 `TileAoe.IsInTileRange`(정사각형)로 남아 있다(결정 4, 저작이 칸 단위 조준).
표기가 그 자를 따라가는 것이 맞다. 두 경로가 실제로 갈리는 것을 Play 에서 확인했다(49칸 vs 45칸).

#### 안 한 것 — 윤곽(링)과 채움 언어 재설계

남은 절반은 **구현이 아니라 디자인 결정**이 앞선다:
- 채움/윤곽으로 **언어를 가르는 것**(색이 아니라 형태로)
- **지형 불가를 무채색으로 내리는 것** — 지금 채움이 네 뜻을 겸직하고 그중 둘이 같은 빨강이다
- 링 = 둥근 사각형(footprint 를 사거리만큼 부풀린 형태) + 다크 라이너 + 정렬 4번째 렌더러 편입

이 셋은 화면을 보고 정해야 하고 완료 기준도 **실기기 스크린샷·Play 육안**이다. 위 채움 수정으로
「거짓말」은 닫혔으므로 **급하지 않다.** 사용자 확인 후 진행한다.

### 설계 확정 — 2026-08-31 (사용자 승인, 조건부)

제안한 「채움/윤곽 분리」로 간다. **사용자 조건 5가지가 계약이다:**

1. **사거리 채움을 옅게 남긴다(α .12 초기값).** 완전 제거는 안 한다 — 사거리 5면 링 지름이
   11칸이라 밀집 전투에서 선이 유닛·프랍에 끊기는 것이 확실하고, 그때 **정보가 0이 된다.**
   채움은 선이 끊겨도 영역을 남기는 **보험**이다.
2. **채움 색은 링과 같은 라임 계열, 알파만 낮춘다.** 시안(고스트 valid)·노랑(점유)·무채색(지형)과
   **색상 자체가 달라야** 채움 두 겹 문제가 재발하지 않는다. 알파들은 외부화해 실기기에서 조정.
3. ⚠ **링·채움 모두 유닛 아래(바닥 대역).** 선을 유닛 위로 올려 끊김을 피하는 방식은 **금지** —
   세계에 그린 도형이 스프라이트를 관통하면 **UI 오버레이로 읽혀 물성이 깨진다.**
   **끊김은 채움으로 흡수하지 정렬로 피하지 않는다.** `SetPlacementHighlightAboveUnits` 등록은
   그대로 한다(빠뜨린 렌더러가 −13 에 굳는 사고 방지 — 궁극기 예고 선례).
4. **SDF 셰이더는 처음부터 `half-extent` 를 받는다.** 오늘 전 유닛이 1×1 이라도 R 하나짜리 원
   셰이더로 만들면 다칸 유닛에서 재작업이다. 판정식 `max(|Δ| − half, 0) ≤ R` 과 셰이더 파라미터가
   **1:1** 이어야 「근사가 아니라 판정의 경계 그 자체」라는 말이 계속 참이다.
5. **무효 시 링은 채도만 낮춘다.** 빨강은 **고스트 충돌 전용**이라는 원칙과 정합.

**방향 지정 유닛(레인 십자)은 이 SDF 에 끼워 넣지 않는다** — 별도 형태로 남긴다(스코프 밖).

### 진행 기록 — 커밋 2(링) 완료 2026-08-31

**셰이더가 판정식 그 자체다.**

```
sim:      length(max(|Δ| − half, 0)) ≤ range
셰이더:   sdRoundedBox(p, _HalfExtent, _Range) ≤ 0
          sdRoundedBox = length(max(|p| − b, 0)) + min(max(q.x,q.y),0) − r
```

둘은 **같은 식**이다 — 둥근사각 SDF 의 정의가 그러하기 때문이고, 내부 항
`min(max(q.x,q.y),0)` 은 상자 **안쪽** 거리를 채울 뿐 경계(=0)에 기여하지 않는다.
`_HalfExtent`·`_Range` 는 저작 값이 아니라 **판정 입력의 복사본**이고, 호출부가 사거리 술어에
넣는 값(`SkillMath.SelfHalfWidthTiles`, `tileRange`)을 그대로 넣는다. 다칸 유닛이 들어와도
저작만 바뀌고 셰이더는 그대로다(사용자 조건 4).

| 항목 | 값 |
|---|---|
| 셰이더 | `Assets/_Project/Shaders/PlacementRangeRing.shader` — SDF, 다크 라이너 내장(선 **바깥**에만) |
| 머티리얼 | `Data/TileSets/PlacementRangeRing.mat` → `TileSetData.placementRangeRingMaterial` (2개 tileSet 배선) |
| 컴포넌트 | `TilemapMapView` 안, 액체 하이라이트와 **같은 관용구**(grid 자식 절차적 쿼드 + 인스턴스 머티리얼) |
| 정렬 | `BoardSortOrder.RangeRingOrder = -8` — 범위 타일(−12)·고스트(−11)·overlay(−10) **위**, 그림자(−5)·유닛 **아래** |
| 쿼드 | `RingQuadCells = 14` 고정(사거리마다 안 키운다 — 셰이더 uv→타일 매핑의 단일 소스) |

**정렬 스위치 등록 — 두 분기가 같은 값이다.** 드래그 중에도 유닛 위로 안 올라간다(조건 3).
그럼에도 목록에 있는 이유는 빠뜨린 렌더러가 옛 값에 굳는 사고 방지다(궁극기 예고 선례).

**링을 안 띄우는 두 경로**: 스킬 조준·텔레그래프(`squareShape` — 그쪽 자가 정사각형이라 링이
거짓말이 된다) · 방향 지정 유닛의 레인 십자(`SetPlacementCells` — 레인은 폭 0 격자 술어라
거리로 옮길 수 없다, 스코프 밖).

#### ⚠ 실측으로 잡은 버그 — `GetCellCenterLocal` 이 링을 0.5 유닛 띄웠다

첫 구현이 `grid.GetCellCenterLocal(cell)` 을 썼는데 그건 **z 에 0.5(셀 중심)를 넣는다.**
부모가 90°X 회전이라 local −Z = world +Y 이므로, 링이 보드에서 **0.5 유닛 뜬 채** 그려졌고
55° 카메라에서 타일과 눈에 띄게 어긋났다. 형제(확정 팝·액체)와 같은 관용구
(`CellToLocalInterpolated` + `local.z = -PropGroundLift`)로 고쳤다.
수치 검증: `ring.localPosition = (12.50, 4.50, -0.02)` · `localScale = 14` · `_HalfExtent = (0.5,0.5)` ·
`_Range = 5` · `_QuadCells = 14`.

#### 남은 판단거리 — 채움이 링 밖으로 삐져나온다

켜진 칸은 **중심**이 술어를 통과한 칸이고, 칸은 한 변 1의 사각형이라 **모서리가 링 밖으로
최대 ~0.66칸 나간다**(사거리 5 기준). 규칙은 일치하는데 그림이 어긋나 보인다.

⚠ **둘 중 링이 더 정확하다.** 적은 점(transform 위치)이므로 「저기 서면 맞나」의 참값은
링이고, 칸 채움은 그 참값을 칸 단위로 양자화한 근사다. 채움이 α.12 로 내려가면(커밋 3)
삐져나옴도 옅어지지만 **사라지지는 않는다.** 받아들일지 판단 필요.

### 진행 기록 — 커밋 3(채움→윤곽 전환 + 예외 철거) 완료 2026-08-31

**채움 알파는 「링이 있느냐」가 정한다.** 새 저작 필드 둘(`TileSetData`):

| 필드 | 초기값 | 뜻 |
|---|---|---|
| `rangeFillAlphaUnderRing` | **0.12** | 링이 떠 있을 때의 채움 알파 = **보험** |
| `rangeRingAlpha` | 0.95 | 링(선)의 알파. 색상은 `rangeColor` 를 그대로 쓴다 |

⚠ **링이 없는 경로는 이 값을 안 쓴다** — 스킬 조준·텔레그래프·방향 레인은 채움이 **유일한
신호**라 `rangePulseMaxAlpha`(0.85) 그대로다. 링 유무로 갈리는 이 분기가 없으면 스킬 조준이
같이 흐려져 안 보인다.

**링 색을 `rangeColor` 에서 끌어온다** — 셰이더 기본값에 맡기면 선과 채움이 조용히 갈린다
(사용자 조건 2: 같은 라임이어야 시안·노랑·무채색과 색상으로 갈린다).

**정렬 — 채움도 바닥에 내려왔다.** `_rangeTilemap` 이 드래그 중 10000 으로 뜨던 것을
**두 분기 모두 −12** 로 고정했다(사용자 조건 3). 그 상승은 `placement-enemy-see-through` unit 6 이
「적 빌보드를 뚫고 보이게」 넣은 것인데, **그 역할은 이제 링이 감당하고 링의 끊김은 채움이
흡수한다.** 정렬로 피하지 않는다.

#### 2026-08-28 예외 철거 — 증상 대응이었음이 드러났다

「사거리 칸 위에서는 전역 불가 표시를 양보한다」는 규칙을 지웠다. 그 예외의 진짜 이유는
**채움 두 겹이 같은 픽셀을 놓고 싸웠기 때문**이다 — 진한 초록 위에 빨강/노랑이 얹히면
사거리 읽기가 흐려지니 하나를 껐던 것이다. 지금은 사거리가 **선 + 옅은 채움**이라 겹칠
픽셀이 없다. **되살리지 말 것** — 되살리면 사거리 안의 못 놓는 땅이 다시 안 보인다.

#### 지형 무채색 — **밝은 쪽으로 뒤집었다**(커밋 1 값 폐기)

커밋 1 의 `(0.12, 0.12, 0.15) α.38` 은 **실패였다.** 링이 생긴 배경에서 다시 보니 원인이
분명해졌다: 아스팔트는 크랙·그림자로 명도가 이미 요동치는 표면이라 **어둡게 덮는 신호는
그 노이즈에 묻힌다.** 가장 큰 불가 영역인 **웅덩이 위에서는 완전히 사라졌다**(어두운 아트 +
어두운 덮개).

옛 빨강이 통했던 건 명도가 아니라 **색상**으로 말했기 때문이다. 무채색으로 같은 분리를
얻으려면 **밝은 쪽**이어야 한다 → `(0.80, 0.84, 0.90) α.40`.

**「조용함」은 밝기가 아니라 채도에서 온다** — 채도 0 이면 아무리 밝아도 «정보»가 아니라
«재질»로 읽힌다. 「덮인 땅」이지 「위험」이 아니다.
