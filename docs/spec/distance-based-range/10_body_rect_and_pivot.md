# 10 — 몸을 사각형으로, 중심을 피봇으로 (계약 1 이행)

> **이 unit 은 새 방향이 아니다.** README **사용자 확정 결정 1**(2026-08-31)이 이미
> 「사거리를 중심점이 아니라 **footprint 가장자리**에서 잰다」고 못박았고, 그 문장이
> 오늘의 증상을 예측까지 했다 — 「대표 셀은 짝수 변의 대표가 어느 칸이냐를 정수 나눗셈으로
> 정한 **동전 던지기**이고, 플레이어에겐 안 보이는데 **사거리를 반 칸 옮긴다**」.
> 캐논을 2×3 으로 켜자 그대로 드러났다. 여기는 그 미이행분이다.

## 사용자 결정 (2026-09-01)

1. **`defender-footprint` 결정 1(sim 무변)을 폐기한다.** 후행 결정이 이긴다.
2. **사직서 드랍 = 피봇**(기하 중심).
3. **픽업·버프장 멤버십 = 유클리드 거리.** 셀 대조를 은퇴한다.
4. 방향 레인은 별건으로 은퇴 — `11_facing_retirement.md`.

## 왜 「중심 이동」만으로는 반쪽인가

세 개가 따로 고장나 있다(코드 확인):
- **중심** — sim 위치가 대표 셀, 스프라이트는 기하 중심 → 짝수 변에서 반 칸 어긋남
- **모양** — `SkillMath.SelfHalfExtentTiles` 가 컴파일 타임 상수 `0`, rect 오버로드 **호출부 0**
- **대상측** — `HitRadius` 는 스칼라 원. 적이 2×3 을 때릴 때도 점이다

중심만 옮기면 「링은 실루엣에 맞는데 몸은 점」이 된다 — 이 코드베이스가 최악으로 규정한
「화면이 규칙을 틀리게 가르친다」 부류다. 그래서 **저작 재개는 PR2 뒤로 게이트한다.**

## PR1 — 좌표계 (시뮬 출력 0 diff)

저장값을 **앵커(좌하단 셀) + W×H** 로 바꾸고 나머지를 파생시킨다.

⚠ 앵커는 **셀 인덱스**다(셀 N 의 중심이 정수 N, `WorldToCell = floor(x+0.5)`).
따라서 **기하 중심 = 앵커 + (W−1)/2** 이지 `W/2` 가 아니다. 1×1 → +0, 2 → +0.5, 3 → +1.
1×1 이면 앵커 = 대표 셀 = 기하 중심이라 **골든이 안 움직인다** — 좌표계를 초록인 채로
갈아끼울 수 있는 유일한 창이다(오늘 저작이 전부 1×1).

**전수 조사는 3중이다.** 컴파일러만으로는 부족하다:
| 조사 | 대상 | 방법 |
|---|---:|---|
| ① `FootprintMath.PrimaryCell` 계열 | 12곳 | `[Obsolete(error:true)]` — 단일 asmdef·리플렉션 0 이라 성립 |
| ② `DefenderTile.cell` | 8곳 | grep (잔존 정당 소비처가 있어 Obsolete 불가) |
| ③ **방어유닛 위치 → 셀 역양자화** | ~14곳 | grep. **①이 시야 밖** — `FootprintMath` 를 안 지난다 |

③이 진짜 지뢰밭이다. 짝수 변 중심은 셀 경계 위라 **어느 칸이 나오는지를 설계가 아니라
부동소수점이 정한다**(결정론은 유지되나 자의적 — README 가 「동전 던지기」라 부른 그 병).

**소비처 4분류**
- ㉮ **정체성 키** → 앵커로 교체. 바인딩·`ReleaseDefenderTile`·재배치 스왑·반납
- ㉯ **점유 rect 를 셀 하나로 묻는 곳** → rect 질문으로. `EffectSpawner:258` 해저드 배치 거절은
  **실재 결함**이다(다칸이면 대표 셀 아닌 점유 칸에 해저드가 선다)
- ㉰ **제품 결정** → 위 결정 2·3 적용
- ㉱ **역양자화** → PR2 에서 전건 재판정

## PR2 — 몸 (판정 변경)

**구조물 선례로 수렴한다.** 본능(3×3)이 이미 `OccupiedCellsBuffer` 로 「나는 이 칸들을
차지한다」를 sim 1급으로 선언하고 `AttackSystem.DistanceSqToTarget` 이 **최근접 점유 칸**으로
잰다. 어휘가 다 있다 — 다만 README:155 가 자인하듯 그 값은 **랭킹에만** 쓰이고 **게이트는
중심 셀**이라 갈려 있다. 방어유닛에 같은 버퍼를 붙이면 「들어오는 몸」이 거의 공짜고,
게이트와 랭킹이 **같은 몸**을 보게 되어 그 갈림이 닫힌다.

- 방어유닛에 `OccupiedCellsBuffer` 부착 + `LocalTransform` = 기하 중심
- `SkillMath` 반폭을 **2축**으로(비정사각). 스칼라 하나면 2×3 을 3×3 으로 오독한다
- 링 API 를 `float` 중심 + 비대칭 extent 로. ⚠ **셰이더는 이미 지원한다** — `_HalfExtent(0.5,1.0)`
  오프스크린 렌더로 세로로 긴 둥근 사각형 확인(2026-09-01)
- ㉱ ~14곳을 rect 질문 또는 지정 셀로 재판정

### 역양자화 처분 (PR2)

`AnchorCellOf` 하나로 수렴시켰다 — 「이 유닛은 어느 칸에 있나」의 **유일한 답**이고,
`DefenderFootprint` 가 있으면 **저장된 앵커**를, 없으면 `WorldToCell(pos)` 를 준다.
sim 위치가 기하 중심이라 짝수 변에서는 그 점이 **셀 경계** 위이고, 거기에 `WorldToCell` 을
걸면 어느 칸이 나올지를 **설계가 아니라 부동소수점이 정한다** — 은퇴시킨 대표 셀과 같은 병이다.

| 지점 | 무엇 | 처분 |
|---|---|---|
| `AttackSystem:507` `atkCell` | 레인·폴백 후보·박스의 기준 칸 | **앵커** |
| `AttackSystem:445` `sCell` | 소환사 순찰 박스 중심 | **앵커** |
| `AttackSystem:321` `bCasterCell` | 폭탄맨 자기 칸 | **앵커** |
| `AttackSystem:254` `casterCell` | 해저드 캐스트 — `castEvt.casterPos` 로 오므로 엔티티가 없다 | 후속 |
| `ProjectileEmitterSystem:88·126` | 융단폭격 풀 · 패턴 스코프 | 후속 |
| `ProjectileHitSystem:696` · `BounceRetarget:56` | **착탄점**이지 유닛 칸이 아니다 | 해당 없음 |
| `ProjectileEmitterSystem` 방향 레인 | — | **unit 11 에서 은퇴** |

⚠ 「앵커는 유닛이 서 있는 칸이 아니라 **정체성 키**」라는 것이 이 함수의 계약이다.
몸 전체가 필요한 질문(겹침·광역)은 셀 하나가 아니라 `FootprintMath.Cells` 로 가야 한다.
