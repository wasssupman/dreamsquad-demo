# unit 13 — 상태별 피사계 심도(DoF)

## 목적

흐림을 **"지금 무엇을 보라는 신호"** 로 쓴다. 두 상태의 주인공이 다르므로 흐림도 달라야 한다.

| 상태 | 주인공 | 흐림이 해야 할 일 |
|---|---|---|
| 배치 | 판 전체 (어디에 놓을지 고른다) | **끈다.** 뒷줄이 흐려지면 배치할 칸이 안 보인다 |
| 전투 | 판 위의 싸움 | 보드 뒤 원경을 빼서 판을 도드라지게 (현행 계승) |

지금은 전역 값 한 벌(`dofBlurStartT` 0.6 / `dofBlurEndT` 0.88)을 두 상황에 똑같이 쓴다.
70° 탑다운인 배치에서 이 값은 **판 뒷줄을 흐려 배치를 방해**한다.

## 변경 대상

- `Assets/_Project/Scripts/Data/CameraDirectionConfig.cs` — 레시피에 DoF 항목 추가, 전역 `dofBlurStartT/EndT` 은퇴
- `Assets/_Project/Scripts/Presentation/CameraDirector.cs` — 상태/전환 구동

## 구현

레시피에 붙는 항목: `dofEnabled` · `dofStart` · `dofEnd` · `dofMaxRadius`.

기준은 **보드 깊이 정규화 하나뿐**이다(0 = 보드 앞단, 1 = 뒷단, 1 초과 = 보드 뒤). 기존
`CameraFramingMath.DofRange` 를 그대로 쓴다 — 화면비가 바뀌어도 같은 그림이 나온다(unit 9 의
성과). **대상 기준(카메라~대상 거리) 축은 만들지 않는다** — 두 상태 모두 판을 보고 있어
소비자가 없다. 유닛 하나에 붙는 흐림이 필요해지면 그때 축을 늘린다.

**끄는 법**: 반경 0 으로는 안 꺼진다. `DepthOfField.IsActive()` 가 반경을 보지 않고 `mode` 만
보기 때문에(URP `Runtime/Overrides/DepthOfField.cs`) 배치 내내 **풀스크린 Gaussian 패스가
반경 0 으로 계속 돈다** — 안드로이드 타겟에서 그냥 버리는 비용이다. 그래서 **반경을 최소로
램프다운한 뒤 전환이 끝난 프레임에 `mode` 를 Off** 로 내린다. 전환 중에 끄면 팝이 나므로
**끄는 시점은 반드시 전환 종료 후**이고, 켜는 시점은 전환 시작 전이다.

**전환 중 블렌딩**: 각 상태의 DoF 를 **절대 3쌍(start, end, maxRadius)** 으로 먼저 푼 뒤,
포즈와 **같은 진행도 t** 로 섞는다. 포즈와 다른 시계를 쓰면 카메라는 도착했는데 흐림이
아직 따라오는 어긋남이 생긴다 — **반드시 같은 t**.

**쓰기 비용은 계약으로 올리지 않는다.** float 2개 `Override` 를 아끼려고 dirty 추적을 명세에
박는 것은, 바로 위에서 풀스크린 블러 패스를 통째로 낭비하던 것과 비용 감각이 뒤집힌 일이다.
포즈 쪽 `_settled` 아이들 최적화가 이미 있고 DoF 는 그 판정에 얹혀 가면 된다.

## 이 모드의 한계 (반드시 알고 저작할 것)

1. **`gaussianMaxRadius` 의 저작 범위는 0.5~1.5 다** (`ClampedFloatParameter(1, 0.5, 1.5)`).
   0 이나 2.0 은 인스펙터로 저작·미리보기가 안 된다(`Override` 는 `m_Value` 직접 대입이라
   런타임 반영만 된다). **세기는 그 범위 안에서만 저작하고, 차이는 `dofStart`/`dofEnd` 범위로 낸다.**
2. **흐림 세기는 해상도에 비례한다.** 실제 반경 = `dofMaxRadius × (화면높이/2 ÷ 1080)`, 상한 2.
   에디터 게임뷰에서 잡은 세기가 폰에서 다르게 보인다 — **실기 확인 필수**(화면비가 저작을
   무너뜨린 unit 9 와 같은 계열의 함정이고, 이번엔 축이 해상도다).
3. **URP Gaussian DoF 는 원경 전용이다.** `DepthOfFieldGaussianPostProcessPass.cs` 가
   `gaussianStart` 를 `farStart` 로 받는다 — 대상 **앞**은 흐릴 수 없다. Bokeh 로 바꾸면
   `focusDistance`/`aperture` 체계라 저작이 통째로 달라진다 — **모드 전환은 범위 밖.**
4. `Volume.profile` 은 sharedProfile 의 런타임 인스턴스라 에디터 Play 에서도 디스크에 남지
   않는다(기존 계약 계승). 모드가 Gaussian 이 아니면 조용히 skip(기존 가드 계승).

## 완료 기준

- 배치에서 판 뒷줄 타일이 **또렷하다**(현행 값에서는 흐려진다 — 이 유닛의 존재 이유).
- 배치에 정착한 뒤 DoF `mode` 가 실제로 Off 다(프레임 디버거로 Gaussian 패스 부재 확인).
  끄고 켜는 순간에 팝이 보이지 않는다.
- 전투 흐림이 현행과 같은 그림이다(회귀 없음).
- 배치↔전투를 빠르게 오가도 흐림이 튀지 않고, 카메라와 **같이** 도착한다.
- 폰 실기에서 두 상태의 흐림을 눈으로 확인(한계 2).
