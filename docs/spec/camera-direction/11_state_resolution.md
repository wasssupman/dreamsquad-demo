# unit 11 — 상태 해석과 절대 포즈 개통 (배치·전투)

## 목적

`CameraDirector` 가 홈 포즈 + 페이즈 델타를 합성하던 것을 그만두고, **지금 어느 상태인지
판단해 그 상태의 레시피를 절대 포즈로 푼다.** (HEAD 에서 페이즈 델타는 게이트로 잠들어 있었다 —
unit 10 의 «사실 관계 주의» 참조. 이관할 실사용 값이 없다.) 대상은 아직 둘 다 보드 중앙 고정 —
커서 추종은 unit 12.

## 변경 대상

- `Assets/_Project/Scripts/Presentation/CameraDirector.cs`
- `Assets/_Project/Scripts/Data/CameraDirectionConfig.cs` — `phasePoses` / `boardFitMargin` / `boardFramePullback` / `boardFrameRaiseY` 제거
- `Assets/_Project/Scripts/Bridge/BattleBridge.cs` — `FrameBoard` 호출부 (보드 bounds 를 "알려주는" 의미로 변경)

## 구현

**상태 해석** — 매 LateUpdate 맨 앞에서 위에서부터:

1. 페이즈가 `Placement` 또는 `Gimmick` 이면 → `Placement`
2. 그 외 전부 → `Battle`

집계(`Tally`)·결과(`Result`)·드래프트(`Draft`)·`None` 은 규칙 2 로 흡수돼 전투 상태를 쓴다.
집계는 판을 계속 보여주는 구간이고 결과는 전면 UI 라 별도 상태가 필요 없다. **"미등록
페이즈 = hold"는 은퇴한다** — 상태가 둘뿐이라 hold 가 표현할 것이 없고, hold 는
"직전에 뭐였는지"에 결과가 의존해 재현이 어려웠다.

**포즈 계산** — 해석된 상태의 레시피를 `SolveStatePose` 로 매 프레임 푼다. 보드 bounds 는
맵 빌드 때 `BattleBridge` 가 넘겨준 값을 Director 가 보관한다(`FrameBoard` → `SetBoardBounds`
로 개명, 이제 포즈를 계산하지 않고 입력만 갱신). 화면비가 바뀌면 다음 프레임이 자연히
새 aspect 로 다시 푼다 — unit 9 의 aspect 재프레이밍 특수 분기가 필요 없어진다.

**은퇴하는 것**: `_homePos` / `_homeRot` / `_homeFov` 캡처, `CameraPhasePose` 배열,
전역 fit 노브 3개. 씬의 Main Camera 포즈는 이제 런타임에 **읽지 않는다**(에디터 미리보기 전용).

**DoF 재구동 (놓치기 쉬운 곳)**: `ApplyBoardDepthOfField` 는 지금 `FrameBoard` 안에서 «fit 거리 +
pullback» 을 받아 돌았다. 그 호출이 사라지므로 **DoF 를 구동할 새 지점이 필요하다** — 해석된
상태의 거리가 바뀔 때(상태 전환·맵 bounds 갱신·aspect 변경) 다시 계산한다. 매 프레임 무조건
덮어쓰지는 않는다(볼륨 오버라이드 쓰기가 공짜가 아니다). 이번 유닛은 **전역 DoF 값을 유지**하고
거리만 현재 상태 기준으로 바꾼다 — 상태별 흐림 저작은 unit 13.

**아이들 최적화(`_settled`)**: 상태 포즈가 매 프레임 같은 값이면 여전히 no-op 로 둔다. 단
«활성 채널 판정» 에 **전환 진행 중** 과 **대상이 움직이는 상태**(unit 12 커서)를
포함해야 한다 — 빠뜨리면 추종이 한 프레임 만에 덮여 얼어붙는다(인스펙트·헤드룸에서 이미 겪은 함정).

**은퇴하는 홈 3필드의 소비처를 이 커밋에서 함께 막는다** (빠뜨리면 기준 없는 채널이 남는다):
`_homeFov` 로 포인터 ray 를 복원하던 드래그 포커스(`CameraDirector.cs:499`)와 인스펙트(`:549`)는
**그 프레임의 상태 fov** 를, 인스펙트 NDC 산출(`:320-322`)은 **그 프레임의 상태 포즈**를 쓴다.
`OnDisable` 의 홈 복귀(`:715-716`)는 **아무것도 복원하지 않는다** — 복원할 홈이 없고, 다음
활성화 프레임이 상태 포즈를 다시 쓴다.

**보드 bounds 가 아직 없을 때는 카메라를 쓰지 않는다** (직전 포즈 유지). 씬 포즈를 더 이상
읽지 않으므로 맵 빌드 전 프레임·`GameManager` 없는 씬·테스트 리그에는 fit 할 판이 없다.
지금은 홈 캡처가 그 구간의 폴백이었다. **Director 가 맵이나 브리지에서 bounds 를 직접
당겨오지 않는다** — 그 유혹이 경계 우회의 입구다. 입력은 브리지가 밀어주는 한 방향뿐이다.

**살아남는 것**: 킥 · 구두점 · 브리딩 · 드래그 포커스 · 손패 헤드룸 · 이동모드 오버뷰.
전부 "base 포즈 위에 얹히는 델타"라 base 가 홈에서 **현재 상태 포즈**로 바뀌기만 하면 된다.
`CameraComposeMath.Compose` 의 시그니처는 그대로 쓰고 첫 인자만 상태 포즈를 넘긴다.

**전환**: 상태가 바뀌면 도착 상태의 `flightSec`/`ease` 로 보간한다. 상태가 둘뿐이라
**전환 쌍별 저작은 두지 않는다** — 판 안에서 실제로 일어나는 전환은 `배치→전투` 하나뿐이고,
도착 상태의 값이 그것을 온전히 표현한다. 두 번째 예외가 실제로 필요해지면 그때 표로 키운다.

**포즈를 얼려서 섞지 않는다** — 매 프레임 양쪽 상태의 레시피를 각각 풀고 그 결과를 섞는다.
그래야 전환 도중에도 대상이 살아 움직인다(unit 12 의 커서 추종이 전환 중에 끊기지 않는다).
전환 중 재전환은 현재 보간값에서 새 목표로 재시작한다(스냅 금지, 기존 계약 계승).
판 시작 시 첫 상태는 스냅(기존 `_phaseAppliedOnce` 계약 유지).

## 완료 기준

- 배치→전투 전환이 두 상태의 레시피 값 사이를 보간하고, 도착 시 전투 레시피 포즈에 정착한다.
- 전투 레시피 값을 바꿔도 배치 포즈가 **한 값도 움직이지 않는다** (이 spec 의 존재 이유).
- 크기가 다른 맵 2개 이상에서 배치·전투 모두 판이 화면에 들어온다.
- 드래그 포커스·킥·헤드룸이 전과 같이 동작한다(기준만 상태 포즈로 바뀜).
- 맵 빌드 전 프레임과 `GameManager` 없는 씬에서 카메라가 **건드려지지 않는다**(에러·점프 없음).
- `BattleBridge` 의 공개 API 가 하나도 늘지 않는다(`FrameBoard` → `SetBoardBounds` 개명뿐).
- EditMode 초록, 콘솔 에러 0, Play 로 배치→전투 확인.
