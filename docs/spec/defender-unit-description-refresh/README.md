# defender-unit-description-refresh — 방어 유닛 능력 설명 개편

> 상태: **완료 2026-07-29 · unit 0 구현/자동 검증·사용자 Play 확인·시트 반영 완료**

## 목표

스쿼드 상세 설명만 읽어도 각 유닛의 평소 역할, 배치 순간 효과, 계속 유지되는 특수
능력을 빠르게 구분할 수 있는가? `DefenderCatalog` 24종을 실데이터 기준으로 감사하고
아래 3줄 형식으로 교체한다.

```text
기본 기능: 평소 수행하는 공격·회복·설치 역할
배치 스킬: 배치 순간 한 번 발동하는 능력 또는 없음
특수 효과: 도발·실드·상태이상·범위 공격 등 상시 특성 또는 없음
```

## 작업 단위

| 0 | 데이터 + 테스트 | `0_roster_description_refresh.md` | 24종 문안·시트 스냅샷·형식 테스트·Play 확인 |
| 1 | 인계 | `1_handoff_summary.md` | 구현·검증 결과와 후속 후보 요약 |

## 공통 계약

- 이름·옛 설명보다 현재 `DefenderUnitData`, 공격 출력, 투사체, 능력 SO를 우선한다.
- 전 유닛은 `기본 기능 / 배치 스킬 / 특수 효과` 순서의 **정확히 3줄**을 쓴다.
  능력이 없으면 생략하지 않고 `없음`으로 표시한다.
- `배치 스킬`은 `onPlace*`와 배치 밀치기만 뜻한다. 주기 능력·적중 효과·도발은
  `특수 효과`에 둔다.
- 항목당 한 개의 짧은 구나 문장. 카드에 이미 있는 클래스·등급·코스트·체력·공격력·사거리·주기는
  반복하지 않는다. 정확한 수치나 “최강/최약”도 쓰지 않는다.
- 이름에서 능력을 추측하지 않는다. 현재 피어서의 기본 투사체는 관통하지 않는다.
- 기존 `UnitKitSummary.Describe`와 `desc`를 그대로 쓴다. 런타임/ECS/씬 wiring 변경은
  없다. 범위는 구현 시점 카탈로그 등록 유닛 전부이며 잔존 에셋은 제외한다.

## 문체 예시

```text
# 실드셔틀
기본 기능: 단일 근접 공격
배치 스킬: 없음
특수 효과: 도발 · 체력 낮은 아군 주기 실드

# 아틸러리
기본 기능: 먼 적 위치에 포탄 발사
배치 스킬: 없음
특수 효과: 착탄 지점 주변까지 공격
```

## 검증 기준

- EditMode에서 카탈로그 전 유닛의 제목·순서·중복·빈 본문을 검사한다.
- 공격 출력·투사체·배치 효과·능력 SO와 최종 문안을 전수 대조한다.
- OutgameScene 상세에서 짧고 긴 대표 문안의 3줄 가독성을 사용자 Play 확인한다.
- Defenders 시트 24행이 로컬 `desc` 스냅샷과 일치하는지 읽기 전용으로 대조한다.
- 생성→렌더 경로 변경이 없어 파이프라인 커버리지 표는 해당하지 않는다.

## 후속 후보

- 배치 트레이나 인게임 유닛 선택 화면에도 같은 3줄 설명을 노출하는 작업.
- 설명의 특수 효과 수치를 SO에서 자동 조립해 밸런스 변경과 함께 갱신하는 작업.
