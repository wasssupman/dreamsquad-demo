# 0 — 카탈로그 24종 능력 설명 개편

## 목적

현재 카탈로그의 모든 방어 유닛 설명을 실제 능력과 맞추고, 큰 글자 상세 카드에서 한눈에
비교 가능한 3줄 형식으로 통일한다. 전투 동작과 UI 구조는 바꾸지 않는다.

## 변경 대상

- `Assets/_Project/Data/Defenders/*.asset` — 카탈로그 등록 24종의 `desc`
- `Assets/_Project/Tests/EditMode/UnitKitSummaryTests.cs` — 카탈로그 설명 형식 전수 검사
- `docs/spec/squad-character-page/defenders_desc.json` — 시트 반영용 최신 24종 스냅샷
- `docs/spec/defender-unit-description-refresh/README.md` — 상태·계약

## 구현

- `DefenderCatalog.units`를 기준으로 각 유닛의 `outputs`, `projectile`, `onPlace*`,
  `abilities`, 도발·수면·넉업·출혈 필드를 대조한다.
- `desc`는 아래 순서의 줄바꿈 2개를 포함한 정확히 3줄이다.
  - `기본 기능: ` — 평상시 공격·회복·해저드 설치 방식
  - `배치 스킬: ` — 배치 순간 1회 효과. 없으면 `없음`
  - `특수 효과: ` — 도발·실드·상태이상·범위/방향 공격. 없으면 `없음`
- 설명 영역은 font 34, 높이 148px로 3줄 예산이다. 존댓말 장문 대신
  `단일 원거리 공격`, `주변 적 잠시 속박`처럼 한 줄 한 구로 압축한다.
- 일반 스탯 6종은 상세 카드의 이름·배지·스탯 영역이 이미 표시하므로 반복하지 않는다.
  정확한 밸런스 수치도 설명에 복제하지 않는다.
- 이름만으로 특성을 만들지 않는다. 가디언의 실제로 없는 해저드 문구를 제거하고,
  피어서에는 현재 투사체 데이터에 없는 관통을 쓰지 않는다.
- 테스트는 카탈로그에서 직접 전수 스캔하여 3줄 수, 제목 순서, 빈 본문, 한 줄 길이를 검사한다.
  신규 유닛이 형식을 지키지 않고 등록되면 같은 테스트가 실패해야 한다.
- 스냅샷은 asset과 같은 `id`/`desc` 24종을 담고, 향후 Defenders 시트 반영 시 사용한다.
