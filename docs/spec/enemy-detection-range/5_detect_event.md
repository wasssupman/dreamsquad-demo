# 5 — 발견을 사건으로 만든다

## 목적

감지는 지금까지 **조용한 상태 변화**다. 적이 갑자기 방향을 틀지만 플레이어는 *왜* 그러는지 모른다.
발견을 1회 사건으로 내보내 화면이 그 순간을 말하게 한다 — 「저 놈이 내 유닛을 봤다」.

이게 없으면 이 기능은 「적이 가끔 이상하게 움직인다」로 읽힌다. 이 spec 이 노리는 것은 교전
밀도이고, 밀도는 **읽혀야** 체감이 된다.

## 변경 대상

- `Assets/_Project/Scripts/Battle/Combat/DetectionEvents.cs` (신규) — 채널
- `Assets/_Project/Scripts/Battle/Combat/DetectionSystem.cs` — 전이에서 enqueue
- `Assets/_Project/Scripts/Bridge/BattleBridge.cs` — 드레인 + 트레이스 + 표식
- `CLAUDE.md` — 채널 목록 29 → 30 갱신(**같은 커밋**)

## 구현

**채널** — Combat→Bridge, `NativeQueue` 싱글턴. 오늘 29개의 30번째.

```csharp
public struct DetectionEvent
{
    public int   enemySimId;    // 발견한 쪽
    public int   targetSimId;   // 발견당한 방어유닛
    public float3 enemyPos;     // 표식을 띄울 자리
}
```

**값 스냅샷이다**(`SkillFiredEvent` 선례). Entity 를 싣지 않는다 — 드레인 시점에 그 적이 이미
죽었을 수 있고, 브리지가 엔티티 핸들을 들면 재활용된 엔티티를 건드린다.

**발화 조건 = 전이 1회.** `hunting` 이 `0 → 1` 로 바뀐 프레임에만 enqueue 한다. 매 프레임 쏘면
초당 60건이 되어 표식이 화면을 덮고 트레이스가 무의미해진다.

⚠ **grace 를 거쳐 다시 잡은 것은 새 발견이 아니다.** unit 4 의 관성 중에는 `hunting` 이 1로
유지되므로 전이가 안 일어나고, 따라서 「죽이고 다음 놈을 무는」 연속 사냥은 표식을 한 번만 낸다.
이건 의도다 — 사용자가 말한 사이클(감지→공격→사망→재감지)에서 **소리를 낼 값이 있는 것은 첫
발견**이고, 그 뒤는 이미 싸우는 중이라는 것이 화면에 있다.

**로깅이 첫 축이다**(CLAUDE.md). 브리지 드레인은 **첫 줄에서** `LegacyTraceRecorder.Ev` 로 기록한다.
표식보다 트레이스가 먼저다 — 연출이 실패해도 사건은 남아야 한다.

**표식은 최소로 간다.** 적 머리 위에 짧은 「발견」 표식 1회. 전용 VFX·사운드·카메라 반응은
**후속 후보**다 — 이 unit 의 검증 질문은 「사건이 채널을 타고 화면까지 도달하는가」다.

⚠⚠ **여기서 계획이 틀렸다 — 「기존 팝업 프리젠터 재사용」이 불가능했다**(코드 리뷰 H6).
이 프로젝트의 팝업 프리젠터는 `DamageNumberSpawner.Spawn(pos, **float**)` 하나뿐이고 **숫자만**
그린다. 「발견」에 쓸 텍스트/기호 팝업이 없고, `Assets/_Project/VFX/` 에도 경보·표식 계열
프리팹이 **0건**이다. 그래서 구현은 `VfxSpawner` 에 슬롯(`detectionMarkPrefab`)을 하나 파고
**미할당이면 no-op** 으로 두었다.

**그 귀결을 숨기지 않는다**: 씬에 프리팹이 없으므로 아래 완료 기준의 「Play 육안: 표식이 뜬다」는
**현재 구조적으로 통과할 수 없다.** 채널·트레이스·전이 판정은 완료됐고 테스트로 고정돼 있지만,
**화면에는 아직 아무것도 안 뜬다.**

⚠ 이건 CLAUDE.md 의 「씬 wiring 을 사용자 수작업으로 미루지 않는다」에 걸리는가? — **아니다.**
그 금지는 **MCP 로 자동화 가능한 배선**을 미루지 말라는 것이고, 여기서 없는 것은 배선이 아니라
**저작물(프리팹)** 이다. 새 VFX 프리팹 제작은 `unity-vfx-authoring` 영역이고 이 spec 의 검증
질문(교전 밀도)에 답하는 데 필요하지 않다 — 제약 9 대로 **후속 작업**으로 분리한다.

**후속 작업의 완료 조건**: 「발견」 표식 프리팹 1개 저작 → `VfxSpawner.detectionMarkPrefab` 에
할당 → 이 unit 의 Play 육안 통과. 그때까지 unit 5 의 상태는 **「채널 완료 · 표식 저작 대기」**다.

⚠ **표식은 «발견한 쪽»에만 붙는다. 대상을 가리키지 않는다.**
`targetSimId` 는 **트레이스·로그 전용**이다 — 화면에서 그 유닛을 하이라이트하거나 선을 긋지
않는다. 이유는 계약 6 의 실측이다: 감지는 직선 최근접을 고르는데 몸은 공용 사냥판을 따라가
**5.0% 의 표본에서 다른 방어유닛에게 간다.** 대상을 가리키면 그 5.0% 에서 화면이 **거짓말을
하고**, 「화면이 규칙을 틀리게 가르치는」 것은 이 프로젝트가 가장 나쁜 종류의 버그로 부르는
것이다(`AttackReach` 헤더의 배치 프리뷰 경고와 같은 부류).

대상을 가리키고 싶다면 선행 조건은 **이동이 그 대상을 향하는 것**이고, 그건 B안 전환이다
(README 후속 후보). 이 unit 에서 임시로 열지 않는다.

⚠ **이 unit 은 골든을 움직인다**(새 트레이스 이벤트가 코퍼스의 이벤트 수를 바꾼다). 그래도
**재베이크하지 않는다** — 코퍼스가 이 spec 이전부터 stale 이라 지금 구우면 남의 세션 변화까지
기준선에 박힌다(unit 6 「골든 코퍼스」 절의 결정). 언젠가 굽게 되면 `SimHarnessRunner.PinMapCondition`
이 도는지 먼저 확인한다 — dev 맵 강제(PlayerPrefs)가 켜져 있으면 「남의 맵」이 기준선에 구워진다.

## 완료 기준

- compile 통과 · EditMode 전체 초록(선행 실패 2건 제외).
- EditMode 신규: `hunting` 이 `0→1` 인 프레임에만 큐에 1건이 들어간다. 유지 프레임엔 0건.
- EditMode 신규: grace 를 거쳐 새 대상을 잡아도 **추가 이벤트가 없다**(전이가 아니므로).
- 판 종료 시 큐가 비고 dispose 된다(다른 29개 채널과 같은 수명 규약).
- 트레이스에 사건이 남는다 — 코퍼스 재생성 후 `long_boss` 에 발견 이벤트가 **1건 이상**.
  0건이면 채널이 죽은 것이고, 통과하지만 아무것도 증언하지 않는 골든이 된다.
- ~~골든 코퍼스 재베이크~~ → **하지 않는다**(위 ⚠). 코퍼스 정리가 선행 조건이다.
- `CLAUDE.md` 채널 목록이 30개로 갱신됐다.
- ~~Play 육안: 표식이 한 번 뜬다~~ → **표식 프리팹 저작 후로 이월**(위 ⚠⚠).
  그때까지는 **트레이스로 대신 확인한다** — 코퍼스 재생성 후 `long_boss` 에 발견 이벤트 1건 이상.
