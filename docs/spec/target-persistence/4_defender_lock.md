# unit 4 — 방어유닛 락 (원칙 1의 본체)

## 목적

**방어유닛이 한 적을 겨누기 시작하면 그 적이 죽거나 사거리를 벗어나기 전까지 갈아타지 않는다.**

방어유닛에는 지속 락이 **아예 없다.** 매 프레임 `bestTarget = Entity.Null` 로 시작해 사거리 내 최근접을 재계산한다. 사용자 원칙 1이 겨눈 바로 그 자리다.

**unit 3 과 위치가 다르다.** unit 3 실측에서 `Nearest` 적 4종 중 셋이 `Halt`(교전 시 정지)라 최근접이 애초에 안 바뀌어 «예전이라면 갈아탔을 = 0» 이었다. 방어유닛은 **반대**다 — 자기는 고정인데 **적이 계속 흘러가므로 최근접이 매 순간 바뀐다.** 락이 실제로 일하는 자리이고, 그래서 **밸런스 영향이 이 spec 에서 가장 크다**.

## ⚠ 착수 조사에서 스펙을 정정한다 — 삽입 위치

README 작업 단위 표는 «facing override **직후**»라고 적었다. **지금은 틀렸다.**

머지 후 현재 사슬 순서:

```
선정(nearest·priority·힐러·frontmost 후보)  :443~612
적 focus 락 (unit 2·3)                      :620~690
어그로 sticky override                       :693~710
frontmost 블록                               :712~750
unit 0 wind-up 커밋 유지                     :754~780   ← 여기보다 앞이어야 한다
facing override                              :786~      ← 마지막으로 bestTarget 을 건드림
```

facing 뒤에 넣으면 **unit 0 의 wind-up 커밋을 덮어쓴다** — 스윙 도중 락이 커밋을 밀어내 «A 겨누고 B 때림»(B1)이 부분 부활한다.

**정정: frontmost 블록 직후, unit 0 wind-up 유지 직전에 넣는다.**

```
… frontmost(:712~750) → [unit 4 방어유닛 락] → unit 0 커밋 유지(:754~) → facing(:786~)
```

이 순서가 층을 맞춘다:

| 창 | 누가 이기나 |
|---|---|
| 스윙 진행 중(`hitDelayRemaining > 0`) | **unit 0 커밋** — 한 공격 안에서는 안 바뀐다 |
| 스윙 사이 | **unit 4 락** — 공격들 사이에서도 안 바뀐다 |

facing 보다 앞인 것도 맞다 — 레인 witness 는 타겟이 아니라 발사 게이트이므로 그쪽이 이겨야 한다(unit 0 과 같은 논거).

## 구현

### 락 그릇은 `FocusTarget` 을 재사용한다

지금 `FocusTarget` 은 적 스폰 경로에서만 붙는다(`BattleBridge:7783`). 방어유닛 생성에도 붙인다. **신규 컴포넌트를 만들지 않는다** — 이름이 진영을 함의하지 않고(«내가 문 대상»), 유지 술어도 `TargetPersistence.KeepsLock` 하나를 공유한다.

### 게이트 — 제외 4종은 누락이 아니라 계약이다

```
!hasFacing ∧ !wantFrontmost ∧ !rankByHealth ∧ !AggroCapacity
```

| 제외 | 이유 |
|---|---|
| facing | 레인 witness 는 발사 게이트지 타겟이 아니다 |
| frontmost(「끝을 보는 눈」) | 카드 계약이 *"매 공격마다 지금의 최전방"* — 락과 정면 충돌 |
| 힐러(`rankByHealth`) | lowest-health 재랭킹이 정체성 |
| 가디언(`AggroCapacity`) | **D1** — 어그로 자석이 *"아직 어그로 안 걸린 적 우선"* 으로 신규 팩을 흡수한다. primary 를 고정하면 자석이 죽는다 |

각 제외 이유를 **코드 주석에 남긴다**. 다음 사람이 "빠뜨렸네" 하고 채우면 넷 다 조용히 망가진다.

### 해제 사유는 셋

**사망 ∨ 사거리 이탈 ∨ 자기 CC 해제**(D5 균일 적용). 적 쪽(unit 3)과 **같은 형태**를 쓴다 — `actionLocked` 면 비우고 재잠금을 건너뛰는 `else` 구조. unit 3 에서 «비우기만 하고 흘리면 즉시 재잠금된다»에 걸렸으므로 여기서도 `else` 로 감싼다.

어그로는 해제 사유가 **아니다** — 그건 적 쪽 규칙이고 방어유닛은 어그로에 끌리지 않는다.

### 골/거점을 특별 취급하지 않는다

`battle-structures` unit 0 이 «거점은 잠금 대상이 아니다» 예외를 제거했다(2026-08-09 사용자 확정). 방어유닛 락도 같은 규칙을 따른다 — 거점을 물면 죽거나 사거리를 벗어날 때까지 유지한다.

## 예상 파급 — 이건 밸런스 변경이다

- 넉백·수면 on-hit, 드림캐쳐 payload(`frost_arrow`·`ember_bite`·니들)가 **한 적에 집중**
- HeavyStrike 의 HP 게이트가 같은 대상을 반복 평가해 **발동 안정화**(개선)
- **동거리 flip-flop 소멸** — 매 프레임 재선정이 사라지므로 진동의 원인이 구조적으로 없어진다. 별도 히스테리시스 불요
- **누수 방어력이 달라질 수 있다** — 흘러가는 적을 사거리 끝까지 물고 늘어지므로, 뒤따라 들어온 적이 무시된다
