# unit 2 — 「가까운 거점부터 팬다」 가 저절로 되는지 실측

## 목적

사용자 질문: **«오른쪽 끝에서 스폰된 적이 가까운 본능을 먼저 패고, 본능이 다 부서지면
마음을 패는 구조가 쉽게 가능한가?»** 그리고 이어진 판단: **«별도의 웨이포인트가 필요한 게
아니라고 생각. 마음 1 + 본능 N(2~3)이다.»**

이 unit 의 결론은 «기능을 만든다» 가 아니라 **«만들 필요가 있는지 잰다»** 다.

## 왜 저절로 될 수 있나

두 사실이 이미 성립한다:

1. **타게팅은 이미 거리순뿐이다.** `AttackSystem` 은 마스크에 든 후보를 `d2 < bestSq` 로만
   고른다 — 거점이라고 우대하거나 미루는 코드가 없다(battle-structures unit 0 계약).
   마음이 우선처럼 보인 건 **타게팅이 아니라 이동** 때문이다: 흐름장이 늘 골로 흐른다.
2. **unit 1 이후 본능은 통행을 안 막는다.** 그래서 적의 골 직행 경로가 본능 셀을
   **지나가거나 스쳐** 사거리에 들어온다. 근접 적(사거리 1)도 3×3 의 바깥 칸에 인접하면
   닿는다 — 다중 셀 거리(`DistanceSqToTarget`)가 이미 그렇게 잰다.

즉 지형이 본능을 경로 위/옆에 놓기만 하면 «가까운 것부터» 는 **창발**한다.
웨이포인트도, 목적지 선택 기계도 없이.

## 실측 (Coil + Duel)

| 잴 것 | 방법 | 기대 |
|---|---|---|
| 적이 본능 셀을 **통과**하는가 | 통과 셀 로그 | footprint 9칸 중 1+ |
| 지나가며 **때리는가** | 본능 피격 카운터 | 0 아님 |
| 본능 파괴 후 **마음으로 가는가** | 파괴 시각 vs 골 도달 시각 | 파괴 후 진행 재개 |
| **경로 밖 본능**을 무시하는가 | 경로에서 먼 본능의 피격 카운터 | **여기서 0 이 나오면 unit 3 승격** |

Duel 은 마음 1 + 본능 2 의 표준 형태다 — 중앙 통로(y5)가 양측 본능 footprint(y2~4·y7~9)와
한 칸 인접이라 근접 적도 사거리에 든다. 이 기하가 «저절로» 의 전제다.

**대조군 필수**: 이전 실측 사고(마음사냥꾼 도발 0회가 사실은 배치 미활성)를 되풀이하지
않는다. 본능 없는 맵에서 같은 카운터가 0 인지 먼저 확인하고 잰다.

|---|---|---|
| footprint 방문 | **1,820** | **0** |
| 잔여 HP | 0 / 1000 | **950 / 1000** |

> 첫 시도는 웨이브 30개를 강제해 동시 348기가 됐고, 그 홍수에선 두 본능이 8.2s·10.7s 에
> **둘 다** 부서졌다. 물량이 두 다리를 모두 채워서지 선택이 일어난 게 아니다 — 순서 판정이
> 오염된 측정이라 웨이브 3개(동시 23기)로 다시 쟀고, 위 표가 그 결과다.

## 판정 — **unit 3 승격**

세 줄 요약:

1. **경로 위 본능은 저절로 맞는다.** 북 본능은 방문 1,820회에 11.9초 만에 파괴됐다.
   unit 1 이 통행을 연 덕에 적이 건물 **위를 지나가며** 팬다 — 타게팅은 손대지 않았다.
2. **경로 밖 본능은 무시된다.** 남 본능은 방문 **0**, 75초 뒤에도 HP 95%(깎인 50은
   지나가던 원거리 적의 유탄). 스폰이 하나면 흐름장도 하나라 **모두 같은 길로 간다.**
3. **「본능 다음 마음」 순서가 성립하지 않는다.** 마음은 6.6초에 이미 깎이기 시작해
   북 본능 파괴(11.9초)보다 **빨랐다.** 일부는 본능을 치고 일부는 그대로 마음으로 갔다.

즉 사용자 판단의 앞 절(«가까운 본능을 자연스럽게 친다»)은 맞고, 뒤 절(«다 부서지면
마음이 우선»)은 **틀렸다.** 지형으로는 못 고친다 — 본능을 유일 경로 위에 놓으면 1기는
되지만 «본능 N 이 차례로 부서진다» 는 저작으로 표현할 수 없다.

**웨이포인트는 여전히 불필요하다.** 필요한 건 경로 저작이 아니라 **목적지 1개 선택**이다.
사용자가 답한 규칙 그대로: **스폰 시 1회 → 부서지면 재선정.**

### 승격 시 유의

- 흐름장 슬롯은 이미 N 목적지를 지원한다(`FlowFieldSingleton.destCells[]` ·
  `SlotFor(destCell, unitLayers)`). 기계 신설이 아니라 **목적지 목록에 본능을 넣는 것**이다.
- 스폰이 하나면 «가장 가까운» 은 전원 같은 답이다((18,5)→북 14.1 vs 남 14.3). 그래서
  선택은 분산이 아니라 **집중**을 만든다 — 북이 죽으면 재선정으로 남, 그 다음 마음.
  이게 사용자가 묘사한 순서다.
- 함정: **죽은 목적지**. 재선정이 없으면 부서진 본능으로 계속 걸어간다(붕괴 골 라우팅과
  같은 계열의 결함).
