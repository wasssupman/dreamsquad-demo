# 8. 카드 그리드 5열 고정 + 카드 확대

## 목적

덱 페이지 컬렉션 그리드를 **5열**로 바꾸고 카드를 그만큼 키운다.
`squad-character-page` unit 18(유닛 그리드 5열)의 쌍이며, 규칙과 산식이 동일하다.

두 페이지의 상세 패널이 똑같이 `detailWidth = 0.34` 를 차지하므로 브라우저 폭도 같다
→ 같은 열 수면 **카드 폭과 유닛 셀 폭이 자동으로 일치**한다. 두 페이지를 나란히 봤을 때
그리드 밀도가 어긋나지 않는다.

## 변경 대상

- `Assets/_Project/Scripts/UI/Outgame/DreamcatcherCardBrowser.cs`

## 구현

### 1) 열 수 = 불변식

`GridLayoutGroup.constraint = FixedColumnCount`, `constraintCount = cardColumns`
(`[SerializeField] int cardColumns = 5`).

바꾸는 이유는 "카드가 작아서"가 아니라 **열 수가 어디에도 저작돼 있지 않아서**다. 지금은
`Flexible` 이라 열 수가 `패널폭 ÷ (150+14)` 로 나오는데, 캔버스가 1920×1080 높이 매치라
참조 폭이 `1080 × 화면비`다 → 16:9 와 20:9 폰에서 열 수가 다르다. 카드 크기만 키우면
16:9 에서만 5열이 된다.

### 2) 카드 폭 = 패널에서 파생

```
cellW = (패널폭 − padLeft − padRight − spacing.x × (cols − 1)) / cols
```

폭은 **자기 RectTransform** 에서 읽는다. Scroll/Viewport/Grid 가 전부 offset 0 stretch 라
폭이 같고, `OnRectTransformDimensionsChange` 는 부모→자식 순서로 불려 그 시점의 자식
rect 는 아직 옛값일 수 있다.

빌드 직후 첫 프레임에는 폭이 0 일 수 있으므로 기준 카드로 그리고, 폭이 확정되면
`OnRectTransformDimensionsChange` 가 재구성한다. 같은 훅이 해상도/종횡비 변경도 흡수한다.

### 3) 카드 안쪽 치수는 하나의 배율로 파생

기준 카드는 150×225. `scale = cellW / 150`.

| 요소 | 기준값 | 파생 |
|---|---|---|
| 카드 높이 | 225 | `225 × scale` |
| 아트 여백(좌·우·상) | 6 | `6 × scale` |
| 아트 하단 여백(라벨 자리) | 42 | `42 × scale` |
| 라벨 높이 / y오프셋 / 폰트 | 36 / 4 / 20 | `× scale` |
| 뱃지 | 88×34 / 폰트 19 / 여백 6 | `× scale` |

16:9 기준 실측 예상: 패널 ≈ 1267 → `cellW ≈ 237`, `cellH ≈ 356`, 라벨 폰트 ≈ 32.

### 4) 배율을 곱하지 **않는** 것

그리드 하단 패딩 `120`(unit 7 — 떠 있는 [저장] 버튼 회피). 이건 버튼 크기에 매인
**화면 공간** 값이지 카드에서 파생되는 값이 아니다. 카드를 키운다고 버튼이 커지지 않는다.
