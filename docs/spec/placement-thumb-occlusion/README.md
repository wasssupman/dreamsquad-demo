# placement-thumb-occlusion

상태: **작성 2026-07-29 · critic 리뷰 반영 완료 · 구현 대기**. 사용자 발의(모바일 D&D 배치 중 손가락이
하이라이트된 배치가능 타일을 덮어 UX 감성이 나쁘다) → 두 방안 아이데이션 후 **둘 다 채택**(원인 제거 +
중복 송출) 확정.

critic 리뷰(REQUEST-CHANGES, Critical 2 / High 3 / Medium 8 / Low 7) 반영 — 초판이 **코드를 잘못 진술한
곳 4군데**를 고쳤다: ① `DropDismountTest` 누락(테스트 전수 주장이 거짓) ② 하단 도달 위험을 clamp 가 이미
막고 있어 unit 2 의 전제가 틀렸음 ③ 라이브 `TileSetData` 를 반대로 지목 + 사막 시즌 사거리 미렌더
④ `aimStyle` 가드가 스킬 조준을 보호하지 않음. 설계 방향(방안 1·2, 작업 분할)은 유지.

## 목표

방어 유닛을 드래그해 놓을 칸을 고르는 동안, **손가락이 그 칸을 가리지 않게** 하고(방안 1),
가려지지 않는 넓은 채널로 **배치 가능/불가를 중복 송출**한다(방안 2).

**검증 질문**: 실기기에서 유닛을 드래그하는 동안 ① 포커스 칸의 하이라이트가 손가락에 가리지 않고
보이는가, ② 배치 불가 칸으로 옮겼을 때 손가락을 치우지 않고도 "안 됨"이 즉시 읽히는가,
③ 그러면서 **최하단 배치가능 행이 여전히 도달 가능한가**(③이 실패하면 ①의 값이 없다)?

## 문제 구조 (load-bearing)

드래그 중 화면에 뜨는 채널이 5개인데 **유효성을 나르는 3개가 전부 손가락 밑**에 있다.

| 채널 | 위치 | 유효성 |
|---|---|---|
| 배치가능 영역(시안 슬랩, 정적) | 판 전체 | 공간 조건만 — 비용 제외가 명시 계약 |
| 포커스 셀 액체 하이라이트 | **손가락 밑** | 초록/코랄 |
| 확정 팝 | **손가락 밑** | 시안/코랄 |
| 공격 사거리(주황 격자 outline) | 손가락 **바깥** | **없음** (유효성 무관이 기존 계약) |
| 거부 라벨(글리프+한글+색) | 포인터 +96px | 사유 3종. 단 **거부 시에만** 등장 |

즉 안 가려지는 넓은 채널은 유효성을 안 나르고, 유효성을 나르는 채널은 다 가려진다.
방안 1이 두 번째·세 번째 행을, 방안 2가 네 번째 행을 고친다.

**방안 2의 실효 구간은 코스트 부족이다.** 공간 무효(경로/점유/Deco)는 시안 슬랩의 *부재*로 이미
주변시에 읽히지만, 코스트 부족은 **타일·사거리 채널에 없다** — 손가락 위 라벨("X 코스트 부족",
`:470-471`)만 나른다. 하이라이트가 비용을 제외하는 건 의도된 계약이다(끼우면 코스트 리젠 경계마다
보드 전체가 깜빡인다). 즉 방안 2 는 그 정보를 **넓고 안 가려지는 채널로 복제**하는 일이다.

## 핵심 계약 (feature-wide)

- **가상 포인터 = 단일 소스.** 배치 판정 포인터는 `실제 포인터 + 화면 up × offset` 이고, 이 변환은
  **포인터를 읽는 seam에서 딱 한 번** 일어난다. 그 아래(고리/줄/고스트/판정 셀/카메라 포커스/거부
  라벨)는 전부 이를 상속하며 내부 관계는 불변이다. **판정만 올리고 프리뷰는 두는 변형은 금지** —
  고스트가 배치 칸에서 `totalDrop + offset` 만큼 멀어져 버그로 읽힌다.
- **원 포인터를 덮어쓰지 않는다.** UI 레이캐스트(`PointerOverUi`/`IsOverUi`), 탭/드래그 승격 임계
  비교, "보드에서 눌렀나" press 가드는 계속 실제 좌표를 쓴다. 오프셋은 *파생값*이지 치환이 아니다.
- **드래그로 승격된 뒤에만 적용.** 트레이 D&D는 세션 첫 프레임부터(슬롯 임계를 이미 넘겨 발화 =
  이미 드래그), armed 보드는 `_boardDragging` 승격 후, 재배치 목적지는 승격 게이트 신설 후.
  **무이동 탭은 누른 칸 그대로** — 탭은 피드백 루프를 볼 시간 없이 커밋되므로 오프셋이 오배치로 읽힌다.
- **하이라이트는 어느 순간에도 거짓말하지 않는다.** `EndDrag`/`ResolveRelease`도 같은 가상 포인터로
  최종 해석한다. 릴리즈 칸 ≠ 드래그 중 보여준 칸이면 오프셋이 아니라 "마지막에 한 칸 튀는" 버그다.
- **오프셋의 대가는 "도달 불가"가 아니라 "손가락이 내려가야 하는 높이"다.** `PlacementCellSnap.Resolve`
  가 결과 셀을 그리드로 **clamp** 하므로(`:39-41`) 손가락을 보드 아래로 내리면 항상 row 0 으로 접힌다 —
  도달 불가는 발생하지 않는다(초판이 "상단 3행 회귀의 대칭"이라 한 서술은 clamp 를 빼먹은 것이다).
  실제 위험은 최하단 행을 노리는 손가락 위치가 **트레이 UI 아래로 밀려나** 손가락 대신 트레이가
  하이라이트를 가리는 것 — 가림이 사라지는 게 아니라 오클루더가 바뀐다. unit 2 가 그 **높이를 계측**하고,
  최종 판정은 실기기 확인이 담당한다. 테스트가 홀로 상한을 정하지는 못한다.
- **값은 전부 데이터.** 오프셋 비율·램프·invalid 색·플래시는 `DragSwaySettings` / `TileSetData`.
  오프셋은 화면 높이 비율(`Screen.dpi` 는 Android 에서 신뢰 불가 → 물리 단위 미사용).
- **사거리 유효성은 별도 setter.** 사거리 페인트는 셀 변경 시만, 유효성은 매 프레임 뒤집힌다
  (슬로우모 0.2× 중에도 전투가 돌아 점유가 변하고 코스트가 리젠된다). 두 수명이 다르므로
  `SetPlacementRange` 에 인자를 얹지 않고 `SetPlacementRangeValidity(bool)` 를 분리한다.
  틴트 재적용 경로는 **신설하지 않는다** — `TilemapMapView.Update()` 가 사거리 셀이 사는 동안
  이미 매 프레임 `ApplyRangeTint()` 를 호출한다(펄스 제거 후에도 남은 경로).
- **조준 채널 보호는 `aimStyle` 이 아니라 owner 전환 seam 이 한다.** `_rangeAimStyle` 로 막힌다고 적었던
  초판은 틀렸다 — `SetSkillAimRange`(`BattleBridge.cs:5068`)와 `PinSkillTelegraph`(`:5077`)는
  `SetPlacementRange` 를 타므로 `_rangeAimStyle = false` 가 된다(`aimStyle: true` 는 드롭 **후** 방향
  지정뿐). 그래서 소유권이 Placement 를 떠나는 `ClearRange(caller)` 에서 validity 를 리셋한다.
  배치 단계의 facing/폭탄 레인(`:4964-4965`)도 `aimStyle: false` 인데 **거기는 적색이 들어와야 맞다**
  (배치 채널) — 색이 아니라 **소유권**이 경계다.
- **순수 Presentation.** ECS Component 읽기/쓰기 0. 전부 `BattleBridge` 게이트웨이 경유.

필드 이니셜라이저 실행 후 YAML 을 덮으므로 신설 필드는 클래스 기본값을 유지한다(에셋 편집이 스위치가
아니다). 따라서 `0` 에서 `DragPlacementReachTest` **와 `DropDismountTest`** 가, `1` 에서
`RelocationPlacementSessionTest` 가 깨지고 각각 같은 단위에서 고친다. 다른 placement 계열 테스트는
`PlaceDefenderAs`/`BeginMoveModeFor` 직접 호출이라 무관하다(전수 확인).

## 교차 참조 (기존 spec 계약을 건드리는 지점)

- `docs/spec/keyring-cord-preview/` — **"고리 = 손가락/마우스 위치"(`README:17`)와 "하이라이트/배치 칸 =
  마우스"(`:19`) 계약의 원 출처**다(컨트롤러 `:349` 주석도 여기를 가리킨다). 오프셋은 이 둘을
  "고리·배치 칸 = **가상 포인터**"로 개정한다 — 고리가 손가락 위 ~65px 에 떠서 손가락 자리엔 아무것도
  없게 된다. 개정이 여기서 일어난다는 사실을 남겨야 다음 사람이 회귀로 오해하지 않는다.
- `docs/spec/placement-cell-snap/` — 판정 기준점(`PlacementCellSnap`, 히스테리시스·throttle·액체
  하이라이트). 전부 무변경으로 가상 포인터를 입력으로 받는다. **오프셋은 상수 평행이동이라
  `placementStickMargin` 과 곱셈적으로 얽히지 않는다**(`Resolve` 는 frac 만 본다). 단 결과 셀의
  그리드 clamp(`:39-41`)가 unit 2 의 계측 설계를 지배한다.
- `docs/spec/placement-attack-range-preview/` — "배치 가능/불가와 무관하게 항상 표시" 계약이
  **형태는 무관, 색은 유효성 반영** 으로 갱신된다. 형태(사각 링)가 사거리 의미를 계속 나르므로
  이중 인코딩이 충돌하지 않는다.
- `docs/spec/placement-eligible-tile-highlight/` — 채널 구성(시안 배치영역 vs 주황 사거리)의 웜/쿨
  대비에 세 번째 상태(적색 사거리)가 들어온다. 시안 언더레이는 무변경.
- `docs/spec/placement-armed-board-drag/` — `_boardDragging` 승격이 오프셋 게이트도 겸한다.

## 후속 후보

- **재배치 무효 표현 통일** [S] · `DefenderRelocationController.UpdateScout:275-276` 은 배치 불가를
  **사거리 소거**로 인코딩한다(적색이 아니라 사라짐). 동작 문제는 없지만 feature-wide 언어가 세 번째
  경로에서만 다르다. 이 spec 범위 밖(제약 9) — 기록만 남긴다.
- **램프 스칼라 통합** [S] · unit 1 은 재배치가 자기 램프 스칼라를 따로 굴린다. 두 컨트롤러가 동시에
  램프를 굴리는 상황은 실제로 없다(`TickMoveMode:123-124` 의 `sessionConflict` 가 트레이 드래그/arm 시
  재배치를 즉시 취소한다 — 확인). 상태 2개를 1개로 줄일 여지.

- **드림캐쳐 카드 드롭의 같은 문제** [M] · `DreamcatcherCardDragSlot` 도 손가락으로 대상 유닛을
  덮는다. 대상이 셀이 아니라 유닛이라 오프셋의 의미가 달라 별도 판단 필요.
- **거부 라벨에 긍정 상태 추가** [S] · 현재는 거부 시에만 등장. "배치 가능 + 코스트" 칩을 상시
  띄우면 유효성 채널이 하나 더 늘지만 상시 노이즈와 교환.
- **색약 대응 강화** [S] · 초록/코랄은 적녹 쌍(최악 조합)이다. 현재는 라벨의 글리프+한글이 유일한
  대체 채널. invalid 사거리의 플래시(명도 변화)가 부분적으로 이를 보완하지만 정공법은 형태 구분.
- **오프셋 물리 단위화** [S] · 대형 태블릿에서 화면 높이 비율은 과보정된다. `Screen.dpi` 신뢰
  가능한 기기 판별이 생기면 dp 로 전환.
- **사거리 invalid solid 승급** [S] · 강도 3단계 중 3번째. `aimRangeTile` 슬롯 선례대로
  `TileSetData` 에 스프라이트 슬롯을 추가하면 코드 무변경으로 켜진다.

## 비목표

- 판정만 올리고 프리뷰는 두는 변형(고스트-칸 이격이 `totalDrop + offset` 으로 커져 버그로 읽힘) ·
  **고리는 손가락에 유지하고 판정·고스트만 올리는 제3안**(줄이 offset 만큼 짧아지고 오프셋 상한이 줄
  화면길이에 묶인다 — 검토 후 기각. 되돌리려는 사람이 다시 파지 않게 남긴다) · 무이동 탭에 오프셋 적용 ·
  포커스 셀 위 핀/깃발 마커(채널 추가인데 정작 타일 자체는 계속 안 보임 — 방안 1이 있으면 불요) ·
  카메라를 밀어 포커스 칸을 올리는 방식(월드 전체가 움직여 방향감각 상실) · 하이라이트에 비용 판정
  끼우기 · 유닛 몸체 틴트 · 사거리 invalid 를 처음부터 solid 로(맵 가림 — 사거리 solid 폐기 결정의 원 이유).
