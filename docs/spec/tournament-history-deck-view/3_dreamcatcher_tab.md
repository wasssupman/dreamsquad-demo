# 4 — 드림캐쳐 탭

## 목적

DeckInfo 팝업의 두 번째 탭. 좌 = 선택 카드 상세, 우 = 카드 목록. 셸과 견고성 계약은 unit 2 가 이미 세웠으므로 여기서는 카드 표현만 얹는다.

## 변경 대상

- `Assets/_Project/Scripts/UI/Outgame/DeckInfoPopup.cs`
- `Assets/_Project/Tests/EditMode/DeckInfoPopupTests.cs`

## 구현

**우측 목록** — `payload.dc.cards` 를 **가변 개수 그리드**로 그린다. 카드는 `DreamcatcherCardCatalog.ById` → `art` / `displayName`. 아트가 있으면 카드 그림 위주(타로형 art 가 이미 있다), 없으면 이름 플레이스홀더.

**좌측 상세** — 선택 카드의 `art` + `displayName` + `description`. 설명은 길 수 있으므로 넘치면 스크롤한다.

**중복 카드** — 같은 카드가 덱에 2장 이상 들어갈 수 있다. 목록은 **온 순서 그대로, 중복도 그대로** 그린다(합쳐서 `x2` 로 접지 않는다 — 이 팝업은 남의 덱을 있는 그대로 보여주는 곳이지 편집기가 아니다). 선택 상태는 **인덱스** 기준이어야 한다 — id 기준으로 잡으면 중복 카드에서 어느 슬롯을 골랐는지 잃는다.

> unit 2 의 스쿼드 탭도 같은 이유로 인덱스 기준 선택이다(드림스톤은 같은 스톤 4개 장착이 설계상 허용된다).

**설명 문안** — 카드 설명은 시트 구동이라 런타임에 갱신된다(`DcSheetImportDto.description`). 팝업은 SO 를 그대로 읽기만 한다 — 자체 포매팅이나 캐시를 두지 않는다.

**프리셋 적용 버튼** — 이 탭에도 unit 2 가 세운 하단 버튼 영역이 있다. 비활성 유지(계약 11). 카드 목록이 비어도 버튼 자리는 그대로 둔다 — 있다 없다 하면 탭을 오갈 때 레이아웃이 뛴다.

## 완료 기준

- [ ] 컴파일 통과
- [ ] 드림캐쳐 탭에서 카드를 고르면 좌측 상세(아트/이름/설명)가 바뀐다
- [ ] 중복 카드가 목록에 **각각** 그려지고, 같은 카드의 다른 슬롯을 고르면 선택 표시가 그 슬롯으로 간다
- [ ] EditMode: 중복 id 목록의 항목 수가 입력 개수와 같다 (dedup 되지 않는다)
- [ ] EditMode: 카드 탭도 unit 2 의 견고성 표를 만족한다 (null 페이로드/빈 배열/미해석 id/카탈로그 null)
- [ ] 탭을 오갈 때 "프리셋 적용" 버튼 자리가 뛰지 않는다 (목록이 비어도 유지)
