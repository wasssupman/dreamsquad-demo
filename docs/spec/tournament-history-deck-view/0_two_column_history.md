# 1 — 히스토리 1뎁스 2컬럼 재설계

## 목적

`패널 → 행 클릭 → 모달`의 2뎁스를 **한 화면 2컬럼**으로 바꾼다. 좌측은 내가 참가한 토너먼트 목록, 우측은 선택된 토너먼트의 랭킹. 선택이 곧 비교가 된다.

## 변경 대상

- `Assets/_Project/Scripts/UI/Outgame/TournamentHistoryPanel.cs` (재구성)
- `Assets/_Project/Scripts/UI/Outgame/TournamentDetailPopup.cs` (**삭제**)
- 호출처: `TournamentHistoryPanel` 의 행 클릭 → 팝업 `Show(entryId)` 경로

## 구현

**레이아웃** — 결과 화면(`ResultScreen`)의 2컬럼 룩을 기준으로 한다. 좌 컬럼 = 토너먼트 목록(스크롤), 우 컬럼 = 랭킹(`LeaderboardList.Render`). 헤더/닫기는 기존 패널 것을 유지한다.

**진입 흐름**

1. `OnEnable` → `GetUnclaimedEntries` (기존 그대로).
2. 응답을 **`createdTime` 내림차순**으로 정렬한다. 서버 정렬에 기대지 않는다. 파싱 실패 행은 맨 뒤로(버리지 않는다).

   > **`createdTime` 은 ISO-8601 이 아니다.** swagger 에는 `format: date-time` 으로 적혀 있지만 dev 서버가 실제로 주는 값은 **epoch 밀리초 문자열**이다(`"1785419835370"` — 2026-07-30 실측). ISO 만 파싱하던 기존 `FormatDate` 는 그래서 **항상 빈 문자열을 반환했고**, 목록의 날짜 칸이 계속 비어 있었다(그게 표시 요청이 나온 이유다). 정렬이 같은 파서를 공유하므로 "최신순"도 사실은 서버 순서 그대로였다. **둘 다 받는다** — 전부 숫자면 epoch(13자리=ms, 10자리=s), 아니면 ISO.
3. 첫 항목을 선택 상태로 만들고 그 `tournamentEntryId` 로 랭킹을 부른다.
4. 목록이 비면 좌우 모두 안내 상태 — 좌 "참가한 토너먼트가 없습니다", 우는 랭킹 대신 같은 안내.

**행 표시** — 토너먼트 이름 / **일시** / 순위 / 점수. 일시는 현행 `FormatDate` 를 살리되 포맷을 `yyyy.MM.dd HH:mm`(로컬)으로 넓힌다 — 목록이 선택 UI 가 되고 최신순 정렬이 붙어 같은 날 참가가 구분돼야 한다. 파싱 실패는 빈 문자열(행을 죽이지 않는다). 정렬과 표시가 **같은 파싱**을 쓰게 해서 "표시는 됐는데 정렬은 맨 뒤" 같은 어긋남을 막는다.

**선택 갱신** — 좌측 행 클릭 → 선택 하이라이트 이동 → 우측 "불러오는 중" → `GetResult` → `BuildRows` → `Render`. 캐시하지 않는다.

**epoch 가드** — 선택할 때마다 epoch 를 올리고, 응답 콜백에서 `epoch != _epoch` 면 버린다. 은퇴하는 팝업이 쓰던 규칙을 패널로 옮기는 것이다. 목록 로드에도 같은 가드가 이미 있으면 유지한다.

**상태 표시** — 로딩/빈/실패를 좌·우 **각각** 가진다. 목록 실패와 랭킹 실패는 서로 독립이다(랭킹이 실패해도 목록은 남아 다른 토너먼트를 고를 수 있어야 한다).
