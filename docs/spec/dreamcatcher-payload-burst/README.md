# Dreamcatcher Payload Burst — 페이로드 다연발 (n초 간격 m발)

> 상태: **초안 (승인 대기)** · 2026-07-27 · 선행: `dreamcatcher-attack-decoupling`(완료)

## 목표

발동 1회에 투사체를 **1발**만 쏘던 페이로드를 **n초 간격 m발**로 확장한다. 첫 실증은 비수(`poke_needle`) — 0.2초 간격 5발.

## 왜 어렵지 않은가 (재사용 자산)

핵심 로직이 이미 있고 검증돼 있다:

- **`VolleyMath.TickBurst(dt, ref remaining, ref timer, intervalSec)`** — 머신거너 10연발(0.1초 간격)이 쓰는 순수 함수. 한 프레임에 여러 발이 밀려도 `while` 로 정확히 소진하고 `intervalSec <= 0` 이면 같은 프레임에 전부 나간다. EditMode 로 이미 고정돼 있다(`defender-directional-volley` unit 0).
- **`SpawnNeedleCarrier` / `PickFallbackTarget`** — `attack-decoupling` 리팩토링에서 세 사건 지점이 공유하는 발사·선정 헬퍼. 버스트의 매 발이 그대로 재사용한다.

즉 이 spec 의 실제 작업은 "**상태를 어디에 두고 언제 틱하느냐**" 하나다.

## 핵심 결정 — 상태는 슬롯에

`VolleyFireState` 를 **재사용하지 않는다.** 엔티티당 1개 컴포넌트라, 머신거너(이미 사용 중)에 비수를 붙이면 서로의 버스트를 덮어쓴다. 비수는 아무 유닛에나 붙는 카드이므로 host 의 볼리 상태와 독립이어야 한다.

버스트 상태는 `DcTriggerSlot` 에 둔다 — 슬롯은 이미 "효과 인스턴스 1개 = 독립 카운터"(`unit-trigger` 계약 4)라, 같은 카드 2장이면 버스트도 각자 돈다.

## 검증 질문

> 비수가 5회째 공격에 **0.2초 간격 5발**을 쏘고, 그 유닛이 머신거너여도 host 볼리와 서로 간섭하지 않는가? 버스트 도중 host 가 죽거나 대상이 사라져도 시뮬이 깨지지 않는가?

## 작업 단위 (초안)

| # | 구분 | 목적 |
|---|---|---|
| 0 | 데이터 | `DcPayloadSpec` 에 `shotCount`·`shotIntervalSec` append + 시트 컬럼 2개. 기본값(1발/0초) = 기존 카드 무손상 |
| 1 | 슬롯+틱 | `DcTriggerSlot` 에 버스트 런타임 필드 + `TickBurst` 를 도는 지점 1곳. 세 아키타입 공통이어야 하므로 `AttackSystem.OnUpdate` 상단(캐스트 드레인 옆) |
| 2 | 발사 | 발동 시 1발 즉시 + 나머지 예약 → 틱이 `SpawnNeedleCarrier` 로 소진. EditMode |
| 3 | 데이터 적용 | 비수 = 0.2초 × 5발. 시트 왕복 + Play 확인 |

## 결정이 필요한 지점 (승인 시 확정)

1. **대상 스냅샷 vs 매 발 재선정.** 머신거너는 `template` 스냅샷("한 번의 공격"이라 도중에 값이 바뀌면 안 된다 — `directional-volley` 계약 8의 결). 비수도 스냅샷이면 선례와 일관되지만, 5발 도중 대상이 죽으면 남은 발이 허공에 간다(호밍이라 투사체는 자동 소멸). **권장: 스냅샷.**
2. **버스트 중 재발동.** period 5 × 0.2초 간격 5발 = 총 1초. 그 사이 공격 5회가 더 들어가면 트리거가 겹친다. 머신거너는 쿨다운을 버스트 종료까지 늘려 구조적으로 막지만(계약 8) 비수는 카운트 기반이라 그 수단이 없다. **덮어쓰기 / 무시 / 누적** 중 택일. **권장: 무시**(가장 예측 가능, 카운터는 계속 돌되 버스트가 진행 중이면 새 버스트를 시작하지 않는다).
3. **host 사망 시 잔여 발.** 슬롯이 엔티티와 함께 사라지므로 자연 중단된다 — 머신거너의 "컴포넌트째 사라져 자연 중단"과 같다. 별도 처리 불요로 본다.

## 계약 초안

1. **버스트는 슬롯 소유.** 상태 쓰기는 `AttackSystem` 전용(`attack-decoupling` 계약 2 의 연장 — host 당 사건 지점 1곳 규칙은 그대로).
2. **기존 카드 무손상.** `shotCount <= 1` 또는 미설정이면 현행 단발 경로와 **바이트 동일**하게 동작한다.
3. **발사당 데이터는 발동 시점 스냅샷.** 카드가 버스트 도중 회수돼도 7번째 발이 1번째와 달라지지 않는다(`VolleyFireState.template` 주석의 의도를 그대로 계승).
4. **`TickBurst` 를 재구현하지 않는다.** 간격/소진 규칙은 `VolleyMath` 한 곳이 권위다.
5. **틱 지점은 1곳.** 세 아키타입(RESOLVE·폭탄맨·캐스터)이 공유한다 — 사건 지점마다 틱을 복제하면 `attack-decoupling` 이 없앤 병이 재발한다.

## 스코프 밖

- **다른 payload 의 다연발.** `ApplyCcToTarget` 등에 확장할지는 비수 실증 후 판단.
- **확산각(spread).** 머신거너의 `spreadAngleDeg` 는 방향탄 개념이라 호밍 니들엔 의미가 다르다.
- **발당 데미지 재조정.** 5발이면 총 100 데미지가 된다 — 밸런스는 시트에서 별도 조정(구조 먼저).
