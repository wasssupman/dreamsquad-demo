# three-minute-survival — 3분 생존 · 처치 점수 개편

> 상태: **units 0~3 구현 완료(컴파일만 검증) 2026-08-07 · Unity 검증 대기**
> 인계: `4_handoff_summary.md` · **검증 체크리스트: `5_verification_checklist.md`
> — `goal-tower-siege` 까지 포함한 통합본이다. 세션 복구 시 이 파일부터 읽는다.**
> 선행: `battle-score-formula`(폐기 대상 산식), `wave-pattern`(케이던스), `battle-leak-limit-hud`(스트레스 배지)
> 자매 spec: `goal-tower-siege` — "적이 골에 살아남아 타워를 때린다"는 **여기 없다**. 이 spec 은
> 유출 즉시 안정도가 깎이는 모델이고, 공성은 그 뒤에 피해 도착 방식만 교체한다.

## 목표

판의 규칙을 **"3분 동안 누가 많이 팼나"** 로 바꾼다. 웨이브 당기기를 없애고, 전멸하면 바로
다음 웨이브가 오고, 골을 뚫리면 골의 **안정도**가 깎인다. 안정도가 0이면 끝이고, 점수는
처치로만 벌며 동점은 남은 안정도로 가른다.

검증 질문: *"플레이어가 '빨리 밀어서 웨이브를 더 받는 것'이 곧 점수라는 걸 3분 안에
체감하고, 안정도 바 하나로 자기가 지고 있는지 즉시 읽는가?"*

## ECS 를 쓰지 않는다 (rev 2 결정)

초안은 골 타워를 ECS 엔티티로 만들어 적이 때리게 했다. 리뷰에서 그 설계 하나가 결함
대부분을 만든다는 것이 확인됐다(공유 체력 미러 산술 오류 · 유출 뷰 despawn 과 충돌 · 원거리
적이 골 앞에서 멈춰 스트레스가 안 오름 · 보스는 `hunting` 이라 골에 도달조차 안 함 · 투사체
피해자 풀 진영 하드코딩 · 드림캐쳐 계약 5곳). **요구사항 4개는 ECS 변경 0으로 전부
달성되므로** 안정도는 브리지가 소유하는 값으로 두고, 공성은 `goal-tower-siege` 로 분리했다.

## Feature-wide 계약

- **패배는 안정도 0 하나다.** 스트레스(`_goalReachedCount`)는 카운터로 남지만 패배 게이트에서
  떼어내고, 배지는 분모·위기색 없이 **개수만** 표시한다(엔드리스의 기존 표시 모드 재사용).
- **승/패 정의**: 3분 완주 = 승리, 안정도 0 = 패배. 웨이브 소진 승리(`CheckVictory`)는 사문화
  되지만 경로는 남긴다.
- **점수는 처치로만 번다.** 시간 축·스트레스 축은 산식에서 삭제한다. 값은 `killScore` 를
  티어(일반/엘리트/보스)로 재장전하므로 **가중 점수**다 — 화면 라벨은 `점수`이고 `처치 N기` 는
  결과 화면의 별도 줄이다. "처치 수 = 점수"라는 표현을 UI 라벨로 쓰지 않는다.
- ~~**서버 제출값 = `판별오프셋 + kills점수 × 1000 + 남은안정도permille`**~~ → **unit 6 이
  폐기했다(2026-08-15).** 제출값 = `killScore` 합 **생값**이고 표시도 변환 없이 그대로다.
  안정도는 패배 조건과 결과 화면의 정보 줄로만 남고 **점수 경로에 전혀 없다**. 동점은 그냥
  동점(정렬은 서버 규칙). 구 인코딩 기록은 변환하지 않고 원값으로 둔다.
- **판 마감은 관문 하나다**(unit 7). 종료 5경로는 판정만 하고 `BattleBridge.EndMatch` 로
  들어온다: 취합(`BuildTally` → `MatchTally`) → 기록(로거) → 통보(서버) → 표시(결과 화면).
  **제출이 표시보다 앞**이라는 순서는 계약이다(화면을 기다리다 앱이 죽으면 기록이 사라진다).
  점수 취합 지점과 제출값 정의는 각각 **한 곳뿐**이어야 한다 — `BuildTally` 와
  `MatchTally.SubmissionScore`.
- ~~**안정도 피해는 유출 즉시 1회**다~~ → **`goal-tower-siege` units 0~1 로 지속 피해 모델로
  교체됨(2026-08-08).** 공격 수단이 있는 적은 골에 남아 타워를 때리고, 없는 적(Runner·Swift)만
  기존 즉발 경로로 자폭한다. 안정도의 정본도 브리지 → `GoalTowerHealth` 싱글턴으로 이동했다.
  이 spec 의 공개 API(`GoalStabilityCurrent`/`Max`)·체력바·tie-break 는 그대로다.
- **웨이브 진행 = 필드에 적 0기 OR 현재 웨이브 트리거 후 20초.** 시계는 `_battleClock`(Battle
  도메인)이다 — 실시간을 쓰면 정지·슬로우모에서 갈라진다.
- **스폰 창 불변식**: `waveSpawnLeadInSec + (N−1) × intraWaveSpacingSec < maxWaveIntervalSec`.
  위반하면 `_pending` 이 영구히 비지 않아 **전멸 트리거가 구조적으로 죽는다**. 수량 상한을
  올릴 때 `intraWaveSpacingSec` 을 함께 내린다.
- **웨이브 상한 100은 명목값**이다. 3분·20초 상한에서 실제 도달은 10~16웨이브이므로 수량
  곡선은 **도달 구간에서 성장이 보이도록** 저작한다.
- **작성 플랜(`WavePlanAsset`) 경로는 기존 시각 스케줄을 유지한다.** 저작된 `durationSec`
  타임라인이 그 모드의 정본이므로 이벤트 구동을 적용하지 않는다(`wave-authoring-test-mode` 계약).
- **같은 맵 = 같은 웨이브 불변식 유지.** 곡선이 바뀌어도 jitter 는 `waveSeed` 파생 rng 이다.
- 새 ECS 컴포넌트·시스템·맥락·이벤트 채널을 만들지 않는다.

## 파이프라인 커버리지

**N/A — 신규 플레이 오브젝트가 없다.** 안정도는 브리지가 소유하는 값이고, 바는 기존
`UnitOverheadView`(UI 레이어)에 스킨을 추가해 그린다. 골 구조물 메쉬는 이미 배치된
`theme.goalStructureProp` 이다. 새 ECS 컴포넌트·이벤트 큐·View 풀·씬 오브젝트가 없어
`docs/reference/object-pipeline-map.md` 갱신 대상이 아니다. (골 타워를 엔티티로 만드는
`goal-tower-siege` 는 자기 spec 에서 Blocking 해저드 아키타입과 대조한다.)

## 후속 후보

- **몽마의 계약 코스트 재지정** [M] · 스트레스 한계가 패배와 무관해지면 "허용치 선불"이
  공짜가 된다. 코스트를 안정도 선불로 옮기는 설계가 필요하다.
- **적 티어 등장 규칙** [M] · 이번엔 값만 티어로 재장전한다. `EnemyClass` 는 행동 아키타입
  (Tanker/Runner/Bruiser/Shooter)이라 강함 티어가 아니므로, 웨이브별 엘리트 비율 규칙은
  라벨 신설과 함께 별도로 잡는다.
- **엔드리스 전용 규칙 재설계** [M] · 엔드리스의 검증 질문("당기기로 킬을 벌고 누수로 깎이는
  리스크/리워드")이 당기기 제거로 소멸한다. `endless-mode` 계약 4 갱신 이상의 재설계가 필요.
- **브리핑 스트립 100웨이브 표현** [S] · unit 2 에서 카드 수에 상한을 걸어 인트로 폭주만
  막는다. 스크롤·요약·구간 표현은 범위 밖.
- **사막 테마 골 구조물** [S] · `desert.asset:71` 의 `goalStructureProp` 이 비어 있어 그 시즌
  에서는 바가 구조물 없이 뜬다. 기본 시즌(forest)에는 영향 없다.
