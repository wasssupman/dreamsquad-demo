# unit 6 — 재배치(이동모드)가 화면 밖에 도달한다

## 목적

이미 놓은 유닛을 **화면 밖 자리로 옮길 수 있게** 한다. 지금 이동모드는 「판 전체가 보인다」를
전제로 짜여 있어, 팬이 들어오는 순간 **보이는 만큼만 옮길 수 있는 기능**이 된다.

넓은 판에서 이건 사소한 제약이 아니다. 배치 유닛 수가 한정된 게임에서 **재배치는 «성긴 방어선의
구멍을 메우는» 유일한 즉시 대응**인데, 그게 화면 안에 갇히면 「봐도 못 막는다」가 된다.
관측 수단(팬·오버뷰)만 늘리고 개입 수단을 안 늘리면 억울함은 그대로 남는다.

## 지금 상태

- `DefenderRelocationController` 는 이동모드 동안 **매 프레임 `SetMoveOverview()` 를 먹인다.**
  코드 주석이 전제를 명시한다 — *"줌아웃 고정 오버뷰(목적지 선택 위해 보드 전체 가시)"*.
  그런데 그 오버뷰는 fit 이 아니라 **고정 dolly**(저작값 −4.5)라, 판이 커지면 전체가 안 들어온다.
  전제가 조용히 깨진다.
- 목적지 지정 제스처가 **보드 press-drag** 라, 이동모드 중에는 그 손가락이 이미 쓰이고 있어
  **팬이 불가능**하다.
- 이동모드에는 타임아웃이 있다.

## 구현

**이동모드에서도 오버뷰 홀드가 열린다.** unit 5 의 계약을 그대로 재사용한다 —
오버뷰는 **커밋만 잠그므로** 「옮기는 중」 상태는 유지된다:
**이동모드 진입 → 오버뷰 홀드 → 목적지 탭 = 워프(이동모드 유지) → 평소처럼 놓는다.**
armed 배치(unit 5)와 **같은 흐름**이라 배울 것이 하나도 늘지 않는다.

**`SetMoveOverview` 는 새 오버뷰 상태로 흡수한다.** 고정 dolly 채널을 유지하면 (a) 큰 판에서
전제가 깨지고 (b) unit 5 의 오버뷰와 이중으로 얹힌다. 채널 하나가 줄어드는 쪽이 맞다.
camera-direction unit 16 의 판단과 같은 계열이다 — *"같은 예외를 다섯 번 쓰면 축이 틀린 것"*.

**타임아웃은 오버뷰 중 정지한다.** 목적지를 고르려고 판을 읽는 시간이 이동모드를 취소시키면 안 된다.
타임아웃 상수는 `DefenderRelocationController` 가 소유한다 — 그 필드가 SO 가 아니면 이 unit 에서
SO 로 옮긴다(제약 6).

## 완료 기준

- 이동모드에서 **현재 화면 밖 셀로 유닛을 옮길 수 있다.**
- 이동모드 중 오버뷰를 눌렀다 떼도 **이동모드가 유지**되고 타임아웃이 그동안 흐르지 않는다.
- 이동모드 오버뷰가 **dolly 이중 적용 없이** 판을 보여준다(unit 5 의 상태 하나만 관여).
- 기존 재배치 회귀 테스트 초록 — 착수 시 `Assets/_Project/Tests/PlayMode/` 에서 재배치를 커버하는
  테스트를 grep 해 이름을 이 줄에 적고 돌린다(`defender-relocation` spec 의 완료 기준이 출발점).
