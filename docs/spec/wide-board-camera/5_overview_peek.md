# unit 5 — 홀드-투-피크 오버뷰 (판 전체를 보는 동사)

## 목적

판 전체를 보는 수단을 준다. 단 **상시 정보가 아니라 동사**로 — 버튼을 **누르고 있는 동안만**.
그리고 이 동사가 「armed 인데 멀리 놓고 싶다」까지 함께 푼다.

## 왜 토글이 아니라 홀드인가

토글 + 읽기 전용으로는 **대가가 성립하지 않는다.** 코스트 회복이 `regenPerSec 0.35` / `maxCost 10`
이라 상한에 닿는 데 약 28초가 걸린다 — 2초 왕복 오버뷰의 자원 손실은 **0** 이고, 판이 끝나는 것도
아니다. 대가가 없으면 3초마다 스팸하게 되고, 그때 남는 건 3분 내내 먼 거리와 가까운 거리를
수십 번 왕복하는 **멀미**다.

홀드는 그 문제를 구조로 없앤다: 손가락이 묶여 있어 읽기 전용이 자동 성립하고, 체류가 자기 제한적이며,
전환을 컷 또는 아주 짧은 페이드로 하면 **왕복 자체가 사라진다.** 이 프로젝트에 이미 있는 어휘다 —
드림캐쳐 카드의 슬로모 수명이 정확히 press~release 다.

## 변경 대상

- `Assets/_Project/Scripts/Presentation/CameraDirector.cs`
- `Assets/_Project/Scripts/Data/CameraDirectionConfig.cs` + `.asset` (오버뷰 레시피)
- `Assets/_Project/Scripts/UI/DefenderDragPlacementController.cs` (워프 탭)
- `Assets/_Project/Scenes/BattleScene.unity` (전투 HUD — 오버뷰 버튼 배선)

## 구현

**오버뷰는 상태다, 채널이 아니다.** `CameraState` 에 `Overview` 를 **enum 끝에 append** 한다 —
값이 `CameraDirectionConfig.asset` 에 정수로 직렬화돼 있어 중간에 끼우면 배치/전투 레시피가 밀린다.
레시피는 `distanceMode = FitBoard` 를 쓴다(그래서 `FitDistance` 가 산다 — unit 2 의 새 스키마).

**워프 탭의 터치 규칙.** 오버뷰 버튼을 누른 손가락은 홀드를 유지하고 **두 번째 손가락**이 판을
탭한다. 이것이 이 spec 이 여는 **유일한 동시 터치**이며(계약 2), 두 포인터의 역할은 겹치지 않는다 —
버튼 터치 id 는 오버뷰 수명만, 보드 터치 id 는 워프 지점만 소유한다. 보드 터치는 워프 1회로 끝나고
팬으로 승격하지 않는다(오버뷰 중에는 팬이 잠긴다). 가로 그립에서 왼엄지 홀드 + 오른엄지 탭이 자연스럽다.
⚠ **에디터 마우스에는 두 번째 포인터가 없다.** 오버뷰 상태에 한해 **버튼 릴리즈 후 grace 0.4초
(SO 저작) 안의 첫 보드 클릭도 워프로 받는다** — 에디터에서 검증 가능하게 하기 위한 통로이고, 실기
확인은 두 손가락 경로로 한다.

**버튼 자리는 기존 코너 예산 안에서 해결한다 — 새 예산을 요구하지 않는다.** 전투 HUD 코너 예약폭은
이미 못박혀 있고(`battle-hud-legibility`), 그 폭이 트레이 슬롯 폭을 정한다. 자리는 우하단 각성 항아리
독 위 세로 스택으로 잡고, 확정되면 `squad-slots-ten` 「검토할 선택지」 3(코너 예약폭 재협상)에
**회수 가능 폭이 줄었다는 사실 한 줄**을 반영한다. 코너 폭을 늘려야 한다는 결론이 나오면 그것은 이
unit 이 단독으로 정할 수 없는 product 결정이므로 **정지하고 질문한다.**

**복귀는 hold 가 아니라 재해석이다.** 오버뷰를 놓을 때 「직전에 뭐였는지」로 돌아가지 않고
**현재 페이즈에서 상태를 다시 푼다.** 「직전 상태로 복귀」는 camera-direction unit 11 이
*"재현이 어려웠다"* 며 은퇴시킨 구조다. 되살리지 않는다.

**관심점은 유지된다.** 오버뷰에서 나오면 들어가기 전 관심점으로 돌아온다(워프하지 않았다면).

**이름 충돌 고지 — 개명은 하지 않는다.** 「오버뷰」는 이미 쓰이고 있다 — `SetMoveOverview` 는
재배치 이동모드용 **additive dolly 채널**(`moveOverviewDolly` 외 3필드, 저작값 −4.5)이다. 성격이 다른
둘이 같은 이름을 쓰지만, **unit 6 이 이 채널을 오버뷰 상태로 흡수하며 제거**하므로 여기서 개명하지
않는다 — 개명 후 삭제는 이중 작업이고 직렬화 필드 4개의 값 소실 위험만 낳는다. 이 unit 에서는
**두 오버뷰가 동시에 걸리지 않게 가드만** 둔다(오버뷰 상태 동안 `moveOverview` dolly 를 0 으로 누르고,
unit 6 이 삭제할 때까지의 임시 가드임을 주석에 남긴다).

**워프 탭 — arm 을 유지한다.** 오버뷰 중 판을 탭하면 그 지점으로 관심점을 옮기고 오버뷰를 나온다.
계약은 **「오버뷰는 커밋을 잠근다」**이지 「배치를 잠근다」가 아니다: arm 도 조준도 **유지**되고,
배치가 확정(커밋)되는 것만 막힌다. 그래서 흐름이 이렇게 된다 —
**arm → 오버뷰 홀드 → 목표 지점 탭 → 워프 + arm 유지 → 평소처럼 배치.**
탭 두 번이 늘 뿐 새 어휘가 없고, 취소존·판정 오프셋·화면 가장자리 어느 것과도 싸우지 않는다.
**이것이 엣지 오토팬을 만들지 않는 이유다**(README 「명시 제외」).

워프 정밀도는 문제가 되지 않는다 — 워프는 구역 정밀도면 충분하고 전투 줌이 좁아 몇 타일 오차는 무해하다.

## 완료 기준

- 버튼을 누르는 동안 판 전체가 보이고, 떼면 **들어가기 전 관심점**으로 돌아온다.
- 오버뷰 중 **배치 커밋·카드 사용이 일어나지 않는다.** arm 과 조준 상태는 **유지**된다.
- arm → 오버뷰 → 탭 → 배치가 **한 흐름으로** 된다(엣지 오토팬 없이 화면 밖에 배치 가능).
- 이동모드 중 오버뷰 버튼을 눌러도 dolly 가 이중으로 얹히지 않는다(개명·흡수 확인).
- 오버뷰 왕복 20회에서 **포즈 오버슈트·프레임 드랍이 없다**(전환 시간 SO 값 0 = 컷이 성립).
  「멀미」는 그 위의 **사용자 체감 확인 1회**로 가른다(실기).
- 오버뷰에서 **「어디가 급한가」가 읽힌다** — 레인 밀집도·뚫리는 방향·골 위치·배치 밀도가 구분된다.
  (「무엇을 내야 하나」=적 종류는 이 unit 의 판정 대상이 아니다 — README 후속 후보 「오버뷰 판독 보강」.)
- **조준 중에도 오버뷰가 열린다** — 손패 카드를 든 채 오버뷰 홀드 → 화면 밖 지점 탭 → 워프 후 조준 유지.
- 배치 페이즈가 꺼져 있어(`placementPhaseEnabled: 0`, 3초 카운트다운) 판을 훑을 시간이 없다는
  점을 Play 로 확인한다. 매치 진입 시 오버뷰에서 관심점으로 내려앉는 1회 비행은 **후속 후보**
  (기존 상태 전환 비행 재사용이라 싸다 — 체감 확인 후 판단).
