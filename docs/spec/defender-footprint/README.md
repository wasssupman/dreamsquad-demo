# defender-footprint — 유닛 Footprint 기반 배치·부착 UX

> 상태: **초안 2026-08-28 — 사용자 승인 대기**
> 사용자 발의(요구 문서 13절) + 아키텍처 결정 4건(2026-08-28, 하단 결정 레코드).
> 원 방향: `docs/spec/placement-mask/` 후속 후보 "footprint 오브젝트 모델"(2026-08-07 방향 탐색)의 UX 축 구체화 — 단, 정본 반전(`MapTileType` 은퇴·blockMask) 없이 현행 논리 타일 체계 위에서 간다.

## 상위 목표

유닛이 임의의 직사각형 **W×H footprint**(가로×세로, 회전 없음)만큼 논리 타일을 점유하게 한다. 이로써 ① 유닛 간 밀집 완화 ② 전투 중 유닛 선택성 개선 ③ 드림캐쳐 부착 오조작 감소 ④ 점유 크기를 활용한 공간 배치 플레이를 얻는다. **별도 배치 Grid·좌표계를 추가하지 않는다** — 기존 논리 타일이 배치·전투 공통 기준이다.

콘텐츠 규격은 1×2·1×3·2×2·2×3·3×2·3×3 이지만 구현은 규격에 비종속(임의 W×H). 기본값 1×1 — **기존 전 유닛 무회귀가 코어 유닛의 완료 기준**이다.

## 검증 질문

> 서로 다른 W×H 유닛이 같은 배치 시스템에서 footprint 만큼 점유하고, 드래그 중 확정될 영역과 **타일별 실패 사유**(지형/점유/맵밖)가 그대로 보이며, 손을 뗀 순간 표시된 위치에 그대로 확정되는가? 밀집 상태에서 탭 선택·드림캐쳐 부착이 의도한 유닛에 안정적으로 걸리고, 배치·부착 직후 연출 구간 안에서 실수를 무손실로 되돌릴 수 있는가?

## 결정 레코드 (2026-08-28 사용자)

1. **sim 무변** — footprint 는 배치 점유(유닛끼리 겹침 금지)와 UX 축만 담당. 적 통행·충돌·전투 규칙 불변(placement-mask B-1 유지: 적은 유닛 칸을 통과·공존). 통행 차단은 후속 후보.
2. **대표 셀 하나** — 사거리·셀 기반 효과의 기준은 footprint 안 대표 셀 1개. 단 **추후 타일 기반 판정을 거리 기반 중심으로 확장할 계획**이므로, 대표 셀 소비처를 단일 헬퍼로 수렴시켜 전환 지점을 한 곳에 모은다.
3. **배치가능 전체 하이라이트 은퇴** — 요구 문서 4절을 문자대로: 드래그 중 배치 가능 칸 전체를 밝히지 않고, **배치 불가 영역 위주** + 손가락 주변 보조 격자로 전환. Ghost 4색이 유효성 전달을 전담.
4. **취소 유예 = 연출 구간** — 배치는 착지 연출~활성화 전(`PendingDeployment`, 전투 미참여 보장이 공짜), 부착은 카드 흡수 비행 완료 전. 되감기(코스트·게이지·덱 원복) 신설.

## Feature-wide 계약

1. **sim 무변** (결정 1): 점유는 전부 브리지(Mono) 소유 — `_occupiedTiles`/`_defenderByTile` 계열의 확장이지 ECS 변경이 아니다. `DefenderTile.cell` = 대표 셀 유지, ECS 컴포넌트·시스템·이벤트 채널 신설 0.
2. **대표 셀 규약** (결정 2): 대표 셀 = footprint 중앙 칸(홀수 변은 정중앙, 짝수 변은 floor). sim 위치(`LocalTransform`) = 대표 셀 중심 — `AttackSystem` 의 좌표→셀 되계산·사거리 산식·스킬 payload(`FiredPosition`) 전부 현행 그대로 대표 셀 기준으로 떨어진다. **앵커↔대표 셀↔점유 셀 열거는 `FootprintMath` 순수 static 하나로 수렴**(거리 기반 전환의 단일 편집 지점). 뷰(Spine)만 footprint 기하 중심에 세운다 — 짝수 변에서 sim↔뷰 반 칸 어긋남은 수용한다(투사체 타격점·데미지 넘버가 반 칸 치우침, 계약으로 명시).
3. **판정·표시 단일 술어 유지 + per-tile 사유**: footprint 판정도 `SpatialPlacementCheck` 계열 한 함수로 수렴하고 UI 는 재판정하지 않는다(placement-eligible-tile-highlight 계약 승계). 판정 결과는 footprint 전체 통과 여부 + 타일별 사유(맵밖/지형/기배치 점유)를 함께 나른다.
4. **표시 원칙 4색** (요구 문서 4절 + 결정 3): 정상 Ghost = 하늘색 / Ghost 안 충돌 타일만 = 빨강 / 기배치 유닛 점유 = 노랑 / 지형 배치 불가 = 무채색. 배치가능 전체 하이라이트(시안 슬랩)는 스위치 오프로 은퇴 — 표시 축은 배치 **불가** 위주 + 손가락 주변 보조 타일 경계.
5. **표시 = 확정**: 릴리즈는 화면에 표시되던 후보를 그대로 쓴다(현행 forceCommit 재해석 유지 — throttle 미대기·같은 규칙 재적용). 근처에 유효 후보가 없으면 원거리 강제 보정하지 않고 배치 불가 유지.
6. **자석 스냅은 유효 앵커 탐색**: 후보 앵커가 무효일 때만 반경 제한 내 최근접 유효 앵커로 흡착. 스냅 거리·유지 범위·히스테리시스 전부 SO 노브(하드코딩 금지, `DragSwaySettings` 선례).
7. **배치와 부착은 별개 상호작용** (요구 문서 8절): 배치 = 타일 선택, 부착·선택 = 유닛 선택. 판정 로직·입력 보조를 공유하지 않는다. 부착·선택 영역은 footprint 와 별개로 확장 가능(1폭 유닛 대응 — 요구 문서 10절).
8. **렌더 순서 ↔ 입력 판정 분리 유지** (요구 문서 9절): 현행도 분리돼 있다(`BoardSortOrder` 행 기준 vs 픽킹 중심거리). 재설계 후에도 앞 유닛이 뒤 유닛의 상호작용을 막지 않아야 하고, 강조 UI 는 스프라이트 중첩 위에 뜬다(현행 UI 오버레이 유지).
9. **취소 유예 = 연출 구간** (결정 4): 유예 중 실제 효과·전투 행동이 시작되지 않음을 상태로 보장(배치 = `PendingDeployment` 전투 미참여 / 부착 = 커밋 효과 적용 시점을 흡수 완료로 정렬하거나 되감기 범위로 포괄 — unit 5 에서 확정). 이미 발생한 전투 결과의 롤백은 불채택. 취소는 무차감 원복(drag-cancel-affordance 계약 1 승계).
10. **footprint 는 배치 중 회전하지 않고**, 표기는 항상 가로×세로. 신규 W×H 추가가 시스템 구조 변경을 요구하면 안 된다(데이터만).

## 후속 후보

- **타일 기반 판정 → 거리 기반 중심 확장** [L] · 공격 범위/판정 등 셀 기반 산식을 거리 기반으로 전환 (2026-08-28 사용자 계획). 이 spec 은 대표 셀 소비처를 `FootprintMath` 로 수렴시키는 것까지만 — 전환 지점 한 곳 확보.
- **적 통행 차단 footprint** [M] · `OccupiedCellsBuffer`+`BlockingHazard` 편입으로 방어 유닛이 통행을 막는 축. 흐름장 1회 굽기 제약(우회 아닌 충돌 정지)과 교착 리스크를 함께 설계해야 함.
- **사거리 다중 셀 판정** [M] · 몸이 큰 만큼 사거리 실효 확대(구조물 최근접 칸 선례). `AttackReach` 소비처 5곳 + 게이트/랭킹 비대칭 정리 포함.
- **footprint 오브젝트 모델 정본 반전** [L] · placement-mask 후속 후보 그대로 — `MapTileType` 은퇴·blockMask 파생. 이 spec 과 독립.
- **콘텐츠 저작** · 유닛별 footprint 실값·선택/부착 영역 튜닝(시트) — 시스템 완성 후 밸런스 작업.
