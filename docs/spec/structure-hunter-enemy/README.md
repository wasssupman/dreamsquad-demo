# structure-hunter-enemy — 거점 사냥꾼 (막을 수 없고, 죽여야만 막힌다)

> ## 목표 3줄
>
> 1. **방어유닛을 쳐다보지도 않는 적을 만든다** — 때려도 반격하지 않고 마음(골)으로 직진한다.
> 2. **유인이 통하지 않는다** — 가디언을 던져도 안 끌려온다. 판의 대응 축 두 개(몸으로 막기 / 화력) 중 앞쪽이 무력화된다.
> 3. **그런데 코드는 한 줄도 안 고친다** — `battle-structures` 가 이 동작을 전부 구현해뒀다. 이 spec 은 그 기계의 **첫 콘텐츠**다.

상태: **unit 0 완료 2026-08-11**(`04a63dd8` + 리뷰 반영) · unit 1 착수 대기 · 사용자 Play 체감 확인 미완

- unit 0 = 저작 + 카탈로그 등재 + 라이브 계측. **`.cs` 변경 0줄**로 끝났다(계약 1 성립)
- ⚠ **덱 편입은 unit 0 에서 빠졌다.** 처음엔 라이브 덱 6종에 넣었으나 리뷰에서 **웨이브 재추첨 회귀**가 확인돼 되돌렸다 — 아래 §덱 편입이 왜 unit 1 인가 참조

## 상위 목표

`battle-structures`(완료 2026-08-10)가 「진영 × 종류」 축을 세우고 **저작 타겟 마스크**와 **도발 범위 게이트**를 구현했다. 그 spec 의 unit 2 는 자기 목적을 이렇게 적었다 — *"유닛을 노리지 않는 적은 유인으로 막을 수 없다. (…) **이것이 거점 콘텐츠가 만드는 첫 전술 축이다.**"*

**그 축을 쓰는 적이 아직 0마리다.** 기존 적 12종은 전부 레거시 마스크(방어유닛 + 방벽 + 방어 마음)로 굽혀 있어 「거점 전담」이 표현만 가능하고 존재하지 않는다.

이 spec 은 그 첫 마리를 만든다.

## 검증 질문

> 가디언을 던져도 안 끌려오고, 방어유닛 사이를 **그냥 지나쳐** 마음을 때리는가?
> 그리고 플레이어가 「막는다」가 아니라 「녹인다」로 대응을 바꾸는가?

이 질문에 답하는 데 필요하지 않은 것은 이 spec 에 넣지 않는다.

## 왜 코드 변경 0 인가 (착수 전 대조 완료)

원하는 동작 넷이 전부 **이미 구현된 경로의 자연스러운 귀결**이다.

| 원하는 동작 | 무엇이 그렇게 만드나 | 근거 |
|---|---|---|
| 도발이 안 걸린다 | `AggroStateSystem` 이 «유닛을 안 노리는 적»에게 `Aggroed` **부착 자체를 막는다** | `battle-structures/2_taunt_scope_gate.md` — 구현·테스트 완료(`StructureOnlyEnemy_IsNotAggroed`) |
| 방어유닛을 안 때린다 | `AttackState.targetMask` 후보에 유닛 비트가 없다 | `battle-structures/1_authored_target_mask.md` — 마스크는 저작값에서 굽는다 |
| 골로 직진한다 | 사거리 안에 때릴 대상이 없으면 `bestTarget = Entity.Null` → FSM `Marching` 유지 | `EnemyAiStateSystem` 현행 |
| 골에 붙으면 때린다 | 후보 쿼리(`FactionTag`+`Health`+`LocalTransform`)는 **거점을 이미 담고 있다** | `object-pipeline-map.md` 거점 표 — *"막던 것은 마스크 리터럴이었다"* |

저작값은 `AttackUnitData.targetFactions` 하나다.

**⚠ 그래서 이 spec 의 첫 번째 위험은 「코드를 고치고 싶어지는 것」이다.** 고쳐야 할 것 같으면 정지하고 «왜 저작으로 안 되나»를 먼저 답한다(계약 1).

### 마스크는 `DefenderCore | BlockingHazard` 다 — 방벽을 빼면 벽에 갇힌다

**마음만 주면 안 된다.** `continuous-agent-movement` 의 확정 계약(D1-b)이 *"막으면 돌아간다"* 이고, **완전 봉쇄의 해소 수단이 「적이 차단 해저드를 부순다」** 다(`destructible-blocking-hazards`, 구현 완료). 같은 spec 이 *"연결성 검사는 없다. 완전 봉쇄 자체는 가능하다"* 고 명시한다.

마스크에서 방벽을 빼면 이 적은 **그 안전망 밖으로 나가** 벽 앞에서 영구 교착된다. 그래서 방벽은 마스크에 남긴다.

**정체성은 손상되지 않는다** — 도발 게이트가 보는 `Factions.AnyUnit` 은 `DefenderUnit | EnemyUnit | NeutralUnit` 이라 `BlockingHazard`(1<<2)가 **포함되지 않는다.** 방벽을 때릴 수 있어도 도발은 여전히 안 걸린다.

## 이 적이 판에 만드는 것

지금 판의 대응 축은 셋이다 — **①유인**(도발) **②길막**(방벽) **③화력**. 거의 모든 적이 셋 다에 걸린다.

거점 사냥꾼은 **①만** 무력화한다. "다 막았는데 한 마리가 통과했다"가 처음으로 성립한다.

**②와 ③은 그대로 통한다.** 방벽은 마스크에 남아 있으므로(계약 4) 경로에 세우면 이 적이 **멈춰 서서 그것을 때린다** — `Halt` + 사거리 1 이라 방벽 하나가 실제 지연 수단이 된다. 드림캐쳐 CC(수면·기절)와 이동 감속도 걸린다. **막히는 것은 유인 하나뿐**이고, 이것이 이 적을 불공평하지 않게 만드는 안전판이다(계약 3).

> **⚠ 「막을 수 없다」는 수사이지 사양이 아니다.** 사양은 «가디언으로 유인할 수 없다» 하나다. 밸런싱할 때 방벽·CC 가 통하는 것을 결함으로 읽지 말 것.

**밸런스 knob 은 HP·이동속도·근접 피해·「한 웨이브에 몇 마리」다.** 막을 수 없으니 HP 로 시간을 사는데, 동시 등장 수가 곧 「살 수 있는 시간」의 총량이라 그쪽이 훨씬 민감하다(unit 1 완료 기준).

**`stabilityDamage` 는 이 적에게 죽은 값이다** — `UnitLifecycleSystem` 이 `canSiege = AttackState 보유` 로 판정하고, 브리지의 유출 처리에서 `canSiege` 인 적은 `stabilityDamage` 를 읽기 **전에** 분기를 빠져나간다. 이 적의 골 압박은 유출이 아니라 **타워 HP 를 직접 깎는 근접 피해**에서 나온다. knob 목록에 넣지 말 것.

### 덱 편입이 왜 unit 1 인가 (되돌린 이유)

unit 0 초판은 라이브 덱 6종의 `attackUnitPool` 에 이 적을 넣었다. **되돌렸다.** 리뷰가 잡은 것:

1. **웨이브 전체가 재추첨된다.** `WavePatternGenerator` 는 `rng.NextInt(0, pool.Count)` 로 뽑는다. 풀이 10→11 이 되면 `waveSeed` 가 고정이어도 **웨이브 1부터** 구성이 전부 바뀐다. 6개 맵의 검증된 난이도 곡선이 통째로 미검증 곡선으로 교체되고, 같은 시드로 기록된 과거 토너먼트 제출과 비교가 끊긴다.
2. **초반 웨이브가 `Enemy_Basic` 쪽으로 쏠린다.** `ResolveWaveEligibleIndex` 는 게이트에 걸리면 **풀 순서로 앞으로** 순환한다. 이 적을 맨 뒤(index 10)에 붙였으므로 웨이브 1~7 에서 index 10 이 뽑힐 때마다 index 0 = `Enemy_Basic` 으로 떨어진다.
3. **`Deck_Endless` 가 빠졌다.** `WaveKillBudgetPinTests` 가 라이브 덱을 **7종**(6 + Endless)으로 열거한다. 6종만 넣으면 무한 모드만 조용히 이 적을 못 본다 — `Kindler` 가 이미 같은 방식으로 누락돼 있어 드리프트가 누적된다.
4. **동시 등장 상한이 없다.** 보스 호위(`bossEscortMin/Max` 3~4)가 이 적으로 뽑히면 400HP·유인 불가 3~4기가 한꺼번에 나온다. 1000HP 타워에 25 피해/1초라 3기면 약 13초에 골이 무너진다.

**따라서 편입은 밸런스와 같은 커밋이어야 한다.** unit 1 이 ⑴ 동시 등장 상한 ⑵ 7종 전부(Endless 포함) ⑶ 풀 삽입 위치 ⑷ **웨이브 재기준을 의도적 결정으로 명시**(시드 변경 여부 포함)를 함께 처리한다. unit 0 의 계측은 강제 스폰 경로로 했으므로 이 되돌림에 영향을 받지 않는다.

**신규 컴포넌트 0 · 신규 시스템 0 · 신규 이벤트 채널 0 · 신규 SerializeField 0.**

## Feature-wide 계약

1. **코드 변경 0 이 목표이자 검증선이다.** 이 적이 요구하는 동작은 전부 `battle-structures` 가 구현했다. 코드를 고쳐야 할 것 같으면 **정지하고 «왜 저작으로 안 되나»를 먼저 답한다.** (예외: unit 1 의 시각 구분이 뷰 계층에서 저작으로 안 되는 경우 — 그때도 sim 은 안 건드린다.)
2. **도발 면역은 부작용이 아니라 정체성이다.** `AggroStateSystem` 의 게이트를 예외 처리하지 않는다. 그 게이트를 뒤집으면 `battle-structures` 의 검증 질문이 무너진다.
3. **대응 수단을 전부 막지 않는다.** CC·이동 감속·화력·드림캐쳐 페이로드는 그대로 통한다. 막히는 것은 **유인 하나뿐**이다. 이 적에게 CC 면역이나 피해 감소를 붙이지 않는다 — 그 순간 «막을 수 없는 적»이 «상대할 수 없는 적»이 된다.
4. **방벽은 마스크에 남긴다.** 「거점만」을 문자 그대로 구현하면 완전 봉쇄에서 영구 교착된다(위 §마스크 참조). 방벽 타격은 도발 게이트를 열지 않으므로 정체성 비용이 0이다. **이 비트를 «불순물»로 보고 빼려는 후속 판단을 막기 위해 계약으로 둔다.**
5. **레거시 폴백을 건드리지 않는다.** `EnemyTargetDefaults.Resolve` 의 «0 = 미저작 = 레거시 마스크» 규약은 기존 12종의 무회귀 근거다. 신규 적은 **명시 저작**으로 그 분기를 안 탄다.
6. **검증은 증상 카운터로 한다.** "가끔 도발된다"는 장면 목격으로 부재를 증명할 수 없다. `target-persistence` 가 쓴 방식(반례를 **세어** 0 확인)을 그대로 쓴다.
7. **스코프는 침략 모드 기준이다.** 공성 모드(적 마음 = 스폰지점)에서의 거동은 확인만 하고, 다르게 만들지 않는다.

## 결정

**결정 1 — 무장은 근접이다.** `attackRange` 1~2 로 골에 붙어서 때린다. 원거리로 두면 골 사거리 밖에서 안전하게 때려 「죽여야만 막힌다」가 「사거리 밖에서 자유롭게 때린다」로 바뀐다 — 그건 다른 적이다.

**결정 2 — 등장은 중반 이후다.** 판의 대응 축 하나를 지우는 적이라 초반 웨이브에 나오면 학습 없이 맞는다. `minWaveNumber` 로 게이트하고 정확한 값은 unit 1 밸런싱에서.

**결정 3 — 「골 락 금지 가드」는 존재하지 않는다(초판 정정).** 초판은 `target-persistence` 계약 3 의 가드가 승계된다고 적었는데 **틀렸다.** `battle-structures` unit 0 이 골의 최후순위·잠금금지 두 예외를 **제거**했고, `AttackSystem` 에는 `GoalTowerTag`/`StructureTag` 참조가 **한 곳도 없다**(`grep` 0건). 코드 주석이 그것을 명시한다 — *"거점을 특별 취급하지 않는다 … 물면 죽거나 벗어날 때까지 유지"*.

즉 이 적은 **골 타워를 물면 죽거나 사거리를 벗어날 때까지 유지한다.** 그게 의도한 동작이므로 이 spec 에는 문제가 없지만, **안전망이 있다고 착각하면 안 된다.** unit 0 계측의 «골 락 고착 0» 은 **관측**이지 보장이 아니다. 거점을 무는 다른 적(예: `DefenderInstinct` 도 노리는 변형)을 만들 때는 이 사실에서 다시 출발한다.

## 미결 (unit 0 착수 시 확정)

**D1 — 이름.** 코드명 후보: `Enemy_Heartseeker` / `Enemy_Sapper` / `Enemy_Beeline`. 세계관(마음·본능·악몽)과 붙는 쪽은 `Heartseeker` 다. 한글 표시명 포함.

**D2 — 시트 등재 여부.** 스탯을 시트에 올리면 시트가 정본이 되고 로그인 임포트가 SO 를 덮는다(기존 함정). 올리지 않으면 SO 가 정본이지만 밸런싱이 수기가 된다. `battle-structures` unit 1 은 *"부류는 스탯이 아니라 정체성"* 이라 마스크는 시트 밖에 뒀다 — **스탯만 등재**가 그 선례와 정합한다.

## 후속 후보 (이 spec 범위 밖)

- **본능(Instinct)도 노리는 변형** [S] — 마스크에 `DefenderInstinct` 를 더하면 끝이지만, **현재 맵에 방어 본능 저작이 없다**. 저작이 생기면 그때.
- **「거점 우선, 유닛도 때림」 변형** [S] — 도발이 걸리는 중간 형태. 지금 코드는 후보 중 **거리로만 경쟁**하므로(`AttackSystem.cs:109`) 「거점 먼저」를 표현하려면 faction 우선순위 축이 필요하다. `targetPriorityClass` 와 같은 shape.
- **스폰 예고에서의 구분 표시** [S] — 예고 라인에 «유인 불가» 신호. 지금은 스폰 후에야 안다.
- **공성 모드 대칭** [M] — 적 마음을 노리는 방어측 유닛. `battle-structures` 계약이 이미 대칭이라 저작 축은 열려 있다.
