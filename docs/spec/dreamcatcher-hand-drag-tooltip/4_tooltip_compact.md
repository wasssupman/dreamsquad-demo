# 4 — 툴팁 세로 압축 (보드 가림 축소)

## 목적

unit 3 으로 툴팁을 상단 중앙에 고정한 뒤, 최장 카드에서 패널이 280px(화면의 26%)까지
자라 **보드 상단을 가린다**는 문제가 나왔다(사용자 보고 2026-07-21).

세로 예산을 줄여 침범을 축소한다. 위치는 그대로 둔다.

## 화면 예산 (1080 기준, 씬 포즈 `(0.86,13.44,-8.75)` · pitch 60° · FOV 43° 에서 계산)

| 구간 | 위치 |
|---|---|
| 보드 원경 가장자리 | 상단에서 **151px** (그 위는 외곽 터레인·원경 프랍) |
| 보드 근경 가장자리 | 상단에서 897px |
| 보드 세로 점유 | 746px (69%) |
| 손패 열렸을 때 상단 | 상단에서 748px |

**카메라로는 못 푼다.** 손패가 열린 상태의 가용 중간 띠는 320~748px = 428px 인데 보드는
746px 이 필요하다(318px 적자). 보드를 내리면 원경에서 번 만큼 근경(골)이 손패 밑으로
들어가는 제로섬이고, 428px 에 맞추려면 FOV 43°→69° 가 필요해 클램프(60) 밖이다.
→ 카메라 헤드룸은 **기각**, 툴팁 축소로 간다.

### 스폰은 가려지지 않는다 (초기 분석 정정)

세로만 보고 "스폰 3개가 전부 가려진다"고 판단했으나 **틀렸다**. 스폰 셀은
`(0,9)` `(14,9)` `(14,6)` 으로 보드 **좌·우 끝단**이다. 원경에서 보드의 화면 가로 범위는
약 x 432~1488(셀당 ~70px)이므로 스폰 셀 중심은 **467px / 1453px** 인데, 툴팁은 폭 480
중앙이라 **x 720~1200** 만 차지한다 — span 밖이다.

실제로 가려지는 것은 **보드 상단 중앙부**(상단 3~4행의 가운데 열), 즉 스폰 직후 경로
구간이다. 게임플레이 정보이긴 하나 "적이 어디서 몇 마리 나오는지"는 잃지 않는다.
이 정정 때문에 압축 목표를 "침범 0"이 아니라 **완화**로 잡았다(사용자 결정).

## 변경 대상

- `Assets/_Project/Scripts/UI/Dreamcatcher/DreamcatcherCardText.cs` — `BodyCompact` 신설
- `Assets/_Project/Scripts/UI/Dreamcatcher/DreamcatcherHandView.cs` — 패딩/간격/offset
- `Assets/_Project/Scenes/BattleScene.unity` — `tooltipTopOffset` 40 → 24
- `Assets/_Project/Tests/EditMode/DreamcatcherCardTextTests.cs` — compact 테스트 2건

## 구현

1. **`DreamcatcherCardText.BodyCompact(card)` 신설**
   - 블록 사이 구분자만 `"\n\n"` → `"\n"`. 내용·라벨·색은 `Body()` 와 동일.
   - `Body()` 와 `BodyCompact()` 모두 private `Assemble(card, compact)` 로 수렴 —
     라벨/색 정의가 한 곳에 남아야 두 화면의 텍스트가 갈리지 않는다.
   - **`Body()` 를 고치지 않는 이유**: 소비처가 4곳(덱빌더 팝업 / 덱 페이지 /
     유닛 인스펙트 / 손패 툴팁)이고, unit 0 계약이 "덱빌더 출력 회귀 금지"를 못박았다.
     덱빌더 팝업은 넓어서 빈 줄이 오히려 가독성에 이롭다.
2. **툴팁 레이아웃 압축** (`DreamcatcherHandView`)
   - `TooltipPad` 14 → **10**
   - 헤더-본문 간격 8 → **4** (`TooltipHeaderGap` 상수로 승격, 매직넘버 제거)
   - `tooltipTopOffset` 40 → **24**. 상단 여백 1px = 툴팁 세로 예산 1px 이라
     가장자리 답답함을 감수하고 예산으로 돌렸다.
3. **씬 값 동기** — `tooltipTopOffset` 은 씬에 직렬화돼 있어(`BattleScene.unity`)
   코드 기본값만 바꾸면 **무효**다. 씬 값도 24 로 맞췄다.

**하지 않은 것**: 본문 폰트 축소(19pt 유지 — 모바일 가독성이 이 위젯의 존재 이유),
툴팁 폭 확대(480 유지 — 아래 "되돌리면 안 되는 것" 참조), 설명문 절삭.

## 결과 (추정)

최장 카드 `Card_IncubusPact` 기준:

| | 이전 | 이후 |
|---|---|---|
| 패널 높이 | ~280px | **~221px** |
| 패널 하단 | 320px | **~246px** |
| 보드 침범 | 169px | **~95px** (−44%) |

수치는 폰트 메트릭 기반 **추정**이다(±1줄 ≈ ±24px). 실측은 Play 확인으로 대체한다.

## 되돌리면 안 되는 것

- **툴팁 폭 480 ↔ `ScoreHudView` 는 결합된 상수다.** 겹침 임계 `safeW < 1278`,
  가로 최소 4:3(1440)에서 여유 81px 뿐. 폭을 642 이상으로 올리면 즉시 겹치고,
  손패 캔버스(sortingOrder 5) < 스코어 캔버스(6) 라 툴팁이 잘려 보인다.
  "한 줄 더 넣으려고 폭을 늘리는" 유혹을 경계할 것.
- `Body()` 와 `BodyCompact()` 는 `Assemble` 하나로 수렴시켜 둔다. 복제하면 두 화면의
  카드 텍스트가 조용히 갈린다.
