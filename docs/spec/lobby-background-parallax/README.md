## 상위 목표

로비 배경(`lobby_bg_day/night`)에 뎁스맵 패럴랙스를 적용해 "살아있는 배경"을 만든다.
기존 `Wassup.DepthParallax` 모듈(배틀 컷신용)을 재사용하되, 로비 특유의 두 제약을 해결한다:
낮/밤 **디졸브 셰이더가 이미 머티리얼을 점유**하고 있고, **전체화면 배경이라 여백이 없다**.

## 검증 질문

- 로비에 들어가면 배경이 아주 미세하게 상시 드리프트하고(앰비언트), 캐릭터를 끌면 그 방향으로
  배경이 깊이감 있게 밀리는가?
- **난간/가로등 경계가 늘어지거나 찢어지지 않는가?** (이 spec 의 존재 이유)
- 화면 가장자리에 캔버스/빈 공간이 드러나지 않는가?
- **낮/밤 디졸브 전환이 기존과 동일하게 동작하는가?** (회귀 금지)
- **배틀 컷신 패럴랙스가 그대로인가?** (`.cginc` 리팩터 회귀 금지, rest no-op diff=0 유지)

## 공통 원칙 / Feature-wide 계약

- **접근 = A안(단일 뎁스맵 + 얇은 구조 평탄화)** (2026-07-15 사용자 결정). 난간·가로등을 **뒤 배경과
  같은 뎁스로 눕혀** 상대 이동을 0 으로 만든다 → 늘어짐이 원천 발생하지 않는다. 대신 난간이 앞으로
  튀어나오는 큐는 포기한다. 레이어 분리 + 인페인팅(B안)은 **후속 후보**.
- **평탄화 레시피 (실측 검증)**: 자동 bake → `median(9)` + `GaussianBlur(12)` → 뎁스 절벽(p99.5 gradient)
  **70.3 → 4.5 (약 15배 감소)**. 큰 영역(하늘=far / 중경 / 테라스=near) 구조는 보존됨.
- **뎁스 1장 공유 (실측 검증)**: 낮/밤은 지오메트리 동일 — flat 뎁스 **상관계수 0.998, 평균차 1.2%**.
  → **뎁스맵 1장**을 앞/뒤 Image 가 공유. 시간대별 스왑 로직 불필요. (UV 샘플이라 해상도 차 무관:
  day 2730×1536 / night 2391×1345, 둘 다 16:9.)
- **Cue 제한 (하드)**: 배경은 **Cue A(뎁스 UV 패럴랙스)만** 쓴다. **`_Persp`=0, `_HiStrength`=0**.
  사다리꼴(Cue B)은 전체화면 배경엔 여백이 없어 가장자리를 안쪽으로 당겨 **캔버스가 드러난다**.
  하이라이트 스윕(Cue C)은 배경에 부적절.
- **오버스캔 (하드)**: UV 시프트가 `[0,1]` 밖을 샘플하면 가장자리가 늘어진다. 배경 Image 를
  **~1.05배 오버스캔**해 시프트 여유를 확보한다(진폭보다 큰 여유). 오버스캔 없이는 진폭을 못 올린다.
- **진폭 보수적**: `amplitude` 0.01~0.02. 평탄화 덕에 이 범위는 안전(절벽이 없어 늘어질 대상이 없음).
- **디졸브 공존**: 앞 Image = `BackgroundDissolve`(+패럴랙스 include), 뒤 Image = 모듈 `DepthParallax_UI`.
  **둘 다 같은 `_Tilt`/`_DepthTex`** 를 받아야 전환 중 어긋나지 않는다.
- **수식 단일 소유**: 패럴랙스 산식은 모듈의 `DepthParallax.cginc` 가 유일 소유. 두 셰이더가 `#include`.
  복붙 금지(모듈이 계속 단일 진실).
- **회귀 금지 (하드)**: ① 로비 낮/밤 디졸브 전환, ② 배틀 컷신 패럴랙스 rest no-op(diff=0).
  둘 다 이미 출시된 기능 — 각 unit 완료 기준에 회귀 검증 포함.
- **모듈 경계 유지**: `Wassup.DepthParallax` 는 여전히 로비/게임 타입 무참조. 로비 드라이버는
  소비처(게임 코드)로서 모듈의 셰이더/수학/SO 를 쓴다.

## 후속 후보 (이번 스코프 밖)

- **B안(레이어 분리)**: 난간+가로등+테라스 알파 컷아웃 + 뒤쪽 인페인팅(낮·밤 ×2) → 난간이 실제로
  앞으로 튀어나오는 진짜 깊이감. A안 체감이 약하면 승격.
- **자이로 입력**: 기기 기울기 연동(Android 센서·지터 대응 필요).
- **드림캐쳐 카드 적용**: `DepthParallaxView` 배선(depth-parallax spec 의 후속 후보와 동일).
- **테라스 바닥 실제 3D**: 참고 문답의 "바닥은 이미지 왜곡보다 실제 Mesh" 권고 — 로비는 정적
  일러스트라 현재 불필요.
