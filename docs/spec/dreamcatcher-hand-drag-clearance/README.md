# dreamcatcher-hand-drag-clearance — 조준 중 손패 하강으로 보드 하단 확보

> 상태: **완료 2026-07-29** — unit 0 구현 · 사용자 Play 확인("이상없음") · 실기기 SafeArea 항목만 handoff Follow-up

## 문제

큰 맵에서 **최하단 행에 배치된 유닛에 드림캐쳐 카드를 부착할 수 없다.**

`DreamcatcherCardDragSlot.OnEndDrag` 는 손패 패널 rect 안에서 손을 떼면 **무조건 취소**한다
(손패로 되돌리기 = 취소 규칙). 큰 맵은 보드 하단 행이 이 rect 뒤로 들어가므로, 가려진 유닛은
"잘 안 보이는" 정도가 아니라 **부착이 원천 차단**된다.

### 두 개의 다른 경계

혼동하기 쉬우므로 분리해서 쓴다. 손패 패널(취소 rect)은 `y 32~264` 지만,
**카드 부채는 패널 밖으로 60px 튀어나온다** — 카드 로컬 top = `handBaseY 16 + arcHeight 46 +
CardH 230 = 292` → 화면 `y 324`, 드래그 중 `localScale 1.08` 이면 **`y 342`**.

| 경계 | 화면 y | 무엇을 결정하나 |
|---|---|---|
| 손패 패널 top | **264** | 취소 판정 (여기 아래서 떼면 취소) |
| 카드 부채 top (조준 중) | **342** | 시각 가림 (여기 아래는 카드에 덮임) |

따라서 **조작 차단(264)과 시각 가림(342)은 다른 선이고, 후자가 78px 더 넓다.**

### 실측 (에디터 16:9 · 손패 열림 = 카메라 헤드룸 적용 상태)

| 맵 | 하단 행 중심 y | 취소 rect(264) | 카드 가림(342) | 그 행의 배치 셀 |
|---|---|---|---|---|
| Zig 8×8 | 278 | +14 안전 | −64 가림 | 0개 |
| Hook 11×7 | 309 | +45 안전 | −33 가림 | 3개 |
| Serpent 15×11 | 218 | **−46 차단** | −124 가림 | 15/15 Place, 13칸 |
| Twin 15×12 | 203 | **−61 차단** | −139 가림 | 12개 중 10칸 |
| Spiral 15×12 | 203 | **−61 차단** | −139 가림 | 10개 중 8칸 |
| Coil 15×12 | 2행 273 | +9 아슬 | −69 가림 | 2행 14칸 |

세로 수치는 캔버스가 `matchWidthOrHeight=1`(높이 매칭)이라 화면비 무관하다. **가로 수치
(손패 x 470~1450, "13칸 차단")는 16:9 기준이며** 20:9 폰에서는 캔버스 폭이 넓어져 차단 칸이 줄어든다.

원인은 3중이다:

1. **프레이밍 보정이 월드 절대값** — `boardFrameRaiseY=2` / `boardFramePullback=4` 는 고정인데
   fit 거리는 맵 크기에 따라 14→21 로 커진다. 큰 맵일수록 같은 오프셋의 화면 효과가 2/3로 준다.
2. **손패 헤드룸이 보드를 아래로 민다** — `handHeadroomPitchDeg=-2` 는 상단 툴팁 공간을 벌려고
   보드를 내리는 것이라 하단을 36px 더 밀어넣는다(hand-drag-tooltip unit 6 의 의도된 트레이드오프).
3. **조준 내내 손패가 남는다** — Defender 모드는 "카드는 손패 고정"(슬더스식)이라 카드가 하단을
   계속 덮는다.

## 카메라로는 못 푼다 (계산으로 기각)

상단 툴팁과 하단 손패가 정면 제로섬이다. Coil 15×12 기준:

| 조정 | 하단 | 상단 툴팁 침범 | 셀 폭 |
|---|---|---|---|
| 현재 | −61 | 86px | 75px |
| pitch 되돌림(headroom 0) | +13 | **125px 악화** | 70px |
| `boardFrameRaiseY` 4.5 | +14 | **195px 악화** | 83px |
| `boardFramePullback` 12 | +13 | 5px 해소 | **55px (−27%)** |

줌아웃만 양쪽을 풀지만 셀이 27% 작아져 dreamcatcher-attach-lockon 이 해결한 밀집 시인성
문제가 재발한다. **이 spec 은 카메라를 건드리지 않는다** — hand-drag-tooltip unit 6 의
헤드룸 계약은 그대로 둔다.

## 해결

**카드를 집어 조준하는 동안만 손패 패널 전체를 아래로 내린다.**

구조가 이미 이 해법에 맞다:

- 카드 슬롯은 전부 `_panel` 자식 → 패널을 내리면 카드가 함께 내려간다. 패널에 Mask 가 없어
  잘림도 없다.
- 취소 판정은 `HandPanelRect`(= `_panel`) 기준 → **패널이 내려가면 취소 영역이 자동으로 따라간다.**
  별도 판정 코드가 필요 없다(읽는 곳 3군데 전부).
- 슬롯 스프링(`SpringSlots`)은 패널 로컬 `anchoredPosition` 에 쓰므로 패널 이동과 독립이다.
- 툴팁은 `SafeAreaRoot` 직속(상단 앵커)이라 영향받지 않는다.

**하강량 기본 210px — 카드 헤더(이름) 띠만 남긴다** (사용자 결정 2026-07-28).

바깥 카드가 아치 때문에 가운데보다 46px 낮으므로, **전 카드의 이름이 읽히는 마지막 지점**이
기준이다: 바깥 카드 헤더 하단(로컬 `handBaseY 16 + CardH 230 − HeaderH 64 = 182` → 화면 214)이
화면 y 4 로 내려오는 210. 이때 가운데 카드는 헤더 + 본문 상단 50px 이 남는다.

| | 하강 후 화면 y |
|---|---|
| 가운데 카드 헤더 | 50~114 |
| 바깥 카드 헤더 | 4~68 |
| 조준 중 카드 top | **132** |

카드 top 132 는 **가장 큰 맵의 보드 하단 모서리(167)보다 아래**다 — 최하단 행 셀이 유닛
전신은 물론 셀 자체까지 통째로 드러난다.

**취소 띠가 얇아지는 것(264−210 = 54px)은 문제가 되지 않는다.** 실질 취소는 패널 rect 가
아니라 "유닛/셀 없음"이 담당하기 때문이다 — Defender/EnemyMark 는 `_hoverEntity == Null`,
ActiveTile 은 `TryScreenToCell` 실패면 `CancelDrag` 다. 카드 헤더 띠(y < 132)에는 어떤 맵에서도
보드가 없으므로(가장 큰 맵도 하단 모서리 167, 작은 맵은 229·256) 거기 놓으면 항상 취소된다.
패널 rect 는 "유닛 위에 놓아도 강제 취소" 라는 안전장치일 뿐이고, 그 역할은 손패가 기준선에
있을 때가 본령이다.

## 공통 원칙 (feature-wide 계약)

1. **취소 rect 는 패널 위치가 단일 소유다.** 하강량을 판정에 따로 반영하지 않는다 —
   `HandPanelRect` 를 읽는 3곳(`OnEndDrag:202` / 포탈 출구 탭 `:305` / `UpdateBriefingStatus:402`)이
   패널 이동을 자동 승계한다. 판정용 오프셋 상수를 새로 두면 두 소유자가 생겨 어긋난다.
2. **하강량·스프링은 SerializeField.** 하드코딩 금지(제약 6). 기본 210 / spring 320 / damping 24.
3. **슬롯 좌표계를 건드리지 않는다.** 하강은 패널 `anchoredPosition.y` 하나로만. 슬롯
   `homePos`/`targetPos` 를 함께 옮기면 스프링·딜인·아치 계산이 전부 오염된다.
4. **하강 판정은 조준 모드와 무관하다.** `IsDragging || IsPortalAiming` 폴링 하나로 5개
   `AimMode`(Defender / EnemyMark / ActiveTile / ActivePortal 1·2단계)를 모두 덮는다. 모드별
   분기 금지. (단 추종 카드의 좌표 갱신은 별개 문제 — unit 0 §C 참조.)
5. **카메라 불변.** 헤드룸(pitch −2 / dolly −1.5)도 `boardFrame*` 도 이 spec 에서 바꾸지 않는다.
6. **복귀는 View 가 상태를 폴링해서 정한다.** 드래그 슬롯이 상태를 소유하고 View 는 읽기만 한다 —
   커밋 / 취소 / ESC / 닫힘 / 페이즈 이탈 어느 경로로 끝나든 별도 해제 호출 없이 복귀한다.
7. **하강은 press, 복귀는 release 로 통일한다.** 판정은 `_focusIndex >= 0 || AnyInteractionActive()`
   하나 — 단순 탭 · 드래그 후 미부착 · 부착 성공이 전부 같은 순간(포인터를 뗀 때) 복귀한다.
   유일한 예외는 포탈 2탭 대기(출구를 보드에서 골라야 해 하강 유지). 이 통일은
   `OnBeginDrag` 가 `_dragging` 을 `SetFocus(-1)` 보다 먼저 세운다는 순서에 의존한다 —
   뒤집으면 press→drag 전환에 한 프레임 복귀가 튄다.

## 후속 후보 (현 spec 범위 밖)

- **취소 rect 와 보이는 손패의 불일치** — 패널(232)이 카드 부채(292)를 감싸지 못해, 카드 상단
  60px 위에서 떼면 지금도 취소가 아니다. 이 spec 이전부터 있던 불일치이고 하강과 독립이다.
  패널 높이를 부채에 맞추면 "취소 rect = 사용자가 보는 손패" 가 일치한다.
- **취소 판정 완화(안전망)** — `insideHand && _hoverEntity == Entity.Null` 일 때만 취소.
  단 **Defender/EnemyMark 에만 성립한다** — ActiveTile/ActivePortal 은 호버 엔티티 개념이
  없고 손패 위 어떤 점도 셀로 매핑돼 취소 수단 자체가 사라진다. 넣으려면 모드별 분기가
  필수이므로 계약 4 와 충돌한다.
- **프레이밍 보정의 맵 크기 의존 제거** — `boardFrameRaiseY`/`boardFramePullback` 을 "하단 N px
  확보" 목표로 fit 거리에 비례 스케일. 근본 수정이지만 전 맵의 프레이밍 감각이 바뀐다.
- **큰 맵 최하단 행의 Place 셀 재배치** — Serpent 는 최하단 행 15칸이 전부 Place 다. 맵
  authoring 차원의 완화책이나 레인 설계 제약이 커 우선순위 낮음.
