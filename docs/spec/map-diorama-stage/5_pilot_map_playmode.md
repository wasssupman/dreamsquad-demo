# 5 — 파일럿 스테이지 + PlayMode 스모크 + 육안 검증 축 4종

## 목적

새 파이프라인의 기능 검증을 닫는다. "디오라마 저작 → 열린 마당 전투"가 실제 플레이 가능한 맵 하나로 성립함을 보이고, 전투 접점 감사(설계 문서)에서 도출한 "코드 무변경·행동 변화" 지점 4곳을 육안으로 확정한다. **밸런스 품질은 범위 밖** (README 계약 10).

## 변경 대상

- 신규 `Assets/_Project/Prefabs/Maps/MapStage_Pilot.prefab` — 정식 파일럿 맵 (Ground 메쉬 + 차단 프랍 배치 + 스폰 2 + 골 1, 컬트오브램식 "열린 마당 + 가장자리 차단" 외곽)
- `MapStagePool.asset` — 파일럿 entry 등록 (기존 덱/플랜 아무거나 짝 — 밸런스 무관)
- 신규 `Assets/_Project/Tests/PlayMode/DioramaStagePlayTests.cs` — 맵 비의존 규율 준수(`docs/reference/test-procedure.md` — 이름 기반 슬롯·픽스처 선언)

## 구현

**PlayMode 스모크** (픽스처 스테이지 기준, 파일럿 프리팹에 비의존):
1. 스테이지 빌드 → 적 스폰 → **셀이 N프레임 안에 바뀐다**(traversal-layers 의 교훈: "라이브에서 유닛의 셀이 실제로 바뀌는가"가 검증 축) → 골 도달 이벤트 수신
2. 열린 셀 배치 성공 + 차단 셀 배치 거부 + BlockZone 셀 배치 거부
3. 차단 프랍 footprint 주위로 flow 가 돌아가는지 (차단 셀 통과 0)

**육안 검증 축 4종** (파일럿 맵, 에디터 Play — 결과를 이 문서 하단에 기록):
- ① 순찰 소환물: 소환사 셀이 Walk 가 된 상태에서 순찰 영역·복귀가 자연스러운가 ("Place=벽" 전제 3곳이 뒤집힌 결과)
- ② 공중 적: 차단 프랍 위를 넘는 그림이 수용 가능한가
- ③ 어그로 추격: 마당 전체 경로에서 포위 접근이 자연스러운가
- ④ 골 균열/붕괴: 마커 뷰 연출 재생 (unit 4 재확인)
