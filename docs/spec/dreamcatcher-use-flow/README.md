# dreamcatcher-use-flow — 사용 흐름 개선 (숙련 보상 + 조준 피드백 + 발동 가시성)

> 상태: unit 0 완료 2026-07-29 (사용자 Play 확인) · units 1~3 대기

## 배경

드림캐쳐 UX 리뷰(2026-07-28)에서 확정된 개선 4건. 핵심 문제 두 갈래:

1. **숙련이 보상받지 못한다** — 카드 1장 쓸 때마다 손패가 자동으로 닫혀, 연속 사용은
   `항아리 탭 → 딜 대기 → 드래그` 사이클을 통째로 반복한다. 슬로모가 "열림"에 붙어 있어
   열어두기가 공짜 보험이 되는 것도 왜곡이다.
2. **피드백 공백** — 부착 불가 유닛은 조준해 봐야 알고, 부착한 카드가 발동했는지는 영영 모른다.

브레인스토밍에서 기각/보류된 대안은 하단 "후속 후보" 참조. **퀵슬롯(3안)과 드래그 스루(2안)는
이번 범위가 아니다.**

## 선행 조건

`docs/spec/dreamcatcher-hand-drag-clearance/` (조준 중 손패 하강)가 **먼저 커밋**되어야 한다.
unit 0 이 그 spec 의 press~release 판정 신호(`_focusIndex >= 0 || AnyInteractionActive()`)를
그대로 공유한다. — 충족: `cb38591e` 로 커밋됨 (2026-07-29).

## 공통 원칙 (feature-wide 계약)

1. **슬로모 수명 = 카드를 잡은 동안** (press~release + 포탈 2탭 대기). 손패가 열려 있어도
   카드를 잡지 않았으면 게임은 실속으로 돈다. 판정 신호는 손패 하강과 **동일한 하나** —
   press = 슬로모 ON + 손패 하강, release = OFF + 복귀가 한 몸으로 움직인다.
2. **사용 후 손패 유지.** 커밋 성공이 손패를 닫지 않는다. 닫기 규칙은 기존 그대로
   바깥 탭 단일(orb-dock 확정)이며, 여기에 **자동 닫힘 = 사용 가능 카드 0장**(전부 dim
   또는 손패 빔)이 추가된다 (사용자 결정 2026-07-28).
3. **자동 닫힘이 확정된 커밋은 재딜인을 생략한다.** 딜인 → 침강이 연달아 나오는 연출
   번잡을 차단한다. 판정(게이지 차감 후 사용 가능 여부)이 연출보다 먼저다.
4. **불가 유닛 붉은 틴트는 드래그(AttachAim) 중에만.** 대상 = 드래그 시작 시
   `_attachable` 스냅샷의 여집합. 드래그가 어떤 경로로 끝나든 원복이 보장되어야 한다.
   화면 문법: **시안 링 = 되는 곳, 붉은 몸 = 안 되는 곳** — attach-lockon 계약 #6 계보의
   확장(락온 유닛 한정 틴트 → 불가 전체)이다.
5. **조준 중 텍스트를 늘리지 않는다** (사용자 결정 2026-07-29). 거절 **사유** 문안화는
   기각 — 읽게 만들지 말고 색/형태로 보여준다. 브리핑 상태줄 기존 문안은 불변.
6. **발동 신호는 드림캐쳐 파이프라인이 소유한다.** bridge/StatusFx 에 kind 분기 금지
   (메커닉 연출은 메커닉이 소유). 카드 `entryId` 귀속이 신호의 단위다.
7. **밸런스 수치는 건드리지 않는다.** 코스트·게이지·슬로모 배율(0.3)은 이 spec 범위 밖.

## 기각·보류 이력 (이번 브레인스토밍)

- **드래그 스루(2안)** — 항아리 press→카드→보드 한 제스처. 반씩은 확립된 문법(무기 휠,
  MOBA 캐스트)이고 부분 제스처가 전부 기지 상태로 강등되는 안전망도 있으나, 합쳐진
  전체가 생소하다는 판단으로 **보류** (사용자 2026-07-28).
- **퀵슬롯(3안)** — 변형 3종 분석까지 하고 **보류** (사용자 2026-07-28). 핵심 긴장 =
  사이클 덱(큐 순서) vs 항상 눌리는 비상 버튼. A 큐 미러형(메커닉 불변·비상성 없음) /
  B 큐 우회형 Active 전용(진짜 비상 버튼·그 카드만 큐 압력 소멸, UI 관점 추천안) /
  C 할증 당김형(절충·규칙 설명 부담). 재개 시 이 분석에서 시작.
- **거절 사유 텍스트 노출** — **기각** (사용자 2026-07-29, 계약 5). `DcRejectReason` 은
  이미 계산되므로, 궁금한 사람을 위한 상세는 덱빌더 카드 상세의 제한 표기
  (attach-requirement spec 후속 후보)와 병합하는 것이 맞다.

## 후속 후보 (현 spec 범위 밖)

- **퀵슬롯** — 위 분석 참조. 핀 지정 UX(덱빌더 지정 권장)도 함께.
- **드래그 스루** — 1안 체감 후 재평가.
- **슬로모 진입/이탈 보간** — press 마다 1.0↔0.3 스냅이 잦아져 거슬리면 TimeManager 에
  짧은 램프. unit 0 완료 기준에서 체감 확인 후 판단.
- **거절 사유의 덱빌더 표기** — attach-requirement 후속 후보와 병합.
