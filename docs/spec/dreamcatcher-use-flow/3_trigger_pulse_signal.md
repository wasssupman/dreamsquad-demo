# 3 — 부착 카드 발동 신호: 머리 위 아이콘 펄스

## 목적

부착한 카드가 **실제로 일한 순간**을 보이게 한다. 현재는 발동 전용 신호 채널이 없어
(payload 가 기존 파이프라인 VFX 를 빌려 쓸 뿐), 조건부 카드(궁지폭발·처형타·진동갑주 등)는
조건이 충족된 적이 있는지조차 알 수 없다 — 피드백 루프의 유일한 빈 칸.

최소 신호: 발동 순간 유닛 머리 위 아이콘 행의 **해당 카드 아이콘이 펄스**(스케일 펀치 + 플래시).

## 변경 대상 (조사 후 확정)

- `Assets/_Project/Scripts/UI/.../UnitOverheadView.cs` — 펄스 연출 (아이콘 행 소유자)
- ECS→Mono 신호 경로 — **조사 선행** (아래)

## 구현

### A. 조사 — 발동 이벤트의 소스와 귀속

이 unit 은 조사부터 시작한다. 답해야 할 것:

1. 트리거 게이트(`DcTriggerSlot`)가 발화하는 지점(Combat/Effects)에서 **어떤 기존 큐가
   이미 흐르는가** — `CastEventsSingleton`/`StatModifierApplyEventsSingleton` 등에 카드
   `entryId` 를 태울 수 있는지, 아니면 발화 사건 자체가 큐에 안 실리는지.
2. 발동 사건을 **card entryId + host entity** 로 귀속할 수 있는 지점이 어디인가 —
   아이콘 행은 entryId 오름차순이므로 entryId 만 맞으면 어느 아이콘인지 특정된다.
3. 기존 큐 재사용이 불가능하면 신규 NativeQueue 채널이 필요하다 — **그 시점에 정지하고
   질문한다** (ECS 맥락 결정, CLAUDE.md 절대 제약).

### B. 연출 (조사 결과와 독립)

- `UnitOverheadView` 에 `PulseCard(entryId)` — 해당 아이콘 스케일 펀치(×1.2 내외) + 짧은
  화이트 플래시. 값은 SerializeField/SO (하드코딩 금지).
- 같은 프레임 다발 발동은 코얼레스(아이콘당 펄스 1회, 타이머 재시작) — 과누적 방지.
- **bridge 에 kind 분기 금지** (계약 6): bridge 는 "entryId 가 발동했다"만 중계하고,
  어떤 연출인지는 드림캐쳐 프레젠테이션이 정한다.
- 적 표식(BountyMark)은 아이콘 행에 없으므로 스코프 밖.

### C. 스코프 아님

- 발동 로그/히스토리, 토스트, 사운드 — 후속 후보.
- 트리거 진행도 뱃지("4/5")는 별개 후속(스냅샷 경로 필요, unit-dreamcatcher-icons 후속과 병합).
