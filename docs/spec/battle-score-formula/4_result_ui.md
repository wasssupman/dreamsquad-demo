# 4 — 결과 화면 3축 분해 표시

## 목적

총점만 보여주면 플레이어가 무엇을 잘했고 무엇을 잃었는지 알 수 없다.
예산 소모 모델은 "얼마를 남겼나"가 곧 피드백이므로, 세 축을 분해해서 보여준다.

## 변경 대상

- 수정 `Assets/_Project/Scripts/UI/ResultScreen.cs`

## 구현

### MatchStats 확장

`ResultScreen.MatchStats` (`:79-83`) 는 이미 `(RemainingSec, Leaks)` 를 나른다.
여기에 세 축을 추가하고, `ShowVictory`/`ShowDefeat` 의 3인자 오버로드(`:88`, `:92`)를
`BattleScore` 를 받는 형태로 확장한다.

**기존 무인자·1인자 오버로드(`:86`, `:87`, `:90`, `:91`)는 지우지 않는다** — 다른 호출부가 있고,
이 스펙 범위 밖이다. 새 오버로드를 추가하는 방향으로 간다.

### 표시

`statsLabel` (`:107`) 한 줄에 시간·유출만 나오던 것을 예산 분해로 바꾼다.
"얻은 점수 / 예산" 형태가 소모 모델을 가장 직관적으로 전달한다:

```
시간      12,400 / 18,000      (남은 2:04)
스트레스   8,100 /  9,000      (유출 1)
처치      10,200               (65기 중 63기)
```

- 시간·스트레스는 예산이 확정값이라 분모를 보여줄 수 있다
- **처치는 분모를 보여주지 않는다** — 킬 만점이 스폰 구성 의존이라 상수가 아니다 (계약 7).
  "65기 중 63기" 같은 마리수는 Bridge 가 스폰 수를 알면 붙일 수 있으나, 없으면 생략한다
- 스트레스 예산 분모는 `deck.defeatGoalReachedCount × 점당점수` 다 (원본값 — 계약 8)

폰트·색·레이아웃은 기존 `scoreSubLabel`/`statsLabel` 스타일을 따른다 (`:374` 근처의 생성 코드).
새 라벨이 필요하면 같은 `CreateLabel` 헬퍼를 쓴다.

### 하지 않는 것

- 점수 카운트업 연출 — 별도 과제다. 이 단위는 값 표시까지
- 계약 지불로 잃은 점수 경고 — README "열린 항목"에 있는 별도 UI 과제
- 리더보드 행 변경 — `BuildRows`/`BuildBotRows` 는 총점만 쓰므로 무변경
