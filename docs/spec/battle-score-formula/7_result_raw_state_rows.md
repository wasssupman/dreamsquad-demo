# 7 — 결과 화면 원시 상태 2줄 (남은 시간 · 스트레스 누적)

## 목적

unit 4 가 좌측 스탯 행을 점수 3축으로 교체하면서 **남은 시간·유출 수 원값이 화면에서 빠졌다**
(`4_result_ui.md` 마지막 줄이 후속 후보로 남겨둔 항목). 정보 자체는 점수의 단조 함수로 보존되지만,
플레이어가 "몇 초 남기고 끝냈나 / 몇 개 흘렸나"를 역산해야 한다.

원시 상태 2줄을 점수 3축 **위**에 얹어 `상태 → 그래서 이 점수` 순서로 읽히게 한다.

## 변경 대상

- 수정 `Assets/_Project/Scripts/Bridge/BattleBridge.cs` — `FinishTally` 인자 2개 추가 + 스트레스 입력 공유 프로퍼티
- 신규 `Assets/_Project/Tests/EditMode/ResultScreenStatTextTests.cs` — 표기 포매터 골든

## 구현

### 표시

```
남은 시간      2:13        ← 원시 상태 (muted)
스트레스       3 / 10      ← 원시 상태 (muted)
──────────────────
시간 점수      1,200
스트레스 점수   6,300
처치 점수      6,400
```

- **라벨에 `점수` 를 붙인다.** 전투 중 HUD 는 유출 배지 캡션을 `스트레스` 로 달고 `3 / 10` 을
  보여준다(`ScoreHudView.cs:671`). 접미사 없이 두면 같은 화면에 `스트레스 3 / 10` 과
  `스트레스 6,300` 이 나란히 서서 어느 쪽이 무엇인지 갈리지 않는다.
- **원시 상태 값은 골드가 아니다.** 칩 값 색이 전부 골드면 원시값도 점수로 읽힌다. 상태 2줄만
  muted 색(`StateValue`)으로 낮추고(볼드도 뺀다), 두 그룹 사이에 2px 헤어라인을 넣는다.
  알파는 0.22 — 0.10 은 이 네이비 위에서 사실상 안 보였다(스크린샷 확인).
- 배치는 기존 스탯 행 블록(`SetStatRows`) 안이다. 레이아웃 코드는 그대로 — 행이 5개 + 디바이더가
  되면 좌측 컬럼 preferred 가 426+352 = **778** 이 되어 패널이 838 로 자란다(1080 기준 여유
  242). flexible spacer 가 0으로 눌려 상태 블록이 캡션 바로 아래로 붙는다.

### 스트레스 누적은 유출 수가 아니다

표시값은 `_goalReachedCount` 가 아니라 **`_goalReachedCount + _leakAllowancePenalty`**(몽마의 계약
선불 포함) 이고, 분모는 `deck.defeatGoalReachedCount` **원본값**(계약 8)이다. 즉 스트레스점수의
실제 입력과 같은 두 값이다 — `(10 − 3) × 900 = 6,300` 이 화면에서 검산된다.

유출 수만 보여주면 계약을 쓴 판에서 검산이 깨진다(유출 1 인데 점수는 `(10−1−2)×900`).
두 곳이 어긋나지 않게 `StressAccrued` / `StressLimit` 프로퍼티를 `CalculateBattleScore` 와
`FinishTally` 가 공유한다.

**엔드리스는 분모를 표기하지 않는다** — 누수로 죽지 않아 한계가 무의미하고, HUD 도 같은 규칙으로
숨긴다(`RefreshLeakHud`, `showLimit: !IsEndless`). `StressLimit ≤ 0` 을 "한계 미표기" 센티널로
쓴다(덱 미배선도 같은 처리). 엔드리스는 타이머가 유일 종료자라 남은 시간은 항상 `0:00` 이고
시간점수 0 과 일치한다.

### 하지 않는 것

- 점수 분모(예산 만점) 복원 — unit 4 rev 에서 걷어낸 결정 유지
- 킬 마리수(`63/65`) — 스폰 수를 팝업이 모른다. 계약 7
- 구 오버로드(`ShowVictory(int, float, int)` 등) 정리 — 범위 밖. `HasBreakdown == false` 분기의
  `남은 시간`/`유출` 2줄 표기는 그대로 둔다
