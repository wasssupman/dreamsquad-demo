# 5 — 유출 한계 조임 (30 → 10)

## 목적

스트레스축에 변별력을 준다. 적이 65기인데 한계가 30이면 잘하는 플레이어는 다들 만점 근처라
스트레스점수가 사실상 상수가 된다.

**이 단위는 밸런스 변경이다.** 앞 단위들과 달리 되돌릴 수 있게 분리했다.

## 변경 대상

- 수정 `Assets/_Project/Scripts/Data/Decks/WaveA.asset` — `defeatGoalReachedCount: 30` → `10`

한 필드다. 코드 변경 없음.

## 구현

`manage_scriptable_object` 로 해당 필드만 수정한다. 씬 저장이나 다른 필드를 건드리지 않는다.

### 파급

이 값은 세 곳이 함께 읽는다. 전부 자동 추종하므로 추가 작업은 없지만, 확인은 해야 한다:

| 소비처 | 영향 |
|---|---|
| 패배 판정 `EffectiveLeakLimit()` (`:3630`) | 유출 10회에 패배 (기존 30회) — **난이도 상승** |
| 유출 HUD `SetLeakStatus` (`ScoreHudView.cs:259`) | `n / 10` 표기로 자동 변경 |
| 스트레스점수 분모 | 예산 27,000 → 9,000 |

### 몽마의 계약 상호작용

`Card_IncubusPact` 의 `leakAllowanceCost: 1` 이 예산에서 차지하는 비중이 3.3% → 10% 로 오른다.
점수로는 지불 1회 = 900점 고정(점당점수)이라 변하지 않지만, **재부착 상한이 29회 → 9회로 줄어든다**
(지불 게이트 `remaining − cost ≥ 1`, `:3647`).

README "결정 기록"대로 재지불은 현행 유지다. 이 단위는 그 상한만 조인다.

## 완료 기준

- [x] `WaveA.asset` 의 `defeatGoalReachedCount` 가 10 (diff 한 줄)
- [x] EditMode 전체 통과 (1091 / 0 실패)

- [x] Play: 유출 HUD 가 `0 / 10` 으로 표기된다 (자동 추종)
- [x] Play: 무유출 시 스트레스점수 9,000 = 예산 만점
- [x] Play: 유출 10(패배) → stress 0 · time 0 (누적 == 한계라 자동)
- [ ] **플레이 감각 확인 — 사용자 판단 대기.** 10이 너무 빡빡하면 여기서 조정한다

확인: 2026-07-20

### 적용 후 예산 실측

```
전투 시작 후 — 시간 예산=18,000  스트레스 예산=9,000
무유출·전멸 가정: time=18,000 stress=9,000 kill=10,300 total=37,300
```

README 예산 표(37,300)와 정확히 일치한다. 이제 문서값이 실물 데이터로 재현된다.

> 배치 단계에서는 시간 예산이 0으로 나온다 — `_timerDuration` 이 `StartBattle` 에서야 잡히기
> 때문이다. 결함이 아니다(결과 화면은 항상 전투 종료 후에 뜬다).

## 되돌릴 때

값을 30으로 되돌리면 스트레스 예산이 27,000 이 되어 **총점 규모가 48% 튀고 축 간 가중치가 뒤집힌다**
(스트레스 혼자 시간+킬 합의 절반). 되돌린다면 `ScoreRulesData.stressScorePerPoint` 를
`9000 / 새 한계` 로 함께 조정해 예산 총량을 9,000 으로 유지할 것.

한계를 10 이외의 값으로 튜닝할 때도 같다 — **한계와 점당점수는 곱해서 예산이 되므로 짝으로 움직인다.**
README 예산 표도 함께 고친다.
