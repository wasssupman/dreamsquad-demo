# unit 8 — 고유 스파인 2종 임포트 + 스왑

## 목적

요구사항 1 을 닫는다 — 소환사와 순찰병에 **기존 스파인이 아닌 고유 스켈레톤**을 입힌다. 에셋 미확보 상태에서 시작했으므로 마지막에 둔다. 스왑은 SO 필드 교체라 저렴하고, 여기까지 오는 동안 메커니즘은 이미 완성돼 있다.

## 변경 대상

- 신규 `Assets/_Project/Spine/` 하위 스켈레톤 2종 (`.json` + `.atlas` + `.png`)
- `Defender_Summoner.asset` · `Defender_PatrolSoldier.asset` — Spine 블록 교체

## 선행: 필요한 애니메이션 트랙

에셋을 수급하기 전에 이 목록으로 검수한다. 없으면 스왑이 반쪽이 된다.

| 유닛 | 트랙 | 용도 |
|---|---|---|
| 소환사 | `idle` | 순찰병 없을 때 |
| 소환사 | **특수 대기** | 순찰병 생존 중 루프 (요구사항 2) |
| 소환사 | `attack` | 소환 순간 (unit 3 이 `AttackState` 재사용) |
| 소환사 | `die` | 사망 |
| 순찰병 | `idle` | 거점 정지 |
| 순찰병 | **`walk`** | 이동 (unit 5 — 이 게임 아군 최초) |
| 순찰병 | `attack` | 근접 교전 |
| 순찰병 | `die` | 사망 |

순찰병의 `walk` 가 없으면 이 유닛의 핵심(이동)이 정지 슬라이딩으로 보인다 — **수급 시 가장 먼저 확인할 항목**이다.

## 구현

**임포트 함정 3중 확인** — 한글 파일명 Spine 이 macOS 에서 깨진 이력이 있다. 세 가지를 함께 처리해야 열린다:

1. 파일명 **NFC 정규화**
2. 확장자 `.json` 명시
3. spine 버전 문자열 확인 (런타임은 4.2)

임포트 후 `SkeletonDataAsset` 이 생성되고 애니메이션 목록이 위 표와 맞는지 먼저 검수한 다음 스왑한다.

**스왑 = SO 필드 교체.** `skeletonDataAsset` · `spineSkinName` · `partSkins`(고유 스켈레톤이면 보통 비움) · `slotColors` · 애니 이름 5종 · `spineVisualScale`. **코드 변경 0 이 목표다.**

`spineVisualScale` 은 리그마다 단위 공간이 달라서 반드시 재조정한다. 타일 크기 대비 눈으로 맞춘다.

**unit 6 산출물 재확인.** 아군 식별 표식이 새 외형에서도 읽히는지, placeholder VFX 가 새 스켈레톤 스케일에 맞는지 다시 본다.
