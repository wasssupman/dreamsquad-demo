# unit 5 — 뷰: 대기 모션 · 걷기 · 아군 식별 · 거점 반경 프리뷰

## 목적

요구사항 2 의 "소환수가 사망할 때까지 특수 대기 모션"을 넣고, **이 게임에서 처음으로 움직이는 아군**이 적으로 오독되지 않게 하고, 배치 프리뷰가 거점 반경을 그리게 한다. 전부 순수 프레젠테이션 — **심 변경 0**.

## 변경 대상

- `Assets/_Project/Scripts/Bridge/BattleBridge.cs` — 소환사 애니 상태 폴링 · 프리뷰 범위 결정
- `Assets/_Project/Scripts/Presentation/` — 아군 식별 표식 · 배치 범위 프리뷰

## 구현

### ⓪ 순찰병 뷰 위치 동기화 — **스펙 작성 시 놓쳤던 필수 항목**

스펙은 "위치 sync 는 이미 매 프레임 돌아서 코드 0줄"이라고 적었는데 **틀렸다**. `SyncMonoUnitViews` 의 두 루프는 각각 `AttackUnitTag` 쿼리(적)와 `_defenderByTile` 순회(방어유닛)이고, 순찰병은 적 태그를 안 붙이고(계약 1) 타일 딕셔너리에도 안 들어간다(`DefenderTile` 미부착). 둘 다 아니라 **뷰가 스폰만 되고 영원히 제자리에 선다.**

`SyncPatrolViews`(`PatrolAnchor` + `LocalTransform` 쿼리)를 신설해 위치·소팅·오버헤드 체력바를 처리한다. 뷰 회수는 `spineUnitPool.DespawnMissing` 이 엔티티 소멸 기준으로 이미 한다.

### ① 소환사 특수 대기 모션

`SummonerState.current` 유효 여부를 `SyncMonoUnitViews` 가 폴링해 Spine 애니를 전환한다 — 신규 채널 없이 체력바 폴링과 같은 형태다(상태 구동, 이벤트 아님).

- `current` 유효 → 특수 대기 애니 루프 (순찰병을 부리는 자세)
- `current` 없음 → 기본 `idle`
- 소환 순간의 공격 애니는 unit 3 이 `AttackState` 를 재사용해 이미 재생된다

애니 이름은 SO 필드로 받는다(하드코딩 금지, 제약 6).

**보류(2026-08-03).** 현재 유일한 스켈레톤 `Casual Character` 에 "소환수를 부리는" 루프로 쓸 트랙이 없다(`Idle`/`Walk`/`Attack*`/`Die` 뿐). 대체 트랙 없이 전환 기구만 만들면 검증할 수 없는 코드가 남으므로, `SpineUnitView` 의 idle 오버라이드 API 신설과 함께 **unit 8(고유 스파인 스왑)로 미룬다** — 그때 특수 대기 트랙이 실제로 들어온다. 지금은 소환사가 기본 `idle` 을 유지하고, 소환 순간에만 `AttackState` 재사용으로 공격 애니가 나간다(unit 3).

### ② 순찰병 걷기 애니

`DefenderUnitData.SpineWalkAnimation` 이 방어유닛에서는 `""` 로 하드코딩돼 있다("디펜더는 타일 고정 → 걷기 애니 불요"). 순찰병은 이동하므로 SO 필드로 열어 채운다. 인터페이스가 이미 "비어 있으면 단일 루프 = 현행 동작" 폴백을 계약으로 갖고 있어 **기존 유닛은 무영향**이다.

채우면 `enemy-walk-anim-speed` 의 발 미끄러짐 보정이 함께 붙는지 확인한다 — 그쪽이 로코모션 루프에만 적용되도록 만들어져 있어 공짜로 얻을 가능성이 높다. 안 붙으면 억지로 붙이지 말고 후속으로 넘긴다.

지금까지 **움직이는 것은 전부 적이었다.** 순찰병이 화면을 가로지르면 플레이어가 적으로 읽을 가능성이 높다. 최소 하나는 넣는다:

- 발밑 아군 링/글로우 (배치 하이라이트와 같은 색 계열)

캐주얼 디펜스 아트 디렉션을 따른다 — 작은 크기에서 읽히고, 밝고 깔끔하게. 채택은 Play 육안으로 고른다.

### ⑤ 배치 프리뷰 거점 반경

이 유닛은 **배치 판단의 전부가 거점 위치**다. 그런데 프리뷰는 `attackRange` 를 그리고, 소환사의 `attackRange` 는 소환 주기의 부산물일 뿐 플레이어에게 아무 정보도 아니다. 안 바꾸면 플레이어가 **순찰병이 어디까지 나갈지 모르는 채로** 배치한다.

기존 프리뷰(노란 격자 outline · `Tilemap.color` tint · 전용 `_rangeTilemap` · Chebyshev `RangeToTiles`)의 **셀 집합 입력만 바꾼다** — 렌더 경로·펄스·sorting 은 그대로 재사용한다.

- `SummonPatrolAbility` 보유 유닛 → `leashTileRadius` 를 Chebyshev 반경으로
- 그 외 → 기존대로 `attackRange`

판별은 **능력 에셋 보유**로 한다(id/kind 분기 금지 — `beamVfxPrefab` 유무가 빔 유닛을 가르는 것과 같은 관례).

**중심은 스냅된 walk 셀**이다(계약 4). 실제 anchor 가 배치 셀이 아니므로 프리뷰도 같은 스냅을 거쳐야 실제 활동 영역과 일치한다. 스냅 실패면 범위를 그리지 않는다 — 그 자리에 놓으면 소환이 취소된다는 신호가 된다.

**공격범위와 거점범위를 동시에 그리지 않는다.** 두 격자가 겹치면 무엇이 무엇인지 읽히지 않는다. 색도 기존 공격범위와 구분한다.
