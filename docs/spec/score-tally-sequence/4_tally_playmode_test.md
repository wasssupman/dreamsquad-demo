# 4 — Tally 흐름 PlayMode 테스트

## 목적

종료 3종을 새 페이즈로 전부 재라우팅했는데 자동 검증이 없다.
**최악은 `onDone` 이 끊겨 결과 화면이 영영 안 뜨는 하드락**이고, 그걸 잡는 테스트가 없다.

사후 감사가 Backlog 로 올린 항목이다. CLAUDE.md 도 "판 흐름 수준 통합은 PlayMode 1개 이상"을 요구한다.

## 변경 대상

- 신규 `Assets/_Project/Tests/PlayMode/TallyFlowTest.cs`

## 구현

`IncubusPactTest` 관례를 따른다 — 씬 로드 → `SetDefenderPool` → `BeginPlacement` → 배치 →
검증, private 상태는 리플렉션 조회.

### 무엇을 검증하나

이 테스트가 지키는 것은 **연출의 모양이 아니라 흐름의 계약**이다. 타이밍·색·폰트는
사람이 볼 문제이므로 건드리지 않는다.

| # | 검증 | 왜 |
|---|---|---|
| 1 | `Battle → Tally → Result` 순으로 전이한다 | 페이즈가 건너뛰어지면 연출이 통째로 사라진다 |
| 2 | **`Result` 에 반드시 도달한다** | `onDone` 유실 = 하드락. 이 테스트의 존재 이유 |
| 3 | Tally 동안 점수 HUD 패널이 살아 있다 | 연출의 주인공이 안 보이면 의미가 없다 |
| 4 | 최종 HUD 점수 == `score.Total` | 계약 2(총점 보존). 연출이 값을 잃거나 더하면 잡힌다 |
| 5 | 스킵해도 4가 성립한다 | 스킵 경로에서 남은 축이 누락되기 쉽다 |

### 하드락을 어떻게 잡나

`Result` 도달을 **타임아웃과 함께** 기다린다. 무한 대기하면 테스트가 멈춰버려 원인이 안 보인다.

```
지정 시간(넉넉히) 안에 Result 로 못 가면 → 실패 + "onDone 유실 의심" 메시지
```

### 판을 어떻게 끝내나

디펜더 0기로 두고 전 웨이브를 당기면 유출이 빠르게 쌓여 **패배**로 끝난다.
승리 유도는 밸런스 의존이라 불안정하므로 쓰지 않는다.

패배는 시간·스트레스가 0이라 연출이 짧지만, **검증 대상인 흐름 계약은 동일하게 지난다**
(0점 축을 건너뛰는 것도 계약의 일부다).

### 총점 비교 방법

`ScoreMath` 를 직접 부르지 않는다 — 그러면 산식을 두 번 구현하는 셈이라 회귀 검출력이 없다.
Bridge 가 계산한 값(`_killScoreTotal` + 로그의 3축)을 읽어 HUD 최종값과 대조한다.
