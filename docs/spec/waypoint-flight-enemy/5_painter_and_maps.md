# unit 5 — 저작 도구 + 검증 맵 2~3장

## 목적

경로 저작을 페인터에 올리고, 검증 질문의 후반부(«맵마다 달라 방어선이 갈리는가»)에 답할 맵 2~3장을 저작한다. **2~3장이 상한이다** — 9장 전부는 검증이 아니라 콘텐츠라 후속으로 뺀다(제약 9).

## 변경 대상

- `Assets/_Project/Editor/MapPainterWindow.cs` — 경로 모드
- `Assets/_Project/Data/Maps/MapDocument_*.asset` — 2~3장 경로 저작(+ 필요시 비행 적을 그 맵 덱에)
- unit 0 의 검증 순수 함수 — 페인터가 같은 함수 호출(신규 규칙 금지)

## 구현

### 페인터 경로 모드

- 경로 선택(추가/삭제) + 셀 순서대로 클릭해 이어 찍기 + 마지막 점 삭제. **재정렬 UI 는 만들지 않는다** — 잘못 찍으면 뒤에서부터 지우고 다시 찍는 것이 저작 비용이 더 싸다(제약 8).
- 오버레이: 경로별 색 + 순서 번호 + 시작·끝 강조. 골/스폰 겹침 경고는 unit 0 의 순수 검증 함수를 **그대로 호출**해 표시한다 — 페인터가 자체 규칙을 갖는 순간 `OnValidate` 와 드리프트가 시작된다.
- 저장은 기존 페인터 bake 경로 그대로(`1_validate_and_bake` 선례).

### 맵 저작 기준

| 맵 | 노림 |
|---|---|
| 1장 — 지상 경로 2개 | 같은 맵에서 적마다 다른 길(검증 질문 2행). 갈래가 실제로 **다른 방어 위치**를 요구하도록 기존 복도 반대편을 지나게 |
| 1장 — Air 경로 1개 | 데코/벽 위를 지나는 경로(검증 질문 3행). 지상으론 불가능한 진입각 |
| (선택) 1장 — 혼합 | 지상 경로 + Air 경로 공존. 슬롯 축이 실전 조합에서 도는지 |

**웨이브 편입 주의**: 비행 적을 덱 풀에 넣으면 그 덱 웨이브가 전부 재추첨된다 — `structure-hunter` unit 1 규칙 그대로(시드 재기준 명시 · 풀 중간 삽입 · 라이브 덱 7종 열거는 `WaveKillBudgetPinTests` 가 정본 · `maxPerWave` 검토).
