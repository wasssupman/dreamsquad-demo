# instinct-turret-readout — 본능이 「누구 편이고 무엇을 겨누는가」를 말한다

> ## 목표 2줄
>
> 1. **아군 본능은 노랗고 적 본능은 빨갛다** — 판을 보면 편이 읽힌다.
> 2. **포신이 겨눈 쪽으로 돈다** — 「저게 지금 누구를 보고 있나」가 읽힌다.

상태: **구현됨 2026-08-20** · units 0~1 완료(라이브 Play 검증) · 사용자 체감 확인 대기

## 왜 지금

Duel·Ford·Isle 에 양편 본능이 서 있는데 **넷 다 같은 빨간 대포**다(`duel_cr_wide.png`). 편도 안
읽히고, 쏘는 순간에도 프랍은 미동도 없다 — 탄만 어디선가 튀어나온다.

거점이 «지형이 아니라 상대»가 되는가(battle-structures 의 검증 질문)에 답하려면, 최소한
**누구 편인지**와 **누구를 보고 있는지**는 프랍이 스스로 말해야 한다. 지금은 둘 다 오버헤드
체력바만 안다(그 바는 이미 진영색으로 갈린다 — 프랍만 안 갈린다).

## Feature-wide 계약

1. **시뮬은 한 줄도 안 바뀐다.** 전부 뷰다 — 타겟팅·피해·투사체 규칙 무변경, ECS 컴포넌트·
   NativeQueue 채널 신설 0. 밸런스에 영향이 없어야 이 spec 이 「읽힘」만으로 평가된다.
2. **색은 틴트가 아니라 메쉬다.** KayKit 은 red/yellow/blue/green 프리팹이 **같은
   `platformer.mat`** 을 쓰고 FBX 만 다르다. 골 붕괴가 쓰는 MPB `_BaseColor` 틴트로는 노랑이
   안 나온다 — **프리팹을 바꾼다.**
3. **진영은 여전히 `StructureData` 에 없다.** 지금은 아군용 SO(수호 본능)와 적용 SO(파수 본능)가
   이미 갈려 있어 각 SO 의 프랍 슬롯이 다른 프리팹을 가리키면 끝난다. **같은 본능을 양편에
   세우고 싶어지면** 그때 «진영별 프랍 선택»을 브리지로 올린다(후속 후보) — 지금 넣으면
   소비자 0인 축이다(제약 8).
4. **벤더 프리팹을 편집하지 않는다.** `Assets/_Project/Prefabs/Structures/` 에 KayKit 프리팹의
   **변형(Variant)** 을 두고, 프로젝트 컴포넌트는 거기 붙인다.
5. **도는 것은 포신뿐이다**(사용자 지시 2026-08-20). 받침(`cannon_base`)과 터렛(`cannon_turret`)은
   고정. 리그는 이미 `base → turret → barrel` 3단이라 자식 하나만 돌리면 된다.
6. **방향은 뷰 공간에서 구한다.** 보드는 grid 가 월드 90°X 로 누운 평면이라 sim 방향을 그대로
   쓰면 엉뚱한 축으로 돈다. 변환 지점은 `BoardSpace.ToViewVector` 하나 — 방어유닛의 방향성
   히트 VFX(`attackVfxFacesTarget`)가 같은 이유로 그렇게 한다.
7. **조준 신호는 기존 채널 하나다.** `UnitAttackVisualEvent`(공격 **시작** 시 1회 · attacker +
   targetWorld)가 이미 본능에도 나온다. 신규 큐 0 · 신규 필드 0.
8. **연출 시간은 배틀 도메인 시계**(`TimeManager.Instance.DeltaTime(TimeDomain.Battle)`) —
   슬로모가 걸리면 포신도 같이 느려진다. `Time.deltaTime` 직독 금지.
9. **탄은 여전히 셀 중심에서 나온다.** 포신을 돌려도 `ProjectileSpawnRequest.origin` 은 본능 셀
   중심이고 브리지가 y 를 `spawnHeight`(0.5) 평면으로 누른다. 총구에서 나오게 하는 것은 별개
   작업(후속 후보) — 이 spec 에서 손대면 sim 좌표를 뷰가 결정하게 된다.

## 결정 — v1 은 「쏠 때 돈다」다 (「계속 따라본다」가 아니다)

본능에는 **지속 조준 상태가 없다.** `AttackState.committedTarget` 은 발사 프레임에 켜졌다
`hitDelaySec == 0` 이면 같은 프레임에 풀린다 — 매 프레임 폴링해도 발사 이벤트와 **같은 것만**
보인다. 즉 「쿨 도는 동안에도 적을 따라본다」는 sim 에 새 상태를 만들어야 성립하고, 그건 계약
1(시뮬 무변경)을 깬다.

그래서 v1 은 **발사 사건마다 목표 각을 갱신하고 포신이 그리 회전**한다. 쿨 1.5초 · 회전 ~0.2초라
같은 대상을 계속 쏘는 동안은 이미 겨눈 상태로 서 있고, 대상이 바뀌는 순간에만 «돌면서 쏜다»로
보인다. 이게 부족하다고 판단되면 지속 조준을 후속에서 sim 축으로 올린다.

## 후속 후보

- **총구에서 탄이 나온다** [S] — `origin` 은 sim 소유라 뷰가 못 건드린다. 발사 위치 오프셋을
  sim 축으로 올리거나, 뷰가 탄의 **첫 프레임 위치만** 총구로 당기는 연출 축을 새로 세워야 한다.
- **쿨 중에도 계속 조준 추적** [M] — sim 에 지속 조준 상태(또는 본능 전용 aim 컴포넌트)가 필요.
- **마음(Core) 프랍도 진영색** [S] — 적 마음은 지금 중립 `structure_A` 를 쓴다.
- **같은 본능을 양편에 세울 때의 진영별 프랍** [S] — 계약 3 참조.
- **파괴된 본능의 프랍 잔존** [S] — instinct-content 에서 이관. 뷰가 맵 수명이라 엔티티가 죽어도
  프랍이 서 있다. 골 붕괴 틴트(`MarkGoalCollapsed`)와 같은 처리 후보.
