# deck-info-preset-apply

> 상태: 구현 완료 2026-07-31 (units 0~5) · 자동 검증 완료, 외부 참가자 덱 live E2E 대기
> 선행: `page-local-presets`(페이지별 프리셋) · `tournament-history-deck-view`(덱보기 팝업) 둘 다 완료.

## 한 줄

히스토리 덱보기 팝업 하단에 스쿼드/드림캐쳐 **프리셋 저장 버튼을 각각 둔다**. 누르면 선택한 종류의 편성으로만 **새 프리셋을 만들고**, 해당 페이지로 이동해 **작업본에 채운 채(미저장)** 보여준다.

## 배경 (왜)

`tournament-history-deck-view` 계약 12 가 버튼 자리와 모양까지 만들고 기능은 별도 spec 으로 남겼다. 그때 가리킨 붙일 자리 `PresetApply.WriteToProfile` 은 **같은 날 `authored-preset-removal` 이 삭제했다** — 두 작업이 병행됐다.

되살리되 같은 것으로 되살리지 않는다. 옛 헬퍼는 "확정 편성 하나를 덮어쓴다" 였다. 프리셋이 30개이고 `[저장]` 이 유일한 기록 경로가 된 지금, 남의 덱을 내 확정 편성에 즉시 덮어쓰는 것은 **파괴적이고 되돌릴 수 없다.** 그래서 적용의 뜻이 바뀐다 — **덮어쓰기가 아니라 새 프리셋 + 미저장 작업본**이다. 마음에 들면 `[저장]`, 아니면 `[되돌리기]`.

## 검증 질문

1. 남의 덱보기 → `스쿼드 프리셋 저장` → 스쿼드 페이지에 `"{참가자명}의 덱"` 프리셋이 새로 생기고, 작업본에 그 사람의 유닛·드림스톤이 들어간 채 **미저장 변경** 상태인가? `[저장]` 하면 남고 `[되돌리기]` 하면 빈 프리셋이 되는가?
2. 드림캐쳐 저장도 같은가? 한 번 누르면 **선택한 종류 하나만** 만들어지는가?
3. 내 빌드가 쓸 수 없는 항목(모르는 id·숨김 카드·상한 초과)이 섞인 덱을 적용하면, 제외되고 **몇 개 제외됐는지** 안내되는가?

## Feature-wide 계약

1. **적용 = 생성 + 작업본 세팅. 저장이 아니다.** 새 프리셋은 **빈 내용으로** 즉시 디스크에 생기고(구조 변경 = 즉시 저장, `page-local-presets` 기존 계약), 랭커의 편성은 **작업본에만** 들어간다 → dirty 배지 on, `[저장]`/`[되돌리기]` 활성. `[저장]` 이 유일한 기록 경로라는 규율을 예외 없이 지킨다.

2. **프리셋 리스트에 쓰는 것은 페이지 컨트롤러뿐이다** (`PlayerProfile.cs:61` 규율). 팝업은 요청 이벤트만 raise 하고, 히스토리 패널은 **예약 + 이동 요청**만 한다. 둘 다 `PlayerProfile` 을 참조하지 않는다 — 팝업의 순수 프레젠테이션 계약(덱보기 계약 9)도 유지된다. 예약 DTO(`PresetApply.Request`)는 **프로필 어휘의 plain id 리스트**다 — `TournamentDeckInfo.Payload`(서버 wire 계약)를 그대로 싣지 않는 이유는 unit 0 에 명문화돼 있다(소유·결합·절약 없음).

3. **버튼이 곧 대상.** `스쿼드 프리셋 저장` → 스쿼드 프리셋(유닛 7 + 스톤 4 **통합**), `드림캐쳐 프리셋 저장` → 덱 프리셋(카드). 두 버튼은 활성 탭과 무관하게 자기 데이터와 자기 이벤트만 사용한다. 둘 다 원하면 각각 누른다 — 한 번의 적용이 두 페이지를 동시에 바꾸지 않는다.

4. **이름은 `"{참가자명}의 덱"`.** 같은 이름이 그 리스트에 이미 있으면 뒤에 ` 2`, ` 3` 을 붙인다(id 가 키라 중복 자체는 무해하지만, 드롭다운에 같은 이름 셋이 쌓이면 고를 수 없다). 참가자명이 비면 `"불러온 덱"`.

5. **내 빌드에서 쓸 수 없는 항목은 제외하고 몇 개인지 안내한다** (사용자 결정 2026-07-31). 제외 대상: 카탈로그 미해석 id · 숨김 카드(`visible == 0`) · `Subconscious`(선물 전용) · 유닛 중복 · 슬롯/덱 상한 초과 · 카드 타입 제한 초과.

   **덱보기의 표시 계약과 의도적으로 반대다.** 저쪽은 미해석 id 를 **남긴다**(남의 덱을 있는 그대로 보는 화면이라 조용히 사라지면 안 된다). 이쪽은 **내가 실제로 반입할 편성**을 만드는 것이라, 유령 id 가 남으면 슬롯이 빈 것처럼 보이는데 채울 수 없고, 저장하면 `FilledCount()` 는 7 인데 스폰은 6 이 된다.

6. **예약은 슬롯 하나이고 다음 페이지 진입에서 소멸한다.** `TryConsume(target)` 은 대상이 맞으면 돌려주고 지우며, **달라도 지운다.** 예약이 시간을 넘어 살아남아 한참 뒤 엉뚱한 진입에 튀지 않게 한다(적용 직후 이동이므로 정상 경로에서는 다음 진입이 곧 그 페이지다). 유령 차단 2겹 보강: **라우팅 실패 시 즉시 `Clear()` + LogError**(unit 2 — 대상 페이지 진입 자체가 없으면 소멸 규칙이 못 돈다), **도메인 리로드 off 대비 static 리셋**(unit 0 — 이 에디터는 `m_EnterPlayModeOptions: 1` 이라 static 이 Play 세션을 넘는다).

7. **차단 사유는 이동한 페이지에서 안내한다.** 30개 상한·프로필 미로드는 `NoticePopup.ShowAlert`. 팝업(sortingOrder 3200)이 이미 닫힌 뒤라 `NoticePopup`(3000)이 가려지지 않으며, 프리셋 목록이 있는 화면에서 안내되므로 "하나 지우고 다시" 로 바로 이어진다. 히스토리 패널에 프로필 참조를 새로 심지 않는 대가로 헛걸음 한 번을 받아들인다.

8. **내 덱에는 버튼이 없다.** 기존 `Show(payload, title, allowPresetApply)` 를 그대로 쓴다 — 내 덱을 내 프로필에 다시 쓰는 건 no-op 이다.

9. **비활성 조건은 하나뿐이다** — 그 탭에 적용할 항목이 0개(덱 정보 없음/빈 섹션). 화면이 이미 "덱 정보가 없습니다" 를 말하고 있어 dim 의 이유가 자명하다. 숨기지 않는 이유는 탭을 오갈 때 자리가 뛰지 않아야 하기 때문(계약 12 와 같은 이유).

10. **ECS 접점 없음.** 전부 MonoBehaviour 계층(UI + Core/Profile). 배틀 시뮬레이션 무관.

## 후속 후보

- **적용 대상 프리셋 고르기** — 지금은 항상 새로 만든다. "기존 프리셋에 덮어쓰기" 는 파괴적이라 확인 절차 설계가 따로 필요하다. Scope: M
- **스쿼드+드캐 한 번에 적용** — 한 번의 조작으로 두 프리셋을 만들고 어느 페이지로 보낼지 정해야 한다. 현재는 대상별 버튼을 분리한다. Scope: S
- **제외 항목 상세 보기** — 지금은 개수만 안내한다. 무엇이 왜 빠졌는지 목록으로 보여주려면 필터가 이유를 반환해야 한다. Scope: S
- **결과 화면에도 덱보기 → 적용** — `LeaderboardList.Render` 의 옵트인 콜백을 켜면 이 경로가 그대로 따라온다(백로그 기존 항목과 합류).
