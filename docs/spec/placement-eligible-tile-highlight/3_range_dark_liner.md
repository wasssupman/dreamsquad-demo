# 3 — 사거리 아웃라인 다크 라이너 (B 성립 조건, 필수)

## 목적

배치 가능 칸을 밝게 하면 그 위의 노란 사거리 링(rangeColor `(1,.85,.1)`)이 명도 대비를 잃는다.
이를 **마스크 반전이 아니라 사거리 restyle 로** 해결한다: 노란 아웃라인에 어두운 라이너를 구워
밝은 배치칸·어두운 경로 양쪽에서 링을 살린다. **전략 B 의 핵심 열쇠 — 옵션 아님.** 코드 0줄(에셋 교체).

## 변경 대상

- Asset: `Assets/_Project/Data/TileSets/tile_grid_outline.png`(현 2px 흰 테두리) → 노란 테두리 안팎에
  어두운 1px 라이너를 함께 구운 스프라이트. PPU/필터/Uncompressed 유지.
- Asset(선택): 조준 화살표 — `AimArrow` 가 `rangeColor` 공유 → 동일 처방. 절차생성이면 그 코드만.

## 근거

- `placement-attack-range-preview` 계약: "형태 조정은 rangeTile 에셋 교체로만, 페인트/펄스 코드는
  스프라이트-agnostic". 이 unit 은 그 계약을 그대로 활용.
- 밝은 테마(사막) 배치칸 위에서 노랑은 라이너 없이는 항상 취약 → B 전제에서 필수.

## 구현/주의

- rangeTile: 노란 2px 스트로크 바깥/안쪽에 어두운 1px(예 `(0,0,0,0.6)`) 라이너.
- **tint 상호작용 확인**: 코드가 `_rangeTilemap.color` 로 노랑 tint 를 전역 곱한다. 라이너 픽셀까지
  곱해지면 라이너가 노래져 무력화된다. → 라이너는 tint 영향을 덜 받게 스프라이트 알파/색 구성(예: 라이너를
  검정 불투명으로, 노랑부는 흰색 solid 로 두어 tint 가 노랑부만 물들이게). unit 1 페이드/사거리 펄스 후
  **에디터 렌더로 라이너 생존 최우선 확인**.

## 완료 기준

- 밝은 배치칸(하이라이트 ON) 위에서 사거리 링이 다크 라이너로 분리돼 또렷(스크린샷 대조).
- 어두운/경로 바닥에서 링 외형 회귀 없음.
- 펄스·색 코드 무변경(에셋 교체만; 조준 화살표 절차생성 시 그 코드만).
