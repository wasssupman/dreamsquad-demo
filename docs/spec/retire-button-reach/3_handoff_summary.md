## Notes — 되돌리면 안 되는 것

1. **씬의 직렬화 값이 코드 기본값을 이긴다.** `BattleScene.unity` 에 `actionButtonHeight` 가
   이미 박혀 있어 **코드 기본값만 바꾸면 아무 일도 일어나지 않는다.** 크기를 다시 조정하려면
   두 곳을 같이 본다. (씬은 당시 미로드 상태라 YAML 직접 편집이 안전했다 — 열려 있었다면
   in-memory 쪽이 이긴다.)
2. **패널은 트레이 상단 y912 아래로 자라도 된다.** 선택 중에는 트레이가 접혀 사라지고
   (`DreamcatcherHandView.OpenRoutine`), 손패는 x470~1450 이라 패널(x24~454)과 가로로 겹치지
   않는다. 바닥은 화면 하단 1080 이다. 부착 3장 기준 패널 하단 y965.5.
   ⚠ **트레이와 패널이 동시에 보이는 경로가 생기면 이 전제가 무너진다.** 그때의 회수 수단은
   `descMaxLines` 2 → 1(부착 행 118.3 → 90, 3행에서 84.9 절약).
3. **에셋 `description` 은 formatter 출력의 부분문자열이어야 한다.** `DreamcatcherCardAsset
   TextTests` 가 강제한다 — 문안을 바꾸면 에셋도 같이 옮긴다. 「폴백이라 놔둬도 된다」는 거짓.
4. **바깥 탭 = 선택 해제는 의도적으로 남겼다**(사용자 결정). 초안에는 「패널 위 탭을 해제에서
   제외한다」는 unit 이 있었으나 **해제 직관이 그 자체로 가치가 있다**는 판단으로 폐기했다.
   그래서 이 spec 은 해제를 막는 대신 **버튼을 키우고 자리를 고정해 미스 자체를 줄인다.**
   패널 배경의 `raycastTarget=false`(카드 드롭·조준 비간섭 계약)도 그대로다.
5. **「정보(위) / 조작(아래)」 읽기 순서 계약을 뒤집었다**(`defender-clock-out` unit 2 주석).
   3분 실시간 판에서는 읽기 순서보다 버튼을 찾는 시간이 비싸다.

## Follow-up

- **시트의 카드 `description` 갱신.** 두 에셋을 옮겼지만 이 필드는 시트가 소유한다 — 시트의
  같은 칸을 고치지 않으면 다음 로비 진입의 임포트가 「퇴근」으로 되돌리고 테스트가 다시
  빨개진다. **이 spec 에서 남은 유일한 미결이다.**
- **아이콘 스프라이트 저작.** `actionIcon` 은 비어 있어 지금은 라벨만 나온다.
- **「철수」의 이름 오독 관찰.** 한국어에서 가장 흔한 예시 이름이고 이 게임 로스터는
  별명투성이다(폭탄맨·이쒸시개·투머치토커). 유닛 이름으로 읽힌다는 보고가 나오면 대안은
  「퇴장」 — 철수 연출(줄이 걸려 끌려나가는 보드빌 훅)과 어휘가 일치한다.
- **카드 이름 「인수인계」·「퇴직위로금」** 은 그대로 뒀다. 조작의 이름이 바뀐 것이지 농담이
  바뀐 것은 아니다. 어색하다는 판단이 서면 별도로.
