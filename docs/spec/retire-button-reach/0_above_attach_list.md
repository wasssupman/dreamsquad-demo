# 0 — 액션 버튼을 부착 목록 위로 올린다

## 목적

퇴근 버튼이 부착 카드 수에 따라 화면 y423~836 을 오르내린다(412px). 급할 때 매번 다시 찾는다.

**부착 목록 위(스탯 바로 아래)로 옮기면 위치가 저절로 고정된다.** 패널 상단은 `dockTop 88` 로
이미 고정이고, 그 위의 헤더·스탯도 높이가 고정이다. 즉 버튼 앞의 모든 것이 상수다.
가변인 것은 부착 목록 하나뿐이고, 그것을 버튼 **뒤로** 보내면 버튼은 움직이지 않는다.

## 변경 대상

- `Assets/_Project/Scripts/UI/Dreamcatcher/DcInspectPanelView.cs`

## 구현

`Layout()` 의 세로 흐름 순서만 바꾼다. 지금은 `헤더 → 스탯 → 부착 → 버튼` 이고,
`헤더 → 스탯 → 버튼 → 부착` 으로 만든다.

1. 액션 버튼 블록(현재 404~409행)을 부착 섹션 블록(340~402행) **앞으로** 옮긴다.
2. 버튼이 꺼져 있을 때(`onAction == null`) `sectionGap` 이 이중으로 들어가지 않게 한다 —
   지금은 버튼이 마지막이라 문제가 없었지만 중간에 끼면 앞뒤 간격이 겹친다.
3. 부착 0장이어도 버튼 위치는 같다. `_attachSection` 을 접는 기존 분기는 그대로 둔다.

좌표는 이 unit 이후 다음과 같이 고정된다(1920×1080, 안전영역 여백 0).
**BattleScene 에 직렬화된 실제 값 기준**(`panelWidth 460` · `pad 14` — 코드 기본값 430/18 이
아니다. 씬이 이미 값을 갖고 있으면 코드 기본값은 적용되지 않는다):

| | 패널 y | 화면 y |
|---|---|---|
| 버튼 상단 | 331.3 | **419.3** |
| 버튼 하단 (높이 60) | 391.3 | 479.3 |

패널 전체 높이는 여전히 부착 수에 따라 자란다 — **버튼만 안 움직이면 된다.**

## 뒤집는 선행 계약

`defender-clock-out` unit 2 의 주석이 명시한 「액션 버튼은 패널 맨 아래 — 정보(위)와
조작(아래)이 분리돼 읽기 순서가 선다」를 **사용자 결정(2026-08-19)으로 뒤집는다.**
읽기 순서보다 **버튼을 찾는 시간**이 비싸다. 3분 실시간 판에서 부착 카드 설명은 급할 때
읽는 것이 아니고, 퇴근은 급할 때 누르는 것이다.

딸려오는 결과(수용): 스탯에서 부착으로 내려가는 시선 경로에 조작 버튼이 놓인다. 오탭 위험은
unit 1 의 크기 확대가 상쇄한다 — 지금 오탭의 주원인은 버튼이 작아서지 위치가 아니다.
