# Map Play Feel — 맵 플레이 감각 개선

**상태: 진행 중 2026-07-24** (유닛 0·1 구현 완료 — EditMode 1264 green/0 fail. 사용자 Play 확인 대기)

## 목표

맵이 5장 있는데 플레이 텍스처가 전부 같다. 경로 실루엣(뱀/나선/지그재그)만 다르고 **배치·타이밍 결정을 바꾸는 구조 축**은 어느 맵에서도 동일하다. 카메라가 보드에 auto-fit(`BattleBridge.cs:4242`) 하므로 유닛 가독성을 지키려면 캔버스는 15폭 안쪽이어야 하고, 그 작은 캔버스에서 실루엣 변주는 이미 포화다.

실루엣이 아닌 **다른 축**으로 변주를 만든다: **레인 길이 비대칭**과 **합류 후 공유 꼬리**. 런타임 코드는 건드리지 않고 authoring 만으로 한다.

**검증 질문**: "폭 1·15폭 제약 안에서, 경로 실루엣이 아니라 *레인 길이 비대칭 + 합류 후 공유 꼬리* 로 기존 맵과 다른 배치·타이밍 결정을 강제할 수 있는가?"

## 근거 — 기존 풀 실측 (2026-07-24, 축소 전)

| 맵 | 크기 | 레인 길이 | 편차 | 공유 셀 |
|---|---|---|---|---|
| Serpent | 20×11 | 21, 21 | 0 | 0 |
| Coil | 20×12 | 24, 25, 25 | 1 | 1 |
| Twin | 20×12 | 34, 34 | 0 | 0 |
| Spiral | 20×12 | 19, 19, 21 | 2 | 1 |
| Zig | 20×12 | 20, 19 | 1 | 0 |

- **레인 길이 편차 0~2** — 5장 전부 사실상 대칭이다. 어느 맵이든 "레인마다 고르게 깔고 시작"이 정답이 되고, 그래서 맵이 바뀌어도 같은 플레이가 나온다.
- **공유 셀 0~1** — 합류 후 공유 꼬리를 가진 맵이 없다. 골 직전 1칸이 전부라 "전 트래픽이 지나는 자리"라는 개념 자체가 존재하지 않는다.

이 두 칸이 이 spec 이 채우려는 빈칸이다.

## 공통 원칙 (Feature-wide 계약)

- **런타임 코드 무변경.** 이 spec 은 authoring 에셋(MapDocument / AttackDeck / MapDocumentPool)만 만진다.
- **합류 트리만, 분기·루프 금지.** flow field 는 셀당 방향이 하나라(`FlowFieldBuilder.cs:91`) 대안 경로를 그리면 전원이 한쪽만 타고 나머지는 **죽은 복도**가 된다. walk 그래프는 반드시 forest(edges == cells − components)여야 한다.
- **폭 1 유지.** 2×2 walk 블록 금지 계약(`docs/spec/map-grid-generation/README.md:16`)은 불변. Map Painter 검증 통과가 bake 전제.
- **전 맵 폭 ≤15.** 카메라 auto-fit 때문에 맵이 클수록 유닛이 작아진다. 유닛 가독성이 전제이고 **풀 전체에 적용되는 기준**이다. 세로는 이미 전부 ≤12.
- **폭을 줄일 때 레인 길이를 보존한다.** 웨이브는 시간 기반(`triggerTimeSec`)이라 레인이 짧아지면 적이 골에 더 빨리 닿아 유효 DPS 창이 줄고 **난이도가 조용히 오른다**. 폭 축소분은 꺾임 추가로 상쇄해 원본 ±10% 안에 유지한다.
- **authored Deco.** Deco 를 직접 칠해 런타임 커빙(`ObstaclePlacer.DesignateDeco`)을 스킵시킨다 — 배치칸이 맵당 고정된다.
- **waveSeed 비0 필수.** 새 덱은 `waveSeed` 를 반드시 채운다(0 이면 "같은 맵 = 같은 웨이브" 결정론이 깨진다 — `project_random_map_pool_done`). 기존 5장이 20260801~05 이므로 신규는 20260806.
- **풀 크기 변경은 시드 매핑을 바꾼다.** `poolCount` 5→6 이면 `seed % poolCount` 결과가 전부 재배정된다. 회귀가 아니라 사양이다.
- **점수 예산 불변.** 예산은 전 맵 동일·스폰 수 무관(`docs/reference/score-formula.md`). 이 spec 은 점수 산식을 건드리지 않는다.

| 맵 | 크기 | 레인 | 편차 | 공유 셀 | 성격 |
|---|---|---|---|---|---|
| Serpent | 15×11 | 22, 22 | 0 | 0 | 분리 2레인 · 각자 골 |
| Coil | 15×12 | 21, 22, 23 | 2 | 1 | 3레인 골에서만 수렴 |
| Twin | 15×12 | 32, 32 | 0 | 0 | 좌우 대칭 · 각자 골 |
| Spiral | 15×12 | 17, 17, 19 | 2 | 1 | 3레인 골 근처 수렴 |
| Zig | 15×12 | 20, 20 | 0 | 0 | 대각 최대 분리 · 전력 분할 강제 |

Hook 이 풀에서 유일하게 레인 편차와 공유 꼬리를 동시에 가진 맵이다. 이 대비가 유닛 2 에서 체감되는지가 이 spec 의 판정 기준이다.

**N/A** — 플레이 오브젝트 신설·생성→렌더 경로 변경 없음. 기존 맵 아키타입(`MapDocument → MapGridBattleAdapter.Build → ToGeneratedMap → FlowField/TilemapMapView/BackgroundPropPlacer`)의 **데이터 변경**일 뿐이라 정거장이 그대로다. (`docs/reference/object-pipeline-map.md` 갱신 불필요.)

## 후속 후보

- **웨이브별 스폰 활성 리듬** — 그리드 고정, 웨이브마다 활성 스폰을 바꿔 시간축 변주. `WavePatternGenerator.EffectiveSpawnIndex` 가 lane 배분을 이미 소유하므로 생성기 지원 확인 필요 → 별도 spec.
- **진짜 분기 / X-교차** — 스폰별 골 배정 + 골별 flow field 가 필요한 시스템 작업. 합류 문법이 소진된 뒤 판단.
- **레인 분리 거리를 설계 축으로** — Zig 처럼 두 레인을 최대한 떼어놓으면 "전력을 쪼갤 수밖에 없는" 결정이 생긴다. 비대칭·합류와 조합 가능한 세 번째 축.
- **기존 맵 명당 리터치** — 뻔한 U턴 안쪽 명당을 Deco 로 마스킹해 배치 텍스처만 바꾸기(레이아웃 불변).
- **이펙트 타일 / 포탈 오버레이** — 15폭에서 물리적으로 못 그리는 토폴로지를 규칙으로 만드는 축(`EffectTilePlacer`·`PortalLink` 기존 자산).
