# selection-entry-narrowing — 선택·손패 진입구 축소

> 상태: **unit 0 구현·컴파일 확인 (2026-08-19) · 사용자 Play 확인 대기**
> 사용자 발의 2026-08-19. 기능을 지우는 spec 이 아니라 **사람이 만지는 입구만 좁히는** 정책 spec 이다.

## 목표

인게임 전투 중 조작을 셋으로 좁힌다.

1. **각성 항아리는 눌리지 않는다.** 드림캐쳐 손패는 **유닛을 선택했을 때만** 등장한다.
2. **판에 놓인 유닛을 직접 찍어도 선택되지 않는다.** 선택 입구는 **하단 트레이 셀** 하나다.
3. **선택해도 카메라가 당겨지지 않는다.** 홈 포즈를 유지한다.

## 검증 질문

> 항아리를 눌러도 아무 일이 없고, 판 위 유닛을 찍어도 선택되지 않으며, 하단 셀을 눌러야만
> 그 유닛이 선택되고 손패가 뜨는가 — 그 사이 카메라가 원래 줌 그대로인가?

## feature-wide 계약

1. **기능을 지우지 않는다.** 세 경로의 코드·연출·데이터는 전부 그대로 두고 **스위치 하나씩만**
   끈다. `true` 로 되돌리면 종전 동작이 그대로 부활한다.
2. **스위치는 `private static readonly bool`.** `[SerializeField]` 로 노출하지 않는다 —
   인스펙터에서 켜고 씬을 저장하면 그 값이 조용히 리포에 박힌다(이 프로젝트에서 반복된 사고).
   `const` 도 쓰지 않는다 — 분기가 상수 폴딩돼 «도달 불가» 경고가 뜨고 게이트 안의 헬퍼가
   미사용으로 잡힌다. 선례: `DcInspectController.RelocationEnabled`.
3. **선택 입구는 트레이 셀 단독.** 새로 만든 어휘가 아니라 **원래 있던 어휘**다 — 유닛이 전부
   `maxOnBoard 1` 이라 배치하는 순간 그 셀이 «소진» 이 되고, 소진 셀 탭은 이미
   `DefenderDragSlot.GoToDeployedUnit → DcInspectController.SelectDeployed` 로 그 유닛을 골라
   줬다. 첫 판 튜토리얼 4.1 도 이미 이쪽으로 유도한다.
4. **보드 탭은 죽지 않는다 — 역할이 «해제» 하나로 줄 뿐이다.** 빈 곳이든 유닛 위든 보드 탭은
   선택과 손패를 함께 걷는다. 항아리가 히트를 놓는 것도 같은 이유다(놓지 않으면 항아리 위가
   dismiss 가 닿지 않는 죽은 구역이 된다).
5. **줌은 피드를 끊어서 끈다.** `CameraDirectionConfig` 의 `inspectDolly`/`inspectFovDelta`/
   `inspectLookWeight` 를 0 으로 만드는 방식은 쓰지 않는다 — 프레이밍 바이어스가 남고, 같은
   채널을 쓰는 `DirectionAimController`(방향 지정 조준 셀 포커스)까지 데이터로 죽는다.
   피드가 끊기면 `CameraDirector` 가 2프레임 staleness 로 자동 해제한다.

## 딸려오는 결과 (수용됨)

- **판에 배치된 유닛이 하나도 없으면 드림캐쳐를 열 수 없다.** 항아리가 유일한 «선택 없이 여는»
  경로였다.
- **선택 전환이 2단계가 된다.** 손패가 열리면 트레이는 접힌다(설계상 상호배타) — A→B 는
  «빈 곳 탭으로 해제 → 다른 셀 탭».
- **액티브 드림캐쳐는 영향 없다.** 선택 중 Active 차단은 `active-ally-zone` unit 3 에서 이미
  폐기됐다 — 끌면 선택만 놓고 손패는 유지된다.

## 후속 후보 (현 스코프 밖)

- 소진되지 않은 셀(=`maxOnBoard > 1` 유닛)에서의 선택 입구. 현재 전 유닛 1 이라 도달 불가다.
- 손패가 열린 채로 트레이를 남겨 선택 전환을 1단계로 되돌리기(트레이↔손패 상호배타 재설계).
