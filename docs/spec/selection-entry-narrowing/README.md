## feature-wide 계약

1. **기능을 지우지 않는다.** 세 경로의 코드·연출·데이터는 전부 그대로 두고 **스위치 하나씩만**
   끈다. `true` 로 되돌리면 종전 동작이 그대로 부활한다.
2. **스위치는 `private static readonly bool`.** `[SerializeField]` 로 노출하지 않는다 —
   인스펙터에서 켜고 씬을 저장하면 그 값이 조용히 리포에 박힌다(이 프로젝트에서 반복된 사고).
   `const` 도 쓰지 않는다 — 분기가 상수 폴딩돼 «도달 불가» 경고가 뜨고 게이트 안의 헬퍼가
   미사용으로 잡힌다. 선례: `DcInspectController.RelocationEnabled`.
3. **입구는 갈라져 있다 — 그래서 한쪽만 끌 수 있다.** 트레이 셀 경로
   (`DefenderDragSlot.GoToDeployedUnit → DcInspectController.SelectDeployed`)는 보드 탭 게이트를
   지나지 않으므로 스위치 값과 무관하게 늘 산다. 새로 만든 어휘가 아니라 **원래 있던 어휘**다 —
   유닛이 전부 `maxOnBoard 1` 이라 배치하는 순간 그 셀이 «소진» 이 되고, 소진 셀 탭은 이미
   그 유닛을 골라 줬다. 첫 판 튜토리얼 4.1 은 이 경로로 유도한다.
   (unit 0 에서는 이것이 **단독** 입구였다. unit 1 이후로는 보드 탭과 **병존**한다.)
4. **보드 탭의 «해제» 역할은 스위치와 무관하게 산다.** 빈 곳 탭과 선택 유닛 재탭은 켜져 있든
   꺼져 있든 선택과 손패를 함께 걷는다(unit 0 에서는 그것이 보드 탭의 **유일한** 역할이었고,
   unit 1 이후로는 선택과 **공존**한다). 항아리가 히트를 놓는 것도 같은 이유다 — 놓지 않으면
   항아리 위가 dismiss 가 닿지 않는 죽은 구역이 된다.
5. **줌은 피드를 끊어서 끈다.** `CameraDirectionConfig` 의 `inspectDolly`/`inspectFovDelta`/
   `inspectLookWeight` 를 0 으로 만드는 방식은 쓰지 않는다 — 프레이밍 바이어스가 남고, 같은
   채널을 쓰는 `DirectionAimController`(방향 지정 조준 셀 포커스)까지 데이터로 죽는다.
   피드가 끊기면 `CameraDirector` 가 2프레임 staleness 로 자동 해제한다.

## 딸려오는 결과 (수용됨)

- **판에 배치된 유닛이 하나도 없으면 드림캐쳐를 열 수 없다.** 항아리가 유일한 «선택 없이 여는»
  경로였다.
- ~~**선택 전환이 2단계가 된다.**~~ unit 1 에서 해소 — 보드에서 다른 유닛을 직접 찍으면 1단계로
  전환된다(손패는 유지). 트레이 셀로 전환할 때는 여전히 2단계다(손패가 열리면 트레이는
  접힌다 — 설계상 상호배타).
- **액티브 드림캐쳐는 영향 없다.** 선택 중 Active 차단은 `active-ally-zone` unit 3 에서 이미
  폐기됐다 — 끌면 선택만 놓고 손패는 유지된다.

## 후속 후보 (현 스코프 밖)

- 소진되지 않은 셀(=`maxOnBoard > 1` 유닛)에서의 트레이 선택 입구. 현재 전 유닛 1 이라 도달
  불가다. (보드 탭 쪽은 unit 1 이후 상한과 무관하게 선택된다.)
- 손패가 열린 채로 트레이를 남기기(트레이↔손패 상호배타 재설계). 전환 1단계 문제는 unit 1 이
  보드 탭 쪽에서 해소했으므로 남는 동기는 «트레이를 보면서 손패를 쓰기» 다.
