# 18. 유닛 그리드 5열 고정 + 셀·텍스트 확대

## 목적

스쿼드 페이지 유닛 목록을 **5열**로 바꾸고 셀과 라벨을 그만큼 키운다.

핵심은 "셀을 키운다"가 아니라 **열 수를 저작 대상으로 만드는 것**이다. 지금 7열은 어디에도
적혀 있지 않다 — `GridLayoutGroup.constraint` 이 `Flexible` 이라 열 수가

```
floor((뷰포트폭 − 패딩 − 간격) / (150 + 14))
```

로 **화면비에서 파생**된다. 캔버스는 1920×1080 기준에 `matchWidthOrHeight = 1`(높이 매치)
이므로 참조 폭이 곧 `1080 × 화면비`다 → 16:9 에서 7열, 20:9 폰에서 9열. 셀 크기만 키우면
16:9 에서만 5열이고 다른 기기에서는 또 다른 숫자가 된다.

그래서 방향을 뒤집는다: **열 수를 고정하고 셀 폭을 뷰포트에서 파생**시킨다.

## 변경 대상

- `Assets/_Project/Scripts/UI/Outgame/SquadRosterBrowser.cs`

## 구현

### 1) 열 수 = 불변식

`GridLayoutGroup.constraint = FixedColumnCount`, `constraintCount = columns`.
`columns` 는 `[SerializeField] int unitColumns = 5`.

**스톤 모드는 손대지 않는다**(2026-08-20 사용자 결정) — `Flexible` + 기준 셀(150×200)
그대로다. 스톤 130개를 큰 셀 5열로 그리면 26행이 되어 스크롤이 과해진다. 스톤의 열 수도
화면비에 딸려 있지만 그것을 고치는 건 이번 요청 밖이다(유닛만 5열). 모드 전환 시
`ShowUnits`/`ShowStones` 가 각자 `constraint` 를 설정하므로 두 모드가 서로를 오염시키지
않는다.

### 2) 셀 폭 = 뷰포트에서 파생

```
cellW = (viewportW − padLeft − padRight − spacing.x × (cols − 1)) / cols
```

`viewportW` 는 `Viewport` RectTransform 의 실폭이다. 그리드가 만들어진 프레임에는 레이아웃이
아직 안 돌아 0 일 수 있으므로 `ShowUnits`/`ShowStones` 시점에 계산하고, 0 이하면 기존
`cellSize.x` 로 폴백한다.

### 3) 셀 안쪽 치수는 하나의 배율로 파생

현행 셀(150×200)이 기준이다. `scale = cellW / 150`.

| 요소 | 기준값 | 파생 |
|---|---|---|
| 셀 높이 | 200 | `200 × scale` — 아래 예산과 일치 |
| 안쪽 여백 | 6 | `6 × scale` |
| 초상화 정사각 | `cellW − 24` | `cellW − 24 × scale` |
| 라벨 밴드 높이 | 46 | `46 × scale` |
| 라벨 폰트 | 24 | `24 × scale` |
| 뱃지 | 88×34 / 폰트 19 | `× scale` |

높이 예산의 내역: `12(안쪽 여백×2) + 6(초상화 상단) + (cellW−24)(초상화) + 10(간격) + 46(밴드)`
= `cellW + 50`. 기준 셀에서 `150 + 50 = 200` 으로 `cellSize.y` 와 정확히 일치하므로, 높이는
`cellSize.y × scale` 로 비례 확대하면 예산이 저절로 보존된다 — **현행 비율을 그대로 키운다**.

16:9 기준 실측 예상: 뷰포트 ≈ 1267 → `cellW ≈ 237`, `cellH ≈ 316`, 폰트 ≈ 38.

### 3-1) 폭이 아직 없는 프레임

`SquadCharacterPage.Build()` → 컨트롤러 `OnEnable` → `ShowUnits` 가 **레이아웃 패스 전에**
돈다. 그 시점의 `Viewport.rect.width` 는 0 일 수 있다. 그래서 브라우저는 마지막으로 그린
엔트리 목록을 들고 있다가, `OnRectTransformDimensionsChange` 에서 폭이 바뀌면 다시 그린다.
폭이 0 인 프레임에는 기준 셀로 그리고 확정되는 즉시 재구성된다. 같은 훅이 **해상도/종횡비
변경**도 공짜로 흡수한다(에디터에서 Game View 비율을 바꾸는 검증 경로가 이것이다).

### 4) 하드코딩 금지 준수

위 기준값(150/200/46/24/6/24/10)은 **현행 셀의 형태**이지 밸런스 수치가 아니다. 새 매직넘버를
만들지 않도록 전부 `private const` 로 이름을 붙여 한 곳에 모으고, 배율 하나로만 파생시킨다.
