# 11 — 상세 카드 타이포그래피: 설명문 확대 + 스탯 2열

## 목적

좌측 상세 카드의 **설명문이 작고 잘린다**. 폰트를 24→30 으로 키우되, 카드 높이 예산이 이미 초과 상태이므로 스탯 5행을 2열 3행으로 압축해 공간을 회수한다. 카드 크기·Spine 백드롭은 건드리지 않는다.

## 현재 상태 (측정값)

`cardRoot` 실제 높이 = `(cardHeight 0.56 − cardBottomMargin 0.03) × 1080` = **572px**
(캔버스 `matchWidthOrHeight = 1` → 화면비와 무관하게 높이 1080 고정 — `UiCanvasSetup.cs:39`)

| 항목 | 높이 |
|---|---|
| 패딩(18+40) + 간격(12×8) | 154 |
| 이름 54 + 배지 42 + 스탯 5×38 + 설명 76 + 버튼 84 | 446 |
| **필요 합계** | **600px → 28px 초과** |

**성장 여력이 0이라 확대가 막혀 있다.** 스탯 5행을 유지하면 설명란에 남는 몫은 `572 − 524 = 48px` 뿐 — font 30 의 2줄(71px)조차 못 담는다. 즉 폰트 확대는 스탯 압축 없이는 불가능하다.

> 정정(Play 실측): 이 폰트의 한글 글립은 전각이 아니라 **약 0.65em** 이라, 폭 609px 에서 font 24 는 한 줄 ~38자다. 따라서 최장 desc(가디언 62자)도 **현재 76px 안에서는 잘리지 않았다**. 초기 스펙의 "현재도 잘린다"는 전각 가정에 따른 오판이었다. 압축의 근거는 "지금 잘려서"가 아니라 **"키울 자리가 없어서"** 다.

## 구현

- **스탯 2열 3행**: 행 하나에 (라벨 left + 값 right) 셀 2개를 `HorizontalLayoutGroup`(`childForceExpandWidth=true`)으로 절반씩. 5번째(각성보상)는 홀수라 3행 = 셀 1 + **빈 스페이서 셀**로 좌측 정렬 유지. 스탯 영역 190 → **114px**.
  - **행 간격 44** (Play 튜닝값). 16 으로는 좌측 칸의 우측정렬 값과 우측 칸의 라벨이 붙어 `"데미지 15 체력 800"` 으로 뭉쳐 읽힌다.
- **설명란**: `MakeText(cardRoot, "", 24, TopLeft, 76)` → `(…, 34, TopLeft, 148)`. `enableWordWrapping = true` 유지.
- **예산 재계산**: 비설명 자식 = 54+42+114+84 = 294. 패딩 58 + 간격(자식 7개 → 12×6=72) = 130. 572 − 424 = **설명 148px**. Play 실측 `cardRoot.rect.height = 572.4`, 자식 합계 442 + 130 = **572 정확히 일치**.
- **폰트 34 선정 근거** (폭 609px 실측 줄 수): 30→2줄 71px · 32→2줄 76px · **34→3줄 123px** · 36→3줄 130px. 34 가 148px 슬롯을 채우면서 여유 25px 를 남긴다. 30/32 는 77px 가 빈 채로 남아 설명과 [출전] 사이가 벌어진다.
- **`_statRowGos` 는 행 단위**: 배열 5 → **3**. `SetUnitPartsActive()`(101행)가 스톤 모드에서 스탯을 숨기는 데 쓰므로 행 기준으로 바뀌어야 한다. `_statValues[5]` 는 셀 단위로 유지(`SetStat(index, value)` 계약 불변).
- **스톤 상세도 자동 수혜**: `ShowStone`(77행)이 같은 `_summaryText` 를 쓴다. 스톤 모드는 배지·스탯 행이 숨겨져 공간이 남으므로 확대는 이득만 있다.
