# tutorial-offline-match

> 상태: 완료 2026-08-18 (unit 0)
> 결정: 2026-08-17 사용자 — "튜토리얼 중에는 서버 API 를 쓰지 않는다. 클라 수정만 한다."

## 한 줄

**첫 인게임 튜토리얼 판을 토너먼트에 올리지 않는다.** 로비 `시작` 이 그 판에 한해 참가 신청(`play`)을 발행하지 않고 곧장 배틀로 보낸다. 그 결과 튜토리얼 판은 **게스트 판과 똑같은 모양**이 된다 — attempt 없음 → 제출도 나가기 마감도 자연 스킵.

## 배경 (왜)

서버의 `POST /tournament/complete/{attemptId}/{score}` 가 **HTTP 500 으로 결정적 실패**한다(2026-08-17 라이브 프로브: 신규 계정 2개 · 서로 다른 토너먼트 2개 · 점수/바디 무관, traceId `KYvxTlDQ`·`NP60pt5b`·`S4d09grq`·`nqM2tGvJ`). 판이 마감되지 않으므로 열린 attempt 가 남고, 다음 `play` 는 `400 TOURNAMENT_ALREADY_PARTICIPATING / cannot wait : IN_PROGRESS` 로 막힌다.

증상이 처음 드러나는 자리가 **튜토리얼 직후의 두 번째 `시작`** 이다. 그 계정의 첫 `play` 는 항상 성공하고, 그 판을 어떻게 끝내든 마감이 실패하기 때문이다.

이 spec 은 **그 서버 결함을 고치지 않는다.** 튜토리얼 판을 토너먼트 밖으로 빼서, 온보딩 구간에서 그 벽을 만나지 않게 한다. 서버가 고쳐져도 남길 값이 있는 변경이다 — 튜토리얼 판이 정원(5)짜리 토너먼트의 엔트리 한 칸을 먹고 히스토리에 0점 기록을 남기는 것 자체가 낭비다.

## 검증 질문

1. 첫 인게임 튜토리얼 판에 들어갈 때 서버에 `play` 가 나가지 않는가? 그 판을 나가기로 끝낸 뒤 로비에서 `시작` 이 정상 입장하는가?
2. 튜토리얼을 마친 계정의 다음 판은 예전과 똑같이 토너먼트 판인가(참가 신청 발행 · 점수 제출)?

## Feature-wide 계약

1. **판정 술어는 하나다** — `TutorialProgress.ShouldRunCore(profileSO)`. 배틀 씬이 "이 판에 튜토리얼을 띄울까" 를 정할 때 쓰는 바로 그 호출이다. 별도 플래그를 만들지 않는다: 두 곳이 다른 값을 보면 "튜토리얼이 뜨는 판" 과 "서버에 안 올리는 판" 이 어긋난다.
2. **새 상태를 만들지 않는다.** 발행 창구는 여전히 `BeginMatchFromLobby` 하나(`tournament-flow-guards` unit 8 계약). 튜토리얼 판은 그 창구를 **안 부르는** 것일 뿐이고, 배틀 진입의 `GameManager.OnEnable → BeginMatch()` 가 adopt 할 것이 없어 상태를 리셋한다 — TestMode 진입과 완전히 같은 경로다.
3. **하위 경로는 손대지 않는다.** `ReportResult` / `AbandonMatch` / `ReconcilePending` 는 attemptId 부재로 이미 스킵된다. 튜토리얼 전용 분기를 그쪽에 넣지 않는다.
4. **게스트 판과 같은 모양을 유지한다.** 결과 화면 순위표가 대기 상태로 남는 것은 게스트 판의 현행 동작 그대로다 — 튜토리얼만 다르게 감추지 않는다(경로가 둘로 갈린다).
5. **튜토리얼 판의 맵은 0번 고정이다.** 맵 선택은 참가 응답의 시드에서 나오는데(`BattleBridge` `poolSource=tournament`) 시드가 없으면 `fallback0` 이다. 온보딩엔 결정론이 유리하므로 **의도된 결과로 받아들인다**.
   - **오늘 기준 이건 차이를 만들지 않는다**: 라이브 풀(`MapDocumentPool.entries`)이 1장이라(`duel-live-focus` unit 0) `seed % 1 == 0` — 지금은 모든 판이 이미 0번이다. 풀이 2장 이상으로 늘어나는 순간부터 "튜토리얼 판만 항상 0번" 이 실제 동작이 된다. 그때 0번이 온보딩에 적합한 맵인지 한 번 보라.
7. **튜토리얼이 fail-open 된 첫 판도 오프라인이다.** 배틀 쪽 튜토리얼은 참조 누락·affordable 슬롯 부재면 안내를 생략하고 진행하지만(`FirstSessionTutorialController.OnPlacementReady`), 판정은 START 시점의 `ShouldRunCore` 라 그 판도 참가 신청을 안 한다. 배틀 쪽이 이미 "그 경로도 첫 판은 소비된 것으로 본다"는 같은 결정을 내려 뒀으므로 일관적이다.
6. **`matchesPlayed` 는 건드리지 않는다.** 카운터의 원래 기준은 "히스토리에 남는 판" 이었지만, TestMode 판이 이미 "안 남는데 세는" 선례다(`GameManager.RecordMatchPlayed` 주석). 튜토리얼 판이 그 선례에 합류할 뿐이고, 챕터 D 안내가 뜰 때 기록이 최소 1건은 있으므로 안내는 깨지지 않는다. 빼려면 "이 판은 서버 판인가" 라는 상태를 새로 들어야 하는데(게스트도 세므로 attemptId 부재로는 못 가른다) 얻는 것에 비해 비싸다.

## 비목표 · 후속 후보

- **서버 `complete` 500 수정** — 클라 범위 밖. 서버팀 이관(위 traceId).
- **락 팝업 문구** — 자동 복구까지 실패한 락에 "잠시 후 '시작'을 다시" 는 거짓 안내다(실제 복구는 라운드 롤오버). 튜토리얼 밖에서는 여전히 이 팝업을 만나므로 별도 검토 대상.
- **나가기/reconcile 의 complete 실패가 무성인 것** — 지금은 `Debug.LogWarning` 만 남는다. 완주 제출 실패만 사용자에게 알린다.
