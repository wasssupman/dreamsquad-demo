# drag-cancel-affordance — 배치/사용 드래그의 취소 수단

> 상태: **구현 완료 2026-07-30** (units 0~1 · unit 2 철회) · 사용자 Play 확인 대기

## 검증 질문

**"드래그를 시작한 뒤, 아무것도 잃지 않고 되돌릴 방법이 눈에 보이는가?"**

이 질문에 답하는 데 필요하지 않은 것은 전부 제외한다.

## 문제

집어 든 유닛/카드를 **되돌릴 방법이 없다.**

### 유닛 배치 — 취소가 사실상 존재하지 않는다

`DefenderDragPlacementController.EndDrag` 는 "hoverTile 이 유효하면 배치, 아니면 취소" 다.
취소로 가려면 **무효 칸이 손가락 밑에 와야** 하는데:

- 보드 평면은 무한 평면이라 화면 어디를 눌러도 레이가 맞는다(`TryComputeRingUnit` 은 거의 항상 성공).
- 나온 셀은 `PlacementCellSnap.Resolve` 가 그리드로 **clamp** 한다 — 보드 아래로 내려도 row 0 으로 접힌다
  (`DragPlacementReachTest` 의 하단 주석이 같은 사실을 기록한다).

즉 **"손가락이 맵을 벗어나면 해제"는 구현상 성립하지 않는다.** 접힌 셀이 배치 가능하면(예 Serpent 는
최하단 행 15칸이 전부 Place) 손을 떼는 순간 코스트가 나간다. 트레이 위에서 놓아도 마찬가지다 —
트레이는 raycast 를 안 받는 그림일 뿐이고 배치 판정은 기하로만 돈다.

### 드림캐쳐 카드 — 취소 영역이 보이지 않는다

`DreamcatcherCardDragSlot.OnEndDrag` 는 손패 패널 rect 안이면 취소한다. 그런데

- 패널(232)이 **카드 부채(292)를 감싸지 못한다** — 눈에 보이는 카드 상단 60px 위에서 떼면 취소가 아니다.
- 조준 중 손패는 210px 내려간다(hand-drag-clearance) → 남는 취소 띠가 화면 y 0~54 의 **54px**.

규칙은 있는데 **보이는 것과 판정이 다르고 띠가 얇아** 사용자에게는 없는 것과 같다.

## 해결 — 되돌리기 + 예고

| 축 | 유닛 | 드림캐쳐 |
|---|---|---|
| **되돌리기 취소** | 트레이 패널 rect 로 되돌리면 취소 | 손패 rect(=보이는 카드 부채)로 되돌리면 취소 |
| **취소 예고** | 고스트 룩 + `✕ 놓으면 취소` 배너, 보드 하이라이트/사거리 소거 | 손패 취소 힌트 배너 + 기존 브리핑 상태 줄 |

**키/버튼 하드 취소는 철회했다**(사용자 결정 2026-07-30). 모바일에서 드래그 중에는 뒤로가기에
손가락이 닿지 않는다 — 떼는 순간 이미 릴리즈다. 취소 수단은 **드래그를 유지한 채 도달 가능한
화면 영역**이어야 한다. 상세 사유는 `2_escape_cancel.md`.

### 유닛 취소 존은 **가상 포인터**로 판정한다 (도달성 무손실의 핵심)

배치 판정 포인터는 손가락보다 `placementPointerOffsetHeightRatio × Screen.height`(현재 6% = 1080 에서 65px)
**위**다(placement-thumb-occlusion). 취소 판정을 어느 좌표로 하느냐가 도달성을 가른다:

- **손가락(raw) 기준이면 충돌한다.** 트레이는 화면 y 32~190 인데, 큰 맵 최하단 행(중심 y≈218~254)을
  노리는 손가락은 y≈153~189 로 **트레이 y 대역 안**에 있다. 그 행이 통째로 배치 불가가 된다.
- **가상 포인터 기준이면 충돌이 구조적으로 없다.** 조준점이 트레이 rect(top 190) 안이려면 손가락이
  y ≤ 125 여야 하고, 그때 조준점은 최하단 행(≥218)에 절대 닿지 않는다. **두 의도가 겹치는 좌표가 없다.**

부가 효과로 규칙이 세션 전체와 일관된다 — 하이라이트·사거리·거부 라벨이 전부 가상 포인터를 쓰므로
"고스트가 트레이로 돌아가면 취소"가 화면에 보이는 그대로다.

## 공통 원칙 (feature-wide 계약)

1. **취소는 무차감이다.** 코스트·쿨타임·카드 소비·엔티티 생성 어느 것도 일어나지 않는다. 취소는 전부
   커밋(`TryBeginDefenderDeployment` / `Commit*`) **이전**에 갈라지므로 환불 경로가 필요 없다 —
   환불이 필요한 지점(방향 지정 페이즈)은 이 spec 의 범위 밖이다.
2. **취소 rect 는 사용자가 보는 UI 하나가 소유한다.** 유닛=트레이 패널 `RectTransform`,
   드림캐쳐=손패 패널 자식 `CancelZone`. 판정에 상수 오프셋을 더하지 않는다 — 더하면 소유자가 둘이 되고
   패널이 움직일 때(손패 하강) 어긋난다.
3. **유닛 취소 판정은 가상 포인터, 드림캐쳐는 손가락.** 유닛은 조준계 전체가 가상 포인터를 쓰고
   (§ 위 근거), 드림캐쳐 카드는 손가락에 그대로 붙어 다니므로 오프셋 개념이 없다. 이 비대칭은 의도다.
4. **취소는 놓기 전에 예고된다.** 취소 존에 들어가면 (a) 프리뷰/손패가 취소 룩, (b) 보드 하이라이트·
   사거리·거부 라벨이 소거, (c) 짧은 한글 문구. 색 단독 표기 금지(글리프 `✕` + 문구 동반).
5. **시뮬 경로는 취소 대상이 아니다.** 탭 배치 비행(`_simulatedDrag`)은 이미 확정된 배치의 연출이다.
   비행 중 손가락이 트레이 위를 지나도 취소되지 않는다.
6. **취소는 arm 을 건드리지 않는다.** 드래그 취소 후 트레이 슬롯의 arm(탭 선택) 상태는 그대로다 —
   arm 해제는 슬롯 재탭이 담당한다(defender-tap-to-place unit 1, 기존 동작).

## 후속 후보 (현 spec 범위 밖)

- **방향 지정 페이즈 취소** — 드롭 = 코스트 확정이라 취소하려면 spend 되감기 경로가 먼저 필요하다.
  `docs/spec/README.md` Follow-up Backlog 의 "배치 취소/코스트 환불" 항목과 같은 건이다.
- **재배치(DefenderRelocation) 취소** — 이미 배치된 유닛을 드는 경로라 "무차감" 정의가 다르다
  (원위치 복귀가 취소). 별도 판단 필요.
- **손패 패널 배경을 부채 크기로 키우기** — 이 spec 은 판정 rect 만 부채에 맞추고 배경 그림은 그대로
  뒀다(hand-drag-clearance 후속 후보 그대로). 배경을 키우면 보드 가림이 60px 늘어난다.
- **취소 존 진입 햅틱** — 모바일에서 존 진입 시 짧은 진동. 실기기 확인이 필요해 분리.
- **손패의 ESC 취소 제거** — `DreamcatcherHandView` 의 기존 ESC 는 이 spec 이전 동작이라 남겼다.
  unit 2 철회 사유가 그것에도 적용되지만 제거는 별건 판단이다(`2_escape_cancel.md`).
