# 0. 파이프라인 맵 문서 + CLAUDE.md 규칙

## 목적

플레이 오브젝트 아키타입별 생성→렌더 정거장 체크표를 `docs/reference/` 에 만들고, spec 작성 시 대조를 강제하는 규칙을 CLAUDE.md 에 박는다. 문서와 규칙은 서로 없으면 무의미하므로 한 커밋으로 묶는다.

## 변경 대상

- `docs/reference/object-pipeline-map.md` (신규)
- `CLAUDE.md` — "문서화 구조 > 구성 원칙" 에 필수 섹션 규칙 1항목, "기본 워크플로우" 5번(feature 종료)에 맵 갱신 확인 1구절, "참조 문서" 표에 진입점 1행

## 구현

### object-pipeline-map.md

- 머리: 사용 규칙 1단락 — "플레이 오브젝트 spec README 작성 시 가장 가까운 아키타입 표를 복사해 `파이프라인 커버리지` 섹션으로 붙이고, 해당 없는 정거장은 `N/A + 이유` 를 적는다. 대조 중 표가 실제 코드와 어긋나면 그 자리에서 표를 고친다."
- 본문: 아키타입별 표. 실측 조사 기반으로 확정하되 예상 목록 — 방어 유닛 / 적 / 투사체 / 해저드(tornado·meteor·portal) / 힐 / VFX / 데미지 넘버 / 히트바·게이지 / 프랍·타일. 표 컬럼: 정거장 / 코드 앵커(파일 경로) / 확인 포인트 한 줄.
- 정거장 어휘(공통): 데이터 SO → 스폰 진입점 → ECS 컴포넌트(소유 맥락 명시) → 시뮬 시스템 → 이벤트 큐(생성·drain·Dispose) → View/Pool → 씬 wiring(Play 검증). ECS 를 거치지 않는 아키타입은 해당 정거장을 구조적 N/A 로 표기.
- 꼬리: 유지 규칙 — 갱신 트리거는 구조 변경만(새 아키타입/정거장, 앵커 이동·개명). 기존 스킬 포인터(unity-feature-wiring, unity-vfx-*, unity-prop-tile-authoring)는 해당 정거장 행에서 참조.
- 분량 가드: 전체 150줄 내외. 동작 설명 산문 금지.

### CLAUDE.md

- "문서화 구조 > 구성 원칙" 에 1항목: 플레이 오브젝트 신규/변경 spec 의 README 는 `파이프라인 커버리지` 섹션 필수 (`docs/reference/object-pipeline-map.md` 대조, N/A 는 이유 필수).
- "기본 워크플로우" 5번에 1구절: handoff 작성 시 파이프라인 맵 구조 변경(새 아키타입/정거장/앵커 이동) 여부를 확인하고 필요 시 맵을 같은 커밋에서 갱신.
