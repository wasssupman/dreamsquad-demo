# Spec — Defender Relocation (배치 유닛 재배치)

상태: units 0~6 구현 완료 2026-07-24 · **units 8~10 (대가 모델 개정) 완료 2026-08-13
— 자동 검증 + 사용자 Play 확인 통과.** 인계는 `11_handoff_summary.md`.

## 검증 질문

**units 0~6 (완료)**

> Battle 중 배치된 유닛을 집어 들고(슬로모), 탭 또는 드래그로 다른 타일에 내려놓으면,
> 유닛이 비행 연출로 이동한 뒤 재전개 시간을 거쳐 전투에 복귀하는가?

**units 8~10 (rev — 대가 모델)**

> 코스트를 내고 유닛을 다시 내려놓으면 — 다른 칸이든 **제자리든** — 체력이 차고 배치 스킬이
> 다시 터지는가? 그래서 판에 한 기뿐인 유닛을 계속 굴리는 것이 남는 코스트의 소비처가 되는가?

## 상위 목표

배치 확정을 "되돌릴 수 없는 결정"에서 "대가를 지불하면 조정 가능한 결정"으로 완화한다.

**rev 2026-08-13 — 대가 모델 개정.** 원안의 대가는 **전투 이탈 시간 단독**이었다(코스트 0).
`defender-board-limit` 이 유닛당 판 위 1기 상한을 도입하면서 두 가지가 동시에 생겼다: 후반에
**쓸 데 없는 코스트가 남아돌고**, 유닛 하나하나가 대체 불가능해져 **그 한 기를 살려 쓰는 것**이
플레이의 중심이 됐다. 재배치가 그 두 구멍에 맞는 소비처다 — 코스트를 내면 유닛이 회복하고
배치 스킬이 다시 터진다. 이제 재배치는 **비용이 아니라 구매**다.

UX 는 기존 배치와 대칭: 선택 → 액션 버튼으로 이동모드 진입(슬로모) → 탭투플레이스 / 프레스 드래그
양방 지원 → 비행 연출.

## feature-wide 계약

1. **비용 = 코스트 + 재전개 시간** *(rev — units 8~10)*. 원안은 **코스트 0 · 시간 단독**이었다.
   확정 프레임에 `unitData.cost` **전액**을 차감한다(배치가 쓰는 `CostRuntime.TrySpend` 그대로).
   재전개 시간은 **그대로 유지** — 코스트가 시간을 대체하지 않고 **더해진다**. 회복·재발동이라는
   이득이 붙었으므로 대가도 그만큼 있어야 하고, 라인이 잠시 비는 위험이 "언제 쓸까"를 고민하게
   만든다. 코스트 배율 노브는 두지 않는다(유닛 코스트가 이미 에셋에서 온다 — 튜닝이 필요해지면
   그때 만든다). 배치 쿨다운(`PlacementCommitted`)은 **여전히 미발화** — 상한 1 이면 트레이 셀이
   이미 소진이라 쿨타임이 화면에 뜨지도 않는다(defender-board-limit 계약 10 과 같은 판단).
   모든 노브는 `RelocationSettings` SO.
2. **이탈 구간 = `PendingDeployment` 재사용**: 확정 프레임에 재부착 → 비행·재전개 내내
   비타겟(피격 불가)·비무장(공격 불가)·시너지 제외 — 신규 배치 대기 상태와 완전 대칭.
   기존 메커니즘: `AttackSystem.cs` 후보 쿼리 `WithNone<PendingDeployment>`.
3. **상태 보존**: 엔티티 유지 — 실드/모디파이어/드림캐쳐 부착/`DeployedFacing` 전부 그대로.
   *(rev — unit 8: **HP 만 예외**다. 재정비의 보상이 회복이므로 계약 12 가 이 한 축을 덮어쓴다.
   나머지는 여전히 손대지 않는다 — 재배치는 유닛을 새로 만드는 것이 아니다.)*
   방향 유닛은 **기존 방향 유지**(재조준 없음 — `DeployedFacing` 1회 기록 불변 계약을 건드리지 않는 유일한 선택.
   재조준은 후속).
4. **on-place 스킬 재발동** *(rev — unit 8)*. 원안은 **미재발동**이었고 사유는 "공짜라서 무한
   재시전"이었다. 계약 1 이 코스트를 붙이는 순간 그 사유가 사라진다 — **대가가 곧 재발동의 안전장치**다.
   구현은 확정 프레임에 `_onPlaceTriggeredEntities` 에서 그 엔티티를 **빼는 것 하나**다. 활성화 경로가
   이미 부르는 `TriggerDeploymentOnPlaceSkill` 이 알아서 다시 돈다(신규 경로 0).
   - **효과 타일은 재적용하지 않는다.** 지금 같은 가드 안에 동거하므로 가드를 둘로 쪼개
     효과 타일만 엔티티당 1회로 남긴다. **이유는 "같은 효과가 겹쳐서"가 아니다** — 효과 타일은
     병합키(같은 유닛 · `stackId=2` · 같은 stat)로 **덮어쓰기(refresh)** 라 같은 stat 은 겹치지 않는다.
     진짜 구멍은 **`duration=∞` 인데 회수(revocation)가 없다**는 것: 공속을 주는 타일에서 공격력을
     주는 타일로 옮기면 공격력이 새로 붙고 **공속은 영원히 남는다**(stat 이 다르면 슬롯이 갈린다).
     회수를 먼저 만들기 전엔 재적용을 열지 않는다.
   - **밀치기(`ApplyOnPlacePush`)는 포함**하되 **활성화 시점**에 부른다 — 즉시 배치 경로
     (`TriggerOnPlaceAndSynergy`)가 on-place 와 밀치기를 한 묶음으로 부르는 것과 **같은 모양**이다.
     드래그 배치만 확정 시점에 부르는데, 재배치는 확정과 도착이 비행만큼 떨어져 있어 그 모양을
     따르면 **빈 칸을 민다**.
   - 컷신은 계속 스킵.
5. **원자 스왑 시점**: `_occupiedTiles`/`_defenderByTile`/`DefenderTile` 은 **확정 프레임**에
   from→to 스왑(비행 중 양쪽 타일 이중 배치 차단, 사망 이벤트 셀 = to 로 일관).
   `LocalTransform` 은 **착지 프레임**에 갱신(뷰 순간이동 방지 — 뷰는 프리뷰가 비행).
6. **시너지 재계산 양쪽**: 확정 시 `RecomputeSynergyFor(from)`(이탈 반영), 활성화 시
   `RecomputeSynergyFor(to)`(기존 활성화 경로가 이미 수행).
7. **슬로모**: 이동모드 진입 시 기존 드래그 배치와 동일(`TimeDomain.Battle`, `dragSlowmoScale` 0.2×,
   priority 0) → **확정 또는 취소 시 해제**. 비행은 실시간 — 유닛의 DPS 공백이 보이는 것 자체가 대가의 시각화.
   남용 방지 = 진입 쿨다운(취소해도 적용) + 이동모드 타임아웃(자동 취소).
8. **연출·판정 재사용, 커밋만 분기**: 키링 프리뷰·비행 궤적·hover/팝·reject 피드백·`TryScreenToCell`·
   `SpatialPlacementCheck` 는 기존 파이프라인 재사용. 커밋 꼬리만 신설 `TryBeginDefenderRelocation`.
   *(rev — unit 8)* 이 꼬리가 지나지 않는 것은 이제 **엔티티 스폰·컷신·`PlacementCommitted`** 뿐이다.
   **코스트 차감과 on-place 는 지난다** — 다만 배치 경로를 재사용하는 것이 아니라 이 꼬리 안에서
   같은 함수(`CostRuntime.TrySpend` / `TriggerDeploymentOnPlaceSkill`)를 부른다.
9. **ECS 쓰기는 Bridge 창구 직접**: `DefenderTile`/`LocalTransform` 갱신은 스폰(`CreateDefenderEntity`)과
   동일하게 BattleBridge 가 `_em` 으로 직접 쓴다. 신규 NativeQueue 채널 없음. 코드는
   `BattleBridge.Relocation.cs` partial 로 분리(`BattleBridge.Dreamcatcher.cs` 관례).
10. **입력 소유권**: 진입 조건 = Battle 페이즈 && 활성 비행 없음 && 진입 쿨다운 경과 && 유닛 비-busy.
    *(unit 5 에서 홀드 진입은 폐기 — 진입은 `BeginMoveModeFor` 외부 호출 단독.)*
    *(rev — unit 10)* 여기에 **코스트 충분**이 더해지고, 진입 호출자가 둘이 된다: 플립북 이동 버튼과
    **선택된 유닛 칸에서 시작된 드래그**(carried-press). 짧은 탭은 여전히 소비하지 않고
    `DcInspectController` 에 양보한다 — 임계 하나가 "닫기"와 "이동모드"를 가른다.
11. **엣지 자동 취소**: 이동모드 중 대상 유닛 사망 → 즉시 취소(슬로모 해제 포함).
    ~~to == from 은 취소 취급.~~ → *(rev — unit 9)* **to == from 은 제자리 재정비 확정**.
    자리가 이미 최적인데 회복만 받고 싶은 상황이 상한 1 에서는 흔하다.

12. **재정비 보상 = 배치 스킬 재발동 + 최대 체력 비율 회복** *(신규 — unit 8)*.
    회복량은 `RelocationSettings.refitHealRatio`(기본 **0.5**) — 수리는 되지만 완전 리셋은 아니라
    누적 피해가 결국 유닛을 잃게 만든다. 회복은 `IncomingHeal` 버퍼 append 로 끝난다(모든 방어유닛에
    스폰 때 이미 달려 있다). **ECS 시뮬 변경 0 · 신규 채널 0** — 회복 숫자와 VFX 도 기존
    `HealAppliedEventsSingleton` 경로로 따라 나온다. 적용 시점 = **활성화 프레임**(재전개 완료 =
    정비 끝) — 스킬 재발동과 같은 순간에 묶어 한 사건으로 읽히게 한다.

13. **취소 = 보드 밖 릴리즈 + 타임아웃** *(rev — unit 9)*. 자기 칸 탭이 확정으로 넘어가면서
    취소 제스처 하나가 사라진다. **취소 버튼을 새로 얹지 않는다** — 대신 진입 시 이미 켜지는
    소스 칸 하이라이트의 **의미를 바꾼다**: "출발지" → "여기 놓으면 재정비". 밝은 영역 밖은
    전부 취소라는 것이 학습 없이 읽히고, 위젯도 늘지 않는다.
    - **목적지 판정은 `TryScreenToCellStrict`.** 관대한 변형은 보드 밖을 가장자리 셀로 clamp 해
      true 를 주므로 "보드 밖 = 취소" 가 성립하지 않는다(unit 9 에서 실측으로 드러났다 — 그전엔
      자기 칸 탭이 실질 취소를 도맡아 이 헐거움이 가려져 있었다). 릴리즈와 hover 가 **같은**
      판정을 써야 손과 화면이 어긋나지 않는다.

## 후속 후보 (현 스코프 밖)

- **동시 다중 비행 지원** — 현재는 단일 세션 가드로 한 번에 한 유닛만 이동(review H1). 여러 유닛이
  동시에 날게 하려면 `_flightGen`/`_activeFlightEntity` 를 per-entity generation map 으로 교체. UX 결정 선행.
- ~~**탭↔홀드 전이 구간 겹침 폴리시** (review MEDIUM)~~ → **해소 2026-07-24**: 인스펙트 선택을
  터치다운→탭 릴리즈로 이동해 홀드 중 카메라 이동 제거(`4_tap_inspect_reconcile.md` 개정 참조).
- **DefenderDragPlacementController.PointerOverUi 도 같은 잠복 버그** [S] — armed 보드-탭 경로가
  `IsPointerOverGameObject` 기반이라 보드 위에서 오판 가능. relocation 과 같은 명시좌표 RaycastAll 로
  통일 후보(이번 스코프 밖 — 사용자 보고는 relocation 이었음).
- **착지 후 재조준 페이즈** (방향 유닛) — `DeployedFacing` 쓰기 소유권 재정의 선행. directional-volley 백로그
  "배치 후 방향 재지정"과 합류.
- **Placement 페이즈 중 재배치** — 초기 배치 수정 QoL. 슬로모·재전개 무의미 구간이라 규칙 별도 설계.
- **풀 유닛 상태 화면** — 스탯/모디파이어/스킬 표시. DcInspect 확장 방향으로 별도 spec.
- **어그로 chase 재계산** — 가디언 이동 시 쫓던 적은 옛 목적지로 감(aggro-tile-chase 백로그와 합류).
- **이동 가능 타일 프리하이라이트** — 이동모드 진입 시 유효 타일 표시(`placement-attack-range-preview` 재사용).
- **재전개 시각 연출 고도화** — 현 스코프는 기존 PendingDeployment 표현 재사용.
- **effect-tile × relocate 정책** — 이동해도 원 타일 효과가 유지되고 새 타일 효과는 미적용.
  unit 8 에서 on-place 가드와 **분리해 명시적으로 exactly-once 로 남겼다**(재발동에 딸려 누적되는
  것을 막기 위해). 효과 타일 위/밖 이동이 잦아지면 "타일 이탈 시 해제 + 진입 시 적용" 재설계 후보 —
  그때는 해제 쪽을 먼저 만들어야 한다.
- **재정비 전용 연출** — 제자리 재정비는 거리 0 이라 기존 비행 아치가 "폴짝 뛰었다 내려앉는" 그림을
  공짜로 낸다(unit 9). 회복·재발동을 별도로 강조하는 연출은 체감 확인 후 판단.
- **재정비 코스트 배율** — 지금은 배치 코스트 전액. 이동과 제자리에 다른 값을 매기거나 유닛별로
  차등하려면 `RelocationSettings` 배율 또는 SO 필드 신설. 실제로 필요해지기 전엔 만들지 않는다.
- **연속 재정비 억제** — 진입 쿨다운 3초 + 코스트가 현재의 유일한 제동. 코스트가 남아도는 후반에
  약하다고 판명되면 회복량 체감(연속 재정비마다 비율 감소) 후보.
- **보드 유닛 직접 드래그로 집어들기 — 상한 2+ 결정과 묶는다.** 지금 진입은 트레이 초상화
  드래그(unit 10)와 이동 버튼 둘뿐이고, 둘 다 "그 유닛" 을 슬롯으로 지목한다. 상한이 2 이상인
  유닛이 생기는 순간 **어느 기를 집을지 표현할 방법이 없어진다**(현재 `TryGetDeployedEntity` 는
  첫 번째를 집는다 — 상한 1 이라 우연히 맞을 뿐이다). 그때 필요한 것이 보드 유닛을 직접 눌러
  끄는 경로다. 둘은 경쟁이 아니라 보완이다: 트레이 = "내 하나뿐인 그 유닛", 보드 = "저기 **저**
  유닛".
  - ⚠ **홀드(길게 누르기)로 만들지 말 것.** 원안 unit 1 이 1초 홀드였고 unit 5 에서 걷어냈다 —
    UI 판정 오류로 아예 발동하지 않았고(`14ceb047`), 홀드 중 카메라 이동이 조작을 방해했으며
    (`5a777294`), 리뷰가 탭↔홀드 전이 겹침을 지적했다. 보드 press 는 이미 소유자가 다섯이다
    (유닛 탭·카드 조준·포탈 2탭·존 지정·손패 dismiss 캐처). 시간을 유일한 구분자로 얹으면 그
    다섯이 전부 "그 0.5초 동안 무엇인가" 를 답해야 한다.
  - 만든다면 **트레이와 같은 탭/드래그 문법**으로: 짧은 탭 = 선택, 임계 초과 = 집어들기.
    새 문법도 대기 시간도 없다. 선행 작업은 위 다섯 소유자와의 우선순위 정리다.
  - 지금 미리 만들지 않는 이유: 쓰이지도 않는 경합 처리를 떠안는다. 상한 2+ 콘텐츠가 실제로
    생길 때 함께 한다.
