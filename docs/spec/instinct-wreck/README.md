# instinct-wreck — 부서진 본능은 잔해로 남는다

> ## 목표 2줄
>
> 1. **체력이 0 이 된 본능이 화면에서 「부서졌다」고 말한다** — 지금은 포탑이 멀쩡히 서 있다.
> 2. **파괴 순간(포신이 떨어지고 연기가 터진다)과 그 이후(잔해가 계속 연기를 뿜는다)를 나눈다.**

상태: **완료 2026-08-21** · units 0~2 · 사용자 라이브 Play 확인

## 왜 지금

본능은 체력을 갖고 무너지지만, **프랍은 아무 일도 없었던 것처럼 서 있다.**
붕괴는 이미 관측되고 있다 — `BattleBridge.SyncGoalStability` 의 else 분기가 게이지를 숨기고
돌파편 VFX 1회를 터뜨리고 로그를 찍는다. 다만 **프랍에게는 아무도 말해주지 않는다.**

뿌리는 수명이 다르다는 것이다: **프랍은 맵 수명**(배치 페이즈부터 보여야 해서
`SpawnStructureViews` 가 맵 빌드 때 세운다), **엔티티는 판 수명**. 엔티티가 죽어도 프랍을
지우는 사람이 없고, 지우는 것이 답도 아니다 — 3×3 짜리 건물이 소리 없이 증발하면 그건
「부서졌다」가 아니라 「사라졌다」로 읽힌다.

방어 마음(골)은 이 처리가 이미 있다(`TilemapMapView.MarkGoalCollapsed` — 그을림 + 60% 주저앉음).
**본능만 없다.** `instinct-content`·`instinct-turret-readout` 두 스펙의 후속 후보에
「파괴된 본능의 프랍 잔존」으로 적혀 있던 그 구멍이다.

## 결정 (착수 시 확정분)

- **적용 대상은 본능뿐**(사용자 결정 2026-08-21). 적 마음·방어 마음은 이 spec 에서 손대지 않는다.
  붕괴 감지 분기는 셋이 공유하지만, 잔해 연출을 받을지는 **프랍이 컴포넌트를 갖는가**가 정한다.
- **메쉬 정점은 건드리지 않는다**(사용자 결정 2026-08-21). 탐색 결과 KayKit `cannon_base` 리그가
  이미 `base → turret → barrel` **3개의 별개 GameObject + 각자 MeshFilter/MeshRenderer** 라,
  「포신이 떨어진다」는 정점 조작이 아니라 **트랜스폼 하나 떼어내는 일**이다.
  런타임 정점 변형을 채택하지 않은 이유 셋: (a) 메쉬가 공유 에셋이라 잔해마다 `Mesh` 사본이
  필요하고, (b) 저폴리라 찌그러뜨리면 형태가 뭉개지며, (c) 「어떻게 찌그러지는가」를 코드가
  소유하게 되어 제약 6(수치는 데이터)과 충돌한다. **실루엣 변형은 부품 분해 + 주저앉음 +
  그을림으로 만든다.** 정식 파괴 아트가 생기면 프리팹 슬롯 교체로 끝난다.
- **잔해가 되어도 편은 읽힌다**(사용자 결정 2026-08-21). 그을림은 «탄 것»과 «어느 편이었나»가
  둘 다 남는 선(0.45)에서 멈춘다 — 새까맣게 태우면 `instinct-turret-readout` 이 만든
  「아군은 노랗고 적은 빨갛다」가 죽는 자리에서 죽는다.
- **연기의 출처는 `VFXPACK_FIRE_WALLCOEUR/Prefab/VFX_Smoke.prefab` 한 벌**(사용자 지정).
  거기서 사본 둘을 떠서 성격을 가른다 — 파괴 직후의 **버스트**(짧고 굵게 1회)와
  파괴 이후의 **잔불 연기**(가늘게 계속).

## Feature-wide 계약

1. **시뮬은 한 줄도 안 바뀐다.** 전부 뷰다 — ECS 컴포넌트·NativeQueue 채널·시스템 신설 0,
   밸런스 영향 0. 붕괴 관측은 **이미 있는** `SyncGoalStability` 의 else 분기 하나를 쓴다.
2. **원복 기계를 새로 만들지 않는다.** 잔해는 판 수명의 표식이고 프랍은 맵 수명인데,
   `TeardownCurrentBattle`·`TeardownGeneratedMap` 둘 다 `ClearStructureViews` 를 거쳐
   **프랍을 통째로 재생성**한다 — 원복이 공짜다. 잔해 상태를 프랍 밖(브리지 dict 등)에
   캐시하면 그 순간 원복 지점이 둘이 되고, 하나가 빠지면 「지난 판에 부순 본능이 이번 판
   배치 페이즈에 그을린 채 서 있는」 형태로 샌다.
3. **뷰는 셀로 잇는다.** 프랍은 맵 수명, 엔티티는 판 수명이라 엔티티 참조로 묶으면 매 판
   재배선이 필요하다. 셀은 두 수명 모두에서 불변이다 — `_structureTurretsByCell` 이 이미
   그렇게 하고 있고, 잔해 사전도 같은 규칙·같은 자리에서 채우고 비운다.
4. **저작 위치는 프랍 프리팹이다.** 낙하 시간·그을림 색·주저앉음 비율·연기 슬롯은 전부
   `StructureWreckView` 의 SerializeField. `StructureData`(SO)에 넣지 않는다 — 잔해의 모양은
   「이 프랍이 어떻게 생겼나」이지 「이 거점이 얼마나 센가」가 아니다
   (`StructureTurretView.turnDegreesPerSecond` 선례).
5. **포신을 돌리던 손을 먼저 놓게 한다.** `StructureTurretView` 는 매 `Update` 에
   `barrel.rotation` 을 덮어쓴다. 붕괴 시 그 컴포넌트를 끄지 않으면 떨어지는 포신의 회전이
   매 프레임 원복돼 **누운 채로 조준하는 포신**이 된다.
6. **코드가 구동하는 연출의 시간은 배틀 도메인 시계**(`TimeManager.Instance.DeltaTime(TimeDomain.Battle)`).
   `Time.deltaTime` 직독 금지 — 슬로모가 걸리면 포신 낙하와 주저앉음도 같이 느려져야 한다.
   ⚠ **파티클은 이 계약 밖이다.** Shuriken 은 자기 시뮬레이션으로 돌아 배틀 도메인 시계를
   모른다(이 프로젝트의 모든 `VfxSpawner` 원샷이 같은 한계). 연기가 슬로모를 안 타는 것은
   이 spec 의 결함이 아니라 기존 경계이고, 여기서 고치지 않는다.
7. **보드는 월드 XZ 평면이고 프랍은 월드 업라이트로 선다.** 그래서 낙하는 월드 −Y,
   연기 상승은 월드 +Y 로 **그냥 맞는다** — 벤더 VFX 의 「바닥 평면 불일치」 함정은 이 축에서
   성립하지 않는다. 대신 **정렬 대역**(벤더 order 0~2 vs 유닛 수백대)은 그대로 걸린다.
8. **벤더 에셋 무접촉.** `Assets/VFXPACK_FIRE_WALLCOEUR/**` 는 읽기 전용이다. 사본은
   `Assets/_Project/VFX/` 로 뜬다(`Burnout_Smoke.prefab` 선례). 벤더 머티리얼은 참조만 하고
   수정하지 않는다.
9. **잔해 컴포넌트가 없는 거점은 조용히 지나간다.** 마음은 원래 프리젠터가 없고 그게 정상이라
   경고 대상이 아니다(포신 미발견을 경고하지 않는 것과 같은 판단).
   ⚠ 이 침묵은 **컴포넌트 유무**에만 적용된다. 컴포넌트가 있는데 그 안의 **슬롯이 비어 있으면**
   경고한다 — 「피해는 들어가는데 화면에 아무것도 없는」 상태를 조용히 넘기지 않는다는
   `VfxSpawner` 규율(unity-vfx-integration red flag)은 그대로 적용된다.
10. **정리 코드에 `?.` 를 쓰지 않는다.** `TeardownCurrentBattle` 은 `OnDestroy` 에서도 불리고,
    그 시점엔 형제 컴포넌트가 이미 파괴돼 Unity 의 fake-null 이다. C# 의 null 조건 연산자는
    fake-null 을 모르므로 `x?.Foo()` 가 **MissingReferenceException 을 던지고 그 뒤 정리
    전체가 중단된다** — 이 파일에 실측 사고가 주석으로 박혀 있다(`BattleBridge.cs:648-658`,
    2026-08-15, `retireFlight?.CancelAll()`). **가장 좋은 답은 정리 경로를 새로 만들지 않는
    것**이다 — 떼어낸 오브젝트를 `_structureViews` 에 넣어 **이미 있는** `ClearStructureViews`
    스윕이 가져가게 한다(unit 1 채택안). 그래도 외부 참조가 남는 자리가 생기면
    **`?.` 대신 `if (x != null)`**. (`OnDisable` 자기정리도 여기선 안 된다 — 브리지 자식
    트리는 아무도 비활성화하지 않아 `OnDisable` 이 불리지 않는다.)

## 파이프라인 커버리지

새 플레이 오브젝트는 없다 — 거점 아키타입(`battle-structures`)의 **뷰 정거장 하나**에
프리젠터가 붙는다. 신설되는 것은 프랍에 **부착되는** VFX 두 벌뿐이라
`docs/reference/object-pipeline-map.md` 의 「VFX (one-shot)」이 아니라 「본 부착 VFX」 쪽 형태를
따른다 — 스포너도 큐도 새로 만들지 않고, **프랍 프리팹이 VFX 를 들고 있고 프리젠터가 켠다.**

| 정거장 | 이 spec | 확인 포인트 |
|---|---|---|
| 데이터 SO | **N/A** — `StructureData` 무변경 | 잔해 수치는 프리팹이 소유(계약 4) |
| 프리팹 소스 | `_Project/Prefabs/Structures/Instinct_{Ally,Enemy}.prefab` 변형에 잔해 리그 추가 | 벤더 KayKit 프리팹은 무접촉 — 이미 프로젝트 변형이다 |
| VFX 소스 | `_Project/VFX/InstinctWreck_{Burst,Smolder}.prefab` (VFX_Smoke 사본 2벌) | 벤더 원본 무접촉(계약 8) |
| ECS | **N/A — 시뮬 무관**(계약 1) | 컴포넌트·큐·시스템 신설 0 |
| 트리거 | 기존 `BattleBridge.SyncGoalStability` 붕괴 분기 | **신규 큐 0** |
| View | `Presentation/StructureWreckView.cs`(신규) | 프랍당 1개, 프랍 수명과 동일 |
| Pool | **N/A** — 맵당 소수(현재 최대 4기), 프랍과 같은 수명 | |
| 정렬 | `BoardSortOrder` 에 잔해 연기 대역 1개 추가 | 벤더 order 0~2 → 유닛 뒤에 깔린다(계약 7) |
| 씬 wiring | **N/A — 씬 오브젝트·SerializeField 신설 없음** | 프리팹 참조는 프랍이 들고 있다 |

## 후속 후보

- **적 마음·방어 마음의 잔해** [S] — 붕괴 분기는 이미 공유한다. 컴포넌트를 그 프랍에 붙이는
  저작만 남는다. 골은 이미 그을림·주저앉음이 있어 연기만 얹는 형태가 될 것.
- **정식 파괴 아트로 교체** [S] — 부품 분해로 만든 실루엣을 전용 잔해 프랍으로 대체.
  계약 4 덕분에 코드 0(프리팹 슬롯).
- **부서진 본능이 배치 구역을 연다** [M] — `instinct-content` 에서 살아 있는 후보.
  「부숴서 연다」는 `placeMask` 런타임 갱신이 필요해 뷰가 아니라 규칙 변경이다.
- **파괴 사운드** [S] — 이 spec 은 그림만 다룬다. `SoundManager` 축은 따로.
- **잔해에 잔불(GroundFire)** [S] — 연기만으로 부족하면 같은 팩의 `VFX_GroundFire_Circle` 를
  같은 방식으로 얹는다. 먼저 연기만으로 판단한다.
