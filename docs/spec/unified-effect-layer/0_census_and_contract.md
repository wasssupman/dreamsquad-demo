# 0 — 전수 표와 계약 싣기 (문서)

## 목적
구멍 H1~H6 의 **범위를 코드에서 센다.** 하드 케이스 둘은 표본일 뿐이라, 같은 구멍이 다른 트리거·효과에도 있는지 전수 표로 확정하고 unit 1~5 의 변경 대상을 그 표에서 뽑는다. 코드 변경 0.

## 변경 대상
- 이 폴더에 `census.md`(장부) — 표 3개:
  1. **트리거 × 원점**: `TriggerKind` 전부 × (원점 좌표의 출처 · 원점 항 형 · 대상 엔티티 유무 · 오늘 그 값을 채우는 파일:심볼).
  2. **효과 × 원점 소비**: 스킬 concrete 전부(`Scripts/Skills/Concrete/`) × (원점을 어디서 읽나: `target.CellA` / `p.EventPosition` / `ctx.Position(caster)` / 없음) · 귀속(`Source`) 을 무엇으로 채우나.
  3. **출처 × 검증 경로**: 카드 · 유닛 능력 · 악몽 · 기믹 · 액티브 × (빌더 · 거절 규칙 목록 · 그 규칙이 「원점 불가」인지 「출처 관례」인지).
- `docs/reference/battle-core-architecture.md` — 트리거/효과 절에 계약 1~6 을 **예정** 표기로 · §8 불변식 후보.
- 탐침 두 파일 머리 주석: 「`unified-effect-layer` 완료 기준」 · 각 `[Ignore]` 사유 끝에 해제 unit 번호(H1·H2 → 1 · H3 → 2 · H6 → 3). U3 로 이름·단언이 바뀌는 둘(`…귀속은_H` · `…귀속만_다르고…`)은 unit 2 에서 고친다고 적는다.
- `docs/spec/README.md` 목록 행 · Follow-up Backlog 「통합 효과 층」을 이 spec 으로 연결.

## 구현
- 표는 코드를 읽어 채운다(추측 칸은 `?` 로 두고 사유). 표 2 에서 원점 읽기 방식이 셋 이상 나오는 것이 H1 의 실체다.
- 표에서 이 spec 범위 밖(예: 원점이 필요 없는 스탯 버프)은 「N/A + 이유」.

## 완료 기준
- 표 3개 빈칸 없음(`?` 는 사유 포함) · 리드가 표본 5칸을 코드와 직접 대조.
- unit 1~5 문서의 「변경 대상」이 표와 어긋나면 이 커밋에서 같이 고친다.
- 테스트 파일은 주석만(헤드리스 918 · Ignore 5 동일).
