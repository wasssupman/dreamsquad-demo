# unified-effect-layer — 통합 효과 층

> **상태: spec 작성 2026-09-26 · 승인 대기.** 출발 맥락 = `docs/spec/battle-core-rebuild/12_next_unified_effect_layer_guide.md`(하드 케이스 실측 · 코드 지도). 계약의 근원 = 같은 spec README 「조각 E 사용자 결정」 ⑪.

## 상위 목표

**효과 하나를 어느 출처(유닛 스킬 · 드림캐쳐 · 악몽)가 어느 트리거로 쏘든 같은 경로로 발동한다.** 출처는 「누구 몫인가 · 언제까지 사는가」만 말하고, 트리거는 「어디서 터지나(원점 좌표)」만 말한다. 검증 질문은 둘이다.

- 하드 케이스 1: 「배치 시 N 안 적 전원에게 호밍 100」(유닛 A) 을 드림캐쳐 AA 가 「새로 배치된 유닛마다」 시전할 수 있나 — **그 유닛 자리에서.**
- 하드 케이스 2: 같은 운석 탄으로 「지정 칸 · N · 100」(액티브) 과 「맞은 적 자리 · M · 30」(타격 드림캐쳐) 를 만들 수 있나 — **반경·예고·낙하 그림까지.**

## 계약 (⑪ 을 코드 언어로)

1. **효과 = f(원점, 파라미터).** 원점 = 좌표 + 원점 항(제약 13: 자리형 = 칸 반폭 0.5 · 몸형 = 발동 주체의 몸) + 선택적 대상 엔티티(호밍). 효과는 출처를 모른다.
2. **트리거 = 사건 → 원점 산출기.** 커맨드 = 지정 칸 · 타격 = 맞은 적 · 남의 배치 = 배치된 유닛 · 자기 사건(사망·퇴근·주기·배치) = 주체. 산출은 트리거 종류별로 **한 곳**에 모인다.
3. **호밍 여부는 탄 궤적의 성질**이다. 요청 조립은 「대상 갈래 / 자리 갈래」로 가르지 않는다 — 반경·예고·비행시간은 효과 파라미터에서 온다.
4. **킬 귀속 = 발동 주체, 수명 = 둘 다 살아 있는 동안** (사용자 결정 U2·U3). 탄의 소유자(킬 귀속 · OnKill 연쇄 · 위협)는 **탄이 나간 유닛**(AA 면 새로 배치된 유닛, 타격 운석이면 때린 유닛)이다. 바인딩을 든 자(AA 의 호스트)는 「이 규칙이 언제까지 사는가」만 정한다. 버스트는 **원점 주체 또는 바인딩을 든 자 중 하나라도 사라지면 멈춘다.** 출처(`BindingOrigin`)는 수명·표기 꼬리표로 남는다.
5. **라이브 콘텐츠 무변.** 오늘 저작된 카드·유닛 능력·악몽의 동작은 한 줄도 안 바뀐다 — 새 조합이 열릴 뿐. 증거 = 골든 11 Verify · `EffectWitness` · 기존 코어 테스트. (골든 11 은 합성이라 이 경로를 거의 안 탄다 — 무변이 곧 동일의 증거는 아니므로 탐침·위트니스가 본 증거다.)
6. **판정 자는 하나**(제약 13). 새 경로·정리하는 경로 모두 `SkillMath.ReachFrom*` / `AttackReach.InReach*` 만 호출한다.
7. **저작 거절은 「원점을 못 뽑는 조합」만.** 출처별 블랙리스트(「카드는 OnPlace 불가」「카드 발사 명세는 주기만」「셀 탄 불가」)는 이 기준으로 다시 쓴다.
8. **enum 은 append-only**(`DcTriggerKind` · `DcPayloadKind` · 코어 `CoreEvent`/`CoreTraceChannel`). 새 사건·채널을 열면 트레이스 정거장도 같이 연다.

## 사용자 결정 (2026-09-26)

- **U1 예고는 카드마다 저작 선택** — 「맞은 적 자리에 떨어지는」 탄의 착탄 예고 원은 저작 체크 하나로 켠다(기본 꺼짐). 액티브 운석(켬)·퇴근 운석(끔) 등 기존 동작 무변.
- **U2 연사 중 원점 유닛이 사라지면 멈춘다** — AA 연사 도중 새 유닛이 퇴근·사망하면 남은 발은 나가지 않는다(호스트가 죽어도 멈춘다 — 오늘 그대로).
- **U3 킬은 탄이 나간 유닛 몫** — AA 탄의 킬·「처치 시」 연쇄는 새로 배치된 유닛에 귀속. ⑪ 의 「출처 = 귀속 꼬리표」 중 **귀속** 은 이 결정으로 「발동 주체」로 정정됐다(출처는 수명 꼬리표).
